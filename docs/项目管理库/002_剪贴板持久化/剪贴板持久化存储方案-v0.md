# 剪贴板持久化存储方案 v0

状态：implemented-v0
最后审阅：2026-07-05
来源级别：project technical proposal

本文是 [App 数据存储架构规范 v0](数据存储架构规范-v0.md) 的第一个落地场景。目标不是把现有内存数组简单落盘，而是让剪贴板历史进入统一的生产数据架构：`ClipboardRepository` 作为唯一生产事实源，SQLite 管元数据和检索，sidecar 管大图片，UI 只消费 repository read model。

## 原始事实

- 改造前 `AppState` 用内存态 `clipboardRecords`、`clipboardPayloads`、`clipboardPinnedMetadata` 驱动 UI，重启后回到 fixture/default。
- `ClipboardLiveCaptureService` 轮询 `NSPasteboard.general.changeCount`，生成 `ClipboardRecorderRecord` 和 `ClipboardRecorderPayload`。
- `ClipboardController.ingestLiveCapture` 当前只做内存插入和 changeCount/signature 去重。
- `AppState.applyClipboardPolicySilently` 当前是插入后的内存裁剪，不是保存前 capture policy，也不能跨重启。
- `ClipboardRecorderStore` 是 debug / fixture JSON store，不作为生产持久化路径。

## 目标边界

必须支持：

- App 重启后保留非排除 App 的支持类型历史。
- 文本、富文本、URL、file URL、图片 payload 可本地恢复。
- 按内容、summary、来源 App、时间、格式、Pinboard、固定状态检索。
- retention days、max items、preserve pinned、excluded bundle IDs。
- 删除、清空、策略裁剪时同步删除 DB payload、FTS、Pinboard metadata 和 sidecar。
- agent、日志、helper stdout、provider audit 默认只接触 redacted summary。

首版不做：

- 云同步、跨设备同步、团队共享、语义向量检索。
- 复杂密码管理器 / Office / 设计软件专用格式的完整恢复保证。
- helper 生产写入和 App Group 共享数据库。
- SQLCipher 默认加密。
- JSON debug store 自动迁移。

## 推荐架构

```text
NSPasteboard
  -> ClipboardLiveCaptureService
  -> ClipboardCapturePolicy
  -> ClipboardRepository
       -> SQLite metadata / search / pinboard / policy
       -> BlobStore sidecar for large payloads
  -> AppState view state
  -> Clipboard UI / paste / preview
```

`ClipboardRepository` 的职责：

- 创建和迁移剪贴板 schema。
- 插入 live capture snapshot，并做保存前 policy、去重、payload 生命周期管理。
- 加载最近记录和必要 payload。
- 提供 search/filter query。
- 固定、取消固定、移动 Pinboard、重命名、删除、清空未固定、策略裁剪。
- 保证任何删除路径都会清理 sidecar。
- 使用完整 signature 做生产去重；`signature_sha256_12` 只用于展示、诊断和兼容现有模型。

`AppState` 的职责：

- 保留 `@Published` 视图态、当前选择、筛选状态和状态提示。
- 调用 repository 后刷新 view state。
- 不直接把内存数组当作生产事实源。

## Schema v1

迁移版本通过 `PRAGMA user_version` 管理；v1 迁移必须幂等。

### `clipboard_items`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY | 兼容 `ClipboardRecorderRecord.id`。 |
| `created_at` | REAL | epoch seconds。 |
| `updated_at` | REAL | 最近元数据更新。 |
| `change_count` | INTEGER | pasteboard changeCount，仅诊断。 |
| `kind` | TEXT | `text` / `rich_text` / `image` / `url` / `file_url` / `mixed` / `unknown`。 |
| `format_summary_json` | TEXT | UTI、长度、字节数、URL/file 数量 JSON。 |
| `source_app_json` | TEXT NULL | 来源 App 候选 bundle id、名称和候选标记 JSON。 |
| `signature_sha256` | TEXT | 完整内容签名，用于生产去重。 |
| `signature_sha256_12` | TEXT | 展示和诊断短签名。 |
| `fixture_owned` | INTEGER | fixture/debug 标识。 |
| `pinned` | INTEGER | 固定状态。 |
| `restorable` | INTEGER | 是否有可恢复 payload。 |
| `excluded` | INTEGER | 是否命中排除。 |
| `snapshot_skipped` | INTEGER | 是否跳过内容快照。 |
| `summary` | TEXT | redacted 或短预览 summary。 |
| `search_text` | TEXT | 规范化检索文本；排除项不得写完整内容。 |

必须建立 `created_at`、`pinned + created_at`、完整 signature 唯一约束和短 signature 诊断索引。短 hash 字段只用于展示和诊断。

### `clipboard_payloads`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `record_id` | TEXT PRIMARY KEY | FK 到 `clipboard_items.id`。 |
| `text` | TEXT NULL | 文本 / URL / file path 文本。 |
| `rtf_data` | BLOB NULL | RTF bytes。 |
| `png_data` | BLOB NULL | 小图片 bytes。 |
| `png_sidecar_path` | TEXT NULL | 大 PNG sidecar 相对路径。 |
| `url_string` | TEXT NULL | URL / file URL 原值。 |
| `payload_byte_count` | INTEGER | payload 大小。 |
| `created_at` | REAL | 写入时间。 |

规则：文本、URL、file URL、RTF 入库；PNG 小于等于 1 MiB 入库；PNG 大于 1 MiB 写 `Blobs/`，DB 保存引用。

### `clipboard_pinboards`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PRIMARY KEY | 兼容当前内置 ID。 |
| `name` | TEXT | 展示名。 |
| `color_name` | TEXT | 色彩 token。 |
| `sort_index` | INTEGER | UI 排序。 |
| `created_at` | REAL | 创建时间。 |
| `updated_at` | REAL | 更新时间。 |

### `clipboard_pinned_metadata`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `record_id` | TEXT PRIMARY KEY | FK 到 `clipboard_items.id`。 |
| `display_name` | TEXT NULL | 用户重命名。 |
| `pinboard_id` | TEXT | FK 到 `clipboard_pinboards.id`。 |
| `updated_at` | REAL | 更新时间。 |

### `clipboard_fts`

FTS5 可用时创建，用于低敏 `search_text`。如果 FTS5 不可用，repository search 使用规范化 `LIKE` fallback。`search_text` 若包含正文、URL、file path 或 RTF 文本，安全等级等同 payload；agent/CLI 默认搜索可以命中，但不能回显匹配原文。FTS 不索引 excluded payload 原文。

## 写入规则

1. `ClipboardLiveCaptureService` 只负责读取 pasteboard 和构造 snapshot。
2. `ClipboardCapturePolicy` 在保存前判断 paused、excluded bundle、支持类型、大小限制。
3. 支持类型且未排除：保存 record + payload，计算 signature 和 payload hash。
4. 排除、暂停、不可支持或超限：只保存 skipped record、来源候选、时间和原因，不保存 payload、sidecar、FTS 和完整 `search_text`。
5. `ClipboardRepository.insert` 在事务内完成完整 signature 去重、主表、payload 和 FTS 更新。
6. `AppState` 调用 repository 后刷新 view state，并按设置调用 repository policy prune。

## 读取与搜索

- 启动加载最近 500 条，并保留 pinned。
- UI 列表读取 record + 预览所需 payload；大图片可以懒加载。
- 搜索和筛选下沉到 repository：格式、时间、来源、Pinboard 用普通索引；文本走 FTS5 或 `LIKE` fallback。
- agent/CLI 默认只读 redacted fields；完整内容读取必须走 preview confirmation，且不得直接读 SQLite 或 sidecar。

## 验收标准

- 低敏文本复制后重启 App，历史仍显示并可粘贴。
- 低敏图片复制后重启 App，历史仍有缩略图并可恢复。
- 固定、移动 Pinboard、重命名后重启仍保留。
- 中文连续片段和英文关键词搜索均可命中低敏文本。
- max items/retention 触发后，未固定旧 payload 和 sidecar 被删除，固定条目保留。
- excluded bundle 不保存 payload，UI 只显示隐私占位。
- 日志、helper stdout、provider audit、agent 默认查询不包含完整原文、图片 base64、secret 或完整文件路径。
- 删除和大量裁剪后没有 sidecar orphan；敏感清空路径执行 WAL checkpoint/truncate 或等价清理。

## v0 实施结果

- 已完成 `SQLiteConnection` / `MigrationRunner` / `BlobStore` / `ClipboardRepository` 和 repository smoke。
- 已完成 AppState 启动加载、live ingest、删除、固定、取消固定、Pinboard 移动、重命名、策略裁剪接入 repository。
- 已完成完整 signature 去重、FTS5 可用检测、LIKE fallback、sidecar 路径防护和 skipped payload 不落库验证。
- 搜索 repository API 已落地；当前 UI 仍保留现有内存过滤 API，后续如需大历史分页/复杂筛选，可继续把列表查询整体下沉到 repository。

## 待复核

- 1 MiB 图片阈值需要用真实低敏样本评估 DB/WAL 增长。
- helper/App Group 是否进入后续阶段；如果进入，必须先复测 signing 和共享容器。
