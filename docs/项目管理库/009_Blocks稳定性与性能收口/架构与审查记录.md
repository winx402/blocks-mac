# 架构与审查记录

## 1. 剪贴板生命周期

当前单一事实链路为：

1. `ClipboardLiveCaptureService` 只观察系统 pasteboard `changeCount`，即时抑制 Blocks 自写入；真实外部变化生成低敏快照。
2. `ClipboardFeatureCoordinator` 使外部捕获失效所有活动或待授权粘贴事务。
3. `ClipboardPasteOrchestrator` 为一次用户请求持有唯一 generation、token 和请求创建时的 pasteboard 版本；新请求取消旧请求。
4. `ClipboardAutoPasteCoordinator` 写入待粘贴内容后持有 write lease；恢复目标 App/输入焦点期间持续响应取消，并在发送 `Cmd-V` 前确认 pasteboard 仍属于该事务。
5. 只有仍为当前事务、确实完成写入且 pasteboard 版本未被外部复制替换时，`ClipboardStore.markCopied` 才能更新 `lastCopiedAt`。
6. Repository、内存记录、搜索和面板统一使用 `lastCopiedAt → createdAt → changeCount → recordID` 严格降序。

删除的旧复杂度：粘贴请求不再通过 `pasteQueueTail` 串行等待；激活等待不再创建脱离父任务的嵌套 Task；取消后的 `try? sleep` 不再继续轮询或发送按键；置顶不再重新加载全部记录和预览。

## 2. 已确认根因与证据

### 2.1 测试污染正式数据

- 旧 hosted `BlocksAppTests` 启动完整 AppModel，并曾打开正式 Application Support 数据库。
- 正式库中一条旧图片记录的 `lastCopiedAt` 修改时刻与测试宿主运行日志精确一致；这是此前排序测试文本和无用户操作顺序变化的直接来源之一。
- 修复后测试宿主使用每进程、每次启动唯一的临时存储根目录，并禁用迁移、全局快捷键、实时捕获和验证面板自动打开。
- 全量 hosted 测试前后，正式数据库文件 mtime、大小、记录数、最大 `lastCopiedAt` 和最大 `changeCount` 均未变化。该证据不包含任何剪贴板正文。

### 2.2 过期粘贴事务

- 旧 `pasteQueueTail` 会让旧请求在新请求后继续排队；目标激活等待又使用独立嵌套 Task，父任务取消不能及时终止它。
- 待辅助功能授权请求在外部复制后没有清空，后续权限刷新可重新执行旧记录。
- 请求创建到面板关闭之间没有 pasteboard 版本校验；旧请求可覆盖这段时间的新复制。
- 写入后恢复目标 App/焦点期间没有 pasteboard 所有权校验；用户复制新内容后仍可能发送 `Cmd-V` 或提升旧记录。

当前通过请求前版本、写后 lease、generation/token、取消传播和外部捕获失效共同关闭上述窗口。100 轮假 pasteboard 交错测试验证外部复制后旧 lease 不能发送或提升。

## 3. 状态与性能收口

- `AppModel` 只转发跨场景需要的功能开关，不再把每个 Feature Store 的变化广播到整个主窗口；功能页继续直接观察自己的 Store。
- `ClipboardStore` 维护轻量搜索 revision，标签变化合并到下一主线程周期；置顶只更新单条数据库记录和内存排序，不再整库读取预览。

## 6. 剪贴板 I/O 进程隔离

### 6.1 已确认边界

- `Blocks` 生产 App target 不再直接访问 `NSPasteboard.general`。系统剪贴板的 `changeCount`、types、单项 representation 读取、竞争校验、清空和写入全部位于嵌入式命令行进程 `BlocksClipboardBroker`。
- Broker 不注册 LaunchAgent，不修改系统 defaults、TCC 或 Screen Sharing 配置，不申请网络、Accessibility、App Group 或 Mach lookup。签名 Debug 产物的 Broker entitlement 只有 `app-sandbox` 与 `inherit`。
- App 与 Broker 使用长度前缀 binary plist 管道。每个请求有 1 秒硬截止；超时后 App 对所持 PID 执行确定性终止并重建，旧 generation 的 write lease 自动失效。
- `BlocksClipboardBroker` 与翻译选区 helper 只允许复用无状态工程基础设施；两者保持独立进程、权限、IPC、生命周期和故障域。

### 6.2 捕获与写入热路径

- 被动捕获只保留一个 in-flight 与一个 latest pending；中间变化合并。用户主动写入会取消 staging、终止被阻塞的被动 Broker，并在新 generation 上优先执行。
- observation task 持有独立 identity；stop/start 后旧 generation 的 defer 无权清除新任务 slot 或消费新任务 pending。
- 捕获顺序固定为：自写入确认、前置策略过滤、一次 types、marker 过滤、选择一个 representation、一次内容调用、`changeCount` 复核。representation 优先级为 file URL、PNG/TIFF 二选一、URL、RTF、text。
- remote、Transient、Concealed、AutoGenerated marker 不读取内容。Screen Sharing 活跃但 marker 缺失时，observe 只返回包含 `changeCount`、选定 representation family/type 与 advertised types 的无正文 ticket；500 ms 后才首次解析。
- 首次解析沿用 1 秒硬截止；超时后只为同一 `changeCount` 等待 1.5 秒并补试一次，补试窗口为 250 ms。版本变化、失败或第二次超时都会永久结束该条处理；单条最多两次正文调用，不创建空历史记录，也不让该失败污染后续变化的 poisoned/circuit 状态。
- 普通 observe 超时使用同一 poisoned `changeCount` 并计入 30 秒内三次重启的全局保护；baseline 超时只计重启次数，不生成 poisoned 版本；deferred resolve 超时两者都不参与，避免一个远端条目暂停后续变化。用户主动写入保持显式优先级，会终止正在执行的被动 Broker；等待中的 ticket 在写入改变版本后由 Broker 前置 `changeCount` 校验拒绝，不读取正文。
- Screen Sharing 与前台来源应用状态由 `NSWorkspace` 启动、终止、激活通知维护；启动时只扫描一次 `runningApplications`，0.7 秒轮询不再遍历进程或读取应用名称。
- file URL 只保存引用，普通文本路径不触发文件 I/O；RTF 文本从已取得的 RTF 本地派生；PNG 读取失败不再继续请求 TIFF。
- 写入继续遵循新内容预构造、实际 `changeCount` 竞争检查、一次 `clearContents()`、一次 `writeObjects()`，失败不读取或恢复旧剪贴板。
- 普通历史粘贴不使用 0.7 秒被动轮询缓存作为 CAS 基线；事务实际开始时向 Broker 获取当前 baseline。只有已经成功写入、等待辅助功能重试的请求才复用 prepared write lease。

### 6.3 数据与生命周期

- `ClipboardRecorderPayload` 的运行时 PNG/RTF 改为 `Data?`；显式 JSON/fixture 仍兼容 `png_data_base64` 与 `rtf_data_base64` key。SQLite schema 和现有 BLOB/sidecar 结构不迁移。
- 超过 1 MiB 的图片使用随机 staging token。App 与 Broker 都固定持有 staging 根目录 FD，并用 `openat`/`fstatat`/`unlinkat` 操作；根目录为 `0700`、payload 为 `0600`，token 与 inode/device 均校验。
- App 终止先进入不可逆 `finalizing`，拒绝新 staging lease，等待已有 root operation 归零，再清理并删除根目录；生产进程不能从 `terminated` 回到运行态。
- Broker 每 250 ms 检查声明的父 PID；父进程消失后清理并退出，清理自身若不返回则由 1 秒 `SIGALRM` 硬截止兜底。剪贴板功能关闭或被动监听停用后，空闲 Broker 在 1.5 秒内回收。

## 7. 全局性能治理与截图阶段切换

### 7.1 截图事实链路

- 冻结模式先完成一次全显示器快照，再创建选择 overlay；第一帧选择层直接显示这组快照，不存在 live overlay 到 frozen image 的异步替换。
- 冻结窗口、区域和显示器都由同一组显示快照规划、裁剪和构建 editing context；鼠标完成后不重新查询 ScreenCaptureKit 内容，也不再调用独立 live window capture。
- 非冻结模式进入选择时保持真实桌面。鼠标完成后按相关显示器各捕获一次，最终图片和 editor source context 共用这组快照；窗口选择从可见显示快照裁剪，因此不会为了编辑范围额外捕获第二份显示内容。
- `ScreenshotSelectionSurfaceHandoff` 是一次性关闭权。普通交互捕获完成后，选择层继续可见但不接收鼠标；Editor Store、HostingView 与 Panel 完成布局和首帧提交后，在同一主线程无动画事务中显示编辑器并结束 handoff。失败与权限异常由 defer/失败路径结束，滚动截图因必须让用户操作桌面而在滚动捕获前结束。

### 7.2 轻量诊断

- Clipboard 只保留 inspect/defer/resolve/timeout/retry/persist 的高信号 `Logger`/`OSSignposter`；无变化 observe 和 baseline start/finish 降为 debug。
- Screenshot 记录 shortcut、snapshot-ready、selection-ready、selection-finished、editor-first-frame，不记录截图像素、路径、OCR 文本或其他内容。
- 不建立持续全局采样器。只有下列预算失败并取得采样栈的路径，才进入后续重构。

### 7.3 Release 验收预算

- 阻塞 provider 场景主线程 heartbeat 最大间隔 `<100 ms`；Broker 首次超时并回收 `<1.25 s`；同一变化正文调用不超过两次。
- 30 分钟空闲时 Blocks + Broker 平均 CPU `<1%`；预热后 RSS 增长 `<30 MB`；helper 数量不增长；`ClipboardBroker` info 日志每分钟不超过 2 条。
- 冻结模式 mouse-up 到 editor first frame p95 `<150 ms`；非冻结模式 p95 `<350 ms`。
- 连续 20 次截图后 RSS 相对预热基线增长 `<50 MB`；关闭编辑器后 IOSurface 回落到基线的 `120%` 内。

这些数值是验收阈值，不是当前已通过结论。自动化可以验证调用次数、顺序、超时回收和日志结构；30 分钟 soak、真实 Screen Sharing 与截图 p95 必须由签名 Release 安装版实测后才能记为 PASS。

### 7.5 2026-07-28 截图过渡与气泡拖动收口

- 选择 overlay 与参数工具条先以透明状态完成创建、布局和绘制，再在同一个零时长 AppKit 事务中提交；冻结模式的首次目录和快照在任何选择窗口出现前完成，动态切换冻结仍使用独立刷新路径。
- 默认冻结路径复用首次 `SCShareableContent`；非冻结路径优先从该目录取得 Blocks 自身 application 并按 application 排除，因此 mouse-up 后无需再次查询窗口目录。只有首次目录无法识别自身 application 时才执行既有 fresh-query 窗口排除回退。
- `finish` 只停止输入并提交结果，不释放选择层依赖的候选、显示器和冻结像素。最终 editing context 生成后，选择层改用同一 composite source 的静态 handoff frame；视觉资源只在 handoff、取消或失败的统一终点释放。

- 工具条不再通过 reserved canvas 缩小或平移桌面截图；全屏和靠边 crop 始终使用完整 source frame，工具条只在画布上方浮动。
