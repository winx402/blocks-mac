# 009 Blocks 稳定性与性能收口

状态：implementing
最后审阅：2026-07-27
来源级别：project index

## 目标

- 消除能够改变用户数据顺序、造成误粘贴或提交过期渲染结果的竞态。
- 收敛 AppModel、剪贴板面板和截图编辑器的高频状态边界，降低无关重绘和主线程工作。
- 统一设置表单尾列与截图步骤布局的已确认交互契约。
- 以隔离测试、静态分析、全量回归和安装版低敏操作验证结论，不把推断写成根因。

## 当前范围

- 剪贴板：捕获、自写入抑制、粘贴事务、记录置顶、Repository/Store/搜索刷新。
- 截图：步骤文字动态布局、选择底图失效、渲染任务取消和脏结果拒绝。
- UI/架构：水印设置尾列、AppModel 发布边界、悬浮详情事件驱动更新。
- 验证：测试数据隔离、低敏事件序列、Debug/Release/Analyze、现有 P14/P15/P17/P3-C 门禁。
- 剪贴板 I/O：独立 Broker、可回收超时边界、最新值背压、单表示读取、受限 staging、父进程与 idle 生命周期。
- 剪贴板远端 promise：Screen Sharing 未标记条目延迟解析、单 changeCount 两次上限、后续变化不连带降级。
- 截图阶段切换：冻结快照先于选择层、交互捕获单一源图、选择层到编辑器首帧原子交接。
- 性能预算：只对有采样证据且违反固定 Release 预算的路径实施修复。

## 非目标

- 不改变剪贴板严格排序规则及 quick paste 的既有产品语义。
- 不重构未发现 P0/P1 证据的整个模块，不推进 005、006 的项目阶段。
- 不读取、记录或提交真实剪贴板正文、截图或水印内容。
- 不尝试修复 Blocks 退出后仍存在的 macOS Screen Sharing 双向剪贴板系统故障，也不修改相关系统配置。
