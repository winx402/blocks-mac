## 1. 阶段目标

Step 4 聚焦剪贴板条目详情页：让详情页从只读信息面板升级为可编辑、可阅读、布局稳定的信息面板，并明确编辑后对内部内容、派生字段、可见摘要、搜索索引和更新时间的影响。

本阶段只覆盖详情编辑与元数据组织，不进入 Step 5 隐私页真实 App 清单 / CLI 广义对象管理，不进入 Step 6 集成验收，不写技术方案，不做开发实现。

## 4. 明确非目标

本阶段不覆盖：

- 图片本体编辑、裁剪、涂抹、重编码或替换。
- 文件本体编辑、移动、重命名、打开 Finder、同步外部文件或改写真实文件路径。
- 其他非文本类 payload 本体编辑。
- 完整富文本编辑器扩展，例如字体、字号、颜色、表格、图片内嵌、复杂 HTML 清理工具栏。
- 系统剪贴板同步写回；保存历史记录不改变当前系统剪贴板内容。
- Step 5 隐私页真实 App 清单、系统 App 图标、CLI 广义对象管理。
- 日志、CLI、provider、自动化输出策略重设计。
- Step 3 面板 hover、toolbar、单击 / 双击控件和列表密度继续重设计。

## 5. 用户路径

Step 4 优先保障以下路径：

1. 用户打开某条剪贴板记录详情。
2. 对可编辑类型进入编辑态或直接在详情编辑区修改内容。
3. 修改后出现 dirty state，保存 / 取消操作区保持稳定位置。
4. 用户点击保存，保存成功后详情内容、摘要、搜索索引和更新时间更新。
5. 用户点击取消，编辑区恢复到最近一次已保存内容。
6. 保存失败时，用户看到失败反馈，当前编辑内容保留，可重试或取消。
7. 用户试图在 dirty state 下切换条目或关闭详情时，系统明确要求保存、放弃或继续编辑。
8. 用户查看详情元数据，短项紧凑展示，长项单独成行，长内容可复制或查看完整语义。

### 6.1 URL 编辑规则

- URL 类型在 Step 4 中保持 URL record kind，不因输入普通文本自动转换为 text record。
- URL 保存前必须满足技术方案定义的 URL 合法性规则；PRD 建议至少要求可解析的绝对 URL。
- 非法 URL 不应静默保存；应显示 inline 错误，保存按钮保持不可用或保存失败后停留在编辑态。
- URL 编辑不触发网络请求，不验证远端是否可访问。

技术方案待确认：当前 URL record 的数据模型是独立 payload、文本 payload 附带识别，还是派生 URL 字段；保存时如何保证 record kind 和搜索字段一致。

### 6.2 富文本编辑规则

产品目标：

- 用户编辑富文本文本内容后，尽量保留原富文本格式。
- 格式保留至少应评估段落、链接、粗体 / 斜体、列表等常见格式是否可稳定保留。
- 保存后派生纯文本需要同步更新，用于摘要和搜索。

硬性边界：

- 不得把“富文本可编辑”默认为“可以静默丢格式”。
- 如果技术方案确认无法可靠保留格式，必须回到项目负责人处做范围取舍。可选取舍包括降级为纯文本化编辑、只编辑派生纯文本、或暂缓富文本编辑。
- 任何降级都需要在 PRD 或后续方案中明确用户可见影响，不能只在实现中隐式发生。

### 6.3 图片 OCR 文本编辑规则

- OCR done 且存在可编辑 OCR 文本时，允许编辑 OCR 文本。
- OCR pending / running 时，不进入编辑态；详情展示 OCR 处理中状态。
- OCR failed / retry 状态下，不直接编辑 OCR 文本；保留 Step 1 已接受的重试入口或状态承载。
- OCR done 但未识别到文字时，详情展示空结果状态；是否允许用户手动新增 OCR 文本属于技术 / 产品后续确认项，不作为 Step 4 默认交付。
- 编辑后的 OCR 文本标记为用户编辑内容或等价状态，避免后续 OCR retry 静默覆盖用户编辑结果。

技术方案待确认：OCR 文本当前是 OCR overlay、派生字段、搜索文档字段还是独立 annotation；重试 OCR 时如何处理用户已编辑 OCR 文本。

## 7. 编辑状态矩阵

| 状态 | 进入条件 | 用户可见行为 | 可用操作 | 退出条件 |
| --- | --- | --- | --- | --- |
| read-only | 记录不可编辑，或 OCR 尚无可编辑文本。 | 内容只读，展示不可编辑原因或状态。 | 复制元数据、查看内容；如 OCR retry 可见则可重试。 | 切换到可编辑记录，或 OCR 完成并生成可编辑文本。 |
| edit-clean | 可编辑记录打开，当前草稿与已保存内容一致。 | 编辑区可输入；保存按钮占位稳定但禁用或弱化；取消可用或弱化。 | 编辑、切换条目、关闭详情。 | 用户修改内容后进入 dirty。 |
| dirty | 草稿与已保存内容不同。 | 保存 / 取消操作区保持固定位置；显示未保存状态。 | 保存、取消、继续编辑；切换条目 / 关闭时触发未保存变更处理。 | 保存、取消、放弃更改。 |
| saving | 用户点击保存。 | 保存按钮显示处理中；编辑区可暂时锁定或保持可读；不得页面跳动。 | 等待保存完成；可按技术方案决定是否允许取消保存。 | 保存成功或失败。 |
| save-success | 保存事务完成。 | 内容显示为新保存值；dirty 清除；更新时间更新；成功反馈可短暂显示。 | 继续编辑、切换条目、关闭详情。 | 成功反馈消失后回到 edit-clean。 |
| save-failed | 保存事务失败。 | 失败反馈明确；用户当前草稿保留；已保存内容不被部分污染。 | 重试保存、取消回到已保存内容、继续编辑。 | 重试成功、取消、继续编辑后保持 dirty。 |
| cancel | 用户点击取消。 | 草稿恢复到最近一次已保存内容；dirty 清除；布局不跳动。 | 继续编辑、切换条目、关闭详情。 | 回到 edit-clean。 |
| dirty-navigation | dirty 状态下切换条目、关闭详情或关闭面板。 | 提示保存、放弃更改或继续编辑。 | 保存、放弃、继续编辑。 | 保存成功后继续原动作；放弃后继续原动作；继续编辑则停留。 |

## 8. 保存模型

### 8.1 显式保存 + 取消

必须满足：

- 编辑不会自动提交。
- 保存和取消是显式操作。
- 保存 / 取消按钮或操作区有稳定布局位：dirty state 出现或消失时，不得导致详情页整体跳动。
- PRD 建议采用固定 footer / toolbar 或常驻占位按钮；按钮可根据状态启用、禁用、loading，但不能突然插入导致内容重排。
- 保存中状态应防止重复提交。
- 取消只撤回当前未保存草稿，不删除历史记录。

键盘和可访问性：

- 保存 / 取消操作必须可键盘访问。
- 如果支持快捷键，`Command-S` 可保存、`Escape` 可取消或关闭确认；具体快捷键由 UI / 开发确认。
- VoiceOver 应能读出当前 dirty / saving / failed 状态和保存 / 取消按钮状态。

### 8.2 保存失败与回滚

保存失败必须满足：

- 用户编辑草稿保留在编辑区，不丢失输入。
- 已持久化内容、派生字段、摘要、索引和更新时间不得处于部分成功的用户可见状态。
- 如果底层发生部分写入失败，用户可见结果必须回滚到最近一次一致状态，或明确保持在“保存失败、未提交”状态。
- 失败反馈应在操作区或编辑区附近显示，不遮挡主要内容。
- 用户可以重试保存，也可以取消回到最近一次已保存内容。

技术方案待确认：payload、派生字段、搜索索引、摘要和更新时间能否在同一事务中更新；如果索引更新失败但 payload 已保存，如何回滚或标记待重建。

### 8.3 未保存变更切换 / 关闭

dirty 状态下，用户切换条目、关闭详情、关闭面板或点击会导致离开编辑上下文的操作时，必须出现明确处理路径：

- 保存并继续。
- 放弃更改并继续。
- 继续编辑，留在当前条目。

不得静默丢弃 dirty 内容，也不得静默保存。

补充规则：

- 保存成功后，搜索新内容应可命中，旧内容不应继续作为当前记录的命中依据，除非技术方案定义了索引异步重建中的短暂 pending 状态。
- 如果搜索索引更新采用异步队列，用户必须能看到保存已完成但索引待更新或可恢复的状态；不能把索引失败静默吞掉。

## 10. 编辑区布局要求

必须满足：

- 编辑区默认高度为 2 行。
- 编辑区最多展示 4 行。
- 超过 4 行后，编辑区内部滚动，不把详情页整体无限撑高。
- 详情内容字体不受条目列表字体大小设置影响。
- 编辑区在 read-only、edit-clean、dirty、saving、failed 状态下尺寸稳定。
- 错误提示、dirty 提示、保存 / 取消操作不得挤压编辑区到不可用。
- 长文本、长 URL、富文本纯文本和 OCR 文本都应在编辑区内有明确换行 / 滚动策略。

PRD 不指定具体字体、行高和 px 高度；这些由 UI / 技术方案确认，但必须满足 2 行默认、4 行上限和内部滚动。

## 11. 元数据组织

### 11.1 布局原则

- 正文编辑区优先级高于元数据区。
- 短元数据项一行两个，形成紧凑两列。
- 长元数据项单独一行，避免挤压另一列或正文编辑区。
- 元数据区可以在详情页内部滚动或折叠，但不得导致编辑区高度跳动。
- 元数据值可截断、换行、展开、复制或通过 tooltip / accessibility label 保留完整语义。

### 11.2 短项与长项建议

| 元数据类别 | 默认布局 | 示例 |
| --- | --- | --- |
| 短项 | 两列 | 类型、创建时间、更新时间、大小 / 字符数、OCR 状态、标签数量。 |
| 条件短项 | 两列，过长时降级为长项 | 来源 App、来源窗口、bundle id 摘要。 |
| 长项 | 单行 | URL、file URL 摘要、长文件名、长来源 App、长标签列表、错误详情。 |
| 标签 / 收藏 | 单行或可换行区域 | 收藏、普通标签、多标签列表。 |

### 11.3 长内容处理

必须满足：

- 长 URL 不撑破详情页；可显示 host / path 摘要，并提供复制完整值路径。
- file URL 不展示真实本机完整路径到验收证据；UI 可展示有界路径摘要，复制完整值的具体边界由技术方案确认。
- 长来源 App 名称不挤压编辑区；视觉截断时保留 accessibility label。
- 长标签列表不覆盖正文编辑区；可换行、截断或折叠。
- 多语言长句、长单词和日文长文案不导致元数据两列重叠。

## 12. UI / 交互验收

### 12.1 编辑入口

PRD 接受以下任一首版形态，由 UI / 技术方案选择：

- 可编辑类型打开详情后，文本区直接可编辑。
- 可编辑类型打开详情后，点击编辑按钮进入编辑态。

无论采用哪种形态，必须满足：

- 用户能明确知道当前是否可编辑。
- 不可编辑类型有明确原因或只读状态，不让用户误以为保存失败。
- 进入编辑态不导致保存 / 取消区域插入式跳动。

### 12.2 保存 / 取消

验收样例：

- 修改 plain text 后，保存按钮从禁用变为可用，操作区位置不变。
- 点击取消后，文本恢复到修改前已保存内容，dirty 清除。
- 点击保存成功后，详情内容、面板摘要、搜索索引和更新时间更新。
- 保存失败后，草稿仍在，失败反馈可见，可重试或取消。
- dirty 状态下切换条目，出现保存 / 放弃 / 继续编辑路径。

### 12.3 富文本

验收样例：

- 富文本 fixture 含粗体、链接或列表时，保存后应尽量保留原格式。
- 如果技术方案确认某些格式不能保留，必须在方案或复审中明确降级范围。
- 不允许保存后悄悄把富文本变成普通纯文本而无任何产品取舍记录。

### 12.4 OCR 文本

验收样例：

- OCR done 且有文本的图片条目可以编辑 OCR 文本。
- OCR pending / running 时展示状态，不提供编辑。
- OCR failed 时展示失败和可重试状态，不把失败 OCR 文本当成可编辑正文。
- 保存 OCR 文本后，图片本体不变，OCR 文本展示和搜索命中更新。
- 后续 OCR retry 不得静默覆盖用户已编辑 OCR 文本；具体冲突策略待架构确认。

### 12.5 元数据

验收样例：

- 短项两列展示，视觉对齐。
- 长 URL 单独一行，不挤压编辑区。
- 长来源 App 和长标签不与正文编辑区重叠。
- 元数据复制、展开或 tooltip 路径可用。
- 窄窗口下元数据降级为单列或长项单行，不重叠。

## 13. 低敏测试 fixture 建议

验收证据必须使用 synthetic / fixture 内容，不复制真实用户剪贴板正文，不包含真实 home path、邮箱、secret、Authorization header、二维码、验证码或真实文件路径。

| fixtureID | 类型 | 用途 |
| --- | --- | --- |
| `detail_text_alpha_004` | plain text | 文本编辑、dirty、保存、取消、搜索更新。 |
| `detail_text_long_004` | plain text | 2 行默认、4 行上限、内部滚动。 |
| `detail_url_valid_004` | URL | URL 编辑、摘要和搜索索引更新。 |
| `detail_url_invalid_004` | URL | 非法 URL inline 错误和保存阻止 / 失败。 |
| `detail_rtf_format_004` | rich text | 富文本格式保留风险，含粗体、链接、列表。 |
| `detail_image_ocr_done_004` | image OCR | OCR 文本编辑和索引更新，示例 token `VISION-004`。 |
| `detail_image_ocr_pending_004` | image OCR | OCR 处理中不可编辑状态。 |
| `detail_image_ocr_failed_004` | image OCR | OCR 失败 / 重试状态与不可编辑边界。 |
| `detail_file_readonly_004` | file URL | 文件本体不可编辑，仅展示元数据。 |
| `detail_metadata_long_004` | metadata | 长 URL、长文件名、长来源 App、长标签、多语言长句。 |
| `detail_save_failure_004` | save failure | 保存失败、草稿保留、回滚和重试。 |

最低验收矩阵：

- 可编辑类型：plain text、URL、富文本、图片 OCR 文本。
- 不可编辑类型：图片本体、文件本体、其他非文本类 payload。
- 状态：read-only、edit-clean、dirty、saving、save-success、save-failed、cancel、dirty-navigation。
- 布局：默认宽度、窄宽度、长内容、多语言。
- 数据更新：payload / 派生字段 / 摘要 / 搜索索引 / 更新时间 / 系统剪贴板不更新。
- 可访问性：保存 / 取消、错误反馈、dirty 状态、元数据复制和 OCR 状态可键盘访问并有可理解语义。

## 14. 需要 App 架构师确认的问题

1. 富文本 payload 当前保存格式是什么，是否能在编辑文本内容后可靠保留格式。
2. 富文本格式保留的最低可接受范围是什么；如果无法保留，应该降级为哪种产品语义。
3. plain text、URL、rich text、OCR text 的保存事务如何覆盖 payload / 派生字段 / 摘要 / 搜索索引 / 更新时间。
4. 搜索索引更新是同步事务、异步队列还是混合模型；索引失败时如何回滚或标记待修复。
5. URL record 的类型模型是什么，非法 URL 如何阻止保存，以及是否允许 URL record 改变 kind。
6. OCR 文本当前存放位置是什么；用户编辑后的 OCR 文本如何与 OCR retry、confidence、language metadata 共存。
7. OCR retry 是否可能覆盖用户编辑后的 OCR 文本；如可能，需要怎样的冲突策略。
8. 更新时间字段应更新 record updatedAt、contentUpdatedAt、ocrTextUpdatedAt 还是多个字段。
9. 保存中切换条目、记录被删除、外部更新同一记录时如何处理冲突。
10. 详情页元数据展示是否应基于 bounded read model，避免为了布局一次性读取不必要的大 payload。

## 15. 需要角色复审的问题

### 15.1 UI / 交互设计师

- 编辑入口采用直接编辑还是点击编辑更符合当前详情页信息结构。
- 保存 / 取消操作区采用固定 footer、toolbar 还是常驻占位按钮。
- dirty、saving、failed、read-only、OCR 状态的文案和视觉反馈。
- 2 行默认 / 4 行上限的编辑区在中文、英文、日文长文本下的可读性。
- 元数据短项两列、长项单行在窄宽度下的降级方式。

### 15.2 开发

- 保存事务和回滚能否覆盖 payload、派生字段、摘要、索引和更新时间。
- 富文本、URL、OCR 文本编辑分别落在哪些模型和 repository path。
- dirty state、切换条目确认、保存中防重复提交的状态流。
- 编辑区内部滚动、详情页整体滚动和元数据区滚动是否冲突。
- 是否需要新增 Step 4 专属 verifier 或沿用 P13 系列门禁。

### 15.3 测试 / 质量

- 可编辑类型、不可编辑类型、保存失败和 dirty-navigation 的 fixture 是否足够。
- 搜索索引更新和系统剪贴板不更新如何用低敏证据证明。
- 富文本格式保留如何验证，无法保留时如何标记为阻塞或待决策。
- OCR pending / running / failed / done 状态与编辑态互斥如何验收。
- 元数据长内容、多语言、窄宽度和可访问性检查清单。

## 16. 建议门禁方向

PRD 不指定实现脚本，但建议后续技术方案提供 Step 4 专属门禁，可命名为 P13D 或等价 gate，最低断言包括：

- Step 4 PRD、技术方案、开发记录存在并引用当前阶段。
- plain text、URL、富文本、图片 OCR 文本的可编辑 / 不可编辑边界有 fixture 覆盖。
- 保存 / 取消操作区布局稳定，不因 dirty state 出现 / 消失导致跳动。
- 保存成功更新 payload 或对应派生字段、摘要、搜索索引和更新时间。
- 保存失败不丢草稿，不产生用户可见的部分提交。
- 系统剪贴板不被保存动作更新。
- 富文本不能静默丢格式；如降级必须有项目负责人接受记录。
- OCR 文本编辑不改图片 payload 本体。
- 编辑区默认 2 行、最多 4 行、超过内部滚动。
- 元数据短项两列、长项单行，长内容不挤压编辑区。
- 低敏 fixture 和证据不含真实剪贴板、真实路径、secret、二维码或验证码。
