# 004_剪贴板打磨 Step 4 技术方案 v1 复核 v0

## 结论

结论：`technical-plan-accepted`。

App 架构师已产出 `step_4/App架构师-技术方案-v1.md`。项目负责人复核认为：技术方案 v1 已吸收技术方案复审收敛中的 P1，范围保持在 Step 4，可以进入开发派发。

不需要回用户澄清。

## P1 关闭判断

### Mutable content revision / optimistic concurrency token

状态：关闭。

v1 已明确：

- 不复用 capture-based revision。
- 新增 `contentRevision` / `content_version` 语义。
- 保存命令使用 `expectedContentRevision`。
- 保存成功返回 `newContentRevision`。
- P13D 覆盖 revision 前进、stale revision conflict 和 cache invalidation。

### Schema migration v4 与 OCR source backfill

状态：关闭。

v1 已明确：

- v4 migration。
- OCR source 默认 `none`。
- 仅 succeeded 且 OCR text 非空的旧行回填 `vision`。
- pending / failed / empty / non-OCR 保持 `none`。
- userEdited 只能由 Step 4 save command 写入。
- P13D / P13A 覆盖 v3 到 v4 migration smoke。

### P13D per-scenario evidence 与 deterministic fixtures

状态：关闭。

v1 已明确：

- P13D 缺脚本、缺 scenario、缺 fixture id、缺 mutation count、缺 sanitizer、缺 purpose matrix、缺 state ownership、缺 call graph negative scan 均 fail。
- 使用 isolated temp database / fixture repository、deterministic record id、fake clock、synthetic content。
- fault injection 覆盖 search document fail、FTS fail、transaction rollback、record deleted、payload missing、expectedContentRevision mismatch、late OCR completion。
- 输出 per-scenario evidence，不只输出汇总布尔值。

### P13D state ownership、purpose matrix 和 call graph

状态：关闭。

v1 已明确：

- AppState / AppModel / ClipboardController 不成为 detail fact source。
- DetailStore 只持有 draft / UI 状态。
- Repository 是持久化事实源。
- 正向 purpose 包含 `detailEditRead`、`detailFullValueRead`、`detailEditSave`。
- 如实现 copy full value，使用显式 `detailCopyFullValue` 或等价动作。
- 负向禁止复用 hover / paste / copyPlainText / translationPreview / ocrInput / searchIndex / provider。

### Pasteboard read/write 与 full value copy

状态：关闭。

v1 已明确：

- save path `pasteboard_read_attempts=0` 和 `pasteboard_write_attempts=0`。
- static / call graph denylist 同时覆盖读写 API。
- `detailFullValueRead` 不等于系统 pasteboard 写入。
- copy full value 是独立显式动作，使用 fake pasteboard / spy 验收。
- P13D 分开输出 full value read/copy 与 pasteboard read/write。

### Rich text fidelity 和 URL validation

状态：关闭。

v1 已明确：

- `ClipboardRichTextFidelityService` 是 conservative service。
- rich text evidence 分项输出 link、paragraph、inline style、list、kind、plain text derivation。
- 不能只比较 plain text。
- `ClipboardDetailURLValidator` 只做本地解析，不发网络、不 open URL、不触发系统动作。
- URL pass/fail fixture 明确，URL 全文不进入 evidence。

### Low-sensitive sanitizer 与 denylist

状态：关闭。

v1 已明确：

- P13D stdout、stderr、JSON、manifest、failure detail、fixture snapshot 均过 sanitizer。
- Forbidden pattern 覆盖 Authorization、Bearer、API key、token、password、OTP、private key、cookie/session/JWT/webhook、base64/data:image、OCR full dump 等。
- failure schema 不输出命中原文。
- Step 4 touched files 和 call graph 禁止 provider / network / automation / permission 相关能力。

## 接受边界

技术方案已接受，但仍保留实现阶段风险：

- Rich text fidelity 需要开发阶段 fixture 证明；无法证明时不得静默降级，必须回到项目负责人做降级 / 暂缓 / 只读接受。
- 真实 UI / 真实 VoiceOver / 多语言极端布局仍需后续低敏 evidence 或 Step 6 回扫；技术方案阶段不声称已实测。
- Copy full value 若写系统 pasteboard，必须通过显式动作和 fake pasteboard / spy 验收，不得与保存路径混淆。
