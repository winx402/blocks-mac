## 技术方案范围

只覆盖 Step 4：详情编辑与元数据组织。

必须覆盖：

1. Bounded detail read model 和 bounded metadata snapshot。
2. 完整 payload read、edit draft、save mutation 的 purpose 边界。
3. 单一 Store / Repository detail edit save command 或等价窄 API。
4. plain text、URL、rich text、OCR text 的保存模型。
5. 保存事务、异步 reindex 例外、`saved-index-pending` / `reindex-failed` 的技术边界。
6. 保存失败、record missing、payload missing、save conflict 的回滚和 UI 状态输入。
7. 系统 pasteboard 不写入的 fake pasteboard / adapter spy / static scan 证据路径。
8. 富文本格式保留能力评估和降级 gate。
9. URL absolute URL / scheme / custom scheme / file URL 边界。
10. OCR user-edited / override / locked source 与 retry / late completion 冲突处理。
11. 编辑区 2 行 / 4 行、固定 action bar、元数据两列 / 窄宽度单列所需数据与状态输入。
12. P13D fail-closed verifier 的职责、fixture、输出 schema 和与 P13A / P13B / P13C / P8 / P8I / P9A / P9B / P11E 的关系。

明确不覆盖：

- Step 5 隐私页真实 App 清单、图标和 CLI 广义对象管理。
- Step 6 集成验收。
- 完整富文本编辑器功能扩展。
- 图片本体 / 文件本体编辑。
- 系统剪贴板同步写回。
- Provider / 自动化输出策略重设计。

## 技术方案必须回答的问题

PRD v1 第 20 节的 12 个问题必须逐条回答。尤其：

- 富文本 payload 当前格式与可保真范围。
- 无法保真时的降级 / 暂缓 / 只读技术判断，以及需要项目负责人接受的触发条件。
- 单一 detail edit save command 的 Store / Repository 边界。
- payload、summary、search document、FTS、updatedAt、detail read model 的事务或异步 reindex 方案。
- 系统 pasteboard 不写入的证据机制。
- URL 校验和标准化。
- OCR user-edited 标记位置与 retry / late completion 冲突。
- detail edit read / save purpose 命名和隔离。
- record missing、payload missing、save conflict 的状态流。
- P13D 的具体 verifier 组合和 bounded JSON evidence 字段。

## 方案质量要求

- 不得让 View 分散写 payload、summary、search document、FTS 或 OCR 状态。
- 不得复用 hover / paste / copy / translation / provider purpose 承载详情编辑读写。
- 不得把保存成功写成 UI-only 成功；必须定义事实源一致性。
- 不得把系统剪贴板不更新只写成“不会调用”；必须有可验证证据路径。
- 不得把富文本不可保真时的降级藏在实现里；必须给出需要项目负责人接受的决策点。
- 不得输出真实剪贴板正文、真实路径、OCR 原文、URL 全文、图片/base64、secret。
