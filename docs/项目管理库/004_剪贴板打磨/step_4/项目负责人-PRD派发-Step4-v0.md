## Step 4 阶段目标

- 让剪贴板条目详情页成为可编辑、可阅读、布局稳定的信息面板。
- 明确文本、URL、富文本文本内容、图片 OCR 文本的编辑边界。
- 将保存、取消、失败回滚、搜索索引更新和更新时间更新定义成可验收的用户行为。
- 重新组织详情页元数据展示，让短项紧凑、长项可读，且不挤压正文编辑区。

## 必须覆盖

1. 可编辑类型：
   - plain text。
   - URL。
   - 富文本文本内容。
   - 图片 OCR 文本。
2. 不编辑范围：
   - 不编辑图片本体。
   - 不编辑文件本体。
   - 不编辑其他非文本类 payload 本体。
3. 保存模型：
   - 使用显式保存 + 取消。
   - 保存 / 取消按钮或操作区必须有稳定布局位，dirty state 出现或消失时页面不能跳动。
   - 需要定义保存成功、保存失败、取消、失败回滚、未保存变更切换条目 / 关闭详情时的行为。
4. 数据更新：
   - 保存后更新内部内容、原始 payload 或对应派生字段、可见摘要、搜索索引和更新时间。
   - 不同步更新系统剪贴板。
   - 保留 createdAt / source App / 来源类元数据的规则必须清楚。
5. 富文本：
   - 产品目标是尽量保留原格式。
   - 如果技术评估无法可靠保留富文本格式，PRD 需要把降级口径写为待架构确认问题，不能默认静默丢格式。
6. OCR 文本：
   - 图片 OCR 文本可编辑时，只更新 OCR 文本、索引和详情展示。
   - 不改写图片 payload 本体。
   - 需要考虑 OCR 不存在、处理中、失败、可重试与可编辑状态之间的关系。
7. 编辑区域：
   - 默认高度 2 行。
   - 最多展示 4 行。
   - 超过 4 行后编辑区内部滚动。
   - 详情内容字体不受条目列表字体大小设置影响。
8. 元数据组织：
   - 短项一行两个。
   - 长项单独一行。
   - 长 URL、长文件名、长来源 App、长标签等不得挤压正文编辑区。
   - 需要定义复制、截断、展开或 tooltip 等可用路径。

## 明确不覆盖

- 图片本体编辑。
- 文件本体编辑。
- 完整富文本编辑器扩展。
- 系统剪贴板同步写回。
- 隐私页真实 App 清单与 CLI 广义对象管理。
- Step 3 面板 hover / toolbar / click 模式继续重设计。

## 需要产品经理重点设计的问题

- 详情页进入编辑态的入口：自动可编辑、点击编辑、还是文本区直接编辑。
- dirty state 的稳定布局：保存 / 取消按钮常驻禁用、占位显示，还是固定 footer / toolbar。
- 保存失败后的文案、焦点、回滚和重试。
- 未保存变更时切换条目、关闭面板、点击外部区域的处理。
- URL 编辑后的合法性校验：是否允许任意文本、是否提示非法 URL、是否改变 record kind。
- 富文本编辑的用户预期：保留格式、纯文本编辑但保留原 payload、或需要技术方案确认后再定。
- OCR 文本编辑的空态、失败态、重试态与编辑态互斥关系。
- 元数据两列 / 单列布局在窄宽度、长字段、多标签、多语言下的降级。

## 验收要求

PRD v0 至少需要包含：

- 用户可见行为。
- 明确非目标。
- 状态机或状态表：只读、编辑中、dirty、保存中、保存成功、保存失败、取消、切换条目。
- 可编辑类型与不可编辑类型矩阵。
- 保存后数据更新矩阵。
- 富文本和 OCR 的特殊边界。
- 元数据布局验收样例。
- 低敏 fixture 验收建议，不使用真实剪贴板内容。
- 需要 App 架构师确认的技术问题列表。
- 需要 UI/交互、开发、测试/质量重点复审的问题列表。

## 质量边界

- PRD 不得把“富文本可编辑”写成已经技术闭合；应先提出产品目标和风险，让 App 架构师确认实现方案。
- PRD 不得把“保存后更新系统剪贴板”写入本阶段目标。
- PRD 不得把 Step 5 的隐私页 App 清单或 CLI 广义对象管理提前带入。
- PRD 应延续 Step 1 的明文优先原则，但日志、CLI、provider、自动化输出仍按已有低敏输出边界处理。
