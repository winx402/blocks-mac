## 技术方案 v1 必须吸收的 P1

### P1-1 Mutable content revision / optimistic concurrency token

问题：方案 v0 使用 `expectedRevision` / `newRevision` / `ocr_locked_revision`，但当前代码里的 `ClipboardSearchDocumentBuilder.revision(for:)` 基于 capture `changeCount:signatureSHA256_12`，不是可编辑内容版本。用户编辑 payload / OCR text 后该 revision 不会自然前进。

技术方案 v1 必须明确：

- Step 4 不复用 capture-based revision 作为 detail edit optimistic concurrency token。
- 新增或等价提供 `contentRevision` / `contentVersion`。
- 每次 detail edit save、OCR user-edited save、必要内容级更新时推进该版本。
- `ClipboardDetailReadModel.revision` 和 `ClipboardDetailEditCommand.expectedRevision` 使用 mutable content revision。
- 保存成功返回 `newContentRevision`，并用它失效 detail edit cache / preview snapshot / current search result。
- capture signature 继续作为原始捕获身份，不承担可编辑内容版本职责。
- P13D 新增 `detail_revision_advances_004`、`detail_stale_revision_conflict_004`、`detail_cache_invalidation_004` 或等价断言。

### P1-2 Schema migration v4 与 OCR source backfill

问题：方案 v0 建议 `ocr_text_source DEFAULT 'vision'`，会把非 OCR、pending、failed、empty、notRequired 或无 OCR 文本的旧记录错误标记为 Vision 来源。

技术方案 v1 必须明确：

- 独立 `Schema Migration v4` 小节。
- `MigrationRunner` 支持 v4，`currentVersion > 4` 才 unsupported。
- OCR source 默认值为 `none` 或等价空来源，不使用 `vision` 作为全量默认。
- 仅对 `ocr_status == succeeded` 且 `ocr_text` 非空的旧行回填 `vision`。
- `userEdited` 只能由 Step 4 detail edit save 写入。
- `ignoredLateVision` 只由 late completion 被 user-edited guard 拒绝后写入或记录为低敏事件。
- 同步列出 `loadSearchDocument`、bindings、upsert、updateOCRResult、rebuildSearchDocuments、Codable / initializer 的修改点。
- P13D / P13A 覆盖旧 v3 fixture DB 迁移 smoke：无 OCR、succeeded non-empty、pending、failed、succeeded empty、user-edited save 后 retry / late completion。

### P1-3 P13D per-scenario evidence schema 与 deterministic fixtures

问题：方案 v0 P13D 输出仍有汇总布尔字段，不能证明每个 PRD v1 P1 / failure path 都被执行并可复跑。

技术方案 v1 必须明确：

- P13D 输出按 fixture / scenario 拆分，而不是只输出汇总 true。
- 至少覆盖并输出：save success、search index、save failure、async reindex / not applicable、URL validation、pasteboard、rich text、OCR、dirty navigation、content revision。
- 每个场景记录 fixture id、执行结果、mutation count、failure reason 或 sanitizer 结果。
- 缺任一必测 scenario、fixture id、mutation count 或 sensitive-output scan 结果时，P13D fail。
- P13D 使用 isolated temp database / fixture repository，不读真实用户数据库。
- fixture 使用 deterministic record id、revision、updatedAt fake clock 和 synthetic content。
- fault injection 支持 search document write fail、FTS write fail、transaction rollback、record deleted before save、payload missing、expectedRevision mismatch、late OCR completion。
- baseline red 必须证明缺 implementation / 缺 evidence 会失败。

### P1-4 P13D state ownership、purpose matrix 和 call graph 负向扫描

问题：方案 v0 对 View / Store / Repository 边界方向正确，但 P13D 还没有把 AppState / AppModel / ClipboardController 不扩权、detailFullValueRead 正向存在和 purpose 负向复用写成可检查合同。

技术方案 v1 必须明确：

- P13D 输出 `state_ownership` 或等价字段，检查 AppState / AppModel / ClipboardController 不成为 detail payload、OCR text、search document、save result 的事实源。
- `ClipboardDetailStore` 只持有 draft / UI 状态，不持久化事实源。
- P13D purpose matrix 正向要求 `detailEditRead`、`detailFullValueRead`、`detailEditSave`。
- 负向要求 Step 4 detail edit / metadata full value / save 路径不得复用 `.hoverDetail`、`.paste`、`.copyPlainText`、`.translationPreview`、`.ocrInput`、`.searchIndex`、provider purpose。
- P13D 对 save call graph 做正向约束：View -> `ClipboardDetailStore.save()` -> `ClipboardRepository.saveDetailEdit(command:)` 或等价路径。
- AppModel 只能承载非事实源 facade / status，不得保存 detail payload、OCR text 或 search document。

### P1-5 Pasteboard read/write、metadata full value copy 和间接写入路径

问题：方案 v0 对保存不写系统 pasteboard 方向正确，但安全合规和测试要求同时覆盖真实 pasteboard 读取、间接写入路径，并区分保存路径与显式 copy full value。

技术方案 v1 必须明确：

- 保存路径不得读写真实系统 pasteboard，P13D 输出 `pasteboard_read_attempts=0` 和 `pasteboard_write_attempts=0` 或等价字段。
- Static scan denylist 覆盖读取和写入 API：`NSPasteboard.general`、`clearContents`、`setString`、`setData`、`writeObjects`、`string`、`data(forType:)`、`pasteboardItems`、`readObjects`、`availableType` 等。
- P13D 以 save path call graph / adapter spy 为准，证明 `saveDetailEdit(command:)`、`ClipboardDetailStore.save()` 和其依赖不可达 pasteboard write / read。
- `detailFullValueRead` 仅表示读取完整值，不等于系统 pasteboard 写入。
- 如果实现 metadata `copy full value`，必须是单独显式用户动作和单独 adapter / purpose，例如 `detailCopyFullValue` 或等价命名，并用 fake pasteboard 验收。
- P13D 区分 `full_value_read_attempts`、`full_value_copy_attempts`、保存路径 pasteboard read/write。

### P1-6 Rich text fidelity 和 URL validation 的可执行合同

问题：富文本和 URL 方向可接受，但需要把“保真”和“本地校验”写成可实现、可验收的 helper / fixture 合同。

技术方案 v1 必须明确：

- `ClipboardRichTextFidelityService` 是 conservative service；不能证明代表格式未丢失时返回 failure。
- 分项输出 `link_preserved`、`paragraphs_preserved`、`inline_style_preserved`、`list_representation_preserved`、`kind_remains_rich_text`、`plain_text_derivation_updated`。
- 不允许只比较 plain text 就声称 rich text fidelity 通过。
- 明确 BlocksCore 是否允许使用 `NSAttributedString` / AppKit RTF API，Blocks App 和 BlocksCLI 构建都必须覆盖。
- `ClipboardDetailURLValidator` 或等价 helper 明确 pass/fail fixture：`https`、`http localhost`、`mailto` 通过；empty、relative、missing scheme、control char、`file:`、custom scheme 默认失败。
- URL validation 不发网络、不 open URL、不触发 App launch / Finder / provider / system permission。
- P13D 输出不得包含 URL 全文，query/path 需低敏化。

### P1-7 Low-sensitive sanitizer、provider / automation / network denylist 和 failure schema

问题：低敏输出已写方向，但安全合规要求凭据类 forbidden pattern、provider / automation / network touched-file denylist 和 failure detail schema 更可执行。

技术方案 v1 必须明确：

- P13D 复用既有 sanitizer 或定义与 P13A/B/C 一致的 sanitizer。
- Forbidden patterns 至少覆盖 Authorization、Bearer、Basic、X-API-Key、api_key、access_token、refresh_token、id_token、sk- / sk_proj / sk-proj、password、otp、2fa/mfa、private key block、cookie/session/JWT/webhook、token query、base64/data:image、full OCR 字段名。
- 输出只能报告 pattern label、relative file、field、count、pass/fail，不输出命中原文。
- Step 4 新增 / touched 的 detail edit、metadata、URL validation、rich text、OCR text edit 文件不得引入 `URLSession`、provider route、image upload、多模态 provider call、Authorization header、Bearer token、shell/Process、AppleScript、CGEvent、Accessibility、ScreenCaptureKit、Finder / System Settings 打开动作。
- URL validation 仅本地解析，不触发网络可达性检查。
- OCR text edit 不重新运行 OCR、不调用 provider、不触发自动化外发。
- `failures[]` 也必须走低敏 schema，只包含 rule id、relative path、line / symbol、pattern label、count、low-sensitive reason。

## 技术方案 v1 应吸收的 P2 / 推荐口径

1. Stable detail editor 默认是稳定详情编辑面，不是 hover preview / 临时 popover；优先 in-panel detail editor。
2. Fixed action bar 的 `view`、`edit-clean`、`dirty`、`invalid`、`saving`、`save-failed`、`record-unavailable` 高度和主要按钮位置要有证据。
3. Dirty-navigation 默认焦点在 `Continue Editing`；`Discard Changes` 标记 destructive；`Save and Continue` 失败不得导航。
4. Metadata copy full value 有 `copying`、`copied`、`copy failed` 低敏反馈。
5. 空 plain text 保存需要明确允许或禁止；若允许，summary 显示 `Empty text` 或等价文案，正文搜索不匹配但标签 / 来源仍可找回。
6. Batch A 建议前置 `ClipboardDetailStore` 空状态机 skeleton 和 stable editor 入口占位，避免 Batch D 才发现 UI 承载面不匹配。
7. 如果本阶段不启用异步 reindex，P13D 应输出 `async_reindex_enabled=false` 和 `not_applicable_reason`。
