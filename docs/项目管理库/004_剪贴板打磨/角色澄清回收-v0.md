## 多角色一致认为阻塞 PRD 的问题

### 1. OCR 是否进入 PRD v0

多角色来源：产品经理、UI/交互、App 架构师、开发、测试/质量、安全合规顾问。

原因：

- 用户要求搜索覆盖图片 OCR。
- 如果本期做真实 OCR，需要定义图片 payload 处理、OCR pipeline、索引字段、失败状态、性能、日志、CLI/provider 外发边界。
- 如果本期不做真实 OCR，只做图片类型关键词和文件名/URL/来源命中，则验收标准完全不同。

项目负责人判断：

- 这是当前第一优先级澄清项。
- PRD v0 不能只写“搜索图片”，必须明确是真 OCR，还是类型关键词命中。

### 2. CLI / provider / 自动化 / 日志全文边界

多角色来源：产品经理、开发、测试/质量、安全合规顾问、App 架构师。

原因：

- 用户已确认 payload 保护整体取消。
- 但取消遮挡不等于允许后台静默外发、无限制日志落盘、CLI 默认输出大段真实内容或自动化执行危险动作。
- 如果不写清，本期范围会从剪贴板面板打磨扩大到多链路 payload 输出与系统状态变更。

项目负责人判断：

- 需要把“明文优先”与“操作可控”并列写入 PRD。
- 建议默认边界是：App 内明文展示和搜索优先；provider/自动化全文读取必须由明确用户动作或 agent 指令触发；日志/CLI 可以明文输出但需要格式、分页、截断或显式参数控制；系统状态变更类 CLI 命令需要 dry-run/显式确认/危险动作白名单。

### 3. 文本详情编辑保存模型与可编辑类型

多角色来源：产品经理、UI/交互、App 架构师、开发、测试/质量、安全合规顾问。

原因：

- 用户已确认“目前只支持文本类记录”，但还需定义文本类是否包括 URL、富文本纯文本化记录。
- 保存模型会影响 UI 控件、dirty state、失败回滚、repository 事务、payload/index/updatedAt 原子更新和验收断言。

项目负责人判断：

- PRD 必须明确：可编辑类型、保存触发、取消/撤销/失败回滚、保存后字段更新。
- 建议默认采用“显式保存 + 取消”，避免失焦或自动保存误改历史内容。

### 4. 标签合并规则

多角色来源：产品经理、UI/交互、App 架构师、开发、测试/质量。

原因：

- 用户已确认标签需要合并。
- 合并规则影响设置页 UI、标签唯一性、record-tag 关联迁移、颜色、排序和重名校验。

项目负责人判断：

- 这个问题不一定必须再问用户，可以由 PRD 给出默认规则。
- 建议默认：用户选择目标标签；目标标签保留名称、颜色和排序位置；被合并标签的条目关联转移到目标标签；标签名去首尾空格后不允许重复；重名校验建议大小写不敏感。

## 多角色认为 PRD 必须写清的验收口径

### 内容展示与搜索

- 面板默认展示明文可读内容，不再只显示字符数。
- 搜索覆盖字段必须列清：正文、标签、来源 App、URL、时间、类型、富文本纯文本、文件名，以及 OCR 是否进入本期。
- 类型同义词和多语言关键词要有样例，例如 `pic`、`picture`、`image`、`图片`、`图`、`ima` 命中图片类条目。
- 搜索排序、空结果、索引中、不可搜索和失败状态要可测。

### 面板交互与布局

- 筛选组 hover 退出需要有安全区域或距离阈值，短暂离开展开区不应立即收起。
- 筛选组展开宽度不得遮挡右侧关键操作。
- 搜索框需要缩短，为筛选组让出空间。
- 条目选中反馈必须即时，不能明显滞后于鼠标动作。
- 单击/双击设置使用显性控件，不再使用下拉菜单。
- 条目上下边框或内边距收窄，但内容、标签、来源、时间和操作按钮不能重叠。

### 标签与收藏

- 旧 pinboard/固定概念在 UI 和数据模型上完全替换为标签/收藏。
- “收藏”是内置标签，五角星图标、默认第一、不可删除。
- 一个条目可以有多个标签。
- 右键菜单支持添加标签、删除标签、新建标签。
- 设置页支持标签颜色、排序、重命名、合并。
- 不做批量删除、删除前二次确认、自动清理空标签。
- 旧 pinboard/固定逻辑直接移除，不做迁移和兼容。

### 隐私页 App 管理

- UI 默认展示 `/Applications`、`~/Applications`、`/System/Applications` 下真实 `.app`。
- 使用真实系统图标，图标读取失败要 fallback。
- 列表需要搜索/过滤和稳定排序，避免全量 App 不可浏览。
- CLI 管理登录项、helper、命令行工具等额外对象时，需要明确 typed subject / 标识模型。
- 真实 App 图标和清单只做本地枚举与展示，不应上传 provider。

### 文本详情编辑

- 只支持文本类记录编辑；非文本类显示不可编辑状态。
- 编辑框默认 2 行、最多 4 行，超过出现滚动。
- 详情内容字体不受面板条目字体大小设置影响。
- 保存后更新内部 payload、搜索索引和更新时间。
- 不更新系统剪贴板。
- 保存成功、保存失败、未保存变更、取消/回滚要有明确反馈。
- 元数据两列组织，长字段单独成行，不能挤压正文编辑区。

### 风险与验证

- 明文优先是显式风险接受，但凭据、API key、Authorization header、provider secret、私钥、验证码仍不得写入仓库文档、示例、verification JSON 或 bug report。
- provider / 自动化不得因为剪贴板全文可读就变成后台静默上传或任意系统自动化执行器。
- CLI destructive 或系统状态变更类命令需要显式命令、显式参数、dry-run/confirm 机制和低歧义对象标识。
- 验收记录应使用 synthetic/fixture 内容，不复制真实用户剪贴板。
- 需要保留 repository 持久化、删除/裁剪一致性、搜索索引更新、标签筛选、详情编辑事务和 CLI/log 输出控制的自动化门禁。
- 真实 UI 路径需要低敏录屏或截图证据，尤其是搜索、筛选 hover、选中反馈、标签菜单和详情编辑。

## 项目负责人收敛建议

### 建议向用户补问

1. OCR 是否进入 PRD v0 和首批验收。
2. 内容保护整体取消后，是否接受 provider/自动化后台静默读取并外发全文；如果不接受，则采用“明确用户动作或 agent 指令触发”的边界。
3. 日志/CLI 是否允许默认输出完整正文；如果不接受无限制输出，则采用分页、截断、显式参数或结构化格式控制。
4. 详情编辑的保存模型是否采用“显式保存 + 取消”，可编辑类型是否限定为 plain text，URL/富文本只作为文本化内容处理。

### 建议项目负责人直接定规则

1. 标签合并默认规则：选择目标标签，目标保留名称、颜色、排序位置，被合并标签的条目关联转移到目标，标签名去首尾空格且大小写不敏感地去重。
2. 隐私页 UI 默认只展示真实 `.app`，登录项、helper、命令行工具先通过 CLI 管理；是否在 UI 展示额外对象可后续再扩展。
3. 搜索排序默认可以先由 PRD 规定，并在后续体验验收中调整。

## 推荐阶段拆分

1. 004-A：Payload 明文展示与搜索基础架构。
2. 004-B：标签/收藏数据模型替换。
3. 004-C：文本详情编辑。
4. 004-D：隐私页真实 Applications 与 CLI 广义对象管理。
