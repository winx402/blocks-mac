## 2. 总体判断

Step 3 PRD v0 方向正确，范围也守住了。它聚焦高频面板路径：筛选 hover、搜索 / 筛选 / 右侧操作布局、条目点击反馈、单击 / 双击显性控件、条目密度和长内容不重叠，没有把 Step 1 搜索底座、Step 2 标签事实源或 Step 4 详情编辑拉进来。

PRD 已经做对的部分：

- hover 容错写成用户可见结果，而不是过早指定像素方案。
- 选中反馈延迟没有臆断原因，要求开发通过低敏运行时验证确认。
- 搜索框缩短、筛选组展开和右侧操作保留空间被放在同一个 toolbar 约束里考虑。
- 单击 / 双击设置明确不再使用下拉，要求显性点击、互斥、键盘和 VoiceOver 可用。
- 条目密度要求扩大核心内容区域，同时保留点击目标和状态可辨认。
- 长文本、长标签、长来源 App、多语言长句、OCR / 索引状态承载都进入验收。
- 低敏截图 / 录屏边界清楚，不保存真实剪贴板和敏感内容。

需要回写的是可测性：Step 3 是纯体验打磨阶段，如果 PRD 只写“不要误收起”“不要遮挡”“即时反馈”“不重叠”，开发和测试仍可能各自理解。建议在 PRD v1 或技术方案输入中补一组最小交互规则和截图矩阵。

## 3. 必须改

### 3.1 Hover 安全区域需要给出首版交互规则

PRD 已要求安全区域、距离阈值或延迟收起，但还没有明确首版推荐规则。进入技术方案前，UI 侧建议先收敛成“安全桥 + 短延迟收起 + 明显离开即收起”的组合，避免实现时只做延迟或只做 hover hit-test，仍然出现误收起。

必须补充：

- 触发区与展开内容区之间必须有连续安全区域，不允许出现 hover 断裂窄缝。
- 短暂移出时延迟收起，明显离开时可预测收起。
- 延迟只保护误操作，不应让展开层长时间挡住其他操作。
- 展开层不应捕获不相关区域点击，导致右侧操作或搜索框难以使用。

建议 PRD 可吸收口径：

> 筛选组展开采用“触发区到内容区的安全桥 + 短延迟收起”。鼠标从触发区斜向移动到展开内容区不收起；短暂离开安全区域后返回不收起；明显离开筛选相关区域后在可预测延迟内收起。延迟用于容错，不用于长期保持展开状态。

验收样例：

- 鼠标斜向从筛选按钮移到第三个标签项，展开层不收起。
- 鼠标短暂移出展开层边缘再返回，展开层仍可操作。
- 鼠标移动到搜索框或列表区域并停留，展开层按预期收起。

### 3.2 Toolbar 布局需要明确空间优先级和窄宽度降级

PRD 已写筛选组展开宽度、搜索框缩短和右侧操作不遮挡，但还缺优先级。没有优先级时，开发可能只调一个宽度，窄窗口下仍会互相挤压。

必须补充：

- 右侧关键操作的可见性和可点击性优先级最高，不应被筛选展开层覆盖。
- 搜索框必须有最小可用宽度，不能被压到无法识别当前查询。
- 筛选组在宽窗口下展开更多内容，在窄窗口下应内部滚动、截断或进入更多菜单。
- 筛选展开 / 收起不应让搜索框、右侧操作和列表发生大幅跳动。
- 需要明确至少三类窗口宽度验收：宽、常规、窄。

建议 PRD 可吸收口径：

> 顶部工具区空间优先级为：右侧关键操作保留可点击空间，搜索框保留最小可读宽度，筛选组在剩余空间内展开。宽窗口下筛选组可展示更多标签；常规宽度下搜索框和筛选组弹性分配；窄窗口下筛选组使用内部滚动、截断或更多菜单，不覆盖右侧关键操作。

验收样例：

- 宽窗口：筛选展开显示多个标签，不遮挡右侧操作。
- 常规窗口：搜索框可读，筛选组可操作，右侧操作可点击。
- 窄窗口：筛选组降级但不与搜索框、右侧操作重叠。

### 3.3 selected / focused / hover / active filter 需要视觉层级规则

PRD 已要求这些状态不混淆，但还需要明确层级关系。否则后续实现可能出现 hover 覆盖 selected、keyboard focus 与 selected 混在一起、active filter 与条目 selected 使用同一种视觉 token。

必须补充：

- `selected` 是条目持久选择状态，优先级高于 hover。
- `focused` 表示键盘焦点，可以与 selected 同时存在，但不能只靠 selected 代替。
- `hover` 是临时预览状态，不应覆盖 selected。
- `active filter` 是 toolbar / 筛选组状态，不应与条目 selected 使用同一语义。
- 点击反馈需要在 mouse down 或 click 后即时出现，不等待耗时动作。

建议 PRD 可吸收口径：

> 状态层级建议为：条目 selected 表示当前选中记录，hover 只作为临时指向状态且不覆盖 selected；keyboard focused 使用可访问焦点样式，可与 selected 并存；active filter 只表达当前列表筛选条件，不能与条目 selected 混用。点击条目后 selected 反馈先出现，再执行粘贴、复制、详情加载或其他耗时动作。

验收样例：

- 鼠标 hover 非选中条目时，已选中条目仍保持 selected。
- 键盘移动焦点时，VoiceOver / focus ring 能读出当前焦点，不依赖 hover。
- 选择 `Work` filter 后，toolbar active 状态不会让某个条目看起来被选中。

### 3.4 单击 / 双击显性控件需要推荐首版控件策略

PRD 已给 segmented control、radio group 或等价控件，但进入开发前建议收敛首版策略。单击 / 双击设置是用户设置项，不应因为文案变长而回退为下拉。

必须补充：

- 如果每组选项是 2-3 个短选项，优先 segmented control。
- 如果选项较长或需要说明，使用 radio group 或按钮组 + 辅助说明。
- 单击和双击应是两个清晰分组，不要把所有动作混在一个控件。
- 当前值无需展开即可可见。
- 中文、英文、日文文案下不溢出。

建议 PRD 可吸收口径：

> 单击行为和双击行为分别使用显性互斥控件。短选项可用 segmented control；长选项或多语言文案较长时使用 radio group。控件不得回退为下拉；当前值常显；键盘和 VoiceOver 可切换。

验收样例：

- 不打开菜单即可看见单击当前行为。
- 不打开菜单即可看见双击当前行为。
- 日文长文案下控件换行或分组，不遮挡右侧说明。

### 3.5 条目密度需要有基线对照和最小点击目标

PRD 要求条目上下边框或内边距收窄，但没有要求保存前后对照。没有对照就很难判断“核心内容区域更大”是否达成，也可能把点击目标压得过小。

必须补充：

- 验收需要包含当前基线和调整后对照截图或等价记录。
- 密度收窄不能降低主要点击目标可用性。
- hover、selected、focused 仍要清楚。
- OCR 状态、标签、来源、时间和操作按钮不得因为密度收窄而重叠。
- 动态高度变化应受控，避免 hover / OCR 状态出现时列表跳动。

建议 PRD 可吸收口径：

> 条目密度验收需要提供同一组 fixture 的调整前 / 调整后低敏截图或录屏，证明核心内容区域增加且点击目标仍可用。密度收窄只调整边距、分隔和内部布局，不牺牲 hover、selected、focused 可辨认性。

验收样例：

- 同一文本 fixture 调整后正文区域更大。
- 鼠标点击条目主体仍能稳定选中。
- 图片 OCR failed 状态出现时不压住操作按钮。

### 3.6 低敏截图 / 录屏矩阵需要具体化

PRD 已要求低敏截图或录屏，但矩阵还不够明确。Step 3 的验收核心是可见行为，建议把矩阵写成必须项，避免最后只有零散截图。

必须补充：

- 视口矩阵：宽、常规、窄。
- 状态矩阵：默认、搜索中、筛选展开、active filter、OCR / indexing 状态、长内容。
- 交互矩阵：hover 斜向移动、短暂移出、明显离开、点击选中、快速连续点击。
- 设置矩阵：单击 / 双击控件在中英文日文长句下的截图。
- 证据不得包含真实剪贴板、真实 home path、邮箱、secret、验证码或二维码。

建议 PRD 可吸收口径：

> Step 3 验收至少保留一组低敏截图 / 录屏矩阵：3 个窗口宽度，6 类面板状态，3 类 hover 路径，2 类点击反馈路径，以及设置页单击 / 双击控件的中英文日文长文案检查。截图只使用 fixture 内容。

验收样例：

- 录屏 1：筛选 hover 斜向移动和短暂移出。
- 截图 1-3：宽 / 常规 / 窄窗口 toolbar 展开状态。
- 截图 4-6：长文本、长标签、长来源 App 的条目布局。
- 录屏 2：快速点击不同条目，selected 跟随最新点击。

## 4. 可优化

### 4.1 Hover 延迟毫秒数可以留给技术方案

PRD 不必写死 150ms、250ms 或其他具体值。只要用户可见结果和验收路径明确，具体延迟、距离阈值和动画曲线可由技术方案和运行时调试确定。

### 4.2 筛选组可后续加入搜索标签能力

Step 3 只需要处理筛选组展开、容错和布局。标签很多时的标签搜索、分页、分组可以后续优化，不应阻塞本阶段。

### 4.3 高级动效可后续做

展开 / 收起动画、selected 状态过渡、hover 微动效可以后续 polish。Step 3 首要目标是可预测、不误收、不遮挡、不延迟。

### 4.4 复杂响应式断点可由开发方案细化

PRD 可以要求宽 / 常规 / 窄三类验收，不必在产品文档写死所有像素断点。

## 5. 可吸收建议

建议产品经理或后续技术方案吸收以下交互规则：

1. **Hover 规则**：安全桥 + 短延迟收起；短暂移出保护，明显离开收起。
2. **Toolbar 优先级**：右侧操作 > 搜索框最小可读宽度 > 筛选组展开内容。
3. **状态层级**：selected 持久、focused 可访问、hover 临时、active filter 属于 toolbar。
4. **显性控件**：短选项 segmented，长选项 radio group；不回退下拉。
5. **密度规则**：缩窄边距但保留点击目标；用前后低敏截图证明核心内容区域增加。
6. **截图矩阵**：宽 / 常规 / 窄 + 默认 / 搜索 / 筛选展开 / active / 长内容 / OCR 状态。

可直接吸收的短文案建议：

- 搜索框清空：`清除搜索`
- 筛选清除：`显示全部`
- OCR 处理中状态承载：`图片文字识别中`
- OCR 失败状态承载：`图片文字识别失败`
- 单击设置 label：`单击条目时`
- 双击设置 label：`双击条目时`

这些文案只是首版建议，最终应按现有 String Catalog 和产品语气统一。

## 6. 验收样例

### 6.1 Hover 容错

- 从筛选触发区斜向移动到展开内容区，不误收起。
- 短暂移出展开区再返回，不误收起。
- 明显离开筛选区域后，可预测收起。
- 展开层不遮挡右侧关键操作。

### 6.2 Toolbar 布局

- 宽窗口：筛选展开显示多个标签，搜索框可读，右侧操作可点击。
- 常规窗口：搜索框、筛选组、右侧操作不重叠。
- 窄窗口：筛选组降级为内部滚动、截断或更多菜单，右侧操作仍可达。
- 长搜索词在输入框内处理，不撑破 toolbar。

### 6.3 状态层级

- hover 非选中条目时，selected 条目仍清楚。
- keyboard focused 状态可见且可被 VoiceOver 读出。
- active filter 不与条目 selected 混淆。
- 快速连续点击不同条目时，selected 跟随最新点击。

### 6.4 单击 / 双击控件

- 单击设置和双击设置分别是显性互斥控件。
- 当前值常显。
- 键盘可切换。
- 中文、英文、日文长句下不溢出。

### 6.5 条目密度与长内容

- 条目核心内容区域比基线更大。
- 文本、URL、富文本、图片、file URL fixture 不重叠。
- 多标签和长标签不覆盖正文、来源、时间和操作按钮。
- OCR 状态和索引中状态不覆盖正文。
- 点击目标仍可用，hover / selected / focused 清楚。

### 6.6 低敏证据矩阵

建议至少保留：

- 3 张 toolbar 截图：宽、常规、窄。
- 3 张条目截图：长文本、长标签、长来源 App。
- 1 段 hover 录屏：斜向移动、短暂移出、明显离开。
- 1 段点击反馈录屏：普通列表、搜索结果、筛选结果。
- 3 张设置页截图：中文、英文、日文长文案下的单击 / 双击控件。

## 7. 对项目负责人的建议

建议结论：`approve-with-changes`。

没有发现需要退回用户澄清或否定 Step 3 范围的问题。建议要求产品经理回写或在技术方案输入中吸收以下必须改点：

1. Hover 容错补成“安全桥 + 短延迟收起 + 明显离开收起”的首版规则。
2. Toolbar 补空间优先级和宽 / 常规 / 窄降级验收。
3. selected / focused / hover / active filter 补视觉层级规则。
4. 单击 / 双击显性控件补首版选择策略。
5. 条目密度补基线对照和点击目标保底。
6. 低敏截图 / 录屏矩阵补成明确验收门槛。

这些修改不改变 Step 3 范围，也不要求提前做全量面板视觉重设计；它们主要让当前 PRD 的体验目标更可实现、可复查、可验收。
