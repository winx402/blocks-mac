## 总体判断

技术方案主线成立：范围限定在面板 UI / interaction 层，未扩大到 Step 1 搜索/OCR 底座、Step 2 标签事实源、Step 4 详情编辑或 Step 5 隐私页。hover 安全桥、toolbar 空间约束、paste activation 显性控件、selected/focused 先写、row/card 稳定密度和 P13C 门禁方向均可进入开发前收敛。

需要在技术方案 v1、开发派发或 P13C 实现说明中补强三处可验收细节：evidence manifest 结构、事件日志 pass/fail 判定、keyboard/VoiceOver 手工证据模板。否则 P13C 可能只验证“有截图/有日志/有 checklist”，但不能 fail-closed 地证明覆盖了正确断点、状态和低敏边界。

## P0 / P1 / P2 Findings

### P0

无。

### P1

1. P13C evidence manifest 的 fail-closed 规则需要更具体。
   当前方案要求截图/录屏 manifest、event logs 和 counts，但 `输出 schema` 主要是 booleans/counts。为避免假通过，P13C must 检查每条 evidence 的相对路径存在、归属当前 Step 3、绑定 viewport category / panel position / state / fixture id，并跑低敏 sanitizer。只记录 `screenshots: 8` 或 `recordings: 3` 不应通过。

2. selected/focused 事件日志需要补成可判定规则。
   当前方案给了单条示例和“先写”目标，但 P13C must 检查单击 paste、双击 paste、detail/OCR retry、快速 A->B 连续点击和 stale async completion。事件必须有 monotonic sequence、relative timestamp、record fixture id、action type；`selected` / `focused` 必须早于 `pasteRequested` / `detailRequested` / `ocrRetryRequested`，且旧 completion 不得把 selected 回写到旧 record。

3. keyboard / VoiceOver 证据需要手工记录模板或等价 manifest。
   当前方案要求 checklist evidence 存在，但未定义记录字段。P13C final gate 可以接受手工证据，但 must fail closed：缺 tester/date/build-or-commit、viewport、panel position、locale、fixture id、逐项 pass/fail、问题记录和低敏附件路径时不得通过。

### P2

1. viewport 断点本身可复跑，但需要在开发记录中确认实际面板最小宽度是否高于 360pt；如果高于 360pt，应记录实际 minimum category，而不是硬造 360-459pt。

2. 多语言长文案和 VoiceOver 质量可能需要 UI/交互二次微调；测试侧建议作为实现验收 residual risk 记录，不阻塞技术方案进入开发准备。

3. 最终验收矩阵建议补通用 build/CLI/diff：Blocks App build、BlocksCLI build、`blocks --help`、`git diff --check`。技术方案当前只显式写了 `git diff --check`，但 Step 3 会改 SwiftUI 面板代码，构建 gate 不应遗漏。

## P13C Must Assertions

P13C 可以组合静态检查、fixture manifest、低敏事件日志、截图/录屏 manifest 和手工 checklist，但必须 fail-closed。建议最低 must 断言如下：

1. 事实源：引用当前 `产品经理-PRD-v1.md`、`App架构师-技术方案-v0/v1` 和当前开发记录；旧草稿、旧 story、旧 acceptance 只能作为 `baseline_reference`，不得参与 `ok`。
2. evidence 文件：manifest 中的截图、录屏、event log、keyboard/VoiceOver checklist 使用相对路径；文件必须存在；路径不得包含真实 home、真实文件路径、邮箱、secret、Authorization header、二维码、验证码或 OCR 原文。
3. viewport matrix：必须覆盖 `wide`、`regular`、`narrow`、`minimum` 四类；每类记录实际 width、panel position、fixture id、状态；如实际 minimum width 高于 360pt，必须记录原因和实际宽度。
4. panel position：side panel 与 bottom panel 均需覆盖；不能只用一种布局证明全部通过。
5. toolbar：search min width、filter max width、fixed trailing actions 或等价约束存在；filter expanded 不遮挡 settings、close、paste activation、clear filter。
6. hover：不再只依赖即时 `onHover(false)` 收起；存在安全桥 / delayed collapse / re-enter cancellation / obvious leave collapse 或等价实现；option click、group switch、Esc、panel close、window focus loss 立即收起。
7. paste activation：面板顶部 active 切换不使用 `Menu` / 下拉；若 Settings 提供同一设置，必须共用 `clipboard.panel.pasteActivationMode`。
8. selected/focused：事件日志证明 selected/focused 早于 paste/detail/OCR retry/async action；快速连续点击旧 completion 不覆盖最新 selected。
9. row/card：side list row 与 bottom tray card 分别有 metrics / fixed slots / before-after evidence；hover、selected、focused、OCR、indexing、excluded、skipped、favorite、long tag 不改变外部尺寸。
10. keyboard：有逐项 pass/fail 证据；缺清除筛选、回到全部、active 控件切换、OCR retry 可达性等关键路径时 fail。
11. VoiceOver：有逐项 pass/fail 证据；selected/focused、active filter、favorite、OCR 状态或长标签语义不可读时 fail。
12. 回归边界：P13C 不修改或重新定义 Step 1 search/OCR 底层算法，不修改或重新定义 Step 2 tag fact source。
13. 低敏输出：P13C 输出只允许 counts、booleans、fixture id、synthetic record id、viewport category、relative timestamp、relative path 和 category，不输出真实内容。

## P13C Should Assertions

1. 输出 schema 建议增加 `evidence_manifest_summary`，列出每个 viewport / panel position / state 的 coverage，而不是只给总数。
2. 事件日志建议增加 `scenario` 字段：`single_click_paste`、`double_click_paste`、`detail_open`、`ocr_retry`、`rapid_click_stale_completion`。
3. 截图/录屏 manifest 建议记录 `locale`、`fontScale` 或等价环境信息，降低多机器复验歧义。
4. keyboard/VoiceOver checklist 建议允许人工记录，但要求和 P13C JSON 一起归档，避免验收记录只写“已检查”。
5. P8 可吸收 Step 3 panel polish 断言，但 P13C 应作为 Step 3 专属 gate，不应把 P8 变成唯一阻断来源。

## Viewport Matrix 判断

技术方案给出的断点可复跑：

- 宽：`>= 760pt`
- 常规：`600-759pt`
- 窄：`460-599pt`
- 最小可用：`360-459pt` 或实际面板 minimum width

建议补充规则：

- 每个断点必须记录实际 width，不只写 category。
- 每个断点至少覆盖 toolbar 默认、filter expanded、active filter、long content 或 OCR/indexing 状态之一；完整矩阵可分批记录，但 P13C final gate 不应缺 `filter expanded` 和 trailing actions 可达性。
- 如果实现无法稳定设置某个宽度，验收记录必须标为未覆盖或用实际最接近宽度替代，并说明原因。

## Selected / Focused 事件日志判断

当前方案方向足够，但需要把示例扩成判定规则。推荐 P13C 事件日志最小模板：

```json
{
  "scenario": "single_click_paste",
  "record": "txt_alpha_004",
  "events": [
    {"seq": 1, "t": 0, "event": "pointerDown", "record": "txt_alpha_004"},
    {"seq": 2, "t": 4, "event": "selected", "record": "txt_alpha_004"},
    {"seq": 3, "t": 6, "event": "focused", "record": "txt_alpha_004"},
    {"seq": 4, "t": 11, "event": "pasteRequested", "record": "txt_alpha_004"}
  ]
}
```

Pass：

- `selected` 和 `focused` 均早于耗时动作 request。
- 快速点击 A 后点击 B，最终 selected/focused 为 B。
- 旧 detail/OCR/paste completion 不覆盖最新 selected/focused。

Fail：

- 只有 `pasteRequested` 后才出现 selected/focused。
- 只有视觉截图，没有时序或相邻帧证据。
- record id、payload、preview body、OCR text、真实路径或真实 App 名进入日志。

## 回归矩阵判断

P13A/P13B/P8/P8I/P9A/P9B/P11E 组合足以防 Step 1/2 主要回归，但建议明确职责：

- `P13A`：Step 1 明文展示、搜索状态、OCR 状态承载回归；Step 3 不重新定义 OCR pipeline。
- `P13B`：Step 2 标签/收藏事实源、single tag filter、favorite first 回归；Step 3 不引入 OR/AND 或修改 tag store。
- `P8`：吸收 Step 3 panel polish 用户可见断言，包括 toolbar、density、selected feedback、visible controls。
- `P8I`：仅当 Step 3 触碰 Settings 同一设置时检查同 key；若不新增 Settings 控件，不应阻断。
- `P9A`：repository storage smoke 应保持不受 Step 3 UI 改动影响。
- `P9B`：AppState / Repository integration 保持 selected/filter facade 不回退旧事实源；view-local focused state 不应进入 repository 层。
- `P11E`：低敏输出和 clipboard hardening baseline，覆盖 event log / screenshot manifest 不输出 payload、完整路径、OCR 原文或 secret。
