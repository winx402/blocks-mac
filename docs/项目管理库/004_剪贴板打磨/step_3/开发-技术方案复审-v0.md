## 1. 结论

开发结论为 `approve-with-changes`。

技术方案主线成立：Step 3 可以聚焦 hover 容错、toolbar 空间、selected/focused 先写、paste activation 显性控件、row/card 密度和 P13C 低敏证据门禁，不需要触碰 Step 1 搜索/OCR 底座、Step 2 标签事实源、Step 4 详情编辑或 Step 5 隐私页。

进入开发前建议补清 4 个 P1 级契约：实际 viewport 矩阵、activation coordinator 的最小接入路径、focused/hover 状态所有权、P13C evidence manifest 的 fail-closed 规则。它们不是推翻方案的问题，但如果不写清，开发时容易扩大范围或产生验收分歧。

本复审只读分析；未修改业务代码，未触发真实 App、真实剪贴板、provider、Keychain、TCC、系统设置或自动化。

## 2. 当前代码事实

只读抽样确认：

- `ClipboardFilterClickGroup` 当前通过 `onHover(false)` 立即调用 `onExpandedHoverExit()`，方案识别正确。
- `ClipboardFloatingPanelView.header` 当前包含 search bar、filter strip、spacer、bottom-only paste activation menu、clear filters、settings、close。
- `ClipboardFloatingPanelView` 当前 SwiftUI frame 为 bottom `minWidth: 720`、side `minWidth: 340`；`FloatingPanelFrameStore` side width 为 `390`，bottom 宽度实际来自屏幕 visible frame。
- `ClipboardBottomTrayLayout` 已有 bottom tray/card 高宽约束：bottom tray min height `126`，card min/max height `118/330`，card min/max width `180/520`。
- `ClipboardFloatingRecordRow` 和 `ClipboardFloatingRecordCard` 当前都通过 `highPriorityGesture(TapGesture(count: pasteActivationMode.tapCount).onEnded { onPaste() })` 触发 paste，double-click 模式的普通 tap 才调用 `onSelect()`；single-click paste 路径存在 selection 后写或不写的风险。
- `selectRecord(_:)` 当前写 view-local `selectedRecordID` 和 `clipboardStore.floatingSelectedRecordID`；尚无独立 focused state。

## 3. P0 / P1 / P2 findings

### P0

无。

### P1-1：viewport 矩阵必须按当前 bottom / side 实际尺寸重写

技术方案给出宽、常规、窄、最小可用四档，并列出 `360-459pt` 的最小可用示例。但当前 bottom panel 的 SwiftUI min width 是 `720pt`，side panel 实际宽度由 `FloatingPanelFrameStore.clipboardSideWidth = 390pt` 决定，直接套同一组断点会导致 P13C evidence 不可复跑。

建议技术方案 v1 写成“按 position 分别定义矩阵”：

- bottom：以实际全宽 / 高度变化为主，至少覆盖当前屏幕 visible width 下的 wide/regular，以及高度 min/default/max 对 bottom tray 的影响；如果 bottom 宽度不可缩到 720 以下，不要求伪造 360-459pt bottom 截图。
- side：以 390pt 固定宽度和当前 min height 覆盖 side narrow/minimum 口径，重点验收 search/filter/trailing actions 是否有可达路径。
- P13C manifest 中每条 viewport evidence 记录 `position`、`widthCategory`、`actualWidthBucket`、`actualHeightBucket`，而不是只记录抽象类别。

### P1-2：activation coordinator 需要定义最小 API 和现有 gesture 替换点

方案提出 `ClipboardRecordActivationCoordinator` 是正确方向，但还不够可执行。当前 row/card 的 `highPriorityGesture` 直接调用 `onPaste()`，single-click paste 模式不会先选中。开发前应明确最小接入：

- row/card 不直接把 `TapGesture(count:)` 终点接到 `onPaste()`；应接到 `onPrimaryActivation(recordID, source)` 或等价 handler。
- handler 内顺序固定为 `selectRecord` / `focusRecord` / event record，再触发 paste/detail/OCR retry/copy。
- double-click 模式下 first click 只 select/focus，double-click handler 再 select/focus + paste。
- 快速点击 A 后 B 的 async completion guard 可以先用 interaction token / latest record ID，不需要引入全局 store。
- P13C 至少静态检查 row/card 不再存在 `TapGesture(...).onEnded { onPaste() }` 直连，并读取低敏 event manifest 验证 selected/focused 先于 paste/detail/OCR retry。

### P1-3：focused / hovered 状态应明确为 view-local，不进入 AppState / Repository

方案建议新增 `focusedRecordID` 是必要的，但应明确所有权：

- `focusedRecordID` 和 hover tracking 是 panel view-local 或 view model-local 状态，不应进入 `AppState`、`ClipboardStore`、`ClipboardRepository` 或持久化层。
- 现有 `clipboardStore.floatingSelectedRecordID` 可作为 selected facade 继续保留，但 Step 3 不应扩展出新的全局 focused fact source。
- event recorder 应通过窄 closure 或 local recorder 注入，不应写 payload、preview body、OCR text 或真实路径。
- P13C 应做负向检查：`focusedRecordID` / hover bridge runtime state 不得出现在 repository 或 AppModel/AppState 事实源中。

### P1-4：P13C evidence manifest 需要 fail-closed 细则

方案已说明 P13C 读取 manifest，不启动真实 App 或真实剪贴板；还需要补清 manifest 的格式和失败条件，避免实现时把截图生成、真实 UI 操作或剪贴板读取塞进 verifier。

建议：

- P13C 只读取仓库内相对路径 manifest，例如 `docs/项目管理库/004_剪贴板打磨/step_3/evidence/P13C-manifest-v0.json` 或等价路径。
- manifest 只允许相对路径、fixture id、viewport category、event name、boolean/count、relative timestamp。
- P13C 不启动 App、不读系统剪贴板、不调用 provider/Keychain/TCC/系统设置，不生成截图，只验证已提交或开发记录指向的低敏 evidence。
- final acceptance 的 P13C 对缺失 manifest、绝对路径、旧 Step 文档作为 ok 证据、敏感 token、缺 viewport/event/keyboard/VoiceOver evidence 都 fail closed。
- 开发早期可以有 P13C baseline red；但 final P13C PASS 必须来自当前 Step 3 PRD、技术方案、开发记录和当前 evidence manifest。

### P2-1：`NSViewRepresentable` 不应成为默认硬依赖

当前方案写“推荐最小 AppKit interop”，同时允许 SwiftUI overlay + geometry + delayed collapse 等价实现。开发视角建议进一步收敛为：

- 优先用 SwiftUI overlay / geometry union / delayed Task cancellation 实现，除非实测无法稳定处理 window focus loss 或 tracking。
- 若使用 `NSViewRepresentable`，只做 panel 内 pointer tracking / local hit-test，不引入全局 NSEvent monitor，不持有 filter/tag/store 事实源。
- P13C 检查行为和 evidence，不检查具体类型名。

### P2-2：模块数量可压缩

技术方案列出的文件边界清楚，但开发时不必先创建所有文件。可优先复用现有 view 文件或少量局部 helper，只有当代码复杂度上升时再拆出：

- `ClipboardPasteActivationModeControl`
- `ClipboardPanelToolbarLayout` 或 metrics helper
- `ClipboardRecordActivationCoordinator`
- hover bridge / hover state helper

### P2-3：VoiceOver / keyboard 证据建议使用模板

P13C 应读取 keyboard / VoiceOver checklist，而不是开发记录中的自由文本。建议技术方案附最小模板字段：`pathID`、`position`、`locale`、`passed`、`notes`、`checkedBy`、`evidenceRelativePath`。

## 4. 实现风险

- Hover 安全桥如果用 overlay 扩大 hit-test，可能遮挡 search、settings、close 或 paste activation；需要透明 hit-test 区和 trailing action 可点证据。
- Gesture 改造容易和 context menu、hover detail、OCR retry、copy plain text 互相抢事件；activation coordinator 应只接管 row/card 主激活，不吞掉显式按钮。
- selected / focused 如果写入全局 store，后续 Step 4/5 容易把瞬时 UI 状态误当事实源。
- Toolbar metrics 如果不按 bottom/side 分开，会出现底部全宽场景通过、侧边窄宽场景失败。
- Row/card 密度优化如果只改 padding，可能引入状态文本换行、OCR retry 挤压、tag chips 覆盖或 card 高度跳动。
- P13C 如果直接生成截图或启动 App，会违反本阶段低敏、可复跑 verifier 边界。

## 5. 建议开发批次

三批次是合理的，但可以合并为两个较大的开发批次，减少串行成本，同时保留 P13C-first 证据层次。

### Batch A：P13C baseline + Hover / Toolbar / Paste Activation

范围：

- 新增 P13C baseline red 和 evidence manifest schema。
- hover delayed collapse / safe bridge。
- toolbar position-aware metrics。
- paste activation 顶部 `Menu` 退出，改显性互斥控件。

验收重点：

- P13C 能 fail closed 识别当前旧 `onHover(false)`、`Menu` 和缺 manifest。
- bottom/side viewport matrix 初版存在。
- trailing actions 不被 hover / filter expanded layer 遮挡。

### Batch B：Selection / Focus / Density / Accessibility Evidence

范围：

- activation coordinator 或等价 handler。
- view-local `focusedRecordID`。
- selected/focused 先写事件 evidence。
- side row / bottom card metrics 和 fixed slots。
- keyboard / VoiceOver checklist evidence。
- P13C final green + P13A/P13B/P8/P8I/P9/P11E 回归。

验收重点：

- single-click 和 double-click 模式均证明 selected/focused 先于 paste/detail/OCR retry。
- row/card 状态不改变外部尺寸。
- evidence manifest 低敏且相对路径化。

如果实现团队希望更稳，也可以保留原三批次；但不建议把 P13C final gate 独立成只写脚本的最后一批，应从 Batch A 就红灯落地。

## 7. 建议技术方案 v1 吸收口径

可直接吸收如下口径：

> Hover bridge 不绑定具体技术类型。优先使用 SwiftUI overlay/geometry + delayed collapse；如无法稳定满足 focus loss 或 tracking，再使用窄 `NSViewRepresentable`。无论实现方式，safe bridge 必须 hit-test transparent，不得遮挡 search/trailing actions。

> `focusedRecordID`、hover state 和 interaction token 是面板 view-local 状态，不进入 AppState、ClipboardStore、Repository 或持久化层。现有 selected facade 可保留，但 Step 3 不新增全局 UI 瞬时事实源。

> P13C 只读取当前 Step 3 evidence manifest 和当前代码，不启动真实 App、不读取真实剪贴板、不生成截图、不触发 provider/Keychain/TCC/系统设置。final PASS 要求 manifest 完整、相对路径化、低敏，并覆盖 viewport、hover、selected/focused、density、keyboard、VoiceOver。

> Viewport matrix 按 `position` 分开：bottom 使用实际 bottom 面板宽度和高度 bucket；side 使用实际侧边宽度和高度 bucket。不得要求当前 UI 无法达到的虚构断点截图。
