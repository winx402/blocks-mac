## 3. 范围判断

### 3.1 可保持的方向

- Step 3 只聚焦面板交互与布局打磨：hover 容错、toolbar 空间、selected/focused 先写、paste activation 显性控件、row/card 密度和低敏证据门禁。
- 筛选组收起逻辑应从即时 `onHover(false)` 转为安全桥、短延迟、re-enter cancel、明显离开和立即关闭条件。
- 面板顶部 active paste activation 不再使用 `Menu` / 下拉，改为显性互斥控件，并与 Settings 如有同项时共用 `clipboard.panel.pasteActivationMode`。
- side list row 与 bottom tray card 分开定义 metrics，状态变化不得引起外部尺寸跳动。
- P13C 应成为 Step 3 专属 fail-closed verifier，组合静态检查、低敏事件、截图/录屏 manifest 和 keyboard / VoiceOver checklist。

### 3.2 不得扩大到的范围

- 不重做 Step 1 搜索、OCR、preview 或输出边界底座。
- 不修改 Step 2 标签/收藏事实源、筛选语义、favorite built-in identity 或标签事务。
- 不引入 Step 4 详情编辑。
- 不引入 Step 5 隐私页真实 App 清单或 CLI 广义对象管理。
- 不触发真实 App、真实系统剪贴板、provider、Keychain、TCC、系统设置或自动化动作作为技术方案阶段证据。

## 4. 技术方案 v1 必须吸收

### 4.1 Viewport matrix 按 panel position 重写

v1 必须基于当前面板事实，把 viewport evidence 从单一抽象断点改为按 `position` 记录：

- bottom panel：按当前 bottom 面板实际宽度和高度 bucket 验收。若当前 bottom min width 高于 360pt，不要求伪造 360-459pt 截图或证据。
- side panel：按当前 side 宽度和高度 bucket 验收，重点覆盖搜索框、筛选组、active filter、trailing actions 的可达性。
- P13C manifest 每条 viewport evidence 至少记录 `position`、`widthCategory`、`actualWidth`、`actualHeight`、`fixtureID`、`state` 和 evidence 相对路径。
- 如某个理论断点无法稳定复现，必须记录实际最接近宽度和原因；不能用缺失 evidence 通过。

### 4.2 Activation coordinator 最小契约

v1 必须把 selected/focused 先写从体验目标落成最小接入 API 或等价 handler：

- row/card 的主激活手势不得继续把 `TapGesture(...).onEnded` 直接接到 `onPaste()`。
- 主激活应进入 `onPrimaryActivation(recordID, source)` 或等价 handler。
- handler 内固定顺序：`selectRecord`、`focusRecord`、低敏 event record，然后再触发 paste、detail、OCR retry、copy 等耗时或异步动作。
- double-click 模式下 first click 只 select/focus，double-click 再 select/focus + paste。
- 快速点击 A 后 B 的 async completion 必须有 interaction token / latest record guard，旧 completion 不得覆盖 B 的 selected/focused。
- P13C 必须静态检查 row/card 不再存在 paste 直连，并读取低敏事件证明 selected/focused 早于 paste/detail/OCR retry。

### 4.3 focused / hover 状态所有权

v1 必须明确：

- `focusedRecordID`、hover runtime state、interaction token 属于 panel view-local 或 view model-local 状态。
- 不得进入 `AppState`、`ClipboardRepository`、持久化层或新的全局事实源。
- 现有 selected facade 可以按当前实现保留，但 Step 3 不新增 focused 的全局事实源。
- event recorder 只能记录 synthetic id、fixture id、事件名、relative timestamp、boolean/count，不记录 payload、preview body、OCR text、真实路径或真实 App 名。
- P13C 需要负向检查 focused / hover runtime state 不进入 repository 或持久化事实源。

### 4.4 P13C evidence manifest fail-closed 规则

v1 必须把 P13C 证据输入写成硬边界：

- P13C 只读取仓库内相对路径 manifest 和当前代码，不启动真实 App、不读取真实剪贴板、不生成截图、不触发 provider、Keychain、TCC、系统设置或自动化。
- manifest 中截图、录屏、event log、keyboard / VoiceOver checklist 必须使用相对路径，文件必须存在，并归属于当前 Step 3。
- evidence 必须绑定 viewport category、panel position、state、fixture id；仅记录 `screenshots: 8` 或 `recordings: 3` 不得通过。
- 缺失 manifest、绝对路径、旧 step 文档作为 ok evidence、敏感 token、缺 viewport/event/keyboard/VoiceOver 证据，都必须 fail closed。
- sanitizer 禁止真实 home path、真实文件路径、邮箱、secret、Authorization header、验证码、二维码、payload 正文、OCR 原文或图片 base64 进入输出。

### 4.5 selected/focused 事件日志判定

v1 必须定义 P13C 可判定的事件日志结构：

- 每个 scenario 至少包含 `scenario`、`recordFixtureID`、monotonic `seq`、relative `t`、`event`、synthetic record id。
- 必须覆盖 `single_click_paste`、`double_click_paste`、`detail_open`、`ocr_retry`、`rapid_click_stale_completion` 或等价场景。
- `selected` 和 `focused` 均必须早于 `pasteRequested` / `detailRequested` / `ocrRetryRequested`。
- 快速点击 A 后 B，最终 selected/focused 必须为 B；旧 completion 不得回写旧 record。
- 只有截图、只有 paste 后 selected/focused、或事件里包含 payload / OCR text / 真实路径，应判定失败。

### 4.6 Keyboard / VoiceOver 证据模板

v1 必须给出 P13C 可读取的手工或半自动 checklist 字段，至少包含：

- `evidence_id`、`date`、`tester`、`build_or_commit`、`locale`。
- `viewport_category`、`actual_width`、`panel_position`、`fixture_ids`、`artifact_paths`。
- keyboard checks：search focus、filter expand、全部/收藏/普通标签可达、clear filter / show all、record list focus selected、paste activation toggle、settings/close reachable、OCR retry reachable when visible、no focus trap。
- VoiceOver checks：search label、active filter/all readable、expand/collapse state、selected/focused semantics、favorite semantics、OCR status、paste activation mutual exclusion、long tag accessibility label。
- 每项必须有 pass/fail；缺 tester/date/build-or-commit、viewport、position、locale、fixture id、逐项 pass/fail 或低敏附件路径时不得通过。

### 4.7 Toolbar / filter / paste activation fallback

v1 必须补齐最小可用窗口下的 fallback：

- filter fallback 必须保留“全部/回到全量”、收藏、active filter clear 的可达路径。
- 普通标签可以横向滚动、截断或进入更多入口，但 expanded layer 不得遮挡 paste activation、settings、close、clear filter。
- paste activation 默认可用 compact segmented；当窄窗口或本地化文案导致当前值不可读、互斥关系不清或控件挤压时，必须切换为 radio group / 按钮组 fallback。
- fallback 不得退回 `Menu` / 下拉。
- 视觉短标签可以接受，但 accessibility label 必须包含完整动作语义、当前值和互斥关系。

### 4.8 Hover 参数和实现策略

v1 必须明确 hover 首版参数与可调边界：

- 默认值：collapse delay 180ms、safe bridge padding 12pt、safe region inflation 16pt。
- 实现阶段可按低敏 hover evidence 微调；delay 建议保持在 150-250ms 区间。
- 验收以 PRD pass/fail 为准：斜向进入不误收、短暂移出可恢复、明显离开可预测收起、Esc / 失焦 / 点击选项立即收起。
- hover bridge 不绑定具体技术类型。优先使用 SwiftUI overlay / geometry + delayed collapse；若无法稳定满足 focus loss 或 tracking，可使用窄 `NSViewRepresentable`。
- 无论实现方式，safe bridge 必须 hit-test transparent，不得遮挡 search、settings、close、paste activation 或 clear filter。
- 不允许引入全局 `NSEvent` monitor 或把 hover 状态写入事实源。

### 4.9 Row / card density 与点击目标

v1 必须把密度验收从视觉方向变成可验收约束：

- side list row 和 bottom tray card 使用各自 metrics，不用同一套尺寸强套。
- hover、selected、focused、OCR、indexing、excluded、skipped、favorite、long tag 不改变 row/card 外部尺寸。
- row 主体点击区域和 context menu target 不得低于当前基线；如使用数值底线，主要点击高度不低于约 44pt。
- OCR retry、显式按钮、resize handle 等小目标在密度调整后仍必须可达。
- before / after evidence 必须使用同一 fixture、同一 viewport / panel position。

### 4.10 回归矩阵和构建门禁

v1 必须明确最终验收至少串行运行：

## 5. 不要求回写或不作为阻塞

- 不强制技术方案 v1 指定 `NSViewRepresentable` 或 SwiftUI overlay 的唯一实现，只要求行为和证据可验收。
- 文件拆分可以比 v0 建议更少；只要职责清楚，不要求先创建全部 helper 文件。
- hover delay / padding / inflation 的具体数值允许实现阶段微调，但 pass/fail 行为不能降级。
- 多语言长文案和 VoiceOver 细节可以在实现复审中做二次 UI 微调；v1 先提供 evidence 模板和 fallback 条件。
