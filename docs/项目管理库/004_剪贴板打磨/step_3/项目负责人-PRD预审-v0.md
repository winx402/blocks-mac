## 1. 结论

Step 3 PRD v0 可以进入角色复审，当前不进入开发实现。

PRD v0 聚焦面板交互与布局打磨，覆盖 R3、R4、R5、R6、R10、R11、C10、C17，未把 Step 1 搜索/OCR 底座、Step 2 标签事实源、Step 4 详情编辑或 Step 5 隐私页 App 管理提前拉入本阶段。

## 2. 预审通过点

- 阶段目标明确：只处理面板高频交互、筛选/搜索空间、条目点击反馈、单/双击显性控件和条目密度。
- 已引用 Step 1 / Step 2 的已接受边界，但没有改写它们的底层事实源。
- hover 容错写成用户可见结果：短暂移出不误收、明显离开可预测收起，而不是过早指定像素方案。
- 选中反馈延迟没有臆断原因，要求开发通过低敏运行时验证确认。
- 单击/双击设置明确不再使用下拉，要求显性点击、互斥、键盘和 VoiceOver 可用。
- 条目密度要求扩大核心内容区域，同时保留点击目标、状态层级和不重叠约束。
- 宽窄窗口、长文本、长标签、长来源 App、多语言长句、OCR/索引状态承载都纳入验收。
- 低敏截图/录屏证据边界清楚，避免真实剪贴板、真实路径和敏感内容进入验收材料。

## 3. 需要角色复审重点

### 3.1 UI/交互设计师

请重点复审：

- hover 安全区域、延迟收起和明显离开的交互口径是否足够自然。
- 筛选组展开宽度、搜索框缩短、右侧操作保留空间和窄窗口降级是否能形成可实现的布局规则。
- selected / focused / hover / active filter 的视觉层级是否会冲突。
- 单击/双击显性控件建议采用 segmented control、radio group 还是等价方案。
- 条目密度收窄后，主体内容、标签、来源、时间、OCR 状态和操作按钮是否仍有清晰层级。
- 是否需要补充首版文案、状态 label 或低敏截图矩阵建议。

### 3.2 开发

请重点复审：

- 当前筛选组 hover hit-test、popover / overlay / menu 实现是否支持安全区域和延迟收起。
- 选中反馈延迟最可能来自动画、事件顺序、状态更新还是点击动作耦合，需要哪些低敏运行时证据确认。
- 搜索框、筛选组和右侧操作所在 toolbar 是否能满足稳定约束和窄窗口降级。
- 条目密度调整是否影响虚拟列表、滚动性能、动态高度缓存、点击目标或现有 preview/OCR 状态布局。
- 单击/双击设置显性控件是否能复用现有设置组件，是否会触及非 Step 3 设置项。
- 是否需要 App 架构师参与技术方案；如果只是局部 UI/Store 事件处理，开发方案可直接承接。

### 3.3 测试/质量

请重点复审：

- hover 误收起、明显离开收起、展开后不遮挡右侧操作的 pass/fail 样例是否可执行。
- 选中反馈即时性的验收证据：低敏录屏、事件日志、截图时序或其他可复跑证据。
- 宽窄窗口、长文本、长标签、长来源 App、多语言和 OCR/索引状态的 fixture 矩阵。
- 键盘路径和 VoiceOver 检查清单是否足够。
- Step 3 与 Step 1 搜索状态、Step 2 单标签筛选之间的回归边界。

## 4. 当前不需要回用户澄清

预审没有发现必须回到用户确认的问题。以下细节可由角色复审和技术方案收敛：

- hover 安全区域具体坐标、延迟毫秒数和动画曲线。
- 搜索框最小宽度、筛选组最大宽度和窄窗口断点。
- 选中态视觉 token 和事件更新实现。
- 单击/双击显性控件具体组件。
- 条目边距、最小高度、标签显示上限和动态高度策略。
