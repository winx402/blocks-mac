## 1. 阶段目标

Step 3 聚焦剪贴板面板的高频交互与布局稳定性。目标是让用户在已有明文展示、搜索底座和标签/收藏信息结构之上，更稳定地完成筛选、搜索、选择、点击行为设置和列表浏览。

本阶段只做面板交互与布局打磨，不重写 Step 1 的搜索/OCR 底座，不改 Step 2 的标签事实源，不进入详情编辑或隐私页 App 管理。

## 2. 已接受依赖边界

### 2.1 来自 Step 1

Step 3 可以依赖以下已接受边界：

- 面板默认展示真实可读内容。
- 列表/卡片默认使用有界内容预览，不同步加载所有完整 payload。
- 搜索输入、搜索状态、OCR 状态和索引中状态属于 Step 1 底座。
- 搜索框行为、空状态、索引中提示可以被 Step 3 布局承载，但搜索算法、索引字段、OCR 队列和输出边界不在 Step 3 修改范围内。

### 2.2 来自 Step 2

Step 3 可以依赖以下已接受边界：

- Step 2 只支持单标签筛选。
- 筛选入口存在“全部”或等价未筛选状态。
- 收藏第一，普通标签按设置页排序。
- 条目已关联标签按标签组顺序展示。
- 长标签可截断或换行，但不得挤压主要内容。
- 标签事实源、收藏 built-in identity、右键菜单标签关系不在 Step 3 修改范围内。

## 4. 明确不覆盖

本阶段不覆盖：

- 重新设计 Step 1 搜索/OCR 底座。
- 修改 Step 1 搜索索引、OCR 队列、OCR 状态生命周期或输出边界。
- 修改 Step 2 标签事实源、record-tag 关系、收藏 built-in identity 或标签搜索字段契约。
- 详情编辑、保存/取消、富文本编辑和 OCR 文本编辑。
- 隐私页真实 App 清单和 CLI 广义对象管理。
- 旧 pinboard / 固定数据迁移。
- 全量面板视觉重设计或重做整个信息架构。

## 5. 用户路径与状态

### 5.1 高频路径

Step 3 优先保障以下路径：

1. 打开剪贴板面板，浏览条目内容。
2. 使用搜索框输入查询。
3. 展开筛选组，选择“全部”、收藏或普通标签。
4. 点击条目，并即时看到选中/聚焦反馈。
5. 在设置中选择单击/双击行为。
6. 浏览长文本、长标签、长来源 App、图片/OCR 状态和索引中状态，布局不重叠。

### 5.2 状态要求

面板应稳定呈现：

- 默认状态。
- 搜索输入中。
- 搜索有结果。
- 搜索无结果。
- 搜索索引中。
- OCR 待处理 / 处理中 / 完成 / 失败 / 可重试状态的承载位置。
- 标签筛选 active 状态。
- 条目 hover 状态。
- 条目 selected / focused 状态。
- 点击动作触发后的即时反馈状态。
- 单击/双击设置当前值和切换状态。

Step 3 不定义这些状态背后的数据生成逻辑，只定义它们在面板中的布局和交互稳定性。

## 6. 功能需求

### 6.1 筛选组 hover 展开容错

筛选组 hover 展开后，应降低鼠标轻微移出导致自动收缩的概率。

必须满足：

- hover 展开后有安全区域、距离阈值或延迟收起机制。
- 鼠标短暂离开展开区域时，不应立即收起。
- 从筛选触发区移动到展开内容区时，不应误收起。
- 展开内容区与触发区之间不得出现导致 hover 断裂的窄缝。
- 收起必须可预测，不能长时间停留在展开状态影响其他操作。

PRD 默认建议：

- 采用“安全区域 + 短延迟收起”的组合。
- 延迟时间和距离阈值由 UI/开发方案确定，但验收必须覆盖快速斜向移动、短暂移出和明显离开三类行为。

技术方案待确认：具体 hover hit-test 区域、延迟毫秒数、距离阈值和动画时长由 UI/交互与开发确认。该项不影响开发前验收边界，因为 PRD 已定义误收起、短暂移出和明显离开的用户可见结果。

### 6.2 筛选组展开宽度与右侧操作

筛选组横向长度需要扩大，展开后不得遮挡右侧关键操作。

必须满足：

- 展开宽度优先容纳“全部”、收藏和普通标签。
- 展开区域不得遮挡右侧关键操作按钮。
- 右侧关键操作仍可点击、可读、可聚焦。
- 宽窗口下筛选组应尽量利用空间。
- 窄窗口下筛选组应有最大宽度、滚动、折叠或截断策略。
- 展开宽度变化不得导致搜索框、右侧操作和列表内容大幅跳动。

右侧关键操作包括当前面板已有的固定右侧控件，以及 Step 1/2 已接受状态需要保留的搜索清除、状态提示、标签筛选清除或等价操作。具体按钮清单由 UI/开发根据当前实现确认。

### 6.3 搜索框空间协调

搜索框需要适度缩短，为筛选组展开让出空间。

必须满足：

- 搜索框在常见窗口宽度下仍能输入和显示用户查询。
- 搜索框缩短后，不影响搜索状态、清空按钮和索引中提示的可见性。
- 搜索框与筛选组之间有稳定间距。
- 搜索框、筛选组、右侧操作在宽窄窗口下不重叠。
- 搜索框宽度调整不改变 Step 1 搜索底座和搜索字段能力。

PRD 默认建议：

- 搜索框设置最小宽度和弹性宽度。
- 筛选组展开时搜索框可以让出空间，但不得压缩到无法识别当前查询。
- 对长查询使用横向滚动、尾部截断或输入框内部滚动，不撑破 toolbar。

### 6.4 条目点击选中反馈即时

用户点击条目后，应立即看到选中或聚焦反馈，不应出现明显视觉延迟。

必须满足：

- 鼠标 down 或 click 后，选中态应在用户感知上即时出现。
- 选中反馈不得等待后续粘贴、复制、详情加载、OCR 或搜索状态更新完成。
- 点击同一条目、不同条目、搜索结果条目、筛选结果条目都应反馈一致。
- 如果点击同时触发其他动作，选中反馈仍应先于耗时动作可见。
- 选中态、hover 态和 active 筛选态视觉层级不混淆。

PRD 不在需求阶段定性延迟原因。原因可能是动画、事件处理顺序、选中态更新时机或点击动作耦合，需要开发前或实现中用低敏运行时验证确认。

### 6.5 单击/双击显性点击选择控件

剪贴板设置中的单击和双击行为选择应改为显性点击选择控件，不再使用下拉菜单。

必须满足：

- 用户能直接看到当前选择，不需要先打开下拉。
- 用户能通过点击切换单击行为和双击行为。
- 控件应表达互斥关系，避免同时选择多个冲突行为。
- 控件支持键盘导航和 VoiceOver。
- 控件在中文、英文、日文文案长度下不溢出。

PRD 默认建议：

- 使用 segmented control、radio group 或等价显性点击选择控件。
- 如果选项过多导致宽度不稳定，优先拆成两行或使用短标签 + 辅助说明，而不是回退为下拉。

技术方案待确认：具体控件形态由 UI/交互和开发根据当前设置页组件决定。该项不影响开发前验收边界，因为 PRD 已明确显性、可点击、互斥、可访问，不再使用下拉。

### 6.6 条目密度与核心内容区域

条目上下边框或内边距应收窄，让核心内容区域更大。

必须满足：

- 条目核心内容可读面积增加。
- 文本、URL、富文本纯文本、图片缩略图、文件名、标签、来源 App、时间、OCR 状态和操作按钮不重叠。
- 收窄后点击目标仍可用，不得过小。
- hover、selected、focused 状态仍可辨认。
- 行距和分隔线不应造成拥挤或误读。
- 长文本和多标签状态下不遮挡主要内容。

PRD 默认建议：

- 只做局部密度优化，不做全量卡片重设计。
- 保持稳定最小高度或等价内容布局约束，避免 hover、selected、OCR 状态变化导致高度频繁跳动。

### 6.7 宽窄窗口与长内容不重叠

Step 3 必须覆盖布局抗压能力。

必须满足：

- 宽窗口下筛选、搜索和右侧操作利用空间但不过度拉伸。
- 窄窗口下搜索框、筛选组、右侧操作不重叠。
- 长文本有截断、换行或多行预览策略。
- 长标签有截断、换行或数量上限策略。
- 长来源 App 名称有截断或 tooltip / accessibility label。
- 长 URL 或 file path 不撑破条目。
- OCR 状态和搜索索引中状态不覆盖正文或标签。
- 语言切换到中文、英文、日文长句时，不挤压主要操作。

技术方案待确认：具体断点、最小宽度、标签显示上限、tooltip 行为和动态高度策略由 UI/开发确认。该项不影响开发前验收边界，因为 PRD 已定义不重叠、主要内容可读和操作可达。

## 7. 布局约束

### 7.1 顶部工具区

顶部工具区至少包含搜索框、筛选组和右侧关键操作。

约束：

- 搜索框有最小宽度。
- 筛选组有展开最大宽度。
- 右侧关键操作有保留空间。
- 三者之间有稳定间距。
- 搜索框缩短和筛选组展开不能造成右侧操作被遮挡。
- 窄窗口下允许筛选组内部滚动或更多菜单，但不允许整体重叠。

### 7.2 条目区域

条目区域至少需要承载：

- 主体内容预览。
- 标签。
- 来源 App。
- 时间。
- 类型或 OCR 状态。
- hover / selected / focused 状态。
- 必要操作按钮。

约束：

- 主体内容优先级最高。
- 标签和来源信息不应覆盖主体内容。
- 状态文字或图标不应覆盖操作按钮。
- 长内容优先截断或换行，不撑破容器。
- 条目密度提升不能牺牲点击目标和可访问性。

### 7.3 设置页单击/双击控件

约束：

- 单击和双击设置各自有清晰 label。
- 当前值可见。
- 选项互斥。
- 控件不使用下拉菜单。
- 宽度不足时换行或分组，不遮挡右侧说明或其他设置项。

## 8. 可访问性与键盘路径

### 8.1 键盘路径

必须支持：

- 键盘聚焦搜索框。
- 从搜索框移动到筛选组。
- 展开或进入筛选组。
- 选择“全部”、收藏或普通标签。
- 清除筛选 / 回到全部。
- 在条目列表中移动选中。
- 触发单击/双击显性控件切换。
- 访问 OCR 重试入口或状态控件，如果该入口在当前面板中可见。

具体快捷键不在 PRD 中强制指定，但 tab order 和箭头键/space/enter 的基本操作应可用。

### 8.2 VoiceOver 与语义

VoiceOver 至少应能读出：

- 搜索框 label 和当前查询。
- 筛选组当前 active 标签或“全部”状态。
- 筛选组展开/收起状态。
- 条目是否选中。
- 条目主要内容摘要。
- 条目标签名称。
- 来源 App 和时间。
- OCR 状态。
- 单击/双击设置当前值和可用选项。

颜色、五角星、hover 视觉或选中背景不能成为唯一信息来源。

## 9. 验收样例

验收应使用 synthetic / fixture 内容，不复制真实用户剪贴板。

### 9.1 筛选 hover 容错

- 鼠标从筛选触发区移动到展开内容区时，展开内容不误收起。
- 鼠标短暂移出展开内容区后返回，展开内容仍可用。
- 鼠标明显离开筛选区域后，展开内容在可预测延迟后收起。
- 展开/收起过程中搜索框和右侧操作不跳动到不可点击。

### 9.2 筛选宽度与搜索框

- 宽窗口下，筛选组展开后能显示多个标签且不遮挡右侧关键操作。
- 窄窗口下，筛选组展开后不与搜索框、右侧操作重叠。
- 搜索框缩短后仍能输入 `Alpha roadmap item 004` 并显示可识别查询。
- 搜索框清空按钮或等价清除路径仍可点击。
- 搜索索引中提示或 OCR 状态提示不被筛选组遮挡。

### 9.3 条目选中反馈

- 点击普通文本条目后，选中态即时出现。
- 点击图片/OCR 状态条目后，选中态即时出现，不等待 OCR 状态变化。
- 点击搜索结果条目后，选中态即时出现。
- 点击标签筛选后的条目后，选中态即时出现。
- 快速连续点击不同条目时，选中态跟随最新点击，不滞后到旧条目。

### 9.4 单击/双击设置

- 单击行为设置使用显性点击选择控件，不是下拉。
- 双击行为设置使用显性点击选择控件，不是下拉。
- 当前选项无需打开菜单即可看见。
- 键盘可以聚焦并切换选项。
- VoiceOver 能读出当前选项和可选项。
- 中文、英文、日文文案下控件不溢出。

### 9.5 条目密度

- 条目上下边框或内边距比当前基线更紧凑。
- 文本 fixture 显示真实内容片段，不被标签或来源覆盖。
- URL fixture 显示 host/path，不撑破容器。
- 富文本 fixture 显示纯文本片段，不与标签重叠。
- 图片 fixture 显示缩略图或图片状态，OCR 状态不覆盖操作按钮。
- file URL fixture 显示文件名或路径摘要，不展示无界路径。
- 点击目标仍可用，hover/selected/focused 状态仍可辨认。

### 9.6 长内容和多语言

- 长文本被截断或换行，条目不横向撑破。
- 长标签名被截断或换行，不挤压主要内容。
- 多个标签显示时不覆盖正文、来源、时间和操作按钮。
- 长来源 App 名称被截断或通过可访问 label 保留完整语义。
- 中文、英文、日文长句下搜索框、筛选组、条目内容和设置控件不重叠。

## 10. 低敏证据要求

Step 3 验收建议使用低敏截图或录屏，但证据必须满足：

- 使用 synthetic / fixture 内容。
- 不包含真实用户剪贴板正文。
- 不包含真实 home 路径、邮箱、secret、Authorization header、二维码、验证码。
- 图片/OCR fixture 使用短 token，例如 `VISION-004`，不使用真实证件、聊天记录、账单或邮件截图。
- 截图/录屏主要证明 hover 容错、布局不重叠、选中反馈和设置控件显性化。

## 11. 进入技术方案前需确认的问题

### 11.1 UI/交互设计师需确认

1. 筛选组 hover 安全区域、距离阈值和延迟收起的交互方案。
2. 筛选组展开宽度、最大宽度、窄窗口降级方式。
3. 搜索框最小宽度和长查询显示方式。
4. 条目 selected、focused、hover 状态的视觉层级。
5. 单击/双击显性控件具体形态。
6. 条目密度基线、收窄范围和最小点击目标。
7. 长标签、长来源 App、长 URL 的截断/换行/tooltip 策略。

### 11.2 开发需确认

1. 当前筛选组 hover 事件和 hit-test 范围在哪里定义。
2. 选中反馈延迟原因是动画、事件顺序、状态写入时机还是点击动作耦合。
3. 搜索框、筛选组和右侧操作所在 toolbar 是否支持稳定约束。
4. 条目密度调整是否影响虚拟列表、滚动性能或动态高度缓存。
5. 单击/双击设置控件能否复用现有设置行组件。
6. 多语言文案和动态类型下是否需要额外布局约束。

### 11.3 测试/质量需确认

1. 低敏运行时验证方案：hover 误收起、选中反馈即时性、窄宽窗口不重叠。
2. 是否需要视频证据或截图矩阵。
3. 长文本、长标签、长来源 App、多语言和窄窗口 fixture。
4. 键盘路径和 VoiceOver 检查清单。
5. 与 Step 1 搜索状态、Step 2 单标签筛选的回归边界。

## 12. 技术方案待确认项

以下事项超出产品经理职责，不在 PRD 中指定具体实现，但不影响开发前验收边界：

1. hover 安全区域坐标、延迟毫秒数、距离阈值和动画曲线。
   - 不影响原因：PRD 已定义短暂移出不误收、明显离开会收起的用户可见结果。
2. toolbar 具体断点、搜索框最小宽度、筛选组最大宽度和右侧操作清单。
   - 不影响原因：PRD 已定义三者不重叠、右侧操作可达、搜索查询可识别。
3. selected/focused/hover 状态的具体视觉 token。
   - 不影响原因：PRD 已定义即时反馈和层级不混淆。
4. 单击/双击控件采用 segmented control、radio group 或等价控件。
   - 不影响原因：PRD 已定义显性点击选择、互斥、可键盘操作、不使用下拉。
5. 条目边距、分隔线、最小高度、标签显示上限和动态高度缓存。
   - 不影响原因：PRD 已定义核心内容面积增加、不重叠、点击目标仍可用。

## 13. 复审建议

Step 3 PRD 进入开发前，建议由以下角色复审：

- UI/交互设计师：重点检查 hover 容错、布局约束、显性控件、状态层级和多语言可读性。
- 测试/质量：重点补充低敏截图/录屏矩阵、长内容 fixture、键盘路径和 VoiceOver 验收。
- 开发：重点检查事件处理、布局约束、动态高度、滚动性能和设置控件复用。
