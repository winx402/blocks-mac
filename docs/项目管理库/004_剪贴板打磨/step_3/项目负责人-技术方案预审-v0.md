方案主线成立：按“hover 安全桥 + toolbar 空间约束 + selected/focused 先写 + 显性 paste activation 控件 + row/card 稳定密度 + P13C 低敏证据门禁”推进。

## 2. 预审通过点

- 阶段边界正确：未修改 Step 1 搜索/OCR 底座，未修改 Step 2 标签事实源，未进入 Step 4 详情编辑或 Step 5 隐私页。
- 基于当前代码落点写方案：`ClipboardFilterClickGroup`、`ClipboardFloatingPanelView`、`ClipboardFloatingRecordRow/Card`、`ClipboardPanelSettings.Keys.pasteActivationMode` 等文件和结构被正确识别。
- hover 方案保留平台边界：允许窄 AppKit interop，但限定为面板内 pointer tracking / hit-test，不引入全局 event monitor。
- toolbar 方案给出空间优先级、右侧关键操作、search/filter min/max 和四类窗口矩阵。
- paste activation 方案明确面板顶部 active `Menu` 必须退出，并要求同 key `clipboard.panel.pasteActivationMode`。
- selected/focused 方案明确状态先写、动作后做，并提出低敏事件 schema 与 stale async guard。
- row/card 密度方案分别覆盖 side list row 和 bottom tray card，并要求状态不改变外部尺寸。
- P13C 门禁包含静态、fixture manifest、低敏事件、截图/录屏 manifest、keyboard/VoiceOver 和 sanitizer 断言。
- 回归关系覆盖 P13A、P13B、P8/P8I、P9A/P9B、P11E。

## 3. 需要角色复审重点

### 3.1 UI/交互设计师

重点复审：

- hover 首版参数：180ms、safe padding 12pt、safe inflation 16pt 是否合理。
- 安全桥、短延迟、明显离开、Esc/失焦/点击选项立即收起是否符合用户感知。
- toolbar 窗口矩阵和 trailing action 清单是否符合面板体验。
- paste activation compact segmented / radio fallback 是否能覆盖中文、英文、日文长文案和可访问性。
- row/card metrics 是否能在提高密度的同时保持页面质感、点击目标和状态层级。

### 3.2 开发

重点复审：

- hover bridge 推荐 `NSViewRepresentable` 是否必要；SwiftUI overlay 等价方案是否足够。
- activation coordinator 与现有 row/card gestures 的最小改动路径。
- selected/focused 新状态是否应该 view-local，是否会影响 AppState / Repository 层。
- toolbar metrics 是否适配当前 bottom/side panel min sizes。
- P13C 如何读取 evidence manifest，而不是启动真实 App 或真实剪贴板。
- 三个开发批次是否合理，是否可适当合并。

### 3.3 测试/质量

重点复审：

- P13C 静态 + 低敏证据组合是否足够 fail-closed。
- viewport matrix 断点是否可复跑。
- selected/focused 事件日志是否足以证明状态先写。
- keyboard / VoiceOver 证据是否需要手工记录模板。
- P13A/P13B/P8/P8I/P9A/P9B/P11E 回归矩阵是否足以防 Step 1/2 回归。

## 4. 当前不需要回用户澄清

以下均可由角色复审和技术方案收敛，不需要回用户：

- hover 延迟毫秒数和安全区域具体像素。
- `NSViewRepresentable` vs SwiftUI overlay 的具体实现选择。
- paste activation 控件采用 segmented 还是 radio fallback。
- row/card padding、lineLimit、最小高度具体数值。
- P13C 脚本名称和 manifest 格式细节。
