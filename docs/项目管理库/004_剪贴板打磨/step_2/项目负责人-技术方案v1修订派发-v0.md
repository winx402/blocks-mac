## 4. v1 必须固定的内容

### 4.1 数据模型与迁移

- 明确 `AppDatabase` schema version / migration 策略。
- 新增 `clipboard_tags`、`clipboard_record_tags` 或等价模型。
- seed 唯一 favorite built-in tag，重复执行不产生重复 favorite。
- 不迁移旧 pinned / pinboard 数据到新 tag 模型。
- 旧 pinned / pinboard 若短期存在，只能作为 legacy storage，不能作为当前事实源、用户可见文案或 verifier ok evidence。
- 明确 foreign key / cascade 或等价 cleanup 机制。

### 4.2 标签归一化

v1 不再保留算法二选一，必须固定 normalizer：

- NFKC normalization。
- trim 首尾空白和换行。
- 内部 Unicode whitespace run 折叠为单个 ASCII space。
- 空结果失败。
- normalization 后仍含 control character 失败。
- locale-independent case folding。
- reserved aliases 至少覆盖 `favorite`、`收藏` 及其 trim / case / width 变体。

如选择不同算法，必须写清具体算法和 fixture，不得留给开发临场决定。

### 4.3 单事实源

- 优先采用独立 `ClipboardTagRepository`，共享 `AppDatabase` connection / transaction helper。
- `ClipboardTagStore` 是 tags、record-tags、selectedTagID、tag operation state/error 的唯一事实源。
- `ClipboardStore` 可桥接 tag store，但不得复制 tag facts 或双写。
- `AppModel` 只做 facade、status banner 和跨 store 协调，不保存 tag facts。
- View 不直接访问 repository，也不读取旧 pinned / pinboard 事实源。
- `ClipboardController.filteredRecords` 从 `pinboardID` 迁移到 `selectedTagID + RecordTag`。

若 v1 不采用上述命名或结构，必须说明等价单事实源如何被 P13B 证明。

### 4.4 标签事务与 mutation result

v1 必须定义 mutation result，至少覆盖：

- changed tag IDs。
- affected record IDs。
- removed tag IDs。
- selected tag transition：none / clear / switch source to target。

最低事务要求：

- create-and-attach、add、remove 返回当前 recordID。
- rename 返回所有关联该 tag 的 recordIDs。
- delete 返回删除前关联的 affected recordIDs。
- merge 返回 source 和 target 去重后的 affected recordIDs。
- updateColor / reorder 不触发 search invalidation，但必须刷新 tag list。
- search invalidation / reindex hook 只消费 affected recordIDs，不由 View 或 Store 猜旧状态。
- 删除 / 合并失败不得半更新；成功后 selectedTagID 必须按规则清空或切换。

### 4.5 Favorite 内置保护

- favorite 是 built-in identity，不依赖显示名称。
- favorite 固定第一。
- favorite 不能删除、重命名、改色、排序。
- 普通标签不能合并到 favorite；favorite 也不能作为 source 或 target 参与合并。
- favorite bootstrap / reload / restart / reset 后不能重复。
- favorite 关系来自 RecordTag，不来自旧 pinned 字段。

### 4.6 旧 pinned 语义退出

- active UI、Store 当前事实源、repository policy 当前行为或 verifier ok evidence 不得继续依赖 `preservePinned`、`clearUnpinned`、pinned 语义。
- 如果保留“清理时保留收藏项”能力，必须改为 `preserveFavorite` / `clearUnfavorited` 或等价 favorite 语义，并基于 favorite RecordTag 判断。
- 旧命名如因兼容暂存，只能作为 deprecated adapter 或 legacy storage，不进入用户可见文案、当前事实源或开发通过项。

### 4.7 UI 合同

v1 不做视觉重设计，但必须写清最小 UI 合同：

- Settings tag row 结构：颜色 swatch、名称、状态/内置标识、排序控件、操作入口。
- favorite row 固定第一，不暴露可执行删除、改名、改色、排序、合并动作；禁用或隐藏原因可理解。
- 右键菜单 favorite first；checked 表示已添加，点击移除；unchecked 表示未添加，点击添加。
- 右键新建失败反馈贴近输入语境或同屏可见，不清空输入，不改变记录标签关系。
- 删除普通标签文案表达“从所有记录移除此标签”。
- 合并展示 source、target 和结果；合并 active source 后切到 target。
- active filter、hover、focus 可区分；delete active 清空，merge active source 切换到 target。
- 长标签名、颜色 token、排序控件、窄宽度和 VoiceOver / 键盘路径有最低验收口径。

### 4.8 P13B 与搜索 Gate

v1 必须定义 P13B fail-closed 红绿顺序：

- Step 2A 前 P13B 可因缺少 Tag schema / active legacy path 失败。
- Step 2A 后 schema / repository / normalizer / favorite bootstrap 相关断言转绿。
- Step 2B 后 Store / AppModel facade / selectedTagID 相关断言转绿。
- Step 2C 后 UI active token、right-click、filter、settings 相关断言转绿。
- Step 2D 后 search contract 和旧 P8/P9/P11 当前事实源迁移转绿或明确 residual。

P13B legacy scan 必须分层：

- active UI token clear。
- active Store / repository / filter code path clear。
- verifier ok evidence clear。
- legacy storage baseline only。

Search Gate 必须区分：

- `tag_search_contract_gate=pass`
- `tag_search_e2e_gate=blocked_by_step1` 或 residual
- `tag_search_e2e_gate=pass`

Step 2 不得把端到端标签搜索伪装为独立闭合。

### 4.9 Fixture 与低敏证据

v1 必须列出最低可复跑 fixture：

- repository smoke：create、duplicate、rename、delete、merge、add/remove、favorite immutable、persistence。
- UI fixture：favorite first、single tag filter、right-click add/remove/new、settings CRUD、long label/narrow width。
- 错误反馈：duplicate、empty、control character、reserved favorite name、favorite immutable、delete failed、merge failed。
- 输出证据只记录 fixture id、error code、布尔断言和低敏字段，不输出真实剪贴板正文、完整路径或用户内容。

## 5. 开发拆分口径

v1 可以保留 2A/2B/2C/2D 的验证分层，但后续开发派发不必机械拆成四个很小批次。推荐写成：
