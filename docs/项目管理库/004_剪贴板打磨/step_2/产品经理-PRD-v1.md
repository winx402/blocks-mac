## 1. 阶段目标

Step 2 只处理剪贴板标签与收藏模型。目标是用独立的标签事实源替代旧 pinboard / pinned / 固定概念，让用户能给一条剪贴板记录打多个标签、按单个标签筛选、在设置页管理标签，并把“收藏”收敛为一个不可变更的内置标签。

本阶段不处理明文展示、OCR 搜索底座、详情编辑、隐私页 App 管理或全量面板视觉重设计。

## 3. 项目负责人收敛决策回写

Step 2 v1 采用以下收敛口径：

1. 标签模型必须是独立事实源，不是旧 pinboard / pinned 改名。
2. Step 2 只做单标签筛选；多标签 OR / AND 组合筛选后续再设计。
3. “收藏”是内置标签，必须有稳定 built-in identity；显示名和五角星只是呈现。
4. “收藏”在 Step 2 中不可改名、不可删除、不可排序、不可改色。
5. Step 2 禁止普通标签合并到“收藏”；批量收藏未来如需要单独设计。
6. 普通标签可以合并到普通标签，必须有明确反馈和事务边界。
7. 删除普通标签不要求二次确认，但必须有明确影响说明、成功/失败反馈和失败不半更新规则。
8. 标签搜索拆成两层：Step 2 交付标签字段/更新事件/索引输入契约；端到端搜索框命中依赖 Step 1 搜索底座实现后再做集成验收。
9. 旧 pinboard / pinned 不迁移、不兼容；若内部字段短期保留，不得作为当前 UI、筛选、搜索、收藏按钮或验收事实源。

## 4. 明确不覆盖

以下非目标按 `项目负责人-PRD复审收敛-v0.md` 第 5 节保持不变：

- 明文展示、OCR 搜索底座和非标签搜索字段实现。
- 面板筛选 hover 安全区、搜索框宽度、选中反馈、单 / 双击设置、卡片密度和全量面板布局打磨。
- 详情编辑、保存 / 取消、富文本编辑和 OCR 文本编辑。
- 隐私页真实 App 清单和 CLI 广义对象管理。
- 多标签 OR / AND 组合筛选。
- 批量删除标签、删除前二次确认、自动清理空标签。
- 旧 pinboard / 固定数据迁移。

## 5. 标签事实源与唯一性

### 5.1 标签实体

标签是独立实体，不能用显示名称或旧 pinboard / pinned id 作为记录关联主键。

标签至少包含以下产品层字段或等价模型：

- `tagID`：稳定标识。
- `displayName`：用户可见名称。
- `normalizedName`：唯一性归一化名称。
- `colorToken`：受控颜色 token。
- `sortOrder`：普通标签排序值。
- `builtInKind`：内置类型，例如 none / favorite。

标签唯一性规则：

- 唯一性以 `normalizedName` 或等价稳定归一化键判断，不以 UI 临时比较为准。
- 归一化至少包括 trim、折叠连续空白、大小写不敏感。
- 空名无效。
- 控制字符无效。
- 普通标签不能占用“收藏”的归一化名称，也不能通过大小写、空格或本地化绕过占用。
- `displayName` 可以保留用户输入的可读展示形式，但保存时必须绑定唯一的 normalized key。

技术方案待确认：Unicode normalization、全半角处理、locale-independent 规则或项目指定 locale 的具体算法由 App 架构师确认。该项不影响开发前验收边界，因为 PRD 已明确稳定归一化键、最低归一化要求和唯一约束。

### 5.2 RecordTag 关系

记录与标签通过独立关联关系连接。record-tag 关系至少由 `recordID + tagID` 唯一约束，保证同一记录不能重复关联同一标签。

record-tag 关系用于：

- 单标签筛选。
- 条目标签展示。
- 右键菜单已添加 / 未添加状态。
- 收藏按钮状态。
- 标签搜索字段更新契约。

旧 pinboard / pinned 不得作为 record-tag 的事实源、兼容派生源或验收 ok 证据。

### 5.3 持久化要求

以下结果需要跨 reload / 重启 / repository reload 保持：

- 新建标签。
- 标签颜色。
- 标签排序。
- 标签重命名。
- record-tag 关系。
- 收藏关系。
- 合并结果。
- 删除结果。

fixture / import / repository reload 不得产生重复“收藏”内置标签。

## 6. 收藏内置标签

收藏是内置标签，不是旧固定状态，也不是第二套数据模型。

收藏规则：

- 收藏由稳定 built-in identity 表达，例如 `builtInKind = favorite` 或等价模型。
- 显示名和五角星只是呈现。
- 收藏标签默认存在。
- 收藏标签默认第一。
- 收藏标签使用五角星图标。
- 收藏不可删除。
- 收藏不可改名。
- 收藏不可排序。
- 收藏不可改色。
- 收藏不能作为被合并标签删除。
- 普通标签不能合并到收藏。
- 普通标签不能占用收藏的归一化名称。
- 不需要独立快捷筛选入口。

收藏按钮行为：

- 点击未收藏条目的收藏按钮，添加该记录与收藏标签的关系。
- 点击已收藏条目的收藏按钮，移除该记录与收藏标签的关系。
- 收藏按钮不再读写旧 pinned 独立状态。

右键菜单中的收藏：

- 收藏可以作为标签菜单第一项出现。
- 右键菜单中的收藏添加 / 移除语义必须与条目五角星按钮一致。

## 7. 单标签筛选与信息结构

Step 2 只支持单标签筛选。UI 不展示多选、AND 或 OR 语义。

标签在面板筛选组、条目展示、设置页和右键菜单中使用同一排序规则：

- “全部”或等价未筛选状态在筛选入口中可达。
- 收藏第一。
- 普通标签按设置页排序。
- 条目已关联标签按同一顺序展示。
- 右键菜单按同一顺序展示。
- 设置页按同一顺序展示。

筛选规则：

- 选择某个标签后，列表只展示拥有该标签的记录。
- 当前筛选有明确 active 状态。
- 必须提供清除筛选 / 回到全部记录路径。
- 删除当前筛选标签后，筛选回到全部记录。
- 合并当前筛选源标签后，筛选切换到目标标签。

条目展示：

- 条目展示已关联标签。
- 长标签可截断或换行，但不得挤压主要内容。
- 颜色不能是唯一识别方式；必须显示标签名称。
- 收藏可用五角星表达，但仍是标签关系。

技术方案待确认：长标签截断行数、换行策略、标签显示上限由 UI/交互和开发在方案阶段确定。该项不影响开发前验收边界，因为 PRD 已明确排序、active、清除路径和不挤压主要内容。

## 8. 右键菜单

右键标签菜单是当前条目的标签关系编辑入口。

必须支持：

- 添加已有标签到当前条目。
- 从当前条目移除已有标签。
- 新建标签，并把新标签添加到当前条目。

交互规则：

- 已添加标签显示选中状态，点击表示从当前条目移除。
- 未添加标签显示未选中状态，点击表示添加到当前条目。
- `New Tag...` 或等价新建入口固定在标签菜单中。
- 新建标签成功后立即添加到当前条目。
- 空名或重名失败时，不创建标签、不改变条目关系，并在当前输入位置或当前操作语境中展示错误。
- 已添加和未添加标签不能混在无状态列表中。

## 9. 设置页标签管理

设置页是标签实体管理入口。

标签行至少包含：

- 颜色 swatch。
- 标签名称。
- 内置状态。
- 排序控制。
- 操作入口。

设置页必须支持：

- 查看标签列表。
- 查看每个标签的颜色和排序。
- 修改普通标签颜色。
- 调整普通标签排序。
- 重命名普通标签。
- 合并普通标签到普通标签。
- 删除普通标签。
- 新建普通标签。

收藏行：

- 固定第一。
- 可见。
- 删除、改名、排序、改色操作禁用或隐藏。
- 禁用或隐藏原因应可理解，例如文案、tooltip 或可访问性 label。

空状态：

- 没有普通标签时，仍展示收藏行。
- 没有普通标签时，仍提供新建普通标签入口。

质感与可访问性：

- 长标签名、长错误文案和窄宽度下不得覆盖主要操作。
- 颜色不能是唯一信息。
- VoiceOver 能读出标签名、是否内置/收藏、颜色、排序位置和可用操作。

## 10. 标签操作契约

### 10.1 创建

创建普通标签时：

- 输入先经过归一化校验。
- 空名、控制字符、重名失败。
- 失败时保留用户输入并展示错误。
- 失败时不创建标签、不改变任何记录关系。
- 从右键菜单新建成功后，立即添加到当前条目。

### 10.2 重命名

重命名普通标签时：

- 空名、控制字符、重名失败。
- 失败时旧名称继续有效。
- 失败时筛选、条目展示、右键菜单、设置页和标签搜索字段不发生半更新。
- 成功后设置页、筛选组选项、右键菜单、条目标签展示和标签搜索字段同步更新。

### 10.3 改色

普通标签可改色。

要求：

- 使用受控 colorToken。
- 成功后设置页、筛选组和条目展示同步更新。
- 失败时保留原颜色。
- 收藏不可改色。

技术方案待确认：色板数量、具体色值、深浅模式对比度和色弱可辨识策略由 UI/交互与技术方案确认。该项不影响开发前验收边界，因为 PRD 已明确普通标签使用受控 colorToken，收藏不可改色，颜色不能是唯一识别方式。

### 10.4 排序

排序规则：

- 收藏始终第一，不参与普通标签排序。
- 普通标签排序是持久化用户顺序。
- 新建普通标签默认进入普通标签末尾。
- 删除或合并后，普通标签显示顺序应保持稳定，不因内部字段变化造成跳动。
- 排序失败时不改变原排序。

技术方案待确认：排序字段是否压缩、是否允许空洞、拖拽或按钮控件由技术方案和 UI 方案确认。该项不影响开发前验收边界，因为 PRD 已明确收藏第一 invariant、普通标签持久化顺序和新建默认末尾。

### 10.5 删除普通标签

删除普通标签会删除该标签实体，并移除它与所有记录的关联；不删除记录本身。

要求：

- 删除操作位置或操作文案需要说明“会从所有记录移除此标签”。
- 删除成功后，该标签从设置页、筛选列表、右键菜单、条目展示和标签搜索字段中消失。
- 删除当前筛选标签后，筛选回到全部记录。
- 删除失败不应出现标签实体删除但关系残留，或关系删除但标签仍可见。
- 删除失败时保持原状态，并展示失败反馈。
- 删除普通标签不要求二次确认。
- 不做批量删除。
- 不做自动清理空标签。
- 收藏标签删除入口不可用，底层也应拒绝删除。

### 10.6 合并普通标签

Step 2 只允许普通标签合并到普通标签。普通标签禁止合并到收藏；收藏也不能作为源标签被删除。

合并规则：

- 源标签和目标标签不能相同。
- 目标标签保留名称、颜色和排序。
- 源标签关联全部转移到目标标签。
- 同时拥有源标签和目标标签的记录，合并后只保留一个目标标签关联。
- 源标签从设置页、筛选列表、右键菜单、条目展示和标签搜索字段中消失。
- 合并完成后删除源标签。
- 当前正在按源标签筛选时，合并完成后切换到目标标签筛选。
- 合并失败必须保持原状态，不允许部分记录已转移、部分未转移。
- 合并必须有成功或失败反馈。

合并 UI 需要展示源标签、目标标签和结果说明。具体是 popover、sheet 还是等价确认面由 UI/交互方案确定；PRD 不要求删除前二次确认，但合并影响多条记录，需要最小结果说明。

### 10.7 操作反馈与事务边界

创建、重命名、改色、排序、删除、合并都必须有成功或失败反馈。

删除和合并以一致性为优先：

- 删除普通标签必须原子删除 tag entity 和所有 record-tag 关联。
- 合并必须在一个事务或等价一致性边界内完成：转移关联、去重、删除源标签、更新显示、触发标签搜索字段失效或重建。
- 合并多个源标签时，如果本阶段不支持多源合并，则 UI 不应暴露多源合并入口；如果技术方案支持多源，任一源失败应整体失败或明确回滚。
- 失败时不允许出现设置页、筛选组、右键菜单、条目展示之间状态不一致。

技术方案待确认：具体事务 API、错误类型和恢复策略由 App 架构师和开发确认。该项不影响开发前验收边界，因为 PRD 已定义用户可见原子性、失败不半更新和反馈要求。

## 11. 标签搜索依赖拆分

Step 2 标签搜索拆成两层 Gate。

### 11.1 字段契约 Gate

Step 1 搜索底座未最终接受前，Step 2 至少必须交付：

- 标签字段模型。
- 标签名称作为可搜索字段的输入契约。
- 创建、重命名、合并、删除后的标签字段更新事件或等价接口。
- record-tag 关系变化后的索引失效或更新事件。
- 可区分标签字段命中和正文偶然同名命中的 fixture 设计要求。

字段契约 Gate 可以独立于端到端搜索框验收。

### 11.2 端到端搜索 Gate

Step 1 搜索底座稳定后，再验收：

- 搜索标签名可命中拥有该标签的记录。
- 重命名后旧标签名不再命中，新标签名命中。
- 合并后源标签名不再命中，目标标签名命中合并后的记录。
- 删除后标签名不再命中。
- fixture 的正文不得包含标签名，避免正文命中伪装成标签命中。

如果后续决定先接受 Step 2 模型而端到端标签搜索未闭合，接受状态必须标为带残余风险，并纳入 Step 6 集成 Gate。

## 12. 旧 pinboard / pinned 退出边界

用户已确认当前项目没有实际用户，不需要兼容旧逻辑。

Step 2 产品边界：

- 用户可见界面不再出现 `pinboard`、`Pinned Groups`、`Move to Pinboard`、`pinned summaries`、`clear unpinned`、`固定` 作为独立模型。
- 旧 pinboard / pinned 不迁移。
- 旧 pinboard / pinned 不提示迁移。
- 收藏按钮只读写收藏标签关系。
- 标签筛选只依赖 Tag / RecordTag 当前事实源。
- 右键标签状态只依赖 Tag / RecordTag 当前事实源。
- 标签搜索字段契约只依赖 Tag / RecordTag 当前事实源。
- fixture / reset 路径应能构造 Tag 与 RecordTag 事实，不再依赖旧 pinboard fixture 代表标签。
- 如旧字段为开发期数据库兼容短期保留，必须不参与当前 UI / 搜索 / 筛选 / 收藏按钮事实源，并在开发记录中说明。

需要新增 Step 2 专属 fail-closed verification gate，检查：

- 标签模型不是旧 pinboard / pinned 改名。
- 收藏是内置标签关系事实源。
- 用户可见旧 pinboard / pinned / 固定入口已退出。
- 多标签关系由 RecordTag 或等价事实源提供。
- 唯一性、删除、合并事务成立。
- 设置页、面板、右键菜单、filter 使用同一事实源。
- 旧 pinboard / pinned 不作为当前 ok 证据。

## 13. 验收样例

验收应使用 synthetic / fixture 内容，不复制真实用户剪贴板。

### 13.1 多标签与去重

- 记录 A 添加 `Work` 和 `Draft`，条目显示两个标签。
- 按 `Work` 筛选命中 A。
- 按 `Draft` 筛选也命中 A。
- 对 A 再次添加 `Work` 不产生重复关联。
- 移除 A 的 `Draft` 后，A 仍保留 `Work`，不再被 `Draft` 筛选命中。

### 13.2 重名与输入归一化

- 已存在 `Work` 时，新建 `work`、` Work `、`WORK` 均失败。
- 已存在 `Work` 时，新建 `Wo   rk` 是否等同由技术方案归一化规则决定；若折叠连续空白后等同，则必须失败。
- 空白名称失败。
- 控制字符名称失败。
- 普通标签不能命名为 `收藏`，包括首尾空格和大小写等归一化场景。
- 失败不创建标签、不改变任何记录的标签关系。

### 13.3 颜色、排序、重命名

- 修改普通标签颜色后，设置页、筛选项和条目展示一致更新。
- 调整普通标签顺序后，收藏仍第一，普通标签按用户顺序展示。
- 新建普通标签默认出现在普通标签末尾。
- 重命名 `Draft` 为 `Review` 后，设置页、筛选项、右键菜单、条目展示和标签搜索字段同步更新。
- 重命名失败不改变旧名称或记录关系。

### 13.4 删除普通标签

- 删除 `Draft` 后，所有记录上的 `Draft` 关系移除，记录本身保留。
- `Draft` 从设置页、筛选项、右键菜单和条目标签展示消失。
- 搜索 `Draft` 不再因标签字段命中这些记录。
- 删除空标签只删除标签实体，不影响记录。
- 删除当前筛选的 `Draft` 后，筛选回到全部记录。
- 删除 `收藏` 的入口不可用或被拒绝。
- 删除失败不产生半更新。

### 13.5 合并普通标签

- `Draft` 合并到 `Work` 后，原 `Draft` 记录拥有 `Work`。
- 同时有 `Draft` 和 `Work` 的记录合并后只保留一个 `Work`。
- `Draft` 消失，`Work` 保留原名称、颜色、排序。
- 搜索 `Draft` 不再因标签字段命中。
- 搜索 `Work` 命中合并后的记录。
- 当前筛选 `Draft` 时，合并完成后切换到 `Work` 筛选。
- 合并到收藏不可用或被拒绝。
- 合并失败不产生部分迁移。

### 13.6 收藏

- 初始存在唯一“收藏”标签，五角星，第一位。
- 收藏不可删除、不可改名、不可改色、不可排序。
- 收藏不能被普通标签重名占用。
- 未收藏记录点击收藏后拥有收藏标签。
- 已收藏记录再次点击后移除收藏标签。
- 右键菜单中的收藏操作与五角星状态同步。
- 按收藏筛选只显示拥有收藏标签的记录。
- 收藏关系跨 reload / 重启保持。
- fixture / import / repository reload 不产生重复收藏标签。

### 13.7 右键菜单

- 已添加标签和未添加标签状态可区分。
- 添加已有标签后条目展示、筛选、字段契约同步。
- 移除已有标签后同步消失。
- 新建标签并添加到当前记录成功后，设置页和条目同时可见。
- 新建重名失败时，不改变标签列表和当前记录关系。

### 13.8 设置页

- 标签行包含颜色、名称、内置状态、排序控制和操作入口。
- 收藏行固定第一，不可变更操作禁用或隐藏，原因可理解。
- 普通标签为空时，仍展示收藏行和新建普通标签入口。
- 长标签名、长错误文案和窄宽度下操作列不重叠。
- 颜色不是唯一识别方式。
- VoiceOver 能读出标签名、收藏状态、已添加 / 未添加状态、删除 / 合并 / 重命名动作。

### 13.9 标签搜索分阶段

字段契约 Gate：

- 新建、重命名、合并、删除标签时，存在标签字段更新事件或等价索引输入。
- fixture 正文不包含标签名，避免正文命中伪装为标签命中。

端到端搜索 Gate：

- Step 1 搜索底座可用后，搜索 `Work` 命中拥有 `Work` 的记录。
- 重命名 `Work` 为 `Review` 后，搜索 `Work` 不再因标签字段命中，搜索 `Review` 命中。
- `Draft` 合并到 `Work` 后，搜索 `Draft` 不再因标签字段命中，搜索 `Work` 命中合并后的记录。
- 删除 `Work` 后，搜索 `Work` 不再因标签字段命中。

### 13.10 旧逻辑退出

- UI 不再出现旧 pinboard / pinned / 固定独立模型。
- 旧固定筛选和新收藏标签不并列。
- 旧固定数据不迁移、不提示迁移。
- 收藏按钮变更的是收藏标签关系。
- 旧 pinned 状态不影响筛选、排序、搜索或收藏按钮。

## 14. 收敛问题回写清单

### 14.1 标签事实源与唯一性

已回写：

- 标签有稳定 `tagID` 或等价主键。
- 标签至少包含 `displayName`、`normalizedName`、`colorToken`、`sortOrder`、`builtInKind` 或等价模型。
- record-tag 关系是独立关联事实源，由 `recordID + tagID` 唯一约束。
- 标签唯一性基于稳定归一化键。
- 归一化至少包括 trim、折叠连续空白、大小写不敏感。
- 空名和控制字符无效。

### 14.2 收藏内置标签

已回写：

- 收藏由稳定 built-in identity 表达。
- 收藏不可删除、不可改名、不可排序、不可改色。
- 收藏始终第一，不依赖普通排序。
- 普通标签不能合并到收藏。
- 收藏不能作为被合并标签删除。
- 右键菜单收藏操作与五角星状态同步。

### 14.3 单标签筛选与信息结构

已回写：

- Step 2 只支持单标签筛选。
- 默认“全部”或等价未筛选状态。
- 收藏第一，普通标签按设置页排序。
- 筛选组、条目标签、设置页、右键菜单使用同一排序规则。
- 条目展示已关联标签，长标签可截断但不得挤压主要内容。
- active 状态和清除路径。
- 删除当前筛选标签后回到全部记录。
- 合并当前筛选源标签后切换到目标标签。

### 14.4 右键菜单

已回写：

- 右键标签菜单是当前条目的标签关系编辑入口。
- 已添加标签显示选中状态，点击移除。
- 未添加标签显示未选中状态，点击添加。
- `New Tag...` 或等价入口固定在标签菜单中。
- 新建成功后立即添加到当前条目。
- 空名或重名失败时不创建标签、不改变关系，并展示错误。

### 14.5 设置页标签管理

已回写：

- 设置页标签行包含颜色 swatch、标签名称、内置状态、排序控制和操作入口。
- 收藏行固定第一，普通标签从第二行开始排序。
- 收藏不可用操作禁用或隐藏，并让用户理解原因。
- 无普通标签时仍展示收藏行和新建入口。
- 普通标签支持改色、排序、重命名、合并、删除。
- 长标签名、长错误文案和窄宽度下不覆盖主要操作。
- 颜色不是唯一识别方式，VoiceOver 能读出关键状态和操作。

### 14.6 删除、重命名、合并和失败反馈

已回写：

- 删除普通标签删除标签实体及其与所有记录的关联，不删除记录本身。
- 删除后从设置页、筛选列表、右键菜单、条目展示和标签搜索字段中消失。
- 删除操作文案说明会从所有记录移除此标签。
- 删除失败不半更新。
- 重命名空名、重名或无效名展示错误，旧名称和原有关联继续有效。
- 合并只允许普通标签合并到普通标签。
- 合并目标保留名称、颜色和排序；源标签关联转移、去重并删除源标签。
- 源标签和目标标签不能相同。
- 合并失败保持原状态。
- 创建、重命名、删除、合并都有成功或失败反馈。

### 14.7 持久化、旧逻辑退出和门禁

已回写：

- 新建标签、颜色、排序、重命名、record-tag 关系、收藏关系、合并和删除结果需要跨 reload / 重启 / repository reload 保持。
- fixture / import / repository reload 不得产生重复收藏标签。
- 用户可见界面不再出现旧 pinboard / pinned / 固定作为独立模型。
- 收藏按钮不再读写旧 pinned 独立状态。
- 旧 pinboard / pinned 数据不迁移、不提示迁移。
- 旧字段如短期保留，不参与当前 UI / 搜索 / 筛选事实源。
- 需要新增 Step 2 专属 fail-closed verification gate。

### 14.8 标签搜索依赖拆分

已回写：

- Step 2 可独立验收标签模型、设置页管理、右键菜单、标签筛选和收藏切换。
- Step 1 搜索底座未实现前，Step 2 只验收标签字段模型、索引输入契约、更新事件或等价接口。
- Step 1 搜索底座实现后，再验收搜索标签名可命中记录、重命名后旧标签名不再命中、合并后源标签名不再命中、删除后标签名不再命中。
- 如先接受模型而端到端标签搜索未闭合，接受状态必须标为带残余风险，并纳入 Step 6 集成 Gate。

## 15. 技术方案待确认项

以下事项超出产品经理职责，不在 PRD 中指定具体实现，但不会影响开发前验收边界：

1. Unicode normalization、全半角处理、locale-independent 规则或项目指定 locale 的具体算法。
   - 不影响原因：PRD 已定义稳定归一化键、trim、折叠连续空白、大小写不敏感、空名和控制字符无效。
2. 长标签截断行数、换行策略、标签显示上限。
   - 不影响原因：PRD 已定义排序一致、active/clear 状态和不挤压主要内容。
3. 色板数量、具体色值、深浅模式对比度和色弱可辨识策略。
   - 不影响原因：PRD 已定义受控 colorToken、收藏不可改色、颜色不能作为唯一识别方式。
4. 排序字段是否压缩、是否允许空洞、排序控件采用拖拽还是按钮。
   - 不影响原因：PRD 已定义收藏第一 invariant、普通标签持久化顺序和新建默认末尾。
5. 事务 API、错误类型、恢复策略和 repository/store 拆分。
   - 不影响原因：PRD 已定义用户可见原子性、失败不半更新、跨 reload 保持和反馈要求。
6. 标签字段更新事件的具体接口名、搜索索引接入点和 reindex 策略。
   - 不影响原因：PRD 已拆分字段契约 Gate 与端到端搜索 Gate，并明确 Step 1 搜索底座依赖。
7. Step 2 verification gate 的脚本名称、断言落点和旧门禁迁移方式。
   - 不影响原因：PRD 已定义必须证明的旧逻辑退出、事实源、唯一性、合并/删除事务和 UI 同源边界。

## 16. 复审建议

Step 2 PRD v1 进入开发前，建议由项目负责人重点复核第 14 节收敛问题回写清单。

如项目负责人确认第 3、4 节决策和必须修订问题均已回写，建议再交 App 架构师做技术方案拆解。若 Step 1 搜索底座尚未 accepted，建议 Step 2 技术方案先拆标签事实源、单标签筛选、设置页管理、右键菜单和收藏切换；标签端到端搜索按第 11 节拆为后续集成 Gate。
