## 3. 接受范围

Step 2 PRD v1 已覆盖以下阶段范围：

- 标签模型是独立事实源，不是旧 pinboard / pinned 改名。
- 标签至少具备稳定标识、展示名、归一化名、颜色 token、排序和内置类型等产品层契约。
- 记录与标签通过独立 record-tag 关系关联，同一记录不能重复关联同一标签。
- 标签唯一性基于稳定归一化键，至少覆盖 trim、折叠连续空白、大小写不敏感、空名和控制字符无效。
- “收藏”是内置标签，具备稳定 built-in identity，默认第一，五角星图标，不可删除、改名、排序、改色。
- Step 2 只做单标签筛选，不做多标签 OR / AND。
- 条目、筛选组、设置页和右键菜单使用同一标签排序与关系事实源。
- 右键菜单支持添加、移除和新建标签并添加到当前条目。
- 设置页支持普通标签的颜色、排序、重命名、合并和删除。
- 普通标签只能合并到普通标签，不允许合并到收藏。
- 删除和合并有原子性、失败不半更新和用户反馈边界。
- 标签相关结果需要跨 reload / 重启 / repository reload 保持。
- 旧 pinboard / pinned / 固定逻辑不迁移、不兼容，不作为当前 UI、筛选、搜索、收藏按钮或验收事实源。
- 标签搜索拆为字段契约 Gate 与端到端搜索 Gate，允许与 Step 1 搜索底座并发推进但不得混淆验收。

## 4. 必须保持的阶段边界

以下内容仍不进入 Step 2：

- 明文展示、OCR 搜索底座和非标签搜索字段实现。
- 面板 hover 安全区、搜索框宽度、选中反馈、单 / 双击设置、卡片密度和全量布局打磨。
- 详情编辑、保存 / 取消、富文本编辑和 OCR 文本编辑。
- 隐私页真实 App 清单和 CLI 广义对象管理。
- 多标签 OR / AND 组合筛选。
- 批量删除标签、删除前二次确认、自动清理空标签。
- 旧 pinboard / 固定数据迁移。

## 5. 技术方案输入

后续 App 架构师技术方案需要重点落以下边界：

1. Tag / RecordTag 或等价 store / repository 事实源边界。
2. `normalizedName` 或等价归一化键的稳定算法和唯一约束。
3. 收藏内置标签 bootstrap、去重和不可变更保护。
4. 删除、合并、重命名、改色、排序、添加和移除标签的事务边界。
5. 标签字段进入搜索索引的 contract / invalidation / reindex 接口，端到端搜索接入依赖 Step 1 搜索底座。
6. 旧 pinboard / pinned 退出门禁，确保旧逻辑不作为当前事实源或通过证据。
7. Step 2 专属 fail-closed verification gate。

## 6. 后续 Gate

Step 2 后续不能直接进入开发。进入开发前至少需要：

- App 架构师产出 Step 2 技术方案。
- 项目负责人预审技术方案，确认没有重新引入旧 pinboard / pinned 事实源。
- 必要角色对技术方案进行复审，至少包含开发和测试/质量；如涉及搜索索引合流，应同步 App 架构师与 Step 1 技术方案结论。
- 项目负责人更新阶段状态和需求覆盖矩阵。

标签端到端搜索如果在 Step 2 阶段实现验收时仍依赖 Step 1 搜索底座未闭合，只能作为残余风险进入 Step 6 集成 Gate，不能伪装为已完整通过。
