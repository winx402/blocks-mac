## 3. 项目负责人收敛决策

为避免范围膨胀和实现歧义，Step 2 v1 采用以下收敛口径：

1. 标签模型必须是独立事实源，不是旧 pinboard / pinned 改名。
2. Step 2 只做单标签筛选；多标签 OR / AND 组合筛选后续再设计。
3. “收藏”是内置标签，必须有稳定 built-in identity；显示名和五角星只是呈现。
4. “收藏”在 Step 2 中不可改名、不可删除、不可排序、不可改色。
5. Step 2 禁止普通标签合并到“收藏”；批量收藏未来如需要单独设计。
6. 普通标签可以合并到普通标签，必须有明确确认/反馈和事务边界。
7. 删除普通标签不要求二次确认，但必须有明确影响说明、成功/失败反馈和失败不半更新规则。
8. 标签搜索拆成两层：Step 2 先交付标签字段/更新事件/索引输入契约；端到端搜索框命中依赖 Step 1 搜索底座实现后再做集成验收。
9. 旧 pinboard / pinned 不迁移、不兼容；若内部字段短期保留，不得作为当前 UI、筛选、搜索、收藏按钮或验收事实源。

## 4. 产品经理必须回写的问题

### 4.1 标签事实源与唯一性

必须补清：

- 标签有稳定 `tagID` 或等价主键，不能用显示名称作为记录关联主键。
- 标签至少包含 `displayName`、`normalizedName`、`colorToken`、`sortOrder`、`builtInKind` 或等价模型。
- record-tag 关系是独立关联事实源，至少由 `recordID + tagID` 唯一约束保证同一记录不重复关联同一标签。
- 标签唯一性基于稳定归一化键，而不是 UI 临时比较。
- 归一化至少包括 trim、折叠连续空白、大小写不敏感；普通标签不能占用收藏的归一化名称。
- 空名和控制字符无效。

### 4.2 收藏内置标签

必须补清：

- 收藏由稳定 built-in identity 表达，例如 `builtInKind = favorite` 或等价模型。
- 收藏不可删除、不可改名、不可排序、不可改色。
- 收藏始终在标签组第一位，不依赖普通排序值恰好最小。
- 普通标签不能合并到收藏；收藏也不能作为被合并标签删除。
- 右键菜单中的收藏操作与条目五角星状态同步，添加 / 移除语义一致。

### 4.3 单标签筛选与信息结构

必须补清：

- Step 2 只支持单标签筛选；OR / AND 多选不进入本阶段。
- 面板筛选默认有“全部”或等价未筛选状态。
- 收藏第一，普通标签按设置页排序。
- 筛选组、条目标签、设置页、右键菜单使用同一排序规则。
- 条目展示已关联标签，顺序与标签组一致；长标签可截断但不得挤压主要内容。
- 选择某标签后有明确 active 状态，并提供清除 / 回到全部路径。
- 删除当前筛选标签后，筛选回到全部记录。
- 合并当前筛选源标签后，筛选切换到目标标签。

### 4.4 右键菜单

必须补清：

- 右键标签菜单是当前条目的标签关系编辑入口。
- 已添加标签显示选中状态；点击表示从当前条目移除。
- 未添加标签显示未选中状态；点击表示添加到当前条目。
- `New Tag...` 或等价新建入口固定在标签菜单中。
- 新建标签成功后立即添加到当前条目。
- 空名或重名失败时，不创建标签、不改变条目关系，并展示错误。

### 4.5 设置页标签管理

必须补清：

- 设置页标签行至少包含颜色 swatch、标签名称、内置状态、排序控制和操作入口。
- 收藏行固定第一，普通标签从第二行开始排序。
- 收藏的不可用操作应禁用或隐藏，并能让用户理解原因。
- 没有普通标签时，仍展示收藏行和新建普通标签入口。
- 普通标签支持改色、排序、重命名、合并、删除。
- 长标签名、长错误文案和窄宽度下不得覆盖主要操作。
- 颜色不能是唯一识别方式；VoiceOver 能读出标签名、是否内置/收藏、颜色、排序位置和可用操作。

### 4.6 删除、重命名、合并和失败反馈

必须补清：

- 删除普通标签会删除该标签实体及其与所有记录的关联，但不删除记录本身。
- 删除普通标签后，该标签从设置页、筛选列表、右键菜单、条目展示和标签搜索字段中消失。
- 删除前或删除操作位置需要说明“会从所有记录移除此标签”。
- 删除失败不应出现标签实体删除但关系残留，或关系删除但标签仍可见。
- 重命名空名、重名或无效名时展示错误，旧名称和原有关联继续有效。
- 合并只允许普通标签合并到普通标签。
- 合并时目标标签保留名称、颜色和排序；源标签关联全部转移到目标标签；重复关联去重；源标签删除。
- 源标签和目标标签不能相同。
- 合并失败必须保持原状态，不允许部分记录转移。
- 创建、重命名、删除、合并都必须有成功或失败反馈。

### 4.7 持久化、旧逻辑退出和门禁

必须补清：

- 新建标签、颜色、排序、重命名、record-tag 关系、收藏关系、合并和删除结果需要跨 reload / 重启 / repository reload 保持。
- fixture / import / repository reload 不得产生重复收藏标签。
- 用户可见界面不再出现旧 pinboard / pinned / 固定作为独立模型。
- 收藏按钮不再读写旧 pinned 独立状态，只增删收藏标签关系。
- 旧 pinboard / pinned 数据不迁移、不提示迁移。
- 如旧字段为开发期数据库兼容短期保留，必须不参与当前 UI / 搜索 / 筛选事实源，并在开发记录中说明。
- 需要新增 Step 2 专属 fail-closed verification gate，检查标签事实源、收藏内置语义、旧逻辑退出、多标签关系、唯一性、删除/合并事务和 UI/筛选/右键菜单同一事实源。

### 4.8 标签搜索依赖拆分

必须补清：

- Step 2 可独立验收标签模型、设置页管理、右键菜单、标签筛选和收藏切换。
- Step 1 搜索底座未实现前，Step 2 只验收标签字段模型、索引输入契约、重命名/合并/删除后的更新事件或等价接口。
- Step 1 搜索底座实现后，再验收搜索标签名可命中记录、重命名后旧标签名不再命中、合并后源标签名不再命中、删除后标签名不再命中。
- 如果后续决定先接受 Step 2 模型而端到端标签搜索未闭合，接受状态必须标为带残余风险，并纳入 Step 6 集成 Gate。

## 5. 保持不变的非目标

产品经理修订时不得把以下内容写入 Step 2 交付：

- 明文展示、OCR 搜索底座和非标签搜索字段实现。
- 面板筛选 hover 安全区、搜索框宽度、选中反馈、单 / 双击设置、卡片密度和全量面板布局打磨。
- 详情编辑、保存 / 取消、富文本编辑和 OCR 文本编辑。
- 隐私页真实 App 清单和 CLI 广义对象管理。
- 多标签 OR / AND 组合筛选。
- 批量删除标签、删除前二次确认、自动清理空标签。
- 旧 pinboard / 固定数据迁移。

## 6. 下一步

产品经理基于本收敛意见产出 `step_2/产品经理-PRD-v1.md`，不覆盖 v0，不进入实现。

项目负责人复核 v1 后，如确认必须改问题已回写，将 Step 2 状态改为 `prd-accepted`，再决定是否进入 App 架构技术方案或是否等待 Step 1 技术方案先收敛搜索底座。
