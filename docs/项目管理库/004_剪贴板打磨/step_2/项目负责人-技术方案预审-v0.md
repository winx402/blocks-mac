## 1. 结论

Step 2 技术方案 v0 可以进入角色复审，当前不进入开发实现。

方案主线“Tag / RecordTag 独立事实源 + Favorite built-in tag + 原子标签事务 + 标签字段搜索契约 + 旧 pinboard/pinned fail-closed 退出门禁”与 Step 2 PRD v1 和项目负责人 PRD v1 复核结论一致。方案没有把 Step 1 搜索/OCR、Step 3 面板布局、Step 4 详情编辑或 Step 5 隐私页 App 管理提前并入 Step 2。

## 2. 预审通过点

- 明确 Step 2 不能做 UI 改名式迁移，必须建立 Tag / RecordTag 当前事实源。
- 覆盖 Tag / RecordTag schema、稳定 `normalizedName`、record-tag 唯一约束和 favorite built-in identity。
- 覆盖 favorite bootstrap、唯一性和不可删除/改名/改色/排序/合并保护。
- 覆盖创建、添加、移除、重命名、改色、排序、删除和合并事务边界。
- 覆盖 Step 1 search document 的标签字段 contract / invalidation / reindex 边界，并保持字段契约 Gate 与端到端搜索 Gate 分离。
- 覆盖旧 pinboard / pinned 当前事实源退出和 P13B fail-closed verifier。
- 开发子批次 Step 2A-2D 基本可作为后续开发拆分输入。

## 3. 需要角色复审重点

### 3.1 开发

请重点复审：

- Tag schema 是否应作为 AppDatabase V2，migration/backfill 是否可控。
- Normalizer 算法能否在 Core 中稳定实现，尤其 Unicode normalization、空白折叠、case fold 和内置别名表。
- `ClipboardTagRepository` 独立类还是 `ClipboardRepository` extension 更适合当前模块边界。
- `ClipboardTagStore` 与 `ClipboardStore` / `AppModel` 的 objectWillChange、状态同步和 facade 边界。
- delete / merge transaction 是否覆盖 affected recordIDs、search invalidation 和 UI selectedTagID 切换。
- 旧 `preservePinned` / `clearUnpinned` 策略是否必须在 Step 2 改成 preserveFavorite；如果不改，如何避免旧 pinned 文案和行为泄漏。
- P13B 最低断言和旧 P8/P9/P11 迁移是否可落地。

### 3.2 测试/质量

请重点复审：

- Tag repository smoke fixture 是否覆盖 create、duplicate、rename、delete、merge、add/remove、favorite immutable。
- UI fixture 是否覆盖 favorite first、single tag filter、right-click add/remove/new、settings CRUD。
- Legacy exit scan 是否能检测 active UI token、code path 和 verifier ok evidence 中的 pinboard/pinned/fixed。
- Search Gate 拆分是否有明确 PASS / residual risk 标记。
- 删除/合并失败、重复添加、favorite immutable、reserved name、control character 等错误反馈是否可判定。
- reload / restart / repository reload 不重复 favorite 的验收方式。

### 3.3 UI/交互设计师

请重点复审：

- 设置页 tag management row、favorite immutable 表达、禁用/隐藏原因是否够清晰。
- 右键菜单已添加/未添加、favorite first、新建失败反馈是否可用。
- 删除普通标签的影响说明和合并普通标签的结果说明是否足够。
- 单标签筛选 active / clear / delete active / merge active source 的体验是否顺畅。
- 长标签名、颜色 token、排序控件和窄宽度下布局是否需要补充验收。

## 4. 当前需要重点收敛的问题

以下问题不需要回到用户，但角色复审需要给明确建议，项目负责人后续会收敛：

1. `preservePinned` 是否在 Step 2 直接替换为 `preserveFavorite`。倾向：如果 active UI 或策略仍可见，应在 Step 2 处理，避免旧 pinned 概念泄漏。
2. P13B 是否能在 Step 2A 先红灯建立，再随 2A-2D 逐步转绿。
3. Step 1 search document 未落地时，Step 2D tag search contract 应如何记录 residual risk，避免伪装端到端搜索已完成。
4. 旧 pinboard / pinned DB 字段短期保留时，哪些 verifier 能证明它们没有参与当前事实源。
