# 测试/质量技术方案复审：Step 2 标签与收藏模型替换

日期：2026-07-07
角色：测试/质量
复审对象：`App架构师-技术方案-v0.md`、`项目负责人-技术方案预审-v0.md`、`产品经理-PRD-v1.md`

## 结论

`approve-with-changes`

技术方案主线“Tag / RecordTag 独立事实源 + Favorite built-in tag + 原子标签事务 + 标签字段搜索契约 + 旧 pinboard/pinned fail-closed 退出门禁”与 PRD v1 一致，阶段边界清楚，没有把 Step 1 搜索/OCR、Step 3 面板布局、Step 4 详情编辑或 Step 5 隐私页 App 管理提前并入 Step 2。

从测试/质量角度，方案具备可验收基础，但进入开发前仍需要补硬 6 个点：Tag repository smoke fixture 明细、UI fixture 明细、legacy exit scan 的精准范围、Search Gate 的 PASS / residual risk 输出格式、错误反馈与原子性证据、reload/restart 不重复 favorite 的可复跑验收。另需收敛 `preservePinned` 是否在 Step 2 替换为 `preserveFavorite`，否则旧概念可能继续泄漏到 active UI 或行为。

## 必须改

1. 固化 Tag repository smoke fixture。
   技术方案列出了 create / duplicate / rename / delete / merge / add/remove / favorite immutable，但需要写成可复跑 smoke 矩阵。至少应覆盖：
   - `ensureFavorite` 首次创建、重复调用、repository reload、fixture reset 后仍只有一个 favorite。
   - create `Work` / `Draft` / `Review`，验证 normalizedName、colorToken、sortOrder。
   - duplicate：`work`、` Work `、`WORK`、空名、控制字符、`收藏` / `favorite` 失败。
   - add/remove：同一 record 多标签、重复添加去重、移除后其他标签保持。
   - rename：普通标签成功/失败，失败不半更新。
   - delete：普通标签删除关系不删记录，favorite 删除被拒绝。
   - merge：`Draft -> Work`、重复关系去重、source==target 拒绝、source/target favorite 拒绝、失败全回滚。
   - persistence：reload/restart 后标签、关系、颜色、排序、favorite 关系、合并/删除结果保持。

2. 固化 UI fixture 和证据形态。
   UI fixture 不需要全量视觉重设计，但应可判断 pass/fail：
   - filter：`全部` 可达，favorite first，普通标签按排序，单标签 filter active/clear。
   - right-click：favorite first，已添加/未添加可区分，add/remove/new 成功，新建失败不改关系。
   - settings：favorite row first 且 immutable 操作禁用/隐藏；普通标签 CRUD、排序、合并、删除可达。
   - long label / narrow width 只需证明不覆盖主要操作，不要求 Step 3 级视觉打磨。
   - 证据建议使用低敏 fixture 截图、accessibility tree 摘要或 verifier JSON，不使用真实剪贴板正文。

3. Legacy exit scan 要区分 active 事实源与无关 false positive。
   当前代码和 verifier 中 pinboard/pinned 分布很广，轻量静态抽查能看到 `ClipboardPinboard`、`pinnedMetadata`、`togglePin`、`setPinboardFilter`、`clipboard.policy.preservePinned`、P9A/P9B/P8/P7D 等旧断言仍存在。P13B 不能只扫字符串总量，否则会被历史、注释或无关 `fixed width` 干扰；也不能太宽导致误伤 Step 3 布局里的 `fixed`。
   建议 legacy scan 分层：
   - active UI token：`pinboard`、`Pinned Groups`、`Move to Pinboard`、`pinned summaries`、`clear unpinned`、`固定` 作为独立模型出现即 fail。
   - active code path：filter、favorite button、right-click、settings、AppModel/Store facade 仍调用 `pinboardID`、`togglePin`、`renamePinnedRecord`、`move(toPinboard:)`、`pinnedMetadata` 作为当前事实源即 fail。
   - verifier ok evidence：旧 P8/P9/P11 仍以 pinboard/pinned checks 参与 `ok` 即 fail；只能进入 `baseline_reference`。
   - legacy storage：旧 DB 字段/表短期保留可不 fail，但必须不参与 active UI / current Store / current verifier ok。

4. Search Gate 必须输出 PASS / residual risk，而不是二选一混写。
   Step 1 search document 尚未稳定时，Step 2 不能把端到端标签搜索写成已通过。建议 P13B 或验收记录固定字段：
   - `tag_search_contract_gate=pass`：mutation 能产出 affected recordIDs / tag projection / invalidation hook。
   - `tag_search_e2e_gate=pass`：只有 Step 1 search document 可用且搜索框真实命中标签名时使用。
   - `tag_search_e2e_gate=blocked_by_step1` 或 `residual_risk`：Step 1 未落地时使用，并列入 Step 6 集成 Gate。
   - `ok` 不得因为端到端搜索未闭合而误报全绿，除非项目负责人接受带残余风险状态。

5. 错误反馈和原子性要有可判定证据。
   技术方案定义了错误类型，但测试需要能观察到操作失败后状态不变：
   - duplicate / empty / control / reserved favorite name。
   - favorite immutable：delete / rename / recolor / reorder / merge source / merge target 均被拒绝。
   - delete failed：tag entity 和 RecordTag 关系都保持原状。
   - merge failed：source、target、affected recordIDs 全部保持原状。
   - create from context menu 失败：不创建 tag、不附加 record-tag。
   - 输出只记录 error code / fixture id，不输出真实标签来源或剪贴板正文。

6. `preservePinned` / `clearUnpinned` 必须在开发前决定处理口径。
   测试侧建议按预审倾向处理为 P1：如果 active UI 或策略行为仍可见，应在 Step 2 替换为 `preserveFavorite` 或隐藏旧入口，并基于 Favorite RecordTag 行为验收；否则旧 pinned 概念会在用户可见设置、清理策略或 verifier 中继续泄漏。
   可接受口径只有两种：
   - Step 2 内完成 `preserveFavorite` 最小替换，并加入 P13B / P9A smoke。
   - Step 2 暂不改策略，但 active UI 不显示旧文案，开发记录标为 residual，并且 verifier 不把 preservePinned 作为 ok evidence。

7. P13B 应允许先红灯建立，但最终必须 fail closed。
   P13B-first 是合理策略，但需要明确每个子批次的预期：
   - Step 2A 前：P13B 可因 Tag schema 不存在而 red。
   - Step 2A 后：repository smoke 应转绿，UI/legacy active path 可仍 red。
   - Step 2C 后：active UI legacy exit 应转绿。
   - Step 2D 后：旧 verifier ok evidence 和 search contract 应转绿或明确 residual。
   最终验收时 P13B 不应因“旧字段暂存”静默通过，必须证明旧字段不在当前事实源。

## 可优化

1. Normalizer 的 Unicode 细节可由开发记录固定，不必在 PRD 层过度展开。
   测试必验 trim、空白折叠、大小写不敏感、空名、控制字符、favorite reserved；diacritic / 全半角可作为 P2。

2. `ClipboardTagRepository` 独立类还是 `ClipboardRepository` extension 不应阻塞测试结论。
   测试关注 repository API、transaction、reload、smoke fixture 和 View 不直接写事实源。

3. 多标签 OR / AND、批量删除、删除二次确认、自动清理空标签不进入 Step 2。
   不应作为验收失败条件。

4. 长标签布局、颜色对比度、窄窗口视觉质感可以由 UI 复审细化。
   Step 2 测试只需保证可达、可读、不遮挡关键操作，深度布局留给 Step 3。

5. 旧 DB 表的物理删除可以后续做。
   只要 current UI / Store / verifier ok 不读取旧 pinboard/pinned 事实源，短期 legacy storage 可接受。

## 可吸收建议

### 1. Repository smoke 推荐矩阵

| 场景 | 操作 | Pass | Fail |
| --- | --- | --- | --- |
| favorite bootstrap | 连续调用 ensure/load/reset/reload | 始终唯一 favorite，第一位，不重复 | 出现 0 个或多个 favorite |
| create | 新建 `Work` | tag 存在，normalizedName 稳定，sortOrder 在普通末尾 | 空 tag、无 normalizedName、排序不稳定 |
| duplicate | 新建 `work` / ` Work ` / `WORK` | 均拒绝，原状态不变 | 创建出重复普通标签 |
| invalid name | 空名 / 控制字符 / `收藏` / `favorite` | 拒绝并输出错误 code | 创建成功或占用 favorite 名称 |
| add/remove | A 添加 `Work`、`Draft`，重复添加 `Work`，移除 `Draft` | 去重，A 保留 `Work`，不再有关联 `Draft` | 重复关系、移除误删其他标签 |
| rename | `Draft -> Review` | 展示/筛选/右键/search contract 同步 | 旧名和新名混用或半更新 |
| delete | 删除 `Draft` | tag 消失、关系移除、record 保留 | tag 消失但关系残留，或 record 被删 |
| merge | `Draft -> Work` | 关系转移、重复去重、source 删除、target 属性保留 | 部分迁移、target 属性被覆盖 |
| favorite immutable | delete/rename/recolor/reorder/merge favorite | 全部拒绝 | 任一路径改动 favorite entity |
| persistence | reload/restart 后读取 | 标签、关系、颜色、排序、favorite 关系保持 | 状态丢失或 favorite 重复 |

### 2. UI fixture 推荐矩阵

| 场景 | Pass | Fail |
| --- | --- | --- |
| filter favorite first | `全部` 可达，favorite 第一，普通标签按排序，active 明确 | favorite 不在第一，或仍显示 pinboard group |
| single tag filter | 选择 `Work` 只显示有 Work 的记录，clear 回全部 | UI 暗示多选 OR/AND，或结果不确定 |
| right-click add/remove | 已添加/未添加状态可区分，点击可添加/移除 | 无状态列表，或点击后关系不同步 |
| right-click new | 新建 `Review` 后立即附加到当前记录 | 创建成功但未附加，或失败后半更新 |
| settings CRUD | 普通标签可新建、改名、改色、排序、合并、删除 | 入口不可达或状态不同步 |
| favorite immutable UI | favorite 行禁用/隐藏 delete/rename/recolor/reorder/merge，并说明原因 | UI 可触发 favorite 变更 |
| long label/narrow | 长标签不遮挡主操作，名称仍可识别或有可访问标签 | 操作按钮被覆盖、label 溢出不可用 |

### 3. Legacy exit scan 推荐规则

P13B 建议输出以下分组，而不是一个笼统 `legacy_tokens_ok`：

```json
{
  "legacy_exit": {
    "active_ui_tokens_clear": true,
    "active_store_paths_clear": true,
    "filter_state_no_pinboard_fact": true,
    "right_click_no_move_to_pinboard": true,
    "settings_no_pinboard_section": true,
    "verifier_ok_evidence_clear": true,
    "legacy_storage_baseline_only": true
  }
}
```

推荐 fail 条件：

- active UI 中存在 `Move to Pinboard`、`Pinned Groups`、`clear unpinned`、`固定` 独立模型。
- current Store / AppModel facade 仍用 `togglePin`、`setPinboardFilter`、`renamePinnedRecord`、`pinnedMetadata` 决定 favorite/filter/search。
- P8/P9/P11 仍把 pinboard/pinned smoke 当成 `ok` 证据。
- `ClipboardFilterState.pinboardID` 仍是当前筛选事实源。

允许但必须标记 baseline：

- 旧 DB 表字段短期存在。
- 历史归档文档存在。
- verifier 中旧检查作为 `baseline_reference` 输出，不参与 `ok`。

### 4. Search Gate 推荐输出

```json
{
  "tag_search": {
    "contract_gate": "pass",
    "e2e_gate": "blocked_by_step1",
    "affected_record_ids_emitted": true,
    "projection_available": true,
    "fixtures_body_excludes_tag_name": true,
    "residual_risk": "Step 1 search document not yet implemented; end-to-end tag search remains Step 6 integration gate."
  }
}
```

当 Step 1 search document 可用后，`e2e_gate` 才能变为 `pass`，并且必须覆盖：

- 搜索 `Work` 命中拥有 Work 标签的记录。
- `Work -> Review` 后旧名不命中，新名命中。
- `Draft -> Work` 合并后源名不命中，目标名命中。
- 删除 `Work` 后不再因标签字段命中。

### 5. P13B 最低断言建议

- `tag_models_exist`：存在 ClipboardTag / ClipboardRecordTag 或等价模型。
- `schema_constraints_exist`：tagID、normalizedName unique、builtIn favorite unique、recordID+tagID unique。
- `favorite_immutable`：delete/rename/recolor/reorder/merge source/target 都拒绝 favorite。
- `normalizer_contract`：trim、whitespace fold、case fold、empty/control/reserved rejection。
- `repository_transactions`：delete/merge 具备 transaction 或等价一致性边界。
- `record_tag_relation_source`：多标签和 favorite 来自 RecordTag，不来自 pinned。
- `ui_uses_tag_source`：filter/right-click/settings 使用 tag source。
- `legacy_active_paths_clear`：pinboard/pinned 不在 active UI / current Store / verifier ok。
- `search_contract_gate`：mutation 产出 affected recordIDs / projection / invalidation。
- `favorite_bootstrap_idempotent`：reload/reset/restart 不重复 favorite。
- `low_sensitive_output`：JSON 不输出真实剪贴板正文、完整路径、用户数据。

## 残余风险

1. Step 1 search document 未完成时，端到端标签搜索只能作为残余风险或 Step 6 集成 Gate，不能伪装为 Step 2 全绿。
2. 旧 pinboard/pinned 代码路径很多，legacy exit scan 如果过宽会误伤无关 `fixed` 布局，如果过窄会漏掉 active path；必须按 active UI / code path / verifier ok evidence 分层。
3. `preservePinned` 若不在 Step 2 收敛，后续设置或清理策略仍可能暴露旧语义。
4. Normalizer 的 Unicode 细节会影响少量边界输入，需开发记录固定算法，避免随系统 locale 漂移。
