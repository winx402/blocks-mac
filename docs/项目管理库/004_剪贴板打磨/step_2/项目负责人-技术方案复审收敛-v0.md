## 3. 范围判断

### 3.1 可保持的方向

- `Tag / RecordTag` 或等价模型必须成为独立事实源。
- `Favorite` 必须是 built-in tag，不是并行 pinned 状态。
- 旧 pinboard / pinned 不迁移、不兼容当前产品语义；旧数据结构若短期保留，只能是 legacy storage。
- 单标签筛选、favorite first、右键标签增删/新建、设置页标签管理属于 Step 2。
- 标签搜索在 Step 2 只闭合字段契约；端到端搜索命中依赖 Step 1 search document 和 Step 6 集成 Gate。

### 3.2 不得扩大到的范围

- 不重做 Step 1 搜索/OCR 底座。
- 不引入多标签 OR / AND 组合筛选。
- 不做批量删除、删除前二次确认、自动清理空标签。
- 不做 Step 3 的筛选 hover、toolbar 尺寸、选中反馈或条目密度专项打磨。
- 不做 Step 4 详情编辑。
- 不做 Step 5 隐私页 App 清单。

## 4. 技术方案 v1 必须吸收

### 4.1 AppDatabase V2 与迁移契约

v1 必须明确 `AppDatabase` schema version / migration 策略：

- 创建 `clipboard_tags`、`clipboard_record_tags` 或等价表。
- seed 唯一 favorite built-in tag，且 seed 可重复执行不产生重复 favorite。
- 不迁移旧 pinned / pinboard 数据到新 tag 模型。
- 旧 `clipboard_items.pinned`、`clipboard_pinboards`、`clipboard_pinned_metadata` 如短期保留，只能作为 legacy storage。
- active repository、Store、View、Settings、filter、right-click、verifier ok evidence 不得再以旧 pinned / pinboard 为当前事实源。
- 明确 foreign key / cascade 或等价 cleanup 机制是否真实启用；不能只写 schema。

### 4.2 Tag name normalizer 固定算法

v1 不应保留 normalizer 算法二选一。建议固定为：

- NFKC normalization。
- trim 首尾空白和换行。
- 内部 Unicode whitespace run 折叠为单个 ASCII space。
- 空结果失败。
- normalization 后仍含 control character 失败。
- locale-independent case folding。
- reserved aliases 至少覆盖 `favorite`、`收藏` 及其 trim / case / width 变体。

如果 App 架构师选择不同算法，必须在 v1 明确算法和 fixture，不得留给开发临场决定。

### 4.3 Repository / Store 单事实源边界

v1 必须明确推荐结构：

- 优先采用独立 `ClipboardTagRepository`，共享 `AppDatabase` connection / transaction helper。
- `ClipboardTagStore` 是 tags、record-tags、selectedTagID、tag operation state/error 的唯一事实源。
- `ClipboardStore` 可桥接 tag store，但不得复制 tag facts 或与 tag store 双写。
- `AppModel` 只做 facade、status banner 和跨 store 协调，不保存 tag facts。
- View 不直接访问 repository，也不读取旧 pinned / pinboard 事实源。
- `ClipboardController.filteredRecords` 从 `pinboardID` 迁移为 `selectedTagID + RecordTag`。

若 v1 因实现约束不采用独立 `ClipboardTagRepository` / `ClipboardTagStore`，必须说明等价单事实源如何被 P13B 证明，不允许形成双事实源。

### 4.4 标签事务与 mutation result

v1 必须定义标签 mutation 的输出契约，至少包含等价信息：

- changed tag IDs。
- affected record IDs。
- removed tag IDs。
- selected tag transition：none / clear / switch source to target。

最低要求：

- create-and-attach、add、remove 返回当前 recordID。
- rename 返回所有关联该 tag 的 recordIDs。
- delete 返回删除前关联的 affected recordIDs。
- merge 返回 source 和 target 去重后的 affected recordIDs。
- updateColor / reorder 不触发 search invalidation，但必须刷新 tag list。
- search invalidation / reindex hook 只消费 affected recordIDs，不由 View 或 Store 二次猜测旧状态。
- 删除 / 合并失败不得半更新；成功后 selectedTagID 必须按规则清空或切换。

### 4.5 Favorite built-in 保护

v1 必须把 favorite 作为 built-in identity，而不是依赖显示名称：

- favorite 固定第一。
- favorite 不能删除、重命名、改色、排序。
- 普通标签不能合并到 favorite，favorite 也不能作为 source 或 target 参与合并。
- favorite bootstrap / reload / restart / reset 后不能重复。
- favorite 关系来自 RecordTag，不来自旧 pinned 字段。

### 4.6 `preservePinned` / `clearUnpinned` 收敛

项目负责人取舍如下：

- Step 2 不允许 active UI、Store 当前事实源、repository policy 当前行为或 verifier ok evidence 继续依赖 `preservePinned` / `clearUnpinned` / pinned 语义。
- 如果仍保留“清理时保留收藏项”能力，必须改为 `preserveFavorite` / `clearUnfavorited` 或等价 favorite 语义，并基于 favorite RecordTag 判断。
- 旧 `preservePinned` / `clearUnpinned` 名称如因兼容暂存，只能作为 deprecated adapter 或 legacy storage，不进入用户可见文案、当前事实源、通过证据或开发记录通过项。

这项不降级为后续阶段；v1 必须写清处理方案。

### 4.7 UI 交互合同

v1 不需要做视觉重设计，但必须把最小 UI 合同写清：

- Settings tag row 固定结构：颜色 swatch、名称、状态/内置标识、排序控件、操作入口。
- favorite row 固定第一，不暴露可执行删除、改名、改色、排序、合并动作；禁用或隐藏原因必须可理解。
- 右键菜单：favorite first；checked 表示已添加，点击移除；unchecked 表示未添加，点击添加。
- 右键新建失败时，错误反馈应贴近输入语境或有同屏可见反馈，不清空输入，不改变记录标签关系。
- 删除普通标签的文案必须表达“从所有记录移除此标签”。
- 合并必须展示 source、target 和结果；合并 active source 后切到 target。
- active filter、hover、focus 必须可区分；delete active 清空，merge active source 切换到 target。
- 长标签名、颜色 token、排序控件、窄宽度和 VoiceOver / 键盘路径需要最低验收口径。

### 4.8 P13B fail-closed verifier 与旧门禁迁移

v1 必须定义 P13B 红绿顺序和最低断言：

- Step 2A 前 P13B 可因缺少 Tag schema / active legacy path 失败。
- Step 2A 后 schema / repository / normalizer / favorite bootstrap 相关断言应转绿。
- Step 2B 后 Store / AppModel facade / selectedTagID 相关断言应转绿。
- Step 2C 后 UI active token、right-click、filter、settings 相关断言应转绿。
- Step 2D 后 search contract 和旧 P8/P9/P11 当前事实源迁移应转绿或明确 residual。

P13B legacy scan 必须分层：

- active UI token clear。
- active Store / repository / filter code path clear。
- verifier ok evidence clear。
- legacy storage baseline only。

旧 P8/P9/P11 若仍保留旧检查，只能作为 `baseline_reference`，不得参与 Step 2 `ok`。

### 4.9 Search Gate 输出

v1 必须区分：

- `tag_search_contract_gate=pass`：标签 mutation 能产出 affected recordIDs / projection / invalidation hook。
- `tag_search_e2e_gate=blocked_by_step1` 或 residual：Step 1 search document 未实现时使用。
- `tag_search_e2e_gate=pass`：仅在 Step 1 search document 可用且搜索框真实命中标签名后使用。

Step 2 不得把端到端标签搜索伪装为独立闭合。

### 4.10 Fixture 与低敏证据

v1 必须给出最低可复跑 fixture：

- repository smoke：create、duplicate、rename、delete、merge、add/remove、favorite immutable、persistence。
- UI fixture：favorite first、single tag filter、right-click add/remove/new、settings CRUD、long label/narrow width。
- 错误反馈：duplicate、empty、control character、reserved favorite name、favorite immutable、delete failed、merge failed。
- 输出证据只记录 fixture id、error code、布尔断言和低敏字段，不输出真实剪贴板正文、完整路径或用户内容。
