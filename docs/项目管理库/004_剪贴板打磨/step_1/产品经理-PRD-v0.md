## 1. 阶段目标

Step 1 只解决剪贴板面板当前最基础的可用性问题：用户打开面板后应能看到真实可读内容，搜索应能命中主要内容字段，图片内容应通过 macOS 系统 Vision OCR 进入搜索底座。

本阶段同时建立第一阶段的边界表达：项目从“默认遮挡 payload”调整为“真实内容可访问，交互输出可控”。这里的重点是 App 内面板和搜索可用，不是一次性重做 CLI、provider、日志和自动化全链路。

## 2. 本阶段范围

本阶段必须覆盖：

- 面板默认展示真实可读内容，不再只显示字符数或过度遮挡摘要。
- 设置页移除与明文展示目标冲突、且用户不能有效调整的剪贴板存储/内容保护 UI。
- 搜索覆盖正文、来源 App、URL、时间、类型、富文本纯文本化内容、文件名。
- 类型关键词和同义词支持，例如 `pic`、`picture`、`image`、`ima`、`图片`、`图` 命中图片类条目。
- OCR 进入阶段范围，但限定使用 macOS Vision。
- OCR 仅处理剪贴板中已有图片 payload，不做自研 OCR，不使用外部 provider OCR。
- OCR 异步执行，不阻塞面板打开、搜索输入和滚动。
- OCR 状态可感知：待处理、处理中、完成、失败、可重试。
- 日志、CLI、provider、自动化在本阶段先明确“可访问真实内容但输出可控”的原则，不做复杂权限开关或过滤系统。

本阶段不覆盖：

## 5. 产品原则

### 5.1 真实内容可访问

剪贴板面板和搜索应能使用剪贴板记录的真实内容。用户不应再看到只有“多少个字符”而无法判断内容的默认状态。

产品文案应尽量使用“内容”“正文”“原始内容”等用户可理解的表达，不把 `payload` 作为用户界面术语。

### 5.2 交互输出可控

真实内容可访问不等于所有界面、日志、CLI 或 provider 都无限制输出完整正文。本阶段输出控制的理由是性能、可读性、可维护性和防误操作，不再以“内容保护”为主要叙事。

本阶段只要求建立边界表达和避免明显反向设计；CLI、provider、日志、自动化的完整改造不属于 Step 1。

### 5.3 搜索底座可扩展

搜索不应实现为临时的可见文本过滤。Step 1 需要为正文、来源、URL、类型、富文本纯文本、文件名和 OCR 文本建立可扩展索引边界，为后续标签、详情编辑和隐私页管理预留扩展空间。

## 6. 用户可见行为

### 6.1 面板默认展示真实可读内容

用户打开剪贴板面板时，应看到每条记录的可读内容或可识别内容状态：

- 文本记录：展示真实正文的可读预览，不再只展示字符数。
- URL 记录：展示可读 URL 或 URL 文本，不只展示类型名。
- 富文本记录：本阶段展示可读的纯文本化内容；不承诺富文本编辑或格式保留。
- 图片记录：展示图片缩略图、图片类型信息和 OCR 状态。
- 文件或 file URL 记录：展示文件名或可读路径摘要，至少支持文件名进入搜索。

长内容可以使用摘要、截断、多行预览或延迟加载，以保证面板性能和可读性。只要用户能识别内容，本阶段不要求完成详情展开、编辑或完整阅读体验。

### 6.2 设置页移除冲突 UI

设置页应移除或隐藏与本阶段明文展示目标冲突、且用户不能有效调整的剪贴板存储/内容保护 UI。

移除范围以用户可见界面为准。底层配置字段、数据库字段或兼容字段是否保留，由 App 架构方案决定；但这些内部处理不得影响面板明文展示和搜索目标。

保留项边界：

- 与容量、保留天数、性能或清理策略有关的设置，如果仍然真实可用，可以保留。
- 与“默认遮挡真实内容”“只显示字符数”“payload 默认不可读”绑定的说明或设置，不应继续作为用户可见主路径。

### 6.3 搜索字段

搜索应覆盖以下字段：

| 字段 | Step 1 要求 |
| --- | --- |
| 正文 | 搜索真实文本内容，不限于面板当前可见摘要。 |
| 来源 App | 支持来源 App 名称或可见来源字段命中。 |
| URL | 支持 URL 字符串、host 或可读 URL 文本命中。 |
| 时间 | 支持用户可见时间字段的合理搜索或筛选入口；具体输入格式由技术方案确认。 |
| 类型 | 支持类型关键词、同义词、多语言词和部分匹配。 |
| 富文本纯文本化内容 | 支持从富文本记录提取出的可读文本命中。 |
| 文件名 | 支持文件名或 file URL 末级名称命中。 |
| OCR 文本 | 支持系统 Vision OCR 后的图片文字命中。 |

搜索应优先支持用户直觉输入，而不是要求精确字段语法。字段语法、高级搜索和复杂查询语言不属于 Step 1。

### 6.4 类型关键词和同义词

Step 1 需要建立最小类型词典。首批类型同义词建议如下，最终词典位置由 App 架构师确认。

| 类型 | 应命中关键词示例 |
| --- | --- |
| 图片 | `image`、`img`、`ima`、`pic`、`picture`、`photo`、`图片`、`图`、`照片` |
| 文本 | `text`、`txt`、`plain`、`文本`、`文字` |
| URL | `url`、`link`、`链接`、`网址` |
| 文件 | `file`、`filename`、`文件`、`文件名` |
| 富文本 | `rich text`、`rtf`、`富文本` |

类型词命中不应压过正文精准命中。默认排序建议：

1. 正文、URL、文件名、OCR 文本的直接命中。
2. 来源 App 命中。
3. 类型同义词命中。
4. 时间字段命中。

同级命中默认按最近记录时间或更新时间排序。排序权重可在测试和体验复审中调整。

### 6.5 搜索状态

搜索需要有稳定状态：

- 默认状态：未输入搜索时展示正常列表。
- 有结果：展示匹配结果。
- 无结果：展示空结果状态，并保留搜索词。
- 索引中：部分图片 OCR 或内容索引尚未完成时，结果区不应卡死；图片条目可显示 OCR 待处理或处理中。
- 失败：OCR 或索引失败不应导致整个搜索失败；失败项可显示失败状态并允许重试。

## 7. 系统 Vision OCR

### 7.1 产品范围

OCR 进入 Step 1，但范围限定如下：

- 使用 macOS 系统 Vision 能力。
- 只处理剪贴板中已有图片 payload。
- OCR 结果进入搜索索引。
- OCR 结果可用于搜索命中和图片条目的状态展示。
- 不上传图片到 provider。
- 不接入外部 OCR 服务。
- 不做图片本体编辑。
- 不做 OCR 文本编辑；OCR 文本编辑属于 Step 4。

### 7.2 OCR 状态

图片条目至少需要支持以下状态：

| 状态 | 用户含义 | 行为要求 |
| --- | --- | --- |
| 待处理 | 图片已进入剪贴板记录，但 OCR 尚未开始 | 不阻塞列表展示和搜索输入。 |
| 处理中 | OCR 正在执行 | 可显示轻量状态，不用全局阻塞。 |
| 完成 | OCR 已产出文本并进入索引 | 搜索可命中 OCR 文本。 |
| 失败 | OCR 执行失败 | 显示失败状态，不影响其他字段搜索。 |
| 可重试 | 失败后允许再次尝试 | 提供重试入口或后续可恢复机制，具体入口由 UI/技术方案确定。 |

### 7.3 性能体验

OCR 必须异步，不得把面板打开、搜索输入和滚动变成同步等待。

性能要求：

- 面板打开时，已有记录应先可见，OCR 可在后台排队。
- 搜索输入时，不等待未完成 OCR；已索引字段先参与结果。
- 大图、长截图、多图批量入库可延迟处理或分批处理。
- OCR 结果应缓存，避免同一图片反复识别。
- OCR 失败应局部降级，不影响整页可用。
- `fast` 与 `accurate` 的识别等级取舍由技术方案评估；产品目标是优先保证面板响应和搜索可用，再提升识别质量。

### 7.4 OCR 语言与准确率

Step 1 不预先承诺完整语言覆盖。支持语言列表、自动语言检测、中英文混排效果、日文或其他语言表现，需要 App 架构师在技术方案阶段基于目标 macOS 版本和 Vision API 能力确认。

## 8. 第一阶段输出边界表达

Step 1 的输出边界表达用于指导后续实现、文案和验收。

### 8.1 面板和搜索

面板和搜索以真实内容可用为目标。可以为了性能和可读性使用摘要、截断、缩略图、异步索引或延迟加载，但不应再把“默认不可读取真实内容”作为目标。

建议文案方向：

> 剪贴板面板和搜索会使用本地保存的剪贴板内容，以便你直接查看和检索。长内容和后台输出可能会使用摘要或延迟加载，以保持性能和可读性。

### 8.2 日志

本阶段不要求重做日志系统，但日志不应把内容保护作为主叙事。若 Step 1 实现过程中需要新增 OCR、搜索或索引日志，应优先记录状态、长度、类型、耗时、错误码和低歧义 id；是否记录正文片段由技术方案按性能和可排查性决定。

禁止把真实凭据、API key、Authorization header、provider secret、私钥、验证码写入日志样例、验收文档或仓库文件。

### 8.3 CLI

本阶段不要求完成 CLI 全量改造。若 Step 1 触及 CLI 搜索或输出，应遵守：

- CLI 可以在明确命令下读取真实内容。
- 长正文、大 payload 或批量结果应通过截断、分页、结构化字段或显式参数控制。
- 输出应保持 agent 可解析，不应被无限制正文污染结构。

### 8.4 Provider 和自动化

本阶段不新增 provider OCR，不因 OCR 或搜索底座改造而后台静默上传剪贴板图片或全文。

Provider 和自动化可访问真实内容的完整动作设计不属于 Step 1。当前只确认原则：真实内容可访问，但外发或系统状态变更需要明确用户动作或 agent 指令触发。

## 9. 验收样例

验收应使用 synthetic / fixture 内容，不复制真实用户剪贴板。

### 9.1 明文展示

- 给定一条文本 fixture：`Alpha roadmap item 004 search baseline`，面板显示可读正文预览，不只显示字符数。
- 给定一条 URL fixture：`https://example.com/blocks/clipboard-step1`，面板显示可识别 URL 信息。
- 给定一条富文本 fixture，面板显示可读纯文本化内容。
- 给定一条图片 fixture，面板显示图片缩略图或可识别图片内容状态。

### 9.2 设置页

- 设置页不再出现与明文展示目标冲突、且用户不能有效调整的内容保护/遮挡设置。
- 若仍保留容量、保留天数或性能相关设置，其文案不应暗示默认遮挡真实内容。

### 9.3 搜索字段

- 搜索文本正文关键词可命中文本记录。
- 搜索来源 App 名称可命中对应记录。
- 搜索 URL host 或路径片段可命中 URL 记录。
- 搜索文件名可命中文件或 file URL 记录。
- 搜索富文本中的纯文本内容可命中富文本记录。
- 搜索 `pic`、`picture`、`image`、`ima`、`图片`、`图` 可命中图片类记录。

### 9.4 OCR

- 给定一张包含 `VISION-004` 字样的图片 fixture，OCR 完成后搜索 `VISION-004` 可命中该图片记录。
- OCR 进行中时，图片记录可见且搜索输入不卡住。
- OCR 失败时，该图片记录显示失败状态，其他搜索字段仍可工作。
- OCR 失败后存在可重试状态或可恢复路径。
- OCR 不调用外部 provider，不上传图片。

### 9.5 输出边界

- Step 1 新增或改动的日志、CLI 输出或调试信息不应默认无限制输出大段正文。
- Provider 不会因为面板打开、搜索或 OCR 索引而静默接收剪贴板全文或图片。
- 验收文档和 fixture 不包含真实用户剪贴板、真实凭据或完整敏感内容。

### 9.6 覆盖矩阵回归

- R1.1、R1.2、R2 有对应验收样例。
- C1、C12、C13 有第一阶段输出边界和非目标表达。
- C2、C3 有搜索字段和类型同义词验收样例。
- C11 有 OCR 状态、性能和 provider 排除验收样例。
- C16 已通过本 PRD 的范围、非目标和 App 架构师待确认问题体现。
- Step 2-6 条目未被写入 Step 1 交付范围。

## 10. 进入技术方案前需 App 架构师确认的问题

1. 搜索索引模型：正文、URL、来源 App、时间、类型、富文本纯文本、文件名、OCR 文本分别如何入索引，如何更新和删除。
2. 面板明文展示模型：如何在真实内容可访问的前提下避免超大 payload 同步加载导致卡顿。
3. 富文本纯文本化：当前富文本 payload 的可读文本提取来源、更新时机和格式边界。
4. URL 与 file URL：URL、文件名、路径摘要和记录类型之间的标准化规则。
5. 类型同义词词典：词典维护位置、大小写/语言归一化、部分匹配和排序权重。
6. Vision OCR 队列：处理队列、并发、缓存、失败重试、大图/长截图限流和 app 生命周期恢复策略。
7. Vision OCR 语言：目标 macOS 版本下支持语言、自动语言检测和中英文混排能力。
8. OCR 结果存储：OCR 文本作为派生字段还是索引字段保存，如何与图片 payload、删除、裁剪保持一致。
9. 日志/CLI 最小边界：Step 1 如果触及日志或 CLI，应采用怎样的截断、分页或结构化输出规则，避免高复杂度和性能损耗。
10. 回归门禁：如何证明旧 redacted-only 搜索路径、只显示字符数路径和同步 OCR 阻塞路径不再作为 Step 1 主路径。

## 11. 复审建议

Step 1 PRD 进入开发前，建议由以下角色复审：

- UI/交互设计师：重点检查明文预览、OCR 状态、搜索状态和输出边界文案是否清晰。
- App 架构师：重点检查搜索索引、Vision OCR、性能和数据一致性。
- 安全合规顾问：重点检查“真实内容可访问，交互输出可控”是否避免误读为后台静默外发。
- 测试/质量：重点补充 fixture、OCR 状态、搜索字段和性能回归验收矩阵。
