## 2. 已复核通过的关键点

- `ClipboardSearchDocument` / 等价模型作为搜索与 bounded preview 派生内容的单一事实源。
- `clipboard_fts` 仅作为 search document 的查询投影；旧 `clipboard_items.search_text` 如保留，只能作为兼容投影。
- schema migration / backfill 有明确策略：创建派生表或字段、pendingIndex、后台 batch rebuild，且不阻塞 App 启动、面板打开、搜索输入和滚动。
- repository insert / duplicate / delete / prune / policy redaction / OCR result update 的生命周期一致性已写成事务或等价一致性边界。
- `ClipboardContentAccessPurpose` 新命名或旧 purpose 重释义二选一已明确，不再沿用 Step 4D “默认隐私 allowlist”语义。
- bounded preview 数据阈值与 UI 可见 clamp 已区分，避免把完整 payload 暴露到高频 View 路径。
- search state 明确覆盖 `idle`、`results`、`empty`、`emptyIndexing`、`partialIndexing`、`failed`，且局部 OCR/index failure 不升级为全局 search failed。
- synthetic fixture 覆盖 text、URL、rich text plain text、file URL、OCR success/failure/retry、long text、large image。
- Vision OCR 限定为本地 image payload，不读 file URL 本体、不扫描目录、不新增权限、不上传 provider。
- OCR mock / running hold / retry UI 合同已明确。
- 设置页 hardening/redacted 负向 token 和可保留重命名项已列清。
- 低敏输出 schema 与 forbidden pattern 已列清，并要求 PASS/FAIL 输出、开发记录、验收记录同口径。
- P13A baseline red / implementation green、最低断言、旧 P8/P8I/P9A/P9B/P11E 迁移方向已明确。
- 性能、可访问性、最终验收矩阵和开发子批次已可执行。

## 3. 接受边界

接受不代表以下事项已完成：

- 尚未实现代码。
- 尚未运行 App、真实剪贴板、真实 OCR、TCC、provider、Keychain 或系统设置。
- P13A、P8/P8I/P9A/P9B/P11E 迁移仍需开发阶段落地。
- 真实 UI 截图/录屏和低敏实物验收仍需实现后补证。

接受也不改变以下非目标：

- 不做标签/收藏模型替换。
- 不做筛选 hover、toolbar 空间、选中反馈、单/双击控件和条目密度专项打磨。
- 不做详情编辑。
- 不做隐私页真实 App 清单。
- 不做外部 OCR provider 或复杂权限开关。

## 4. Step 1 开发派发条件

可以进入 Step 1 开发派发。开发任务必须按 v1 子批次推进：

1. Step 1A-0：P13A baseline red。
