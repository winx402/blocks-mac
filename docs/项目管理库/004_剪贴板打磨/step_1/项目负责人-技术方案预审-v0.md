## 3. 需要角色复审的重点

### 3.1 开发

请重点复审：

- 新 search document / preview snapshot 与现有 `clipboard_items.search_text`、`clipboard_fts` 共存期间是否会形成双事实源。
- Step 1A-1D 拆分是否可落地，是否还需要更小的开发批次。
- repository transaction、FTS 更新、delete/prune/policy redaction 和 OCR result update 的一致性是否足够明确。
- `ClipboardPayloadReadPurpose` 是否先保留但重释义，还是应在本阶段改名；如改名，影响面是否可控。
- P13A verifier 最低断言是否能在开发中稳定实现。

### 3.2 测试/质量

请重点复审：

- Synthetic fixture 是否足以覆盖 text、URL、rich text plain text、file URL、image OCR success、OCR failure、OCR retry、long text、large image。
- OCR mock/test hook 是否能让 pending/running/failed/retry 状态稳定可测。
- 搜索无结果、emptyIndexing、partialIndexing、failed 状态是否有可判定 pass/fail。
- 性能门槛是否需要补成明确数值或相对阈值。
- low-sensitive output scan 的 forbidden token / pattern 是否足够。
- 旧 P11E/P8/P8I/P9A/P9B 迁移后是否仍能 fail closed，避免旧 Step 4D hardening 断言误伤新目标。

### 3.3 安全合规

请重点复审：

- “链路可访问真实内容”是否被方案正确约束为本地 App 内高频路径可访问，而不是 provider、日志、CLI、自动化默认无限制外发。
- Vision OCR 是否明确只处理已有 image payload，不读 file URL 本体、不扫描目录、不新增权限、不上传 provider。
- CLI / 日志 / verification JSON 的默认低敏输出边界是否可验收且不会过度复杂影响性能。
- URL、file path、OCR text、image base64、凭据类内容的禁止输出清单是否还需补充。

### 3.4 UI/交互设计师

请重点复审：

- bounded preview 的 title/body 阈值和“有界但可读”原则是否支持面板第一阶段体验。
- OCR pending/running/failed/retry 与搜索 empty/emptyIndexing/partialIndexing/failed 的最低用户可见状态是否足够。
- OCR retry 入口放在图片条目状态或等价位置是否可用。
- URL query 不作为 Step 1 必验搜索字段、多语言 OCR 准确率不作为 Step 1 必验，这两个降级是否会造成用户体验预期落差。

## 4. 当前取舍

项目负责人暂时接受以下技术方案取舍，复审角色如认为有 P1 风险应明确指出：

- 不要求 View 直接读取完整 payload 来实现明文展示，采用有界 preview snapshot。
- 不把完整 URL query、完整 file path、多语言 OCR 准确率作为 Step 1 必验项；本地搜索文档可有界索引，日志和验收输出保持低敏。
- OCR 使用 macOS Vision，本阶段不接外部 provider，不新增系统权限，不读 file URL 指向文件本体。
- 旧 Step 4D hardening verifier 不能继续以“默认 payload 不可见”作为 pass 条件，但低敏输出、防 provider 外发和低敏 fixture 的门禁精神保留。
