## 1. 阶段目标

Step 1 只解决剪贴板面板当前最基础的可用性问题：用户打开面板后应能看到真实可读内容，搜索应能命中主要内容字段，图片内容应通过 macOS 系统 Vision OCR 进入搜索底座。

本阶段同时建立第一阶段的边界表达：项目从“默认遮挡 payload”调整为“真实内容可访问，交互输出可控”。这里的重点是 App 内面板和搜索可用，不是一次性重做 CLI、provider、日志和自动化全链路。

v1 在 v0 基础上补强开发前验收契约：搜索状态、OCR 生命周期、搜索索引、明文预览性能、富文本/URL/file URL 标准化、设置页移除负向清单、输出边界和回归门禁。

## 2. 本阶段范围

本阶段必须覆盖：

- 面板默认展示真实可读内容，不再只显示字符数或过度遮挡摘要。
- 设置页移除与明文展示目标冲突、且用户不能有效调整的剪贴板存储/内容保护 UI。
- 搜索覆盖正文、来源 App、URL、时间、类型、富文本纯文本化内容、文件名。
- 类型关键词和同义词支持，例如 `pic`、`picture`、`image`、`ima`、`图片`、`图` 命中图片类条目。
- OCR 进入阶段范围，但限定使用 macOS Vision。
- OCR 仅处理剪贴板中已有图片 payload，不做自研 OCR，不使用外部 provider OCR。
- OCR 异步执行，不阻塞面板打开、搜索输入和滚动。
- OCR 状态可感知：待处理、处理中、完成、失败、可重试。
- 日志、CLI、provider、自动化在本阶段先明确“可访问真实内容但输出可控”的原则，不做复杂权限开关或过滤系统。

## 5. 产品原则

### 5.1 真实内容可访问

剪贴板面板和搜索应能使用剪贴板记录的真实内容。用户不应再看到只有“多少个字符”而无法判断内容的默认状态。

产品文案应尽量使用“内容”“正文”“原始内容”等用户可理解的表达，不把 `payload` 作为用户界面术语。

### 5.2 交互输出可控

真实内容可访问不等于所有界面、日志、CLI 或 provider 都无限制输出完整正文。本阶段输出控制的理由是性能、可读性、可维护性和防误操作，不再以“内容保护”为主要叙事。

本阶段只要求建立边界表达和避免明显反向设计；CLI、provider、日志、自动化的完整改造不属于 Step 1。

### 5.3 搜索底座可扩展

搜索不应实现为临时的可见文本过滤。Step 1 需要建立可重建的搜索文档和独立 index/read model，为后续标签、详情编辑和隐私页管理预留扩展空间。

## 6. 用户可见行为

### 6.1 面板默认展示真实可读内容

用户打开剪贴板面板时，应看到每条记录的可读内容或可识别内容状态：

- 文本记录：展示真实正文的可读预览，不再只展示字符数。
- URL 记录：展示可读 URL、host 或 URL 文本，不只展示类型名。
- 富文本记录：本阶段展示可读的纯文本化内容；不承诺富文本编辑或格式保留。
- 图片记录：展示图片缩略图或清楚的图片状态，并展示 OCR 状态。
- 文件或 file URL 记录：展示文件名或可读路径摘要，至少支持文件名进入搜索。

长内容可以使用摘要、截断、多行预览、缓存或延迟加载，以保证面板性能和可读性。截断后仍必须保留可识别内容，不能退回只显示字符数、redacted 文案或纯类型壳。

### 6.2 明文预览性能边界

面板列表默认展示有界预览，不同步加载所有完整 payload。

要求：

- 列表/卡片默认读取 bounded content preview，可来自 payload、派生纯文本或缩略图，但必须有长度、行数、像素尺寸或解码成本边界。
- 完整 payload 可以由 App 内明确用户路径访问，但不是面板打开、滚动或搜索输入时对所有记录同步读取。
- 长文本、大图、富文本解析、缩略图生成和 OCR 可以异步或缓存。
- 面板首屏应先展示已有记录和可用 preview，后台补充 OCR、缩略图或派生字段。
- 搜索输入不应触发同步 OCR 或大量 payload 同步读取。

技术方案待确认：具体 preview 长度、行数、缩略图尺寸、缓存策略和性能阈值由 App 架构师与 UI/交互在方案阶段定义。该项不影响开发前验收边界，因为 PRD 已明确“有界预览、首屏先可见、不同步全量读取”的产品验收目标。

### 6.3 设置页移除冲突 UI

设置页应移除或隐藏与本阶段明文展示目标冲突、且用户不能有效调整的剪贴板存储/内容保护 UI。

必须从用户可见设置中消失的负向范围：

- “默认遮挡真实内容”“隐藏剪贴板内容”“只显示字符数”“只显示长度”“redacted preview”“payload 不可见”一类文案。
- 与内容保护、遮挡、脱敏预览、只显示字符数绑定的开关、说明、状态行或不可调整设置。
- 暗示面板默认不读取真实内容、搜索默认不搜正文、或 OCR 文本默认不可用于搜索的说明。
- 旧 Step 4D 默认 metadata-first / redacted-first 作为当前通过条件的设置页文案。

允许保留的设置范围：

- 容量、最大条数、保留天数。
- 性能、清理、裁剪策略。
- 与存储生命周期、空间使用、历史清理相关且真实有效的设置。

如果底层字段、数据库字段、兼容字段或旧 key 暂时保留，它们不得影响面板明文展示和搜索验收。用户可见 UI 不得继续暴露与明文目标冲突的内容保护主路径。

技术方案待确认：具体旧 setting key、视图段落和 String Catalog token 需在源码方案阶段列出。该项不影响开发前验收边界，因为 PRD 已给出用户可见负向清单和允许保留范围，测试可据此补充静态/界面检查。

## 7. 搜索底座

### 7.1 搜索索引契约

搜索必须有独立 index/read model，不是临时 UI filter，也不是每次搜索时由 View 直接读取 payload 拼字符串。

每条剪贴板记录应有可重建的搜索文档。最小搜索文档至少包含：

| 字段 | 要求 |
| --- | --- |
| `recordID` | 与 repository record 稳定关联。 |
| `revision` 或 `updatedAt` | 用于判断 payload、OCR、后续编辑或标签变更后是否需要重建索引。 |
| `contentText` | 文本、URL、富文本纯文本化后的主体文本。 |
| `richTextPlainText` | 富文本记录提取出的可读纯文本；可与 `contentText` 合并但模型需能表达来源。 |
| `urlTokens` | URL 原文、scheme、host、path 片段；query 是否完整索引由技术方案按长度和低敏边界决定。 |
| `fileTokens` | file URL 的 lastPathComponent、文件名、扩展名和可读路径摘要。 |
| `sourceTokens` | 来源 App 名称、bundle id 或等价低歧义来源字段。 |
| `typeTokens` | 类型同义词、多语言关键词、缩写和部分匹配词。 |
| `timeTokens` 或 `timeSortField` | Step 1 时间搜索/排序所需字段。 |
| `ocrText` | 系统 Vision OCR 产出的图片文字。 |
| `ocrStatus` | OCR 待处理、处理中、完成、失败、可重试等状态。 |

索引更新或删除触发点：

- payload 新增。
- payload 删除。
- 记录裁剪或清理。
- OCR 完成。
- OCR 失败或重试状态变化。
- 后续 Step 4 详情编辑保存。
- 后续 Step 2 标签变更。

Step 1 不实现标签字段，但索引模型不能排斥后续 tags。标签字段后续应接入同一搜索底座，而不是另做一套标签搜索。

技术方案待确认：搜索文档的具体类型名、存储位置、索引重建策略和更新事务由 App 架构师定义。该项不影响开发前验收边界，因为 PRD 已明确搜索不是 UI filter，并列出最小字段和触发点。

### 7.2 搜索字段

搜索应覆盖以下字段：

| 字段 | Step 1 要求 |
| --- | --- |
| 正文 | 搜索真实文本内容，不限于面板当前可见摘要。 |
| 来源 App | 支持来源 App 名称或可见来源字段命中。 |
| URL | 支持 URL 原文、host、path 片段或可读 URL 文本命中。 |
| 时间 | 支持最小时间查询格式，见 7.4。 |
| 类型 | 支持类型关键词、同义词、多语言词和部分匹配。 |
| 富文本纯文本化内容 | 支持从富文本记录提取出的可读文本命中。 |
| 文件名 | 支持文件名、扩展名或 file URL 末级名称命中。 |
| OCR 文本 | 支持系统 Vision OCR 后的图片文字命中。 |

搜索应优先支持用户直觉输入，而不是要求精确字段语法。高级搜索和复杂查询语言不属于 Step 1。

### 7.3 类型关键词和同义词

Step 1 需要建立最小类型词典。首批类型同义词建议如下，最终词典位置由 App 架构师确认。

| 类型 | 应命中关键词示例 |
| --- | --- |
| 图片 | `image`、`img`、`ima`、`pic`、`picture`、`photo`、`图片`、`图`、`照片` |
| 文本 | `text`、`txt`、`plain`、`文本`、`文字` |
| URL | `url`、`link`、`链接`、`网址` |
| 文件 | `file`、`filename`、`文件`、`文件名` |
| 富文本 | `rich text`、`rtf`、`富文本` |

类型词命中不应压过正文精准命中。默认排序建议：

1. 正文、URL、文件名、OCR 文本的直接命中。
2. 来源 App 命中。
3. 类型同义词命中。
4. 时间字段命中。

同级命中默认按最近记录时间或更新时间排序。排序权重可在测试和体验复审中调整。

### 7.4 时间搜索最小格式

Step 1 支持最小可验收时间搜索，不做复杂自然语言时间查询。

必须支持：

- ISO 日期：`YYYY-MM-DD`，例如 `2026-07-07`。
- 当前 UI 可见日期文本片段，例如列表中实际展示的 `07-07`、`2026/07/07` 或等价格式。
- `today` / `yesterday`。
- `今天` / `昨天`。

不属于 Step 1：

- `最近`、`上周`、`三天前`、`last week` 等开放式自然语言时间查询。
- 范围查询、组合查询和高级字段语法。

技术方案待确认：日期 token 的本地化、时区和 UI 可见格式生成规则由 App 架构师确认。该项不影响开发前验收边界，因为 PRD 已给出最小输入格式和明确排除项。

### 7.5 搜索状态

搜索需要有稳定状态：

- 默认状态：未输入搜索时展示正常列表。
- 有结果：展示匹配结果。
- 确定无结果：所有当前可用索引都完成，且没有匹配结果。
- 当前无结果但索引中：当前没有结果，但仍有 OCR 或内容索引在后台处理，结果可能稍后出现。
- 有部分结果且索引中：已有匹配结果，同时仍有 OCR 或内容索引在后台处理，提示结果可能继续更新。
- 失败：单条 OCR 或索引失败不导致整个搜索失败；失败项可显示失败状态并允许重试。

`indexing` 是局部状态，不阻塞输入、滚动和已有结果展示。

OCR 完成前后，搜索 `VISION-004` 这类 OCR fixture 的状态必须可验收：

- OCR 未完成且无其他命中时：显示“当前无结果但索引中”或等价状态。
- OCR 未完成但已有其他字段命中时：显示部分结果，并提示仍在处理图片文字。
- OCR 完成后：`VISION-004` 命中图片记录。

## 8. 富文本、URL 和 file URL 标准化

### 8.1 富文本

Step 1 只提取富文本中的 plain text 用于预览和搜索，不承诺格式保留、编辑或 round-trip。

要求：

- 富文本 plain text 提取失败时，记录仍可见。
- 提取失败时，可降级为类型、来源、时间等字段可搜索。
- 不因富文本解析失败导致整条记录消失或搜索整体失败。
- 富文本格式保留和编辑属于 Step 4，不进入 Step 1。

技术方案待确认：富文本 plain text 提取发生在 ingest/index pipeline、repository 派生字段还是缓存层，由 App 架构师确认。该项不影响开发前验收边界，因为 PRD 只要求可读纯文本用于预览/搜索，并定义了解析失败降级。

### 8.2 URL

URL 搜索至少覆盖：

- 原始 URL 字符串。
- scheme。
- host。
- path 片段。

query 是否完整索引由技术方案按长度、可读性和低敏边界决定。无论是否完整索引 query，URL 记录在面板中都应展示可识别 URL、host 或 URL 文本。

### 8.3 File URL

file URL 搜索至少覆盖：

- lastPathComponent。
- 文件名。
- 扩展名。

完整路径搜索不作为 Step 1 必验能力。路径展示需要有界摘要，避免完整本地 home 路径或过长路径进入普通验收截图、日志或 verification JSON。

## 9. 系统 Vision OCR

### 9.1 产品范围

OCR 进入 Step 1，但范围限定如下：

- 使用 macOS 系统 Vision 能力。
- 只处理剪贴板历史中已有的图片 payload。
- OCR 结果进入搜索索引。
- OCR 结果可用于搜索命中和图片条目的状态展示。
- 不上传图片到 provider。
- 不接入外部 OCR 服务。
- 不新增 ScreenCapture、Accessibility、Automation、Full Disk Access、TCC reset 或系统设置跳转。
- 不扫描本地文件系统图片。
- 不根据 file URL 自动读取文件本体做 OCR。
- 不做图片本体编辑。
- 不做 OCR 文本编辑；OCR 文本编辑属于 Step 4。

### 9.2 OCR 状态与重试

图片条目至少需要支持以下状态：

| 状态 | 用户含义 | 行为要求 |
| --- | --- | --- |
| 待处理 | 图片已进入剪贴板记录，但 OCR 尚未开始 | 不阻塞列表展示和搜索输入。 |
| 处理中 | OCR 正在执行 | 可显示轻量状态，不用全局阻塞。 |
| 完成 | OCR 已产出文本并进入索引 | 搜索可命中 OCR 文本。 |
| 失败 | OCR 执行失败 | 显示失败状态，不影响其他字段搜索。 |
| 可重试 | 失败后允许再次尝试 | 提供稳定重试入口。 |

OCR 失败和重试入口必须至少出现在图片条目状态中。搜索状态行可以同步提示失败或索引状态，但不能作为唯一入口。

重试状态转换：

- failed -> 用户点击重试。
- retry -> pending 或 running。
- running -> done 或 failed。
- failed 后仍保留失败状态，并允许再次重试或显示不可恢复原因。

失败 fallback：

- Vision 不可用、图片过大、图片格式不适合 OCR、Vision 返回错误等失败可以使用统一失败文案。
- 错误详情用于日志和测试时，只记录低敏错误类别、耗时、图片尺寸、状态码或短 id，不记录图片 base64 或完整识别长文本。

### 9.3 OCR 派生数据生命周期

OCR text 和 OCR status 是 per-record 派生数据，不应只存在 UI 内存状态。

要求：

- OCR text/status 需要持久化或具备 App 重启后可恢复策略。
- OCR text/status 随记录删除、清理、裁剪一起删除或失效。
- 同一图片 payload 应避免重复 OCR，可由 record id + payload revision、payload signature/hash 或等价机制去重。
- OCR 失败重试需要有限流或状态转换规则，避免后台无限重试。
- OCR 文本进入搜索索引后，适用同一输出控制边界；不默认进入普通日志、verification JSON 或 provider 外发。

技术方案待确认：OCR text/status 存储在 repository、派生表、搜索索引旁路还是可重建缓存，由 App 架构师确定。该项不影响开发前验收边界，因为 PRD 已定义 per-record 生命周期、删除/裁剪失效和重启可恢复要求。

### 9.4 OCR 性能体验

OCR 必须异步，不得把面板打开、搜索输入和滚动变成同步等待。

性能要求：

- 面板打开时，已有记录应先可见，OCR 可在后台排队。
- 搜索输入时，不等待未完成 OCR；已索引字段先参与结果。
- 大图、长截图、多图批量入库可延迟处理、排队处理或分批处理。
- OCR 结果应缓存，避免同一图片反复识别。
- OCR 失败应局部降级，不影响整页可用。
- `fast` 与 `accurate` 的识别等级取舍由技术方案评估；产品目标是优先保证面板响应和搜索可用，再提升识别质量。

技术方案待确认：具体并发数、队列优先级、批处理规模、毫秒阈值和测量方式由 App 架构师、开发和测试/质量确认。该项不影响开发前验收边界，因为 PRD 已定义“打开面板不等 OCR、搜索输入不触发同步 OCR、大图多图进入队列或批处理”的最低可测口径。

### 9.5 OCR 语言与准确率

Step 1 不预先承诺完整语言覆盖。支持语言列表、自动语言检测、中英文混排效果、日文或其他语言表现，需要 App 架构师在技术方案阶段基于目标 macOS 版本和 Vision API 能力确认。

验收 fixture 应使用可稳定识别的低敏短 token，例如 `VISION-004`，不使用真实身份证件、账单、聊天记录、邮件、网页 cookie、二维码、验证码或密钥截图。

## 11. 验收样例与门禁

验收应使用 synthetic / fixture 内容，不复制真实用户剪贴板。

### 11.1 明文展示

- 给定一条文本 fixture：`Alpha roadmap item 004 search baseline`，面板显示可读正文预览，不只显示字符数。
- 给定一条 URL fixture：`https://example.com/blocks/clipboard-step1`，面板显示可识别 URL 信息。
- 给定一条富文本 fixture，面板显示可读纯文本化内容。
- 给定一条图片 fixture，面板显示图片缩略图或清楚图片状态。
- 给定一条 file URL fixture，面板显示文件名或路径摘要。
- 给定长文本 fixture，面板可截断但必须保留可识别内容，不退回长度文案。

### 11.2 设置页

- 设置页不再出现与明文展示目标冲突、且用户不能有效调整的内容保护/遮挡设置。
- 负向 token 覆盖“默认遮挡真实内容”“隐藏剪贴板内容”“只显示字符数”“只显示长度”“redacted preview”“payload 不可见”等同义文案。
- 若仍保留容量、保留天数、清理策略或性能相关设置，其文案不应暗示默认遮挡真实内容。
- 若旧 key 仍存在于存储层，只要 UI 不暴露且行为不冲突，应在开发记录中说明。

### 11.3 搜索字段

- 搜索文本正文关键词可命中文本记录。
- 搜索来源 App 名称可命中对应记录。
- 搜索 URL host 或 path 片段可命中 URL 记录。
- 搜索 ISO 日期 `2026-07-07` 可命中对应日期记录。
- 搜索 `today`、`yesterday`、`今天`、`昨天` 可命中对应本地日期记录。
- 搜索文件名可命中文件或 file URL 记录。
- 搜索富文本中的纯文本内容可命中富文本记录。
- 搜索 `pic`、`picture`、`image`、`ima`、`图片`、`图` 可命中图片类记录。
- 搜索 `VISION-004` 在 OCR 完成后可命中图片记录。

### 11.4 搜索状态

- 默认状态：无查询时展示正常列表。
- 有结果：搜索正文、URL、文件名、富文本纯文本、来源 App 和类型同义词可命中。
- 确定无结果：索引均已完成且无命中时，保留搜索词并展示明确空结果文案。
- 当前无结果但索引中：OCR / 内容索引未完成时，展示“仍在处理，结果可能稍后出现”或等价提示。
- 有部分结果且索引中：已有结果继续展示，同时提示仍有图片文字或内容索引处理中。
- 失败：单条 OCR / 索引失败不导致整个搜索不可用。
- OCR 完成前搜索 `VISION-004` 显示无结果但索引中或部分结果仍索引中；OCR 完成后命中图片记录。

### 11.5 OCR

- 成功 fixture：含 `VISION-004` 的低敏图片，完成后搜索 `VISION-004` 命中。
- 排队 fixture：可稳定观察待处理状态，不依赖机器速度碰运气。
- 运行 fixture：可稳定观察处理中状态或等价进度状态。
- 失败 fixture：无效图片或受控 mock 失败，状态为 failed，错误输出低敏。
- 重试 fixture：失败后触发 retry，状态重新进入 pending/running，最终 done 或 failed。
- OCR 进行中时，图片记录可见且搜索输入不卡住。
- OCR 失败时，该图片记录显示失败状态，其他搜索字段仍可工作。
- OCR 不调用外部 provider，不上传图片，不扫描本地文件系统图片，不根据 file URL 读取文件本体。

技术方案待确认：排队、运行、失败、重试 fixture 的具体实现方式可以是 mock、test hook 或可控 fixture pipeline。该项不影响开发前验收边界，因为 PRD 已要求状态可复现，避免依赖机器速度碰运气。

### 11.6 输出边界

- 普通运行日志、verification JSON、开发记录、验收记录不包含真实剪贴板正文、完整 URL、完整 file path、完整 OCR 文本、真实 home 路径、邮箱、secret、Authorization header、二维码、验证码、图片 base64 或 provider raw request/response。
- Step 1 新增或改动的日志默认只记录状态、长度、类型、耗时、错误码、短 id/hash、队列状态等低敏字段。
- CLI 若被触及，默认输出结构化且有界；完整 payload 需要显式命令或参数。
- 面板打开、搜索输入、OCR 入队、OCR 完成、OCR 重试不触发 provider 或自动化外发。
- 验收记录只保存 fixture 行为结果和低敏证据；如手工体验临时使用真实剪贴板，不保存真实内容截图或正文。

### 11.7 性能门槛

- 打开面板不等待 OCR 完成。
- 搜索输入不触发同步 OCR。
- 搜索输入不触发所有记录完整 payload 同步读取。
- 大图、多图进入 OCR 队列、延迟处理或批处理，不阻塞列表渲染。
- 滚动不触发全量 payload decode 或同步 OCR。

具体毫秒阈值、样本规模、测试环境和测量方式由技术方案或开发记录补充。

### 11.8 回归门禁

需要新增或更新 Step 1 verifier，证明：

- 只显示字符数主路径不再作为当前事实源。
- 搜索不再只搜 redacted preview。
- 搜索不能回退到历史 pinned displayName 等非真实内容字段充当主体。
- OCR 不在面板 open、search input、scroll 主路径同步执行。
- 外部 provider OCR 未接入。
- 验收证据只使用低敏 fixture。

旧 Step 4D 安全门禁只能作为历史参考，不能继续以默认 payload 不可见作为 Step 1 的通过条件。历史 P11E 类检查需要更新或降级为输出边界检查，不能阻止明文展示目标本身。
