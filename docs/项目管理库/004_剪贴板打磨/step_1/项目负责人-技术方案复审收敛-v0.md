## 3. 项目负责人收敛判断

技术方案 v0 的方向成立：

- 使用有界明文 preview snapshot，而不是让 View 在高频路径批量读取完整 payload。
- 使用可重建 search document / FTS read model，而不是继续依赖 redacted preview 字符串。
- 使用本地 macOS Vision OCR 队列和 mock recognizer，不接外部 OCR provider。
- 保留低敏日志、CLI、verification JSON 输出边界。
- 迁移旧 Step 4D hardening verifier，不让“默认 payload 不可见”继续阻止本阶段目标。

但进入开发前，必须把以下内容从“方向建议”补成“开发和验收可执行契约”。

## 4. 技术方案 v1 必须回写

### 4.1 Search document 单一事实源

必须补清：

- `ClipboardSearchDocument` 或等价模型是当前搜索与 bounded preview 派生内容的事实源。
- `clipboard_fts` 是由 search document 生成的查询投影。
- 现有 `clipboard_items.search_text` 如保留，只能作为兼容投影，由同一 builder 派生；不得继续由旧 `searchText(for:payload:)` 独立生成。
- P13A 需要 fail closed 检查搜索主路径绕过 search document、只基于 visible/redacted preview 或旧 pinned metadata 时失败。

### 4.2 Schema migration / backfill 策略

必须补清：

- 是否 bump `PRAGMA user_version` 或等价 schema version。
- 打开旧开发期数据库时如何创建 search document / OCR state 表或字段。
- 缺失派生内容的记录如何进入 `pendingIndex` / 后台 rebuild。
- backfill 不得阻塞 App 启动、面板打开、搜索输入和滚动。

### 4.3 Repository 事务与生命周期一致性

必须补清：

- insert 同一事务写 record、payload、search document 和 FTS。
- duplicate / dedupe 路径不得误建新 search document。
- delete / prune 同步删除 record、payload 关联、search document、FTS、OCR state。
- policy redaction 同步失效 payload 派生字段、OCR text 和 FTS，不能只清旧 `search_text`。
- OCR result update 只更新仍存在、revision 匹配、未 redacted / deleted 的 record，并与 search document / FTS 更新保持同一事务或等价一致性边界。

### 4.4 Content access purpose 命名或重释义

必须二选一写清：

- 推荐：引入 `ClipboardContentAccessPurpose` 或等价中性命名，包含 `previewBuild`、`searchIndex`、`ocrInput`、`paste`、`copyPlainText`、`hoverDetail`、`translationPreview`。
- 若保留 `ClipboardPayloadReadPurpose`，必须在方案和 P13A 中明确它已不再是 Step 4D 隐私 allowlist，而是性能 / 生命周期 / 审计分类，并补齐 `previewBuild`、`searchIndex`、`ocrInput`。

### 4.5 P13A 与旧门禁迁移

必须补清：

- P13A 的 baseline red / implementation green 规则。
- P13A 最低断言：bounded preview、View 不批量读 payload、search document/read model、search states、OCR mock、OCR no provider/no file scan/no extra permission、settings negative token、low-sensitive output、current evidence only。
- P11E 的定位：退役为历史 baseline，或改为 output boundary check；不得继续用“默认 UI 不读 payload / redacted read model”阻断 Step 1。
- P8/P8I/P9A/P9B 的迁移方向：bounded plaintext preview、hardening negative token removed、search document / OCR state / FTS smoke、content access purpose 分类。
- 旧 003 / Step 4D 文档只能进入 `baseline_reference`，不能作为 Step 1 当前 `ok` 证据。

### 4.6 Synthetic fixture 与搜索状态验收

必须补清：

- 固化 synthetic fixture 矩阵，至少覆盖 text、URL、rich text plain text、file URL、OCR success、OCR failure、OCR retry、long text、large image。
- 每个 fixture 至少包含 `fixtureID`、record kind、关键字段、预期 preview、预期搜索、预期低敏输出规则。
- 搜索状态 pass/fail：`idle`、`results`、`empty`、`emptyIndexing`、`partialIndexing`、`failed` 的触发条件和失败条件。
- `failed` 只代表查询路径整体失败；局部 OCR/index 失败不得覆盖已有结果或让整个搜索框不可用。

### 4.7 OCR mock、输入边界和 retry UI 合同

必须补清：

- Mock recognizer 可确定性控制 pending、running、failed、retry，不依赖真实 Vision、真实图片质量或机器速度。
- OCR 输入只来自已有 image payload，不读 file URL 本体、不扫描目录、不新增 ScreenCapture / Accessibility / Automation / Full Disk Access / TCC reset / 系统设置跳转等权限。
- OCR/search/preview 新增或 touched 文件不得触发 provider upload、外部 OCR、多模态 provider call、Authorization header 或 image upload。
- 图片条目内或强关联位置必须有 OCR 状态和 retry 入口；retry 后立即反馈，不能只在搜索空状态出现。

### 4.8 Bounded preview 的数据阈值与 UI 可见阈值

必须补清：

- Snapshot 阈值不等于 UI 列表可见行数。
- 面板 row/card/tray 需要 line clamp 或等价约束，避免长文本、长 URL、长路径、OCR 状态和操作区互相挤压。
- `isTruncated` 是内容有界处理状态，不是错误状态。
- URL、file URL、富文本、图片条目分别定义 preview 组成规则，不统一使用前 500 字符直接展示。

### 4.9 低敏输出 schema 和 forbidden pattern

必须补清：

- P13A / sanitizer 的 forbidden token / pattern 清单，至少覆盖 Authorization、Bearer、Basic、X-API-Key、api_key、access_token、refresh_token、id_token、sk-/sk_proj/sk-proj、password/passwd/pwd、otp、验证码、2fa/mfa、private key block、cookie/session/set-cookie/jwt/webhook、token query URL、base64/data:image/full OCR 字段名。
- Verifier、smoke、日志、CLI、开发记录和验收记录统一低敏输出 schema。
- 失败详情也必须走 sanitizer，不能只在 PASS 输出时低敏。
- 默认输出只包含相对路径、suite、boolean、count、fixture id、record id short hash、length、duration、error category 等。

### 4.10 性能与可访问性验收

必须补清：

- 结构性门禁：panel open / search input / scroll 主路径没有同步 OCR、批量 readPayload、全量 image decode。
- 事件化门禁：mock OCR running hold 时，preview 和 search state 必须先返回。
- 最小数值 smoke：开发记录固定样本规模、构建配置、机器环境、首屏可见时间、搜索状态返回时间、OCR 队列开始时间等。
- OCR 状态、retry、搜索空状态、索引中状态、全局失败状态具备文本 label、键盘路径和焦点稳定验收。

## 5. 不要求回写或不作为阻塞

- URL query 不作为 Step 1 必验搜索字段；本地可有界索引，但用户承诺和验收以 host/path/可读 URL 文本为主。
- 多语言 OCR 准确率不作为 Step 1 阻断；必验使用低敏稳定 token，例如 `VISION-004`。
- 真实 UI 手工验收、截图、录屏可以在实现验收阶段补证，不要求技术方案阶段运行 App。
- 搜索 ranking 首版不需要精细化，只需避免排序逻辑散落在 View。
- P13A 是否复用已有 sanitizer 的具体文件名可由开发阶段确定，但 forbidden pattern 和低敏 schema 必须统一。
