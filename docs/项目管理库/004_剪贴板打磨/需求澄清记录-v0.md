# 剪贴板打磨需求澄清记录 v0

状态：clarified-v0
记录日期：2026-07-06
来源：用户对《原始需求记录 v0》中待澄清问题的回答

说明：本文把用户澄清转成后续 PRD 可使用的范围边界。仍未进入实现阶段，技术方案、验收矩阵和角色评审意见需后续补充。

## 已确认范围

### 1. 内容保护整体取消

用户确认“内容保护没有必要”不是只取消剪贴板面板内的默认遮挡，而是搜索、设置、CLI、provider、日志、自动化等默认 payload 保护也一起取消。

产品含义：

- 剪贴板面板默认明文展示内容。
- 搜索可以命中剪贴板正文和其他可检索字段。
- 设置页不再提供或强调内容保护相关设置。
- CLI、provider、日志、自动化等链路不再以“默认不暴露 payload”作为产品目标。

风险说明：

- 这会主动改变此前“默认元数据优先、payload 明确读取”的安全边界。
- 后续 PRD 仍需定义最小必要的防误操作规则，例如日志是否需要避免长文本刷屏、provider 是否需要用户明确触发、CLI 输出是否需要分页或格式限制。这里不是继续做内容保护，而是保证工具行为可控。

### 2. 搜索范围需要全面覆盖

用户确认搜索不只搜索面板可见文本，而是尽量覆盖正文、标签、来源 App、URL、时间、富文本纯文本化内容、图片 OCR、文件名、类型等。

额外要求：

- 搜索需要支持类型相关的同义词或关键词。
- 示例：搜索 `pic`、`picture`、`图片`、`图`、`ima`、`image` 等，都应该能搜出图片类条目。
- 设计时需要考虑关键词归一化、类型别名、跨语言词、缩写和部分匹配。

待方案化点：

- 类型词典需要明确维护位置。
- 搜索结果排序需要定义：正文命中、标签命中、类型命中、来源 App 命中之间谁优先。
- OCR 是否本期实现需要单独确认，因为它涉及图片内容提取链路，而不只是搜索框逻辑。

### 3. 设置页存储内容保护相关 UI 去除

用户未要求理解或管理内部配置字段，只明确产品诉求：需要明文展示，不要设置内容保护。

解释：

- “底层配置项”指代码或数据库里可能存在的存储策略、遮挡策略、allowlist、redaction 开关、迁移字段或兼容字段。
- 用户可见范围内，应移除“剪贴板存储/内容保护”这类不能实际调整、且与明文展示目标冲突的设置项。
- 内部字段是否删除、迁移或保留为临时兼容，由 App 架构方案决定，但不能影响用户侧明文展示和搜索目标。

### 4. 标签管理能力

用户确认标签需要：

- 颜色。
- 排序。
- 重命名。
- 合并。

用户确认暂时不需要：

- 批量删除。
- 删除前二次确认。
- 自动清理空标签。

约束：

- 标签不能重名。
- 一个条目可以有多个标签。
- 右键菜单可以添加标签、删除标签、新增不存在的标签。
- 设置页可以查看和管理标签。

### 5. 收藏标签规则

用户确认“收藏”是默认内置标签。

规则：

- “收藏”标签不可删除。
- “收藏”标签默认排在标签组第一个。
- “收藏”标签使用五角星图标。
- 不需要独立快捷筛选入口。
- 不需要额外排序权重，保持标签组第一即可。
- 固定条目改为收藏条目，点击收藏就是给条目打上“收藏”标签。

### 6. 不兼容旧 pinboard/固定逻辑

用户确认当前项目没有实际用户，不需要写兼容逻辑。

范围结论：

- 旧 pinboard/固定项逻辑可以直接移除。
- 不需要把旧分组名迁移为标签。
- 不需要把旧固定项迁移为“收藏”标签。
- 后续开发方案可以按新模型直接重建相关数据结构和 UI。

### 7. 隐私页 App 范围与 CLI 管理

用户理解页面展示范围包括：

- `/Applications`
- `~/Applications`
- `/System/Applications`

用户补充：

- 登录项、helper、命令行工具等也可以开放管理。
- 页面上展示的 App 和额外对象，都可以通过 CLI 管理。
- CLI 主要给 agent 使用。

范围结论：

- 设置页隐私管理优先展示真实 `.app` 清单和真实系统图标。
- CLI 需要能管理页面范围之外的对象，例如登录项、helper、命令行工具或其他 bundle identifier / path。
- App 图标读取失败时需要 fallback，但默认目标是真实图标。

### 8. 条目详情编辑范围

用户确认详情编辑目前只支持文本类记录。

编辑后的同步规则：

- 不同步更新系统剪贴板。
- 需要更新积木工具内部相关内容。
- 原始 payload 需要更新。
- 搜索索引需要更新。
- 更新时间需要更新。

待方案化点：

- 编辑保存时机：自动保存、失焦保存、显式保存，需要在 PRD 中明确。
- 非文本类记录详情页应展示不可编辑状态，还是隐藏编辑控件，需要 UI 方案确认。
- 编辑后是否保留原始来源 App、原始创建时间和历史版本，需要进一步设计。

### 9. 选中反馈延迟

用户观察到的是视觉上的延迟，但原因不确定。

范围结论：

- 这是体验缺陷，需要作为开发与验收项。
- 原因可能是动画、事件处理顺序、选中态更新时机或粘贴动作耦合，不能在需求阶段定性。
- 后续实现前需要用运行时验证确认。

## 当前仍需设计决策

1. 搜索排序：多字段、多类型、多语言和同义词命中时，结果优先级如何排列。
2. OCR 范围：图片 OCR 是否进入本期，还是只做类型关键词命中图片条目。
3. 日志和 CLI 输出控制：内容保护取消后，是否仍需要分页、截断、显式参数或输出格式控制，避免误操作和长文本污染。
4. provider / 自动化边界：内容保护取消后，provider 和自动化是否默认拿到全文，还是只在明确任务动作中读取全文。
5. 标签合并规则：合并后是否保留颜色、排序位置和关联条目；重名校验如何处理大小写和空格。
6. 详情编辑保存模型：自动保存、显式保存、取消、撤销和失败回滚如何处理。
7. CLI 管理对象模型：CLI 管理 App、登录项、helper、命令行工具时使用 bundle id、路径、进程名还是多字段识别。

## 对 PRD 的影响

- PRD 需要把“明文优先”写成项目核心原则，而不是把它藏在某个 UI 文案里。
- PRD 需要把搜索作为独立能力设计，不应只写“修复搜索框”。
- PRD 需要把标签模型作为数据模型变化处理，不应只写“把分组改名为标签”。
- PRD 需要把 CLI 管理隐私对象纳入范围，但可以拆成单独阶段。
- PRD 需要明确旧 pinboard/固定逻辑不兼容、不迁移。
- PRD 需要把详情编辑限制在文本类记录，避免把富文本、图片、文件编辑误纳入本期。
