## 1. 背景与目标

004_剪贴板打磨承接当前剪贴板体验从“保护优先、元数据优先”转向“明文优先、可搜索、可编辑”的产品调整。本 PRD v0 只定义产品范围、用户可见行为、非目标、验收口径和阶段建议，不进入实现方案。

本轮目标是让剪贴板成为日常可用的本地内容工具：

- 面板打开后直接看到可辨认的真实内容，不再默认只显示字符数或过度遮挡摘要。
- 搜索真正覆盖剪贴板内容、标签、来源、类型和系统 Vision OCR 结果。
- 用标签/收藏替代旧分组/固定模型，形成可扩展的数据与交互模型。
- 高频面板交互更稳定，包括筛选展开、选中反馈、空间利用、单击/双击设置和条目密度。
- 详情页支持受控编辑，并明确保存、取消、失败和格式保留边界。
- 隐私页展示真实 App 清单和图标，并为 CLI 管理更广义对象留下清晰边界。
- CLI、provider、日志、自动化链路具备读取真实内容的权限，但输出和动作需要可控。

## 3. 产品原则

### 3.1 真实内容可访问，交互输出可控

本项目不再以默认遮挡真实剪贴板内容作为产品目标。面板、搜索、设置、CLI、provider、日志和自动化等链路在产品边界上具备读取真实内容的权限。

同时，“可访问”不等于所有界面、日志和命令都无限制展示完整正文。输出控制的理由是性能、可读性、可维护性和防误操作，而不是继续沿用“内容保护”叙事。

### 3.2 高频路径优先

面板阅读、搜索、筛选、收藏、标签、右键操作、详情查看和详情编辑是本项目的优先路径。任何布局和状态设计都应优先服务这些路径。

### 3.3 模型要可扩展

搜索、标签、OCR、富文本、URL、图片派生文本和 CLI 管理对象都应按可扩展模型设计。PRD 不接受把 pinboard 改名为标签、把搜索写成临时字符串过滤，或把富文本默认为静默丢格式的纯文本。

## 4. 范围总览

### 4.1 本期范围

- 剪贴板面板默认明文展示可读内容。
- 搜索覆盖正文、标签、来源 App、URL、时间、类型、富文本纯文本化内容、文件名和系统 Vision OCR 文本。
- 使用 macOS Vision OCR 处理剪贴板图片 payload，不引入外部 provider OCR。
- 标签/收藏替代旧分组/固定模型。
- 面板筛选、搜索框、选中反馈、单击/双击设置、条目密度和详情元数据布局打磨。
- 详情编辑支持 plain text、URL、富文本文本内容和图片 OCR 文本。
- 隐私页默认展示真实 `.app` 清单和系统图标。
- CLI / provider / 日志 / 自动化明确“可读取真实内容，但输出和动作可控”的产品边界。

### 4.2 非目标

- 不做旧 pinboard、旧分组、旧固定项的数据迁移或兼容。
- 不做批量删除标签、删除前二次确认、自动清理空标签。
- 不提供独立于标签的“收藏”第二套状态。
- 不编辑图片本体、文件本体或非文本类 payload 本体。
- 不引入外部 OCR provider，不上传图片给 provider 做 OCR。
- 不新增复杂权限开关、过滤规则或策略系统。
- 不把剪贴板能力扩展为通用自动化执行器。
- 不承诺生产级 packaging/notarization、真实多屏复测或与 004 无关的新工具能力。

## 5. 功能需求

### 5.1 明文展示与设置精简

面板应默认展示可读真实内容，不再只显示字符数或无意义摘要。不同类型记录可以根据可读性采用适合的展示方式，例如文本显示正文片段，图片显示缩略图和类型信息，URL 显示可读链接文本。

设置页应移除用户可见的“剪贴板存储/内容保护”类设置项，尤其是不能实际调整且与明文展示目标冲突的设置。内部字段是否保留、迁移或删除由后续架构方案决定，但不得影响用户侧明文展示和搜索目标。

验收口径：

- 文本类记录在面板中展示可读内容，而不是只展示字符数。
- 设置页不再展示与“内容保护/存储遮挡”冲突且不可操作的设置。
- 明文展示变更不应导致日志、CLI 或 provider 默认无限制输出完整长正文。

### 5.2 搜索与系统 Vision OCR

搜索是本项目独立能力，不是简单修复搜索框。搜索范围包括：

- 正文内容。
- 标签名称。
- 来源 App。
- URL。
- 时间相关可见字段。
- 类型。
- 富文本文本化内容。
- 文件名。
- 图片 OCR 文本。

类型搜索需要支持多语言、缩写、同义词和部分匹配。例如 `pic`、`picture`、`image`、`ima`、`图片`、`图` 应可命中图片类条目。

OCR 进入 PRD v0，但限定为使用 macOS 系统 Vision 能力。OCR 只处理剪贴板中已有图片 payload，不引入外部 provider OCR。OCR 结果进入搜索索引，并参与图片条目的关键词搜索。

OCR 体验要求：

- OCR 必须异步处理，不得阻塞面板打开、搜索输入和滚动。
- 图片条目需要有“索引中”“已索引”“识别失败”“可重试”等可感知状态。
- 大图、长截图、多图批量入库时，允许延迟处理或排队处理。
- OCR 结果应可缓存，避免重复识别导致性能问题。
- 语言支持、自动语言检测和中英文混排效果由技术方案基于系统 API 和目标 macOS 版本验证。

搜索排序默认规则：

1. 当前可见正文或编辑后正文命中。
2. 标签命中，尤其是当前筛选相关标签。
3. OCR 文本命中。
4. URL、文件名、来源 App 命中。
5. 类型同义词命中。
6. 时间字段命中。

同级命中下，默认按最近更新时间或记录时间排序；后续体验验收可调整排序权重。

验收口径：

- 搜索可命中正文、标签、来源 App、URL、类型、文件名和 OCR 文本中的代表样例。
- 图片 OCR 未完成时，搜索结果不应卡死或产生错误闪烁。
- OCR 失败状态可见且不影响其他字段搜索。
- 类型同义词样例能命中对应类型条目。
- 空结果、索引中、失败和正常结果都有稳定状态。

### 5.3 标签与收藏

本项目用标签模型替代旧分组/固定模型。

标签规则：

- 一个条目可以拥有多个标签。
- 标签不能重名。标签名去除首尾空格后校验，默认按大小写不敏感处理重复。
- 标签支持颜色、排序、重命名和合并。
- 设置页支持查看和管理标签。
- 条目右键菜单支持添加标签、删除标签、新建不存在的标签。
- 不做批量删除、删除前二次确认、自动清理空标签。

收藏规则：

- “收藏”是系统内置标签，不是独立状态。
- “收藏”默认排在标签组第一个。
- “收藏”使用五角星图标。
- “收藏”标签不可删除。
- 不需要独立快捷筛选入口。
- 不需要额外排序权重，保持标签组第一即可。
- 点击收藏等同于给条目打上“收藏”标签；取消收藏等同于移除该标签。

标签合并默认规则：

- 用户选择目标标签。
- 目标标签保留名称、颜色和排序位置。
- 被合并标签的条目关联转移到目标标签。
- 合并后删除被合并标签。
- 如果目标标签已存在于某条记录，合并后不产生重复关联。

旧逻辑边界：

- 旧 pinboard/固定逻辑可以直接移除。
- 不需要把旧分组名迁移为标签。
- 不需要把旧固定项迁移为“收藏”标签。

验收口径：

- 同一条记录可添加多个标签，并可按标签筛选。
- 右键菜单可新增标签并立即关联到条目。
- “收藏”始终存在、默认第一、不可删除，点击收藏会写入标签关系。
- 标签颜色、排序、重命名、合并在设置页可完成。
- 旧 pinboard/固定入口不再作为用户可见模型出现。

### 5.4 面板交互与布局

面板交互打磨覆盖筛选组、搜索框、选中反馈、单击/双击设置、条目密度和空间利用。

需求：

- 筛选组 hover 展开后应有安全区域或距离阈值，鼠标短暂离开展开区域不应立即收起。
- 筛选组展开宽度应尽量放大，但不得遮挡右侧关键操作。
- 搜索框可适度缩短，为筛选组展开让出空间。
- 条目点击后的选中反馈应即时出现，不能明显滞后于鼠标动作。
- 单击/双击设置使用显性点击选择控件，不再使用下拉菜单。
- 条目上下边框或内边距应收窄，提高核心内容区域面积。
- 内容、标签、来源、时间和操作按钮不得重叠或挤压到不可读。

验收口径：

- 筛选组在正常鼠标移动下不误收起。
- 展开筛选组不遮挡右侧关键操作。
- 搜索框与筛选区在常见窗口宽度下布局稳定。
- 点击条目后选中态即时可见。
- 单击/双击设置以显性控件呈现并可切换。
- 列表密度提升后，文本和标签仍可读。

### 5.5 详情编辑与元数据组织

详情页从只读信息面板升级为可编辑、可阅读的内容面板。

可编辑类型：

- Plain text。
- URL。
- 富文本文本内容。
- 图片 OCR 文本。

不可编辑范围：

- 图片本体不编辑。
- 文件本体不编辑。
- 非文本类 payload 本体不编辑。

保存模型：

- 采用显式保存 + 取消。
- 保存和取消按钮必须有稳定布局位，不得因为 dirty state 出现或消失导致页面整体跳动。
- 未修改时按钮可以置灰、弱化或显示稳定占位，但页面布局不得跳动。
- 保存失败时展示失败反馈，并保留用户当前编辑内容，避免丢失。
- 取消时回到最近一次已保存内容。

保存后的同步规则：

- 更新积木工具内部内容。
- 更新原始 payload 或对应派生字段。
- 更新搜索索引。
- 更新时间。
- 更新面板可见摘要。
- 不同步更新系统剪贴板。

富文本格式保留目标：

- 富文本编辑的验收目标是尽量保留原富文本格式。
- PRD 不接受静默丢格式。如果技术评估确认无法可靠保留格式，需要回到项目负责人处做范围取舍，并在方案中明确降级为纯文本化编辑的影响。
- 技术方案需要评估当前富文本 payload 保存格式、可逆编辑能力，以及 attributed string、RTF/HTML 或现有 payload 格式的读写一致性。

OCR 文本编辑规则：

- 图片 OCR 文本可编辑。
- 编辑 OCR 文本只更新 OCR 文本、搜索索引和详情展示。
- 不改写图片 payload 本体。

URL 编辑规则：

- URL 可编辑。
- 编辑后更新内部 payload、搜索索引、更新时间和可见摘要。
- 不更新系统剪贴板。
- URL 记录是否因编辑内容改变而改变记录类型，由技术方案评估。

详情布局：

- 编辑区域默认 2 行，最多 4 行，超过出现滚动。
- 条目字体大小设置不影响详情编辑区内容字体。
- 元数据一行展示两个短项。
- 长字段单独成行展示。
- 元数据不得挤压正文编辑区。

验收口径：

- Plain text、URL、富文本文本内容和 OCR 文本均有可编辑路径。
- 非文本类记录显示不可编辑状态，而不是暴露无效编辑控件。
- 保存、取消、保存失败和未保存变更状态清晰。
- 保存/取消控件出现、置灰或状态变化时页面不跳动。
- 富文本若无法保留格式，不得在无明确降级说明的情况下按纯文本静默保存。

### 5.6 隐私页 App 管理

隐私页从少量建议项改为真实 App 管理入口。

UI 范围：

- 默认展示 `/Applications`、`~/Applications`、`/System/Applications` 下真实 `.app`。
- 使用真实系统 App 图标。
- 图标读取失败时提供 fallback。
- 列表需要搜索/过滤和稳定排序，避免全量 App 不可浏览。
- 真实 App 图标和清单只做本地枚举与展示，不上传 provider。

CLI 范围：

- CLI 可管理页面范围之外的对象，包括登录项、helper、命令行工具或其他 bundle identifier / path。
- CLI 管理对象需要明确 typed subject / 标识模型，避免 bundle id、路径、进程名混用导致歧义。
- CLI 主要面向 agent 使用，但仍应保持输出结构清晰、可解析。

验收口径：

- 三个 Applications 目录下代表性 `.app` 可出现在隐私页。
- App 图标优先使用系统真实图标，失败时 fallback 稳定。
- 列表搜索、过滤、排序可用。
- CLI 可用 typed subject 表示 UI 之外对象。
- App 清单与图标处理不产生 provider 上传行为。

### 5.7 CLI / provider / 日志 / 自动化明文边界

本项目确认相关链路具备读取真实内容的权限，但仍要求输出和动作可控。

CLI：

- 可以读取和输出真实内容。
- 长正文、大 payload 或批量结果需要分页、截断、结构化字段或显式参数控制。
- 如果命令会改变系统状态或执行破坏性动作，需要显式命令、显式参数、dry-run / confirm 机制和低歧义对象标识。
- 输出格式应适合 agent 解析，不应因为无限制正文污染结构化结果。

日志：

- 日志可记录排查所需的真实内容片段、长度、类型、状态或关联 id。
- 不应默认无限制落盘完整长正文。
- 日志控制以性能、可读性、可维护性和防误操作为理由，不重新包装为内容保护策略。

Provider：

- Provider 链路具备读取真实内容的权限。
- 不应因为剪贴板全文可读就后台静默上传真实内容。
- Provider 调用需要由明确用户动作或 agent 指令触发。
- 本 PRD 不新增复杂权限开关或过滤系统。

自动化：

- 自动化可在明确任务动作中读取真实内容。
- 不应扩展为后台任意系统自动化执行器。
- 系统状态变更类动作需要明确命令、对象、参数和确认边界。

验收口径：

- CLI、日志、provider、自动化的 PRD 和后续方案不再把默认 payload 保护作为目标。
- 长内容输出存在可读性和性能控制。
- Provider 不会因后台状态或面板打开而静默外发剪贴板全文。
- 系统状态变更类 CLI / 自动化具备 dry-run、confirm 或等价显式边界。

## 6. 验收总口径

PRD 验收应同时覆盖产品行为、状态反馈和边界风险。验收记录应优先使用 synthetic / fixture 内容，不复制真实用户剪贴板。

| 模块 | 必验口径 |
| --- | --- |
| 明文展示 | 面板默认展示可读内容；设置页移除冲突的内容保护 UI；长内容不导致面板不可用。 |
| 搜索 | 多字段命中、类型同义词、OCR 文本命中、空结果、索引中、失败状态可测。 |
| OCR | 使用系统 Vision；异步处理；大图不阻塞；失败可见；不调用外部 provider OCR。 |
| 标签/收藏 | 多标签、右键增删/新建、设置页颜色/排序/重命名/合并、收藏内置且不可删除。 |
| 面板交互 | 筛选安全区域、展开宽度、搜索框让位、即时选中、显性单击/双击设置、密度提升后不重叠。 |
| 详情编辑 | 支持 plain text、URL、富文本文本内容、OCR 文本；显式保存 + 取消；布局稳定；失败不丢内容；富文本不静默丢格式。 |
| 隐私页 | 真实 `.app` 清单、真实图标、fallback、搜索/过滤/排序、本地枚举不上传。 |
| CLI / provider / 日志 / 自动化 | 真实内容可访问；长输出可控；provider 不静默外发；系统状态变更有显式边界。 |

## 7. 风险与技术评估项

- 富文本编辑保格式风险：需要评估现有 payload 格式、富文本读写一致性、RTF/HTML/attributed string 支持边界。不能在未评估时默认降级为纯文本保存。
- OCR 性能风险：需要评估 Vision 队列、缓存、失败重试、语言支持、大图和批量图片处理。
- 搜索索引一致性风险：编辑、标签变更、OCR 更新和删除/裁剪需要同步更新索引。
- CLI / 日志输出风险：明文可访问后，长正文和批量输出可能影响性能、可读性和 agent 解析。
- Provider / 自动化误触发风险：全文可读不等于允许后台静默上传或无边界执行系统动作。
- UI 稳定性风险：保存/取消按钮、筛选展开、OCR 状态、选中反馈和标签菜单都需要避免布局跳动。

## 8. 阶段建议

建议按以下阶段推进，并保持每阶段有独立验收记录：

1. 004-A：明文展示、搜索基础和系统 Vision OCR。
2. 004-B：标签/收藏模型替换。
3. 004-C：详情编辑与元数据组织。
4. 004-D：隐私页真实 App 清单与 CLI 广义对象管理。
5. 004-E：面板交互与布局打磨。
6. 004-F：CLI / provider / 日志 / 自动化输出可控边界收口。

004-E 可与部分阶段并行，但验收上应独立记录，避免 UI 打磨被数据模型和索引改造淹没。004-F 可与 004-A 到 004-D 同步设计，但不应阻塞 App 内明文展示、搜索、标签和编辑的主线实现。

## 9. 仍需确认的问题

当前没有阻塞 PRD v0 起草的用户确认问题。以下问题应在技术方案或阶段评审中回到项目负责人处确认：

- 如果富文本无法可靠保留格式，是否接受降级为纯文本化编辑，以及降级后的用户提示和数据影响。
- OCR 语言支持、准确率和性能是否满足目标体验；如果系统 Vision 在目标 macOS 版本上表现不足，是否降低 OCR 搜索范围。
- CLI / 日志完整正文输出的默认格式、截断阈值和显式参数名称。
- Provider / 自动化在具体动作设计中如何表达“明确用户动作或 agent 指令触发”。

## 10. 进入下一步的条件

PRD v0 经项目负责人复审后，建议进入：

1. UI/交互设计复审：重点审保存/取消稳定布局、筛选展开、选中反馈、标签菜单、OCR 状态和详情密度。
2. App 架构师复审：重点审内容模型、搜索索引、OCR 队列、富文本 payload、标签模型和 CLI typed subject。
3. 安全合规顾问复审：重点审明文可访问后的 provider、日志、自动化和凭据边界。
4. 测试/质量复审：重点补验收矩阵、fixture 策略、低敏证据和回归门禁。
