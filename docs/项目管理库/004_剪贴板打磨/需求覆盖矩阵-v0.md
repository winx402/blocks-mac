# 剪贴板打磨需求覆盖矩阵 v0

状态：coverage-verified
最后审阅：2026-07-07
来源级别：project control

本文由项目负责人维护，用于确保阶段拆解和阶段 PRD 不遗漏原始需求、用户澄清和角色回收问题。产品经理产出每个阶段 PRD 后，项目负责人应回填对应 PRD 覆盖状态；阶段验收完成后继续回填验收状态。

## 状态说明

- `pending-prd`：已分配阶段，但阶段 PRD 尚未产出或尚未复审。
- `assigned`：已派发给对应角色进行阶段 PRD 或方案设计。
- `prd-draft-under-review`：阶段 PRD 已产出，正在项目负责人或角色复审。
- `revision-requested`：阶段 PRD 已完成角色复审，但进入开发前需要产品经理修订。
- `covered-by-reference`：仅在阶段拆解前草稿中出现，不作为正式覆盖。
- `partial-accepted`：跨阶段需求的当前阶段 PRD 已接受，但仍有其他阶段或最终集成 Gate 未闭合。
- `paused-until-step-accepted`：历史暂停状态，表示已产生阶段材料，但根据用户要求切回串行推进，需等待前置 Step 开发验收后恢复。
- `accepted`：阶段 PRD 已被项目负责人接受。
- `verified`：实现和验收已确认。
- `verified-with-p2-residuals`：实现和验收已确认，且最终收口接受保留 P2 residual；这些 residual 不视为需求未覆盖。

## 后续维护规则

- 产品经理提交某阶段 PRD 后，项目负责人必须在本矩阵中把对应条目标记为 `accepted` 或指出缺口。
- 如果阶段 PRD 修改、降级或排除某项需求，必须在本矩阵中记录原因和用户/项目负责人是否接受。
- 开发和验收完成后，测试/质量应协助把对应条目标记为 `verified` 或列入残余风险。
- Step 6 已完成最终回扫；后续如新增或重开需求，必须继续在本矩阵中记录覆盖、验收和 residual 状态。
