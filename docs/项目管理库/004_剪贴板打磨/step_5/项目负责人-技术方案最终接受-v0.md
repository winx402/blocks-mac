## 3. 必须进入开发派发的硬约束

开发派发必须包含以下不可降级条件：

- P13E-first。P13E fail 时不得用 P8 / P8I / P9A / P9B / P11E / P13A-D PASS 代替。
- `ui_interaction` 与 `capture_bridge` 的 required scenarios 不得降级为 optional、baseline_reference 或只读 token scan。
- P13E 需要做值级断言，不只验证 JSON key 存在。
- `ClipboardCapturePolicy` 必须消费 `PrivacyPolicySnapshot`，不得继续只消费旧 `excludedBundleIdentifiers`。
- 旧 `excludedBundleIDs` / `excludedBundleIdentifiers` 不得继续作为 AppModel 或 capture policy 的 active fact source。
- 首版 CLI 不实现 `--include-sensitive-paths`。
- `blocks privacy ... --confirm` 只能确认本 App policy mutation，不得解锁系统危险动作。
- 开发与验证默认不触发真实 App、真实剪贴板、provider、Keychain、TCC、System Settings、Finder、App launch、command execution 或真实系统状态变更。

## 4. 残余风险

以下作为 P2 residual 进入开发验收或 Step 6 回扫，不阻塞技术方案接受：

- 真实机器 `/Applications` 分布、真实 App icon 和真实 VoiceOver 行为未在技术方案阶段验证。
- P13E 验证 synthetic fixture、row model、a11y metadata 和低敏 evidence，不能替代真实 UI 体验验收。
- icon cache 首版仅内存，不跨启动。
- login item / helper / launch label 首版不做系统登记源枚举，只支持 explicit input / existing policy / synthetic fixture。
