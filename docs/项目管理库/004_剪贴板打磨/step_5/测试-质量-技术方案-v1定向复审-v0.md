## 2. P1 关闭确认

### P1-1：P13E UI search / filter / sort / a11y / layout required scenarios

结论：已关闭。

v1 已补齐以下硬证据：

- P13E evidence schema 增加 `ui_interaction.search_fields`、`filter_combination`、`sort_stability`、`a11y`、`layout`。
- P13E required scenarios 明确列入：
  - `privacy_app_search_fields_004`
  - `privacy_app_filter_combination_004`
  - `privacy_app_sort_stability_004`
  - `privacy_app_row_a11y_004`
  - `privacy_app_narrow_width_004`
  - `privacy_app_long_text_i18n_004`
- fail-closed 条件明确：缺任一 required scenario，或 `ui_interaction` 缺 `search_fields`、`filter_combination`、`sort_stability`、`a11y`、`layout` 时 P13E fail。
- 场景断言覆盖 raw home path 不可搜索、filter OR/AND、Clear filters/search/all 区分、icon async 不改变排序、refresh 稳定、row a11y metadata、窄宽度 policy control 可见、长文本 i18n 低敏 fixture。

判断：足以避免 v0 风险中“P13E PASS 但 UI 搜索/过滤/排序/可访问性/布局未验收”的假 PASS。

### P1-2：capture bridge first-class validation object

结论：已关闭。

v1 已补齐以下硬证据：

- `PrivacyPolicySnapshot` 明确包含 `allowedBundleIDs`、`restrictedBundleIDs`、`allowedAppPathHashes`、`restrictedAppPathHashes`、`generatedAt`、`revision`。
- `ClipboardCapturePolicy` 必须消费 `PrivacyPolicySnapshot`，不得继续只消费旧 `excludedBundleIdentifiers`。
- P13E evidence schema 增加 `capture_bridge.snapshot_shape` 与 `capture_bridge.scenarios`。
- P13E required scenarios 明确列入：
  - `privacy_capture_bundle_restricted_004`
  - `privacy_capture_bundle_allowed_004`
  - `privacy_capture_app_path_precedence_004`
  - `privacy_capture_default_allow_004`
  - `privacy_capture_missing_path_fallback_004`
  - `privacy_capture_snapshot_low_sensitive_004`
- capture evidence 合同要求每个 scenario 输出 `decision`、`matched_rule_type`、`mutation_performed=false`、`payload_read=false`、`path_redacted=true`。
- fail-closed 条件明确：snapshot 缺 bundle/app path allow/restrict set、`ClipboardCapturePolicy` 未消费 snapshot、仍只消费旧 `excludedBundleIdentifiers`、capture scenario 缺关键字段时 P13E fail。
- v1 还补充旧 `excludedBundleIDs` migration scenario，并要求旧字段不再是 AppModel / capture policy active fact source。

判断：足以避免 v0 风险中“UI/CLI policy 已实现但 live capture 不生效”的假策略。

## 4. P2 / 实现阶段注意事项

### P2-1：开发派发需禁止降级 P13E required scenarios

v1 已在技术方案中写明 `ui_interaction` 与 `capture_bridge` 不可降级。建议开发派发继续保留同一句硬约束：

```text
P13E 中 ui_interaction 与 capture_bridge 的 required scenarios 不得降级为 optional、baseline_reference 或只读 token scan；任一缺失必须 ok=false。
```

### P2-2：P13E 实现需验证行为字段，不只验证 JSON key 存在

建议实现阶段把以下字段做值级断言：

```text
- capture bridge: decision、matched_rule_type、mutation_performed=false、payload_read=false、path_redacted=true。
- UI search: raw home path query must not match。
- UI sort: sort_order_changed=false after icon async。
- legacy exit: old excludedBundleIdentifiers not active fact source。
```

该项是实现质量要求，不构成技术方案 P1。

### P2-3：真实 UI / VoiceOver / 真实机器 App 清单仍是后续残余风险

v1 的 P13E 验证 synthetic fixture、row model、a11y metadata 和低敏 evidence。真实 VoiceOver 行为、真实 `/Applications` 分布和真实 App icon 行为仍应留到开发验收或 Step 6 回扫，不阻塞技术方案接受。
