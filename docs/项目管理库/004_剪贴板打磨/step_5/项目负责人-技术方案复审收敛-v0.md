## 2. 必须回写到技术方案 v1 的 P1

### P1-1：P13E required scenarios 必须显式覆盖 UI 搜索、过滤、排序、可访问性和布局边界

技术方案 v1 必须将以下场景加入 P13E required scenarios，而不只是写在 fail-closed 或 PRD 说明里：

```text
UI interaction / layout scenarios:
- privacy_app_search_fields_004: display name、bundle id、source directory、path summary、policy status、identity issue code 都能命中；path search 不匹配 raw home path。
- privacy_app_filter_combination_004: 同维度 OR，不同维度 AND，Clear filters / Clear search / Clear all 语义可区分。
- privacy_app_sort_stability_004: display name、bundle id、source directory priority、path summary、path hash tie-breaker；icon async 不改变排序；refresh 同 fixture 顺序稳定。
- privacy_app_row_a11y_004: row 暴露 App name、policy status、bundle id 可用性、source directory、主要异常；policy control 有 label / value / hint。
- privacy_app_narrow_width_004: 窄宽度下 policy status/control 仍可见，长文本不挤压 trailing control。
- privacy_app_long_text_i18n_004: 中文、英文、日文长 App 名、bundle id、path summary 使用低敏 fixture，截断与完整值入口可判定。
```

P13E evidence schema 至少增加：

```text
"ui_interaction": {
  "search_fields": {},
  "filter_combination": {},
  "sort_stability": {},
  "a11y": {},
  "layout": {}
}
```

### P1-2：capture bridge 必须成为 P13E 一等验收对象

技术方案 v1 必须把 capture bridge 加入 P13E required scenarios，避免出现 UI / CLI policy 已实现但 live capture 不生效的假策略。

必须新增：

```text
Capture bridge scenarios:
- privacy_capture_bundle_restricted_004: source bundle id 命中 restricted bundle_id rule -> skip with .excludedSource。
- privacy_capture_bundle_allowed_004: source bundle id 命中 allowed bundle_id rule -> allow。
- privacy_capture_app_path_precedence_004: app_path restricted 优先于 bundle_id allowed；app_path allowed 优先于 bundle_id restricted。
- privacy_capture_default_allow_004: 无 explicit rule -> default allow。
- privacy_capture_missing_path_fallback_004: 无 path hash 时只按 bundle id 规则判断，不伪造 app_path match。
- privacy_capture_snapshot_low_sensitive_004: evidence 只输出 bundle id fixture、path hash、summary、decision code，不输出真实路径、窗口标题、剪贴板 payload。
```

P13E fail-closed 条件必须补：

```text
- PrivacyPolicySnapshot 未包含 bundle_id allowed/restricted 与 app_path allowed/restricted set 时 fail。
- ClipboardCapturePolicy 未消费 PrivacyPolicySnapshot，或仍只消费旧 excludedBundleIdentifiers 时 fail。
- capture bridge scenario 缺 decision、matched_rule_type、mutation_performed=false、payload_read=false 时 fail。
```

## 3. 建议同步吸收的 P2

以下不单独阻断 v1，但建议技术方案 v1 一并吸收，减少后续开发派发歧义：

- 增加 `privacy_policy_legacy_excluded_bundle_migration_004`：旧 UserDefaults fixture -> one-shot migration -> restricted bundle_id rules；migration marker present；AppModel / capture policy 不再读取旧 excluded string 作为 active fact source。
- P13E forbidden pattern 区分 hard forbidden 与 context forbidden，避免把文档中合法描述禁止项的文字误判为泄漏，同时仍禁止可复制危险命令和敏感原文。
- 性能 evidence 输出 `elapsed_ms`、`threshold_ms`、`fixture_count`、`sample_count`；超时只输出 scenario id 和 summary，不 dump app list；允许一次串行重跑，重跑仍失败才 fail。
- 固定 menu button visible label / VoiceOver label / value / hint；duplicate confirmation 按钮文案避免只写泛化 `Apply`。
- issue popover 固定 keyboard focus、Esc 关闭、VoiceOver 标题和 issue label。
- all settings 摘要不得触发完整扫描和真实 icon 加载。
- `canonical_identifier` 只允许为显式创建的 app_path / command_path / app_bundle policy rule 持久化；Default mutation 删除 rule 时清除 path-like 字段。
- 首版默认不实现 CLI `--include-sensitive-paths`；如必须实现，需要明确禁止其用于 P13E、开发记录、验收记录和 golden fixture。
- login item / helper / launch label fixture whitelist 必须是 synthetic source，不读取真实系统登记源。
- dangerous_action_blocked 输出固定 `blocked_capability` 枚举，不拼接用户输入、真实 command path、launch label 或系统配置字段。
