## 2. 预审判断

技术方案 v0 已覆盖：

- P13E-first：新增 `p13e_clipboard_privacy_policy_checks.py`，并要求开发前先定义 evidence schema / fixture / fail-closed。
- Core 单一策略事实源：`PrivacyPolicyRepository` 作为 UI 与 CLI 的唯一策略 store。
- 三层模型：`PrivacyAppInstance`、`PrivacyPolicySubject`、`PrivacyPolicyRule`。
- 三 root 受控递归：root 限三目录，最大深度 2，`.app` bundle 作为叶子。
- 真实图标读取：`SystemAppIconProvider` / `FakeAppIconProvider`，首版只做进程内 icon cache。
- UI 可写策略：policy control、状态机、duplicate bundle id confirmation、failed retry/cancel。
- policy precedence：首版支持 `app_path` override，`app_path` 优先于 `bundle_id`。
- capture bridge：从 source app 增加 path hash / summary，`ClipboardCapturePolicy` 接入 `PrivacyPolicySnapshot`。
- CLI typed subject：resolve/list/get/dry-run/apply/hard-block JSON 输出和 subject resolver。
- command_path / login_item / helper / launch_label 边界：显式输入、已有 policy 或 fixture 白名单，不扫描 PATH、不执行命令。
- 低敏输出和 sanitizer：默认不输出完整路径、TCC raw、provider token、shell / launchctl / tccutil 等危险 token。
- 性能阈值：3000 synthetic apps、首屏 readiness、full index、search/filter、refresh no-blank、icon layout stability、CLI resolve。
- 开发批次：Batch A-D，先 P13E / Core model，再 scanner/icon/store，再 UI/capture bridge，再 CLI/full regression。
