结论：**本记录原有“可控产品问题已关闭、整体通过”结论已于 2026-07-25 作废。最新安装版仍复现剪贴板捕获、详情会话和气泡文字问题，必须以文末“验收结论纠正（2026-07-25）”为准。**

### 补充 P1-03 复制普通线程 ID 文本后卡顿

- **用户现象：** 复制 Codex 线程 ID 后电脑卡死；内容是普通文本，不是大图。
- **事实：** 线程 ID 只负责触发一次新剪贴板记录和面板刷新。修复前主线程采样反复出现 `ClipboardPanelHoverTrackingLayer.body → ClipboardStore.preview(for:) → ClipboardRecorderRecord.preview → Data(base64Encoded:) → NSImage`。
- **根因：** 面板每次重新计算可见行时，同步从 SQLite 重建历史图片完整 payload、Base64 解码并创建图片；历史中存在大图时，一个极小文本变化也会触发重型图片工作。
- **修复：** 行视图只读取内存缩略图；缺失缩略图在串行 utility 队列读取原始图片、通过 ImageIO 降采样后回到主线程发布。捕获规格化和仓储持久化也不再占用 MainActor。
- **最终复验：** 隔离数据中预置 6000×6000 合成图片，打开面板后复制合成线程 ID，RSS 峰值仅增加 352 KB、CPU 峰值 15.2%；连续 20 次复制无冻结、无无界增长。测试后已删除隔离数据并恢复正常 App。

## 验收结论纠正（2026-07-25）

### 重新打开的真实问题

1. 纯文本复制仍可能卡死：旧实现对每次 Pasteboard 变化无条件同步请求 PNG、TIFF、文件 URL、URL、RTF 和文本。Pasteboard owner 可以惰性提供数据，因此即使用户复制纯文本，也可能在主线程等待无关表示。
2. 详情保存后面板失灵：详情文档加载/保存、完整值、元数据与预览共用会互相取消的任务状态；保存后还同步重读 payload、解码图片并清空全量预览缓存。
3. 气泡文字颜色与二维缩放错误：编辑态从连接线/边框样式解析颜色，提交态从文字样式解析；气泡文字框被强制回 `.fixedWidth`，高度拖动会被重新测量覆盖。
4. 新复制内容掉到第二条：现场系统 Pasteboard 出现了新的 `changeCount`，且 `SSPasteboardHelper` 正在运行。Blocks 的排序键没有自发反转；系统剪贴板被外部辅助进程再次覆盖时，历史按真实外部复制记录。来源只能记为“屏幕共享运行期间旧签名重现候选”，不能把候选伪装成已证明的远端来源。

### 本轮修复事实

- Pasteboard 读取迁入串行 utility reader。先取声明类型，只选择一个表示族；纯文本只请求 `public.utf8-plain-text`，不再触碰 PNG/TIFF/文件表示。读取前后及回主线程前均校验 `changeCount`，过期结果不得提交。
- 详情 Store 拆为文档通道与辅助读取通道。打开/保存不会被预览或完整值读取取消；图片 payload、Base64 和缩略图解码离开 SwiftUI `body`；保存只失效当前记录缓存。
- 屏幕共享诊断只在“屏幕共享进程运行＋外部捕获命中既有签名”时展示非阻塞提示，不冻结第一条、不抑制真实重复复制。
- 气泡、步骤和普通文字统一通过语义文字样式解析。气泡使用 `callout.note.color`；气泡文字框改为 `.fixedBox`，宽高均保留，移动和缩放约束到当前裁剪区域。
