# Blocks 插件平台接口契约 v1

状态：Host API v2 / Manifest v6 implementation-baseline
最后审阅：2026-08-11

## 运行模型

事件信封统一包含 `event_id`、`schema_version`、`occurred_at`、`module`、`phase`、`session_id`、`request_id`、`revision`、`causation_id`、`source`、`authorization`、`payload` 与 `resources`。

- `will.*`：按用户顺序串行执行，允许 `allow`、`block`、强类型 mutation、宿主 action、UI state patch 和 diagnostics。
- `did.* / failed.*`：异步执行，只允许 action、UI state patch 和 diagnostics。
- 同一模块的异步后置／失败事件按入队顺序执行；不同模块可以并行，避免无关模块互相阻塞。
- 同一模块后续的 `will.*` 必须等待此前已入队的后置／失败事件完成，确保前一事务的终态先于下一事务的前置 Hook；插件从自身后置事件重入同一模块时由因果链保护拒绝，不允许形成自等待。
- 开启安全模式或开始 App 终止时，宿主使此前排队的异步事件 generation 失效。即使安全模式随后关闭，旧事件也不得恢复执行；任务持有的资源 lease 必须在退出路径释放。App 终止开始后不再接受新的异步后置事件。
- 同一 `plugin + event + causation` 禁止重入；默认 fail-open。
- 交互 Hook 默认 500ms，单插件硬上限 2s，整条链硬上限 5s。

## 首批事件

| 模块 | 事件 |
| --- | --- |
| Clipboard | `clipboard.will_persist_capture`、`clipboard.did_persist_capture`、`clipboard.capture_failed`、`clipboard.will_write_pasteboard`、`clipboard.did_dispatch_paste`、`clipboard.paste_failed`、`clipboard.record_updated`、`clipboard.record_deleted`、`clipboard.tag_changed`、`clipboard.ocr_completed` |
| Screenshot | `screenshot.capture_completed`、`screenshot.capture_failed`、`screenshot.editor_opened`、`screenshot.element_committed`、`screenshot.will_finalize_output`、`screenshot.output_finished`、`screenshot.output_failed`、`screenshot.ocr_completed`、`screenshot.long_capture_assembled` |
| Translation | `translation.input_resolved`、`translation.will_run_session`、`translation.session_completed`、`translation.session_failed`、`translation.source_status`、`translation.source_result`、`translation.source_failed`、`translation.will_commit_result`、`translation.favorite_changed`、`translation.copy_completed` |
| Provider | `provider.route_resolved`、`provider.will_send_request`、`provider.request_completed`、`provider.request_failed` |
| Automation | `automation.will_execute_shortcut`、`automation.did_execute_shortcut`、`automation.manual_trigger`、`automation.scheduled_trigger` |
| App/Plugin | `app.launched`、`app.will_terminate`、`plugin.lifecycle_changed`、`plugin.shared_state_changed`、`plugin.host_action_completed`、`plugin.host_action_failed` |

前置事件只允许修改该事件明确列出的字段。事件身份、授权上下文、revision、causation 和资源引用永远不可修改。后置与失败事件提交的 mutation 会被宿主拒绝。

`clipboard.did_persist_capture` 当前为事件 schema v2：实际保存成功后提供 record ID、类型、来源、去重结果、change count、允许的内联正文或全量正文资源引用。异步 Hook 的资源 lease 持续到 Hook 完成、取消、超时或 generation 失效；v1 插件只读取原有 record ID 与去重投影。

## 宿主动作

- Clipboard：记录读写、置顶、收藏、删除、标签 CRUD/挂载、OCR、复制、Blocks 粘贴。
- Screenshot：捕获、文档快照、标注 CRUD、OCR、水印、圆角、复制、保存、钉住、归档。
- Translation：运行、取消、重试、复制、收藏及翻译/OCR 能力。
- Provider：查询已批准能力、发起受控请求；禁止读取 Secret。
- System：通知、打开插件页面、快捷动作、定时任务、插件存储和授权文件。
- Plugin：调用公开动作、访问获批共享 namespace。

Manifest 的 `platform.host_actions` 必须属于当前 Host API 能力目录。未知动作在安装校验阶段拒绝，而不是运行时静默失败。Manifest v6 通过 `minimum_host_api_version` 声明最低版本；当前 Host API 为 v2，增加通用 `screenshot.color_sample.begin`。每项能力包含稳定 ID、API 版本、输入/输出 Schema 与权限；插件 ID 不参与宿主能力分派。

宿主操作分为两层：

- 异步业务动作：通过 Hook/Action 输出的 `actions[]` 调用，受 Manifest 声明和安装授权约束。宿主分配 operation ID，并只向请求插件发送完成、失败或取消事件。
- 同步运行时操作：`storage.get/put`、`storage.queue.enqueue/dequeue`、`shared.get/put`、`resource.read`，用于插件隔离进程内的状态和资源访问。

FIFO 队列与 KV 共用 CAS revision。私有与共享 KV 的 CAS 均须在跨连接并发下以单个原子事务完成，比较 revision 与写入不可拆分；冲突返回而不得覆盖已成功提交的值。共享 namespace 的成功写入会发布 `plugin.shared_state_changed`，订阅者只收到 owner、namespace、key、schema version 和 revision；值仍须按权限主动读取。

## 资源

- 大文本、图片、文件和长截图使用 `BlocksPluginResourceReference`。
- `resource.read` 按 offset 分块读取，允许取消，并在每次调用校验当前插件授权。
- 分块大小不是业务内容上限；调用方可读取至 `eof` 恢复完整内容。
- 功能会话在 Hook 结束、会话取消、重截或窗口关闭时请求撤销句柄；正在执行的异步 Hook 持有宿主 lease，只在最后一个 lease 释放或取消后物理回收资源。最终撤销后的迟到读取必须失败。

## UI

Manifest 固定声明页面、分区、卡片、列表、表格、网格及展示/输入/操作组件。运行时只允许 Patch 已声明组件的 value、items、status、visibility 和 enabled。禁止绝对坐标、任意颜色字体、HTML、WebView 和原生 UI 代码。

首批插槽：

- 插件中心：`plugin.page`。
- 剪贴板：`clipboard.record_badge`、`clipboard.detail_section`、`clipboard.context_action`、`clipboard.header_action`。
- 截图：`screenshot.tool`、`screenshot.inspector_section`、`screenshot.status_item`、`screenshot.output_action`。
- 翻译：`translation.panel_action`、`translation.result_detail`。
- Provider/设置：`provider.diagnostic_card`、`settings.status_card`。

宿主负责布局、主题、毛玻璃、间距、焦点、VoiceOver、Reduce Motion 与虚拟化。插件只能更新 schema 允许的属性；不存在的组件、非法属性和不允许的根组件均拒绝。

宿主不设置 Hook、动作、UI 项目或业务内容的产品数量上限。包结构、单次 IPC、超时和内存依然有安全边界；超出内联传输边界的业务内容必须通过可取消的资源句柄完整读取，不得截断或以摘要冒充全量数据。

## 权限与生命周期

- 安装确认逐项列出事件、fail-closed Hook、宿主本地化动作、导入来源、共享状态、UI 插槽、网络、数据、Secret、后台和存储关系；审查界面不展示 raw ID 或 Secret。
- `app.will_terminate` 不得声明或执行 fail-closed；终止流程不能由插件阻断。
- Hook 的 `runs_in_background=true` 可用于各事件 phase。`runs_in_background=false` 不表示 `NSApp.isActive`：它只允许非终止的 `will.*` 同步 preflight Hook，并且作为当前 Blocks 工作流的一部分在流程继续前运行。安装校验拒绝其他 false 声明；为兼容已安装历史包，运行时也会拒绝其 false 非合格 binding，且必须 fail-open 继续原宿主信封，不执行 runner、mutation、action 或资源操作，即使持久 binding 记录为 fail-closed。
- 包哈希或声明权限变化后，旧批准失效。
- 插件不能直连数据库、Keychain、任意文件、Shell 或原生动态库。
- 连续崩溃、超时或循环触发达到阈值后安全停用；全局安全模式停止 Hook、后台任务和定时任务。
- 插件停用、卸载、安全停用、安全模式和 App 终止都必须先切断同步 Host Operation 准入并排空已准入请求；私有／共享状态读写还须在数据库事务内复核插件仍启用、已批准且未安全停用。用户明确清除安全停用后，仅在持久化元数据仍可运行时恢复准入。
- v1-v5 插件仍由相同安装、执行、取消、Secret、网络和日志生命周期托管；Manifest v6 Secret 继续由敏感配置字段声明，不得因版本升级丢失。

Manifest v6 的 `presentation` 是宿主渲染用户界面的唯一展示来源，包含本地化名称、摘要、使用场景、示例、数据说明和配置字段标签。该元数据不改变事件、权限或运行行为；缺失时旧版本插件使用兼容回退，但不会获得官方包专属 UI 分支。

Provider URL 仅接受不含 user、password、query 或 fragment 的 URL；持久化前按该边界校验并安全保存。Provider alias 的创建、替换、删除与旧数据迁移必须保持引用生命周期一致，legacy migration 不得留下失效别名引用。已存在 Secret 从 alias A 改为 B 时，Keychain 必须以单次原子更新同时迁移 account 与 secret；失败时继续保留可管理的 A，设置不得先行持久化 B。

## 内置插件边界

- 官方插件包位于签名 App 的内置资源目录，但安装后复制到独立托管目录，与外部插件使用相同校验、审批、XPC 执行、启停和卸载流程。
- 官方保留 ID 仅用于目录身份和防止外部包冒用；Blocks 业务代码不得据此分支执行功能。
- 内置目录只保存包位置、本地化摘要、分类、图标 Token、版本与哈希，不保存插件运行逻辑。
- 数据库 v16 仅增加 `installation_origin` 和 `built_in_catalog_version`；历史插件迁移为 `external`，不改变原配置、Secret、启用状态或 Hook 顺序。

## 调试

- 关闭：仅生命周期、结果、耗时、错误类别、崩溃和权限拒绝。
- 开启：记录受控的事件、结果、状态迁移与计数；插件可控的事件 payload、mutation、action input、UI patch、diagnostic、普通 action/schedule input/output 和堆栈均为安全结构投影，不持久化原始业务正文、字段名或相关哈希。字符串只保留 UTF-8 字节数，数组只保留元素数，对象只保留字段数，数字、布尔和 null 只保留类型；宿主验证后的动作 ID 与诊断级别可作为受控元数据保留。
- Secret、Authorization、Cookie、密码、Keychain 值和安全作用域令牌始终脱敏。
- 每插件日志滚动保留 7 天或 100MB。

网络调试只记录方法、主机、路径是否存在及路径段数量、响应码、允许名单内的标准头名称、自定义头数量，以及正文的字节数和 SHA-256；这是网络专用的 byte count + SHA-256 例外。不得记录 URL 凭据、路径内容、query、fragment、任意头值、自定义头名称或正文内容。关闭调试时不写业务 payload。调试状态持续到用户手动关闭，可从插件中心或 `blocks plugin debug` 修改。

## CLI

通用生命周期入口为 `blocks plugin`，使用独立 Broker 动作 `blocks.plugin.manage` 和 `PluginDevelopmentService`。机器输出统一包含 `schema_version`、`command`、`ok`、`operation_id`、`data` 与 `diagnostics`；退出码固定为成功、参数/Schema、确认/权限、插件运行和宿主不可用五类。Agent CLI 的 digest 与 I/O 在后台执行，并以 generation 和 cancel 语义避免迟到结果覆盖已取消或已更新的请求。

开发闭环包括：`init`、`api list/show`、`validate --strict`、`doctor`、`test --event --expect`、`pack`、`install --plan/--apply --confirm-hash`、`invoke`、`logs show/follow/export/clear`、`enable/disable/remove` 和 `catalog list/install`。隔离测试只使用 fixture 资源和宿主动作桩，不访问真实数据库、剪贴板或用户文件；Secret 只能经交互输入或 stdin 进入。CLI 不开放任意 JavaScript、Shell 或动态库执行。
