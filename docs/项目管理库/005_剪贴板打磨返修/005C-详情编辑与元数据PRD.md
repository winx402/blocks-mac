# 005C 详情编辑与元数据 PRD

状态：confirmation-ready-awaiting-user
日期：2026-07-08
负责人：项目负责人
来源级别：PRD draft

## 1. 目标

让用户在当前剪贴板面板中直接查看和编辑选中条目的内容，不再通过右键 `Edit details` 打开独立浮窗或窗口。详情元数据需要按短字段两列、长字段单列组织，避免挤压正文编辑区域。

本 PRD 涉及 UI 代码改动，必须经用户确认后才能实施。

## 2. 范围

- 选中条目的上方详情卡。
- 详情卡内正文预览和编辑入口。
- 保存、取消、未保存变更、保存成功、保存失败状态。
- 元数据短字段和长字段布局。
- 详情相关可见文案和可访问性标签。

## 3. 详情卡位置

- 详情编辑放在当前面板上方详情卡内。
- 用户选中条目后，详情卡展示该条目的标题、摘要、正文预览、编辑入口和元数据。
- 不再把“编辑内容”作为必须右键触发的独立窗口路径。
- 详情卡不应遮挡历史列表的核心可见区域；如果空间不足，应允许详情卡内部滚动或合理压缩次要信息。

## 4. 编辑行为

- 可编辑内容在详情卡内直接进入编辑态。
- 编辑态显示正文编辑区、保存、取消按钮。
- 保存和取消按钮必须位于正文编辑区内部的底部固定操作栏，不放在详情卡外层标题栏、独立浮层或会挤压元数据的位置。
- 操作栏高度固定为 44pt；编辑态期间始终保留该高度。保存、取消、保存中、保存失败、未保存状态变化只能改变按钮状态和状态文本，不能改变详情卡高度、编辑区外框、元数据位置或历史列表位置。
- 操作栏布局：左侧为状态文本区域，右侧为按钮组；按钮组固定右对齐，顺序为“取消”在左、“保存”在右。
- 按钮尺寸：高度 28pt，最小宽度 72pt，左右内边距 12pt，按钮间距 8pt。中英日文案超过最小宽度时允许按钮在固定按钮组内扩展，但不得换行，不得推动编辑区正文或元数据。
- 样式：保存按钮使用主操作样式；取消按钮使用次级描边或轻量按钮样式。保存不可用时保持原位置但禁用，不隐藏；保存中时保存按钮显示处理中状态但宽度不变。
- 保存成功后，详情卡保留当前条目并回到只读或干净编辑状态；是否自动收起不作为默认要求。
- 取消时恢复进入编辑态前的内容。
- 有未保存变更时，切换条目、关闭面板或执行粘贴前必须提示保存、放弃或继续编辑。
- 保存失败时保留草稿，显示失败原因和重试入口。
- 不可编辑内容应显示只读原因，不提供误导性的编辑按钮。

编辑区按钮示意图：

```text
+----------------------------------------------------------+
| 正文编辑区                                                |
| 这里编辑剪贴板内容，多行文本在上方滚动或扩展。              |
|                                                          |
| 状态：已修改未保存                         [取消] [保存] |
+----------------------------------------------------------+
```

示意图说明：

- `[取消] [保存]` 位于编辑区内部底部操作栏，不在编辑区外部。
- 操作栏高度固定，按钮出现、禁用、保存中或失败时不导致组件变形和位置移动。
- 状态文本在左侧固定区域展示，例如“已修改未保存”“保存中”“保存失败，可重试”“已保存”。

## 5. 元数据布局

### 5.1 短字段

短字段一行两个，适合：

- 类型。
- 来源 App。
- 创建时间。
- 最近复制时间。
- 字符数或字节数。
- 修订号。
- OCR 状态。
- 隐私策略状态。

### 5.2 长字段

长字段独占一行，适合：

- bundle identifier。
- source path。
- file URL。
- hash / payload id。
- 长 URL。
- 其他超过短字段安全长度的值。

长字段默认截断但可选择查看完整值；查看完整值必须是显式动作，避免无意暴露长内容或敏感路径。

## 6. 状态反馈

- 只读：显示可读预览和元数据。
- 编辑中：编辑区明显，保存/取消可见。
- 已修改未保存：状态应明确，不只依靠按钮可用性。
- 保存中：禁用重复保存，显示处理中状态。
- 保存成功：轻量成功反馈。
- 保存失败：错误说明和重试入口。
- 保存/取消按钮状态变化不得改变按钮位置、按钮组宽度、编辑区外框、详情卡高度或元数据位置。
- 切换条目有未保存变更：显示保存、放弃、继续编辑选择。

## 7. 验收标准

- 选中条目后，上方详情卡展示条目详情。
- 编辑正文在详情卡内完成，不打开独立窗口。
- 保存、取消、未保存、保存失败状态可见。
- 保存和取消按钮位于编辑区内底部固定操作栏，出现、禁用、保存中或失败时不导致详情卡、编辑区、元数据或历史列表位置移动。
- 短字段一行两个，长字段独占一行。
- 长字段不会挤压正文编辑区。
- 详情相关文案中英日三语覆盖。
- 键盘和 VoiceOver 至少能识别详情卡、编辑区、保存/取消按钮和状态。

## 8. 验收证据

- 对照 `assets/005-详情内编辑问题.png` 的详情卡截图。
- 编辑前、编辑中、保存成功、保存失败或未保存确认截图。
- 保存/取消按钮在编辑区内的固定操作栏截图；截图需覆盖未修改、已修改、保存中、保存失败状态，证明按钮位置和组件尺寸稳定。
- 短字段两列和长字段单列截图。
- 长 URL 或长路径样本截图。
- 基础键盘路径和可访问性核查记录。

## 9. 自定义标题规则

- 所有历史条目均可设置自定义标题，不要求先收藏或先打标签。
- 未设置自定义标题时，卡片和详情标题显示本地化类型。
- 设置自定义标题后，卡片标题和详情标题均显示自定义标题；类型仍作为 metadata 或弱标识展示。
- 自定义标题为空或只包含空白时，视为清除自定义标题，恢复默认类型标题。
- 自定义标题保存不应改变最近复制时间，不应置顶，不应写系统剪贴板。
- 自定义标题属于 record 级元数据，不依赖旧 pinned/pinboard 体系，也不把条目隐式收藏。

## 10. 代码扫描确认的实施范围

本节只定义实施范围，当前 PRD 确认前不进入 UI 或 repository 代码修改。

### 10.1 详情卡位置和面板集成

- `ClipboardFloatingPanelView.swift`
  - 当前问题：详情编辑通过 `detailEditorOverlay` 在面板上方覆盖，点击遮罩关闭；这仍是浮层体验，不是上方详情卡。
  - 实施范围：把选中条目的详情卡纳入面板主布局。底部布局时详情卡位于 header 下、历史横向列表上方；左右布局时详情卡位于列表上方或详情区域顶部。空间不足时详情卡内部滚动，不遮挡历史列表核心区域。

- `ClipboardHistoryPanelPresenter.swift`
  - 当前事实：面板关闭已经通过 `detailStore.requestPanelClose` 做 dirty guard。
  - 实施范围：保留 dirty guard，但关闭、粘贴、切换条目均需走详情卡未保存确认；不得因为去掉 overlay 而绕过 guard。

### 10.2 编辑区和按钮稳定性

- `ClipboardDetailEditorView.swift`
  - 当前问题：保存/取消位于外层 `fixedActionBar`，编辑态才出现，按钮组会改变外层布局；文案多处硬编码英文。
  - 实施范围：将编辑操作栏移入正文编辑区内部底部，固定高度 44pt；左侧状态文本，右侧 `[取消] [保存]`，保存禁用、保存中、失败、成功状态只改变内容和状态，不改变组件高度和按钮位置。

- `ClipboardDetailStore.swift`
  - 当前事实：已有 dirty、saving、saveFailed、dirtyNavigation 等状态。
  - 实施范围：保留单一 store 状态源，补齐本地化状态文案、保存中宽度稳定、失败可重试和取消恢复逻辑；不要在 View 内创建第二套状态事实。

### 10.3 自定义标题持久化

- `AppDatabase.swift`
  - 当前问题：只有 `clipboard_pinned_metadata.display_name` 能表达命名，但它会隐式绑定旧 pinned/pinboard 体系。
  - 实施范围：新增 record 级自定义标题字段或窄表，并一次性迁移旧 pinned displayName 到新字段；迁移后运行时不再从 pinned metadata 读取标题。

- `ClipboardRepository.swift` / `ClipboardRepository+DetailEdit.swift`
  - 当前问题：`renamePinnedRecord` 会把记录 pin 起来，不适合所有条目的自定义标题。
  - 实施范围：新增独立 rename/clear title 命令；保存自定义标题只更新 metadata/search preview，不更新 payload、不写 pasteboard、不更新最近复制时间。

### 10.4 元数据读模型

- `ClipboardRepository+DetailEdit.swift`
  - 当前问题：metadata 只有类型、创建、更新、revision、OCR、tags、source，且标题英文硬编码。
  - 实施范围：短字段补类型、来源 App、创建时间、最近复制时间、字符/字节、修订号、OCR、隐私策略状态；长字段补 bundle identifier、source path summary、file URL、URL、hash/payload id 等，并用显式动作查看完整值。

- `ClipboardDetailReadModel.swift`
  - 实施范围：读模型需要能表达默认类型标题、自定义标题、标题可编辑状态、短/长 metadata 分类和完整值读取能力。

### 10.5 不进入 005C 的事项

- 不改变复制捕获、去重和 `Cmd+数字` 排序语义，这些归 005A。
- 不重新设计卡片视觉层级、标签筛选或设置页标签管理，这些归 005B。
- 不把自定义标题作为搜索命中内容的唯一来源；搜索是否纳入自定义标题可实现，但不得泄露旧 pinned displayName 路径。
