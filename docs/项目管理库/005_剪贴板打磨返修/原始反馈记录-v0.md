## 3. 原始反馈条目

### F1：剪贴板内容显示仍有很多问题

用户反馈：

- 新数据为什么是单行显示，需要重新检查内容预览显示策略。
- 老数据仍显示字符数量，例如 `23 个字符`、`16 个字符`、`86 个字符`，未按“显示内容”的预期完成。
- 某些记录区域不应该直接显示当前内容，而应展示更合适的信息；具体展示什么需要设计判断。

初步归类：

- 面板条目标题、正文预览、来源/类型摘要的信息结构问题。
- 新旧记录 read model 或 preview snapshot 可能存在不一致。
- 需要区分“文本正文可读预览”和“非正文类记录/来源类记录的更合适摘要”。

### F2：筛选组 hover 收起容错仍未改好

用户反馈：

- 面板筛选组在鼠标离开后自动收缩。
- 监听范围仍太小，容易移出区域后自动收缩。
- 需要把面积扩大一些，离开一定距离才收缩。

初步归类：

- 筛选组 hover 安全区、延迟收起、离开距离阈值仍未达到真实手感预期。
- 后续验收应包含真实鼠标路径或录屏证据，不能只依赖静态门禁。

### F3：收藏功能名称和右键位置存在问题

用户反馈：

- 收藏功能的名称和右键位置需要调整，见截图。
- 当前右键菜单中收藏被放在“标签”子菜单里；用户期望收藏功能独立出来，放在标签上面。
- 筛选组展示了类似 `clipboard.filter.tags` 的内部 key，展示名称有问题。

初步归类：

- 收藏作为内置标签的模型可以保留，但用户交互入口不应被埋进普通标签菜单。
- 需要修复本地化 key 直出问题。
- 需要重新定义右键菜单的信息架构：收藏应是一级动作，标签管理是另一组动作。

### F4：剪贴板隐私页面需要汉化

用户反馈：

- 剪贴板隐私页面仍显示英文，例如 `Clipboard Privacy`、`App capture policy`、`Search apps`、`Filters`、`Discovered Apps`、`Refresh`、`Policy`。
- 需要按照多语言体系进行汉化。

初步归类：

- 本地化覆盖不足。
- 需要通过项目多语言资源处理，不应硬编码中文。

### F5：剪贴板面板条目上下边框或内边距仍偏大

用户反馈：

- 剪贴板面板条目上下的边框可以窄一点。
- 当前核心内容区域面积仍不够大。

初步归类：

- 条目密度、卡片内边距、边框、内容区域比例没有达到预期。
- 后续需要明确视觉基线和真实截图对照，而不是只写“密度提升”。

### F6：编辑条目内容不需要独立窗口

用户反馈：

- 编辑条目内容不需要独立窗口。
- 应直接在详情区域里编辑内容，不需要右键 `Edit details` 后打开独立浮窗/窗口。

初步归类：

- 详情编辑交互路径与用户预期不一致。
- 需要把“查看详情”和“编辑正文”整合到当前详情面板中，减少额外窗口和跳转。

### F7：条目详情元数据组织仍未完成

用户反馈：

- 条目详情里面，部分元数据信息可以重新组织。
- 一行展示两个。
- 如果内容比较长，可以放在后面一行展示一个。
- 当前仍未按该方式改好。

初步归类：

- 详情页信息架构和布局未达预期。
- 需要重新定义 metadata grid：短字段两列，长字段单列，避免挤压正文编辑区域。

### F8：部分场景复制后剪贴板历史看不到记录

用户反馈：

- 部分场景复制东西后，在粘贴板里面看不到。

初步归类：

- 这是剪贴板捕获完整性问题，优先级应高于纯 UI 微调。
- 需要后续区分失败来源：系统剪贴板未捕获、捕获后未入库、入库后被筛选/策略隐藏、去重逻辑错误合并、UI 刷新未同步。
- 后续验收不能只用 fixture，应覆盖真实复制路径；若涉及敏感内容，需要使用低敏文本、低敏 URL 和低敏图片样本。

### F9：点击条目后的自动复制/自动填入输入框链路不稳定

用户反馈：

- 点击后自动复制到输入框，部分场景下复制进去。

初步归类：

- 用户原句存在歧义：可能是“部分场景下没有复制进去”，也可能是“复制目标/输入框填入行为不符合预期”。在 PRD 拆解前需要向用户确认准确失败现象。
- 该问题属于从历史条目点击到系统剪贴板、再到目标输入框的端到端交互链路问题，不应只验证 App 内部状态。
- 需要明确“点击条目”的期望行为：是仅把内容复制到系统剪贴板，还是在当前活跃输入框中执行粘贴/填入。

### F10：选中历史条目再次复制后应提升到最近第一条

用户反馈：

- 选中的条目复制之后，该条目将展示在最近复制的第一条。

初步归类：

- 这是历史记录排序和最近使用语义问题。
- 当用户从历史中选中某条并执行复制，该条目应被视为一次新的复制事件或最近使用事件，在面板中提升到第一条。
- 后续需要定义是否保留原创建时间、更新最近复制时间，以及详情页里如何展示这两个时间概念。

### F11：复制内容需要与历史去重并放在第一条

用户反馈：

- 复制之后，内容需要和历史去重，并放在第一条。

初步归类：

- 这是复制 ingest、去重策略和排序更新的联合问题。
- 相同内容再次复制时，不应生成重复历史条目；应合并到既有条目，并把该条目提升到最近复制第一条。
- 后续需要定义去重键：纯文本是否按归一化文本去重，富文本是否按 plain text 还是 RTF payload 去重，URL/file URL/图片是否按不同 payload 规则去重。

### F12：设置页标签管理视觉和图标位置需要调整

用户反馈：

- 设置页面的标签管理区域中，部分标签管理按钮看起来很奇怪、很乱。
- 标签的图标或者色块最好放在标签名前面展示。
- 还需要考虑 `Cmd+数字` 数字提示和收藏星标是否会重复或冲突；如果重复，需要提前定义处理方式。

初步归类：

- 这是剪贴板标签体系在设置页的 UI 质感和信息架构问题，应纳入 005B UI/交互 PRD。
- 标签列表的主识别区域应采用“图标/色块 + 标签名”的稳定组合，不能把色块放在难以关联的位置。
- 标签管理动作按钮需要统一尺寸、间距、图标语义、hover/focus/disabled 状态和可访问性标签，避免多个小按钮挤在一起造成视觉噪声。
- 数字提示是临时快捷键提示，收藏星标是持久状态/动作；两者不能共用同一视觉槽位，也不能使用容易混淆的形状、颜色或层级。

## 4. 与 004 的关系

004 最终验收保留了真实 App UI、真实鼠标 hover、真实 VoiceOver、真实剪贴板等 P2 residual。本轮反馈说明其中若干真实 UI residual 已经成为明确返修问题，应进入新项目管理。

本项目后续不应只复用 004 的低敏门禁结论。涉及真实手感、布局、菜单和详情编辑路径的条目，需要补真实 UI 证据或更直接的交互验收方式。
