## 1. 审查范围

本轮将 005 PRD 包和用户补充需求交给以下临时子 agent 做只读审查、补充和提问：

- 产品经理
- UI/交互设计师
- App 架构师
- 开发
- 测试/质量
- 安全合规顾问

所有子 agent 均按只读边界执行：未修改文件、未写代码、未创建分支、未启动 App、未触发真实剪贴板、TCC、provider、Keychain 或系统设置。

本汇总只记录审查意见和待确认项，不替代用户对 PRD 的最终确认。

补充说明：本轮子 agent 审查发生在 F12“设置页标签管理视觉和图标位置”新增之前。F12 已进入当前 PRD 草案，但尚未经过同一轮子 agent 复审；进入 UI 实施前，应由项目负责人决定是否补一次 UI/交互或测试复核。

## 2. 用户新增确认口径

以下为本轮审查期间用户追加的需求口径，已同步到当前 PRD 草案：

- `005A` 中“低敏文本”表述需要修正：文本默认都属于剪贴板历史捕获范围，不应理解为只捕获某类低敏文本。验收证据仍使用合成或非隐私样例，避免把用户真实隐私内容写入截图、录屏、日志或项目文档。
- 默认支持 `Cmd+1` 到 `Cmd+9` 粘贴剪贴板历史前 9 条数据；面板未打开时也应可用。
- `Cmd+数字` 快捷粘贴不更新最近复制时间、不置顶、不改变历史排序，保证用户可以连续快速粘贴多个内容。
- 打开剪贴板面板并按下 `Cmd` 键时，前 9 条历史条目应显示对应数字提示；按下数字后粘贴对应条目内容。
- 数字提示的位置和样式必须在 PRD 阶段确定，不能留到开发阶段临时决定。

## 3. 增量审查共识

针对用户新增的“文本默认捕获”和 `Cmd+1..9`，六个子 agent 的增量审查共识如下：

- “低敏”不能作为产品捕获范围限制。产品默认捕获文本，但仍应受隐私页 App capture policy、用户排除规则、系统不可读 pasteboard 类型和 secure input 等限制。
- “低敏”只约束验收样本、截图、录屏、日志、CLI 输出和仓库留证；证据不得留存用户真实文本内容或 raw payload。
- 编号口径已确认：面板打开时按当前可见列表编号，搜索/筛选生效时按过滤后的当前可见列表重新编号；面板未打开时按全局最近历史列表编号。
- 用户已确认快捷键作用域：面板打开和未打开时都应可用。
- 搜索框焦点和数字小键盘口径已确认：面板打开时即使搜索框聚焦，`Cmd+数字` 仍触发快捷粘贴；顶部数字键和数字小键盘都支持。
- 系统/App `Cmd+数字` 冲突时的注册和失败提示仍需实施阶段平台核验。
- `Cmd+数字` 复用双击的剪贴板写入、自动粘贴、权限降级和失败反馈路径，但不复用双击的置顶/排序更新规则。
- 按住 `Cmd` 的数字提示已要求在 005B 中定义显示位置、样式、隐藏时机，以及与收藏、标签、OCR、选中、hover、focus、VoiceOver 的关系。
- 少于 9 条、不可恢复条目、隐私策略排除条目、无 Accessibility 权限、目标输入框不可粘贴时，需要有明确禁用或降级反馈。

## 4. 子 agent 共识

- 005 PRD 包方向正确，覆盖了用户提出的核心范围；用户确认前不能进入实现，UI 改动尤其需要先确认 PRD。
- 当时 PRD 已覆盖 F1-F11，但还没有达到“整包可直接开发”的清晰度，主要缺口集中在信任链路的数据语义、失败状态、证据标准和 UI 可截图验收口径。F12 为本汇总后新增，当前已补入 PRD 草案但尚未复审。
- 信任链路必须先于 UI 打磨实施，这一点已被各角色认可。
- 不能用 004 的静态 PASS 或低敏自动化证据替代 005 的真实 UI 返修验收。
- 核心体验未真实验收时，不能降级成 P2 residual 后标记完成。

## 5. P0 级待补充

### 4.1 最近复制时间与置顶契约

多名子 agent 指出，重复复制合并置顶、历史条目复制置顶、双击粘贴置顶不是单纯 UI 排序问题，而是数据模型和仓库事务问题。

PRD 需要补清：

- 是否新增 `lastCopiedAt` 或等价字段。
- `createdAt`、`updatedAt`、`contentUpdatedAt`、`lastCopiedAt` 的语义。
- 外部重复复制、历史复制、复制纯文本、双击粘贴、自动粘贴部分成功时，哪些动作更新最近复制时间；`Cmd+数字` 已确认为不更新最近复制时间、不置顶。
- `loadRecent`、搜索排序、时间筛选、详情 metadata、保留策略使用哪个时间字段。
- 重复 payload 命中后必须合并既有条目并置顶，不能只返回 duplicate。

### 4.2 原始 payload 去重定义

“按原始 payload 去重”是已确认方向，但还不是可执行规格。

PRD 需要补清：

- 纯文本相同是否合并。
- 富文本同 plain text 但格式不同是否合并。
- URL 是否做大小写、尾斜杠、编码、fragment/query 归一。
- file URL 是否按真实文件路径、URL 字符串或书签/权限信息判等。
- PNG/TIFF、同视觉不同二进制、同图片不同格式是否合并。
- 旧记录缺 payload 时是否参与去重。
- 隐私策略排除内容是只保存 digest/stub，还是不入库。

### 4.3 自动粘贴状态机

单击、双击和快捷键粘贴都需要共同的状态机。

PRD 需要补清：

- “当前活跃输入框”指打开面板前的前台输入框，还是执行动作时的系统焦点输入框。
- 目标 App 变化、焦点丢失、secure input、非文本控件、不可编辑区域时如何处理。
- 无 Accessibility 权限时是否只复制并提示，是否打开系统设置，是否避免重复打扰。
- 写入系统剪贴板成功但粘贴失败时，是否更新最近复制时间。
- `Cmd+1..9` 触发的粘贴复用双击的写剪贴板、粘贴、权限降级和失败反馈状态机，但不复用置顶规则。

### 4.4 详情编辑与去重冲突

当前 PRD 要求上方详情卡内编辑，但未定义保存后的历史语义。

PRD 需要补清：

- 详情编辑是修改历史条目本体，还是编辑用户注释/派生展示内容。
- 保存后是否更新 payload、summary、revision、搜索索引和去重键。
- 编辑成另一条已有内容时，是合并、拒绝、保留两条，还是仅更新展示字段。
- 保存后是否更新最近复制时间。

### 4.5 验收阻塞规则

测试/质量子 agent 明确指出：阶段验收需要有阻塞规则。

PRD 需要补清：

- Phase 1 未真实证明捕获、去重、置顶、双击粘贴、快捷粘贴不重排时，不得进入“已完成”。
- Phase 2 若字符数仍作为卡片主内容，不得通过。
- Phase 3 若收藏仍埋在标签、标签筛选未平铺、右键菜单有内部 key，不得通过。
- Phase 4 若详情仍是独立窗口、保存状态不可见、三语缺失，不得通过。

## 6. P1 级待补充

- 卡片混合摘要矩阵：按文本、富文本、URL、file URL、图片、unknown、旧缺 payload、不可读 payload 定义标题区、主内容区、底部 metadata、禁止展示项。
- 旧历史条目降级规则：能恢复正文或类型摘要的旧记录必须恢复；只有真正不可恢复时才显示“内容不可预览”；禁止字符数作为主内容。
- 标签筛选溢出策略：标签很多时采用横向滚动、前 N 个加更多、还是换行，需要确认。
- 收藏筛选位置：用户已确认收藏和标签筛选放在同一平铺区域；收藏固定第一，使用独立星星图标；普通标签只使用颜色圆点。
- 右键菜单与详情编辑关系：若保留“编辑详情”，应定义为打开或聚焦上方详情卡并进入编辑态，不打开独立窗口。
- 状态反馈位置：复制成功、粘贴成功、已复制但未粘贴、保存成功、保存失败、未保存确认分别显示在何处。
- 本地化不应只放到最后阶段：Phase 2/3 菜单、筛选、状态文案也不能出现内部 key 或硬编码英文。
- OCR/provider 边界：005 阶段如涉及 OCR 状态，只允许本地、fixture 或 mock；任何远端 OCR、LLM、provider 外发必须另行确认。
- 日志、CLI、截图和录屏证据需要 allowlist：禁止 raw payload、完整 URL、完整 file URL、source path、OCR 文本、搜索命中片段、完整临时路径、provider 请求体进入证据。

## 7. P2 级待补充

- hover 安全区和延迟需要可验收参数和录屏脚本。
- normal、hover、selected、keyboard focus、selected+hover、selected+focus 需要状态矩阵。
- 卡片主内容至少保留几行、metadata 不得挤压正文、长标签如何截断，需要可截图标准。
- 空状态和错误状态截图应覆盖无历史、筛选无结果、payload 不可读、策略排除、仓库不可用。
- 可访问性至少覆盖 Tab/Shift-Tab、箭头移动卡片、右键菜单、详情编辑、状态播报。
- VoiceOver 默认不应朗读完整长 URL、长路径或 hash，除非用户显式查看完整值。

## 8. 建议补入 PRD 的结构

### 8.1 005A 信任链路

- 增加“术语修正”：文本默认纳入捕获范围，但仍受隐私策略和系统读取限制；“低敏”只限定验收样本和证据留存。
- 增加 `Cmd+1..9` 快捷粘贴需求、数字提示展示规则、失败降级规则，以及快捷粘贴不重排规则。
- 增加 `lastCopiedAt`、payload identity、duplicate merge transaction、auto-paste state machine、failure taxonomy。
- 增加去重正反样例表和失败状态矩阵。

### 8.2 005B 面板 UI 与交互

- 增加卡片展示矩阵和旧记录降级规则。
- 增加标签筛选溢出策略、收藏与标签同组规则、状态矩阵、hover 录屏脚本。
- 增加按住 `Cmd` 时前 9 条显示数字提示的视觉和布局规则。

### 8.3 005C 详情编辑与元数据

- 增加编辑保存语义、与去重/排序/搜索索引的关系。
- 增加保存/取消按钮固定操作栏规则，避免按钮出现或状态变化导致详情卡、编辑区、元数据或历史列表跳动。
- 明确右键“编辑详情”只打开或聚焦上方详情卡，不打开独立窗口。

### 8.4 005D 本地化与验收

- 增加 F1-F12 证据矩阵。
- 增加阶段阻塞规则。
- 增加三语截图矩阵、硬编码扫描、日志脱敏 allowlist、低敏证据模板。

## 9. 需要用户确认的问题

以下问题确实影响产品行为或实现边界，应由项目负责人统一向用户确认：

1. 双击或快捷键粘贴时，如果没有明确可粘贴输入框，或目标是 secure input、非文本控件、不可编辑区域，期望是“只复制并提示”，还是“阻止并提示失败”？
2. 双击或快捷键粘贴成功后，面板是关闭、保持打开并显示反馈，还是跟随现有设置？
3. 符合隐私策略的文本默认捕获；被 App capture policy、排除 App 或 secure input 等规则排除的来源，是显示 redacted 历史，还是只在诊断或空状态里提示？
4. 是否接受新增 `lastCopiedAt`，并在详情里同时显示“创建时间”和“最近复制时间”？
5. 重复外部复制、历史复制、复制纯文本、双击粘贴、自动粘贴部分成功，是否都更新最近复制时间？`Cmd+数字` 已确认为不更新。
6. 原始 payload 去重是否允许对 URL、file URL、富文本、图片做规范化？如果允许，规范化边界是什么？
7. 旧记录缺完整 payload 时，允许按现有 signature 合并，还是一律不参与 payload 去重？
8. 详情卡内编辑保存后，是修改原历史条目，还是生成新的历史条目或修订记录？
9. 现有“单击粘贴”模式是直接移除，还是仅默认关闭并隐藏在高级设置？
10. 标签很多时，平铺标签 chip 采用横向滚动、显示前 N 个加“更多”，还是允许换行？
11. 005 阶段 OCR 是否限定为本地、fixture 或 mock，明确禁止远端 OCR/provider 外发？
12. 截图、录屏、CLI 日志证据是否允许落入项目文档目录？若允许，应统一使用合成样本和路径脱敏。
13. source path、file URL、bundle identifier、payload id/hash 的完整值是否允许在 UI 中显式查看，还是默认部分遮挡。
14. VoiceOver/键盘可访问性是否作为 Phase 4 阻塞项，还是记录为明确残余风险。

## 10. 不必重复确认的既定项

- PRD 未确认前不进入实现。
- UI 相关实现必须在用户确认 UI PRD 后开始。
- 005 需要覆盖现有 F1-F12 和用户补充的信任链路需求。
- 文本默认纳入捕获范围；“低敏”只限定验收样本和证据留存，不限定真实功能捕获范围。
- 实施顺序为信任链路先于 UI 打磨。
- 单击只选中和预览；双击复制并粘贴。
- 历史条目复制、复制纯文本、双击粘贴、重复外部复制后，应更新最近复制时间并置顶；`Cmd+数字` 快捷粘贴不更新最近复制时间、不置顶、不改变前 9 条映射。
- 重复 payload 不新增重复历史，而是合并并置顶。
- 卡片展示采用混合智能摘要，历史条目也走同一展示规则。
- 收藏和标签筛选放在同一个平铺区域，位于筛选区最后；收藏固定第一，使用星星图标；普通标签只使用颜色圆点，直接点击筛选。
- 收藏独立于标签，在右键一级菜单展示，并位于标签操作上方。
- 中英日三语同步覆盖 005 相关面板、菜单、详情、隐私页、状态、错误和确认弹窗。
- 不使用用户真实隐私剪贴板内容作为验收样本，不调用真实外部 provider。
