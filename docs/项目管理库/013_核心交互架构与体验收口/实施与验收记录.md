## 实施结果

### 剪贴板边界

- 新增 `ClipboardHistoryReadPipeline`，历史加载、搜索、筛选候选、标签和预览快照在后台串行执行；请求携带 generation，旧结果不得覆盖当前面板。
- 查询先按当前可见数量读取，只有稀疏筛选确实需要时才逐级扩展，最终只加载可见记录的预览，不再为一次面板刷新无条件读取 1,000 条 payload。
- 新增 `ClipboardPanelSessionModel`，统一拥有查询、选择、分页、悬浮详情、异步任务和幂等取消；`ClipboardFloatingPanelView` 不再保存另一份并行会话状态。
- 新增 `ClipboardRecordActionPipeline`，面板复制/粘贴所需 payload 读取离开主线程；写 Pasteboard 前仍重新校验当前 session，防止迟到读取触发已取消动作。
- 搜索首页之外的可见记录现在同样可以收藏和删除；删除成功不再依赖首页数组数量发生变化来判断结果。
- 新增 `ClipboardOCRScheduler`，quiet window、重试、取消和结果提交由调度器单独拥有；`ClipboardStore` 只接收最终状态。
- `ClipboardStore` 保留为主线程状态门面和事务写入口；启动和面板刷新改走异步读取快照，旧同步整库重载只保留在需要原子写后立即回读的受控路径。

### 截图编辑器边界

- 新增 `ScreenshotRenderPipeline`，同一时刻只保留最新 revision 的场景渲染；过期任务取消且不能提交，渲染阶段使用不含图像内容的 signpost。
- 新增 `ScreenshotEditorAction`、`ScreenshotEditorChromeState`、`ScreenshotEditorInspectorState` 和 `ScreenshotEditorOutputState`，Presenter 仍使用稳定 Store 门面，Chrome、属性区和输出状态不再通过散落布尔值自行推导。
- Canvas 改为比较不可变 `ScreenshotCanvasSnapshot`；快照没有变化时不再无条件 `needsDisplay = true`。
- 文字输入、光标控制和 OCR 状态视图已经从巨型 Canvas/View 拆为独立文件；当前文档、手势和输出协调器继续作为唯一运行链路，没有保留第二套渲染器或输出分支。
- “更多工具”的鼠标焦点、键盘焦点和真实工具选中态已经分离；鼠标打开面板不会默认绘制键盘焦点，切换到快捷工具后“更多工具”不保持错误选中。

### 设置与全局 UI

- Blocks 品牌标题移出可选择的 Sidebar `List`，列表只包含真实路由；导航和外部跳转时选中路由自动滚入可见区域。
- Detail 继续使用独立、顶部锚定的系统 `ScrollView`，滚动条恢复系统自动显示。
- 设置分区标题移除额外水平内缩，与页面标题和内容表面共享左边缘。
- 剪贴板清理策略改为“按时间 / 按数量”标准分段控件，只显示当前模式对应的值；中英日 String Catalog 已同步。
