# 全局设计原则

## 产品性格

Blocks 的界面应当是：**原生利落、快而克制、稳定可预期**。“爽感”来自直接、准确、连续和可恢复，不来自夸张动画或高饱和装饰。

## 十条原则

1. **任务优先**：一个界面只应有一个当前主任务。次要信息通过详情、菜单或渐进展示提供。
2. **稳定几何**：加载、错误、成功和动态按钮不得挤压输入区、标题、工具或用户滚动位置。
3. **即时反馈**：点击、选择、切换和提交在 100ms 内给出可见反馈；耗时工作随后更新结果。
4. **直接操作跟手**：拖动、裁剪、缩放、绘制和手柄命中都不使用补间动画。
5. **角色一致，不强行等尺寸**：设置表单、浮层 Chrome、稠密工具条和画布控件应共享状态规则，但使用适合自身任务的密度。
6. **原生优先**：优先使用 macOS 导航、焦点、菜单、表单、材质、拖放和窗口行为；自定义仅用于产品任务确有差异的地方。
7. **动效解释变化**：动效只表达来源、去向、层级、完成或恢复，不是界面装饰。
8. **可恢复、可理解**：危险操作必须确认；失败必须说明真实原因、影响和可行下一步。
9. **主题与无障碍同源**：浅深色、失活窗口、提高对比度、降低透明度和减少动态效果不是特殊补丁，而是同一语义系统的输出。
10. **性能属于体验**：过期异步结果不得提交，动画不得遮盖主线程卡顿，可见反馈 p95 目标不超过 33ms。

## 决策顺序

新 UI 需求或冲突按以下顺序处理：

1. 业务任务和用户成功条件。
2. 平台原生交互和无障碍约束。
3. 稳定几何与直接操作。
4. 全局组件和 Token。
5. 功能模块的局部优化。

功能模块不能为了局部视觉效果绕过全局状态、主题、焦点或减少动态效果规则。
