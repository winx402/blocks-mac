## 2026-08-03 路由、刷新边界与历史页面分层返修

### 现场与代码根因

- 插件目录进入详情时使用 `.id(route.token)` 强制重建整个详情树；返回时再通过 `Task.yield + scrollTo` 尝试找回位置。这会同时丢弃局部焦点、临时视图状态和已建立的布局缓存。
- 页面根结点直接观察整个 `BlocksPluginRuntimeCoordinator`，任意插件运行时 UI Patch 都可以使目录、搜索、筛选和无关详情重新求值。
- 插件页的路由、目录策略、运行状态行、详情头和页面编排集中在同一个超大文件；AI 服务又单独使用 `SceneStorage Bool` 管理详情，与设置壳层已有的二级路由不同源。
- AI 能力使用模块私有的标签流和状态文字，本地自动化则在三行内重复展示同一段数据访问说明，导致信息层级和行高节奏不稳定。

### 单轨实施

- `SettingsRouteStateStore` 成为插件与 AI 服务的唯一二级路由所有者；目录、详情和其他设置模块的路由状态互不覆盖。
- 删除插件详情强制身份重建；路由变化只做有作用域的 140ms 透明度过渡，不改变页面几何。
- 插件运行协调器的观察范围下沉到安全模式行、最近运行行和单个 UI Contribution；页面根不再因无关插件状态反复重画。
- 安装、刷新和单插件操作使用带作用域的运行状态；发起操作的行就地显示进度，搜索、筛选、返回和阅读不被全页锁死。
- 插件页拆出 `PluginCenterSettingsComponents.swift`，路由、策略和局部组件与页面编排分层；不增加第二套业务 Store。
- AI 能力列表改用共享状态行，可用／未配置／计划中使用稳定状态槽；本地自动化只在分区首行说明一次数据边界，Broker 和 CLI 状态不再推动后续行。
