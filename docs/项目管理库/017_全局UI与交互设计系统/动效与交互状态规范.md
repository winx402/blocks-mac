# 动效与交互状态规范

## 交互状态

`BlocksInteractionState` 是状态语义源：

- `idle`：可读、不制造额外噪声。
- `hovered`：轻度表面反馈，不改变几何。
- `pressed`：在 80ms 内显示已接收输入。
- `focused`：键盘焦点必须可见，但焦点环不得溢出控件。
- `selected`：表达持久选择，与 hover 分离。
- `disabled`：不可操作但仍可读。
- `loading`：可取消时必须提供取消，不锁死无关区域。
- `success/warning/error`：图标与文字共同表达，不只依赖颜色。

## 动效角色

| 角色 | 时长 | 用途 |
|---|---:|---|
| press | 80ms | 按压接收反馈 |
| hoverFocus | 100ms | 悬浮、焦点 |
| selection | 140ms | 选中、切换 |
| reveal / reflow | 180ms | 内容展开、层级变化 |
| navigation / panel | 220ms | 导航和浮层出入 |
| confirmation | 160ms 入场 / 120ms 退场 | 成功确认 |
| directManipulation | 0ms | 拖动、绘制、缩放、裁剪 |

`microFeedback` 和 `stateChange` 是 Phase 0 的源码兼容角色。后续模块应在真实验收中将其替换为更精确的角色，不得新增自定义时长。

## 减少动态效果

- `directManipulation` 立即切换。
- 其他角色最多使用 100ms 透明度变化。
- 不允许位移、缩放、弹性和玻璃形变。
- 不得在功能代码中写死 `reduceMotion: false`。

## 稳定几何

- 按钮状态切换应复用固定槽位，不推动相邻操作。
- 进度、错误和成功反馈放入预留区域、浮层通知或原位状态，不插入稳定内容之间。
- 列表重排立即提交，不对排序数据使用缓慢补间。
- 动态内容对焦点、滚动位置和窗口大小不得产生隐式副作用。

## 任务所有权

- 每个动效必须由唯一可观察状态触发。
- 新 revision 使旧任务失效，旧任务不得提交 UI 状态。
- 页面离开、窗口关闭和组件替换时，动画、计时器和延迟反馈都必须取消。
