# Phase 3 剪贴板 UI 与交互升级记录

## 范围

本阶段只收口剪贴板面板的视觉层级、直接操作、焦点反馈、稳定几何、动效边界、重绘开销和历史 UI 路径。复制、捕获、排序、自动粘贴和数据持久化语义保持不变。

## 已实施

- 文本、文件、图片和隐私卡片改用语义前景色；只有覆盖在真实图片上的元数据保留白色，浅色、深色和失活窗口不再共用固定白字。
- 卡片收藏、面板设置、固定、清除筛选和详情编辑动作统一使用全局紧凑操作组件；删除剪贴板私有图标按钮尺寸、间距和选中样式。
- 搜索、格式／时间／来源筛选、标签和收藏使用同一控件圆角与语义边界；删除固定白色描边。
- 暂停录制状态改为工具栏固定槽位，状态变化只切换图标，不再插入一整行并推移记录区。
- 左侧、右侧紧凑面板重新计算搜索、筛选、状态和尾部操作的占用宽度；设置和固定按钮在最窄侧栏下不再裁切。

- 条目详情改为单一展示身份状态。记录、字号、内容 revision 和目标 frame 均未变化时不重建窗口、不替换根视图、不重播动画。
- 条目行负责主面板的悬浮视觉状态；本地事件监听器仅处理独立详情面板之外的点击，避免同一指针事件进入两条更新链路。
- 卡片 hover、选择、筛选和详情出现只使用有作用域的短反馈；滚动、宽度调整和记录跟随保持直接操作零补间。
- 删除未使用的侧栏筛选条、重复的菜单筛选条和无效的展开状态分支，避免继续维护不可达 UI 路径。

## 2026-08-03 详情图片解码单轨收口

### 真实问题与根因

- 详情预览虽然已在 `ClipboardRecordActionPipeline` 的后台队列读取并生成缩略图，但历史接口仍把已解码的 `CGImage` 再编码为 PNG 数据。
- `ClipboardFloatingDetailCard` 收到数据后在 `MainActor` 使用 `NSImage(data:)` 再解码一次。快速切换图片条目时，同一缩略图经历“后台解码 → PNG 编码 → 主线程解码”，增加首次详情反馈延迟和主线程卡顿风险。

### 修复与验证

- 详情专用流水线直接返回后台 ImageIO 生成的 `CGImage`；SwiftUI 只负责发布和绘制，不再在主线程解析图片数据。
- 列表缩略图仍保留现有 PNG 缓存接口，两种用途不再互相借用错误的数据形态。
- 新增 2048×1024 合成图片回归，验证详情流水线直接返回不超过 720px 的已解码缩略图并保持宽高比；定向测试通过。

## 2026-08-03 首轮面板负尺寸根因返修

### 证据修正

- 最新安装版冷启动后的第一次剪贴板面板创建会稳定产生 3 组 `Invalid view geometry: width/height is negative`；同一进程再次打开不再出现。该证据推翻了上文早期安装版“未出现负尺寸几何”的过早结论。

- 新增窗口样式契约，禁止剪贴板自定义 Chrome重新带回系统标题栏；与详情图片单轨测试共 2 项执行、0 失败。

## 2026-08-02 详情响应与编辑几何返修

### 真实问题与根因

- 条目按下会立即选择，但详情动作默认等待完整的 `NSEvent.doubleClickInterval`；本机实际值为 500ms。用户已得到选择反馈，却要再等待半秒才看到详情，因此首击容易被理解为无响应。
- 普通文本详情被两层相同的 `contentEditContainer` 包裹，形成重复点击编辑入口；加载编辑快照或保存时，编辑／保存按钮又直接消失，没有稳定的在途反馈槽。
- 详情输入框与元数据块仍维护模块私有背景和描边，和全局交互状态的焦点、主题与提高对比度语义形成双轨。

### 修复口径

- 选择反馈继续立即发生；详情解析等待收敛为 140ms，避免在常规单击上等待完整 500ms。双击到达时仍取消待打开详情并只派发一次粘贴；迟到选择抑制延长到 200ms，覆盖 SwiftUI 按钮与双击手势的调度抖动。
- 删除普通文本详情外层重复编辑容器。编辑快照加载、保存与校验反馈都使用固定操作槽位：按钮位置不变，只切换进度、可用状态和行内错误。
- 输入框和元数据表面迁入 `BlocksSurfaceRole.interactive` 与 `BlocksInteractionState`；详情模块不再自行绘制焦点背景和描边。

- `dismissDetail` 现在只在当前焦点仍属于 `detailRead/detailEdit` 时恢复返回目标。若用户已经进入搜索、筛选、记录或 inactive 状态，迟到回调只清理详情返回状态，不再发出新焦点请求。
- 新增回归测试，明确验证用户进入筛选后重复到达的详情关闭回调不能改变 target 或 generation。
- 删除不可达的 `ClipboardDetailEditorView` 及 Xcode 工程引用；当前详情 UI 只保留 `ClipboardFloatingDetailCard` 单一路径。
- 保留仍被新面板 Header 使用的 `ClipboardFilterClickGroup`；本轮编译曾及时发现误删并恢复，避免把活跃组件错误归为历史包袱。

## 2026-08-03 筛选层级、动效所有权与历史门禁收口

### 真实问题与根因

- 安装版 AX 审计确认格式、时间、来源三个筛选把名称同时写入 label 与 help，VoiceOver 会读成“格式、格式”；展开后，容器的调试 identifier 又被 SwiftUI 继承到每个选项，导致多个可交互元素拥有相同身份。
- 展开筛选的可视转场已经由 `ClipboardFilterClickGroup` 持有，但父页面仍以 `withAnimation` 修改相同状态，同一次点击存在两个动效所有者。它不会稳定复现功能错误，却会造成时序和 Reduce Motion 契约难以判断。
- 筛选主项使用 bold、展开选项仅 10pt；在真实底部面板中层级过重与过弱同时存在，和“原生利落、快而克制”的密度不一致。
