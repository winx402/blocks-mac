# Step 2 PRD：截图历史与本地 OCR

状态：approved-for-implementation
最后审阅：2026-07-12
来源级别：confirmed product requirements

## 1. 目标

- 让用户可选择把完成后的截图保存到现有剪贴板历史，并通过固定系统标签筛选。
- 使用 Apple Vision 提供本地截图 OCR、搜索、重新识别和编辑器临时区域识别。
- GUI、CLI 和 Action 共用同一历史、OCR、搜索与导出契约，不复制业务逻辑。
- 保持隐私优先：默认不保存截图历史、默认不自动 OCR，不调用云端 Provider。

## 2. 范围与非目标

本阶段包含：截图历史开关、自动 OCR 开关、系统截图标签、原子历史提交、重复图片合并、OCR 搜索与重试、编辑器区域 OCR、CLI 查询和导出。

本阶段不包含：长截图、AI 理解或外发、云同步、上传分享、录屏、工程文件持久化和 OCR 强制覆盖用户修正。

## 3. 截图历史

- “保存截图历史”默认关闭。关闭时不得创建临时、隐藏或待清理记录，也不回填或删除已有截图记录。
- 交互截图只在编辑器产生 `.completed` 终态后提交历史；取消、丢弃、重截和关闭不创建记录。
- CLI `--no-editor` 成功捕获即视为完成终态；交互式 CLI 等待编辑器完成。两者都服从 GUI 的历史开关。
- 最终剪贴板写入与历史写入独立执行。单边失败显示对应弱提示；双边都失败仍关闭编辑器并显示明确失败状态。
- “最终渲染成功”是两个 sink 的唯一输入；不得把 pasteboard 成功当作编辑器完成前置条件，也不得把进入编辑器前的原图复制当作最终历史内容。
- 历史提交失败不得留下数据库半记录、孤立 payload 文件或错误 FTS 文档。
- 截图自身写入 pasteboard 必须登记 changeCount 抑制，避免监听器再次捕获。

## 4. 重复图片合并

- 最终图片按解码后的视觉签名去重；原始 PNG 字节另存独立摘要用于 sidecar 完整性校验，避免把编码 metadata 差异误当成不同截图。
- 发现重复时保留当前截图 ID，删除旧重复记录。
- 从旧记录合并收藏、普通用户标签、自定义标题和 `userEdited` OCR；机器/Vision OCR 不合并。
- 用户编辑 OCR 优先级最高，合并后不得进入自动 OCR 队列。
- 合并和删除必须与当前截图 payload、系统标签、搜索文档及 FTS 更新处于同一 repository 事务边界。

## 5. 系统截图标签

- 新增内建 `screenshot` 标签，显示为橙色相机图标。
- 初始位于收藏后的第一个普通标签位置；用户可在普通标签区拖动排序，排序跨面板布局和设置页持久化。
- 标签不可删除、重命名、改色或合并；用户不能手动为普通图片添加，也不能从截图记录移除。
- 若升级前已有同名普通标签，自动改为本地化的“截图（自定义）”并保留全部关联。
- 标签成员关系以 `ClipboardRecorderRecord.origin == .screenshot` 自动派生，不再依赖“为未来截图添加标签”偏好或新截图时物化关联。
- 关闭截图标签只隐藏筛选入口，不删除截图来源、记录或已有普通标签；重新开启后所有历史截图立即恢复可见，不执行回填任务。
- 剪贴板面板不在截图标签旁放置设置齿轮；剪贴板设置页的“截图”标签行提供“截图设置 →”链接。

## 5.1 排序与刷新契约（v19 返修）

- 数据库、内存 Store、搜索结果、快速粘贴和截图历史统一使用 `lastCopiedAt → createdAt → changeCount → recordID` 的降序稳定键。
- 外部复制、重复内容再次复制、面板粘贴、截图完成与钉图归档后，Repository、Store 和当前筛选/搜索结果同步刷新；最新且符合当前条件的记录必须位于第一条。
- 排序诊断只记录阶段、类型、changeCount 和时间，不记录正文、图片、文件路径或完整记录 ID。

## 6. 自动 OCR 与搜索

- “自动识别截图文字”默认关闭，只在“保存截图历史”开启时可操作；历史关闭后保留其值但禁用控件。
- 开启只影响未来完成的截图，不回填旧记录。
- 开关变化不取消已经提交为 `.pending` 的记录；已入队任务继续，结果仍受 payload revision 和用户编辑锁校验。
- 开启时历史记录以 OCR `.pending` 提交；关闭时明确写入 `.notRequired`，通用 OCR drain 不得误处理。
- OCR 完成后更新 OCR 状态、搜索文档和 FTS；失败保留可重试状态。
- 中英日、方向、阅读顺序、revision guard 和用户编辑锁复用共享本地 Vision 服务。

## 7. 编辑器区域 OCR

- OCR 是可配置工具栏命令，默认位于扩展区，可拖到快捷区或隐藏工具库；它不是可持久化画布元素。
- 用户必须拖动选择区域；识别输入是当前裁剪和已提交标注合成后的可见最终效果。
- 识别期间锁定整个编辑器，支持 Esc 和取消按钮；30 秒超时后解锁并显示重试/关闭。
- 结果通过 scene render revision 校验，迟到或过期结果必须丢弃。
- 取消、超时和完成采用 request token 的 first-terminal-wins；任一终态先发生后立即使其他回调失效。
- 成功后立即清除选择框，在约 `360×260pt` 的工具旁浮层展示可编辑文本，提供复制和关闭，不自动复制。
- 手动 OCR 结果不自动写入历史、搜索或日志；用户显式点击“复制”后作为普通文本写入系统剪贴板，不登记截图自写入抑制，可按现有剪贴板策略被捕获为普通文本历史。
- 后续像素 revision 变化立即清除结果；非像素 UI 变化不清除。失败或超时保留选区用于重试，取消清除选区并返回空闲态。

## 8. CLI 与 Action

- 提供截图历史分页查询、搜索、OCR 状态、OCR 重新识别和图片导出。
- 查询 cursor 不透明，默认 24 条、最大 100 条；默认只返回受限 OCR 摘要，完整 OCR 需 `--include-ocr`。
- OCR 重新识别异步入队并返回 `pending + recordID + revision`；用户编辑锁返回 `ocr_locked`，不提供 force。
- 图片不能通过 stdout 或 Base64 返回。导出只写显式文件，使用 FileHandle 和 `0600` 权限。
- 导出拒绝符号链接和未显式允许的覆盖；失败仅清理由本次命令创建的不完整文件。
- PNG 默认保留精确图片；JPEG 显式选择时使用 90% 质量和白色透明背景。
- 日志不得记录图片、OCR 正文、自定义标题或完整输出路径。

## 9. 验收

- 历史关闭、历史开启且 OCR 关闭、历史与 OCR 同时开启三条真实路径行为明确且无重复记录。
- 完成、取消、丢弃、重截、单边失败和双边失败均有可重复证据。
- 重复图片合并保留用户数据、当前 ID 和用户 OCR 锁。
- 系统标签在底部、左侧栏、右侧栏和设置页表现一致。
- 中英日 OCR 可搜索、可重试；编辑器区域 OCR 支持取消、超时和 revision 失效。
- CLI 查询、重识别和 PNG/JPEG 导出与 GUI 数据一致。
