## 2. 已关闭的 Step 2 阻断

1. Broker target 已增加独立 sandbox entitlement，并完成 App bundle 位置、签名和嵌入产物验证。
2. 截图系统标签已从普通标签切换菜单移除；卡片、筛选和设置统一使用系统标签权限与本地化相机语义。
3. history query/search、OCR status/retry 和 export 统一经过截图记录资格校验，普通剪贴板图片会被拒绝。
4. CLI 导出改为同目录 `0600` 临时文件加原子替换；失败清理临时文件，不破坏既有目标，符号链接和非普通文件继续拒绝。
5. sidecar 启动恢复与 orphan cleanup 合并为串行恢复事务；恢复失败时停止 cleanup 并保留 staging。
6. 手动 OCR 使用 request token 和 first-terminal-wins；超时立即解锁，取消不协作任务，迟到结果不能覆盖当前状态。
7. OCR retry 使用原子状态转换，运行中的请求返回结构化 `already_running`，不会伪装成重新排队。
8. sidecar 提交、启动恢复和 orphan cleanup 改为按 blob 目录共享的进程内串行化；两个 `ClipboardRepository` 实例不再能在活动提交期间删除 staging。
9. Broker 状态解析先校验安装 bundle 内 LaunchAgent plist、Mach service 和可执行文件；只有产物确实缺失时才显示不可用。
10. Broker 可执行文件生成并绑定独立 Info.plist，解决 sandbox 初始化阶段缺少 bundle identity 导致的启动崩溃。
11. DEBUG CLI 身份校验改用进程真实路径，并限定同 UID 和项目构建产物；Release 仍按 Team ID 与 designated requirement fail closed。
12. Broker 优先启动其所在 App bundle，避免同 bundle ID 多副本导致冷启动错误版本；host 注册增加 PID 存活校验，清除 App 重启时的陈旧 endpoint 竞态。
13. 截图剪贴板写入移除无效的 `NSFilenamesPboardType`，保留 PNG、TIFF 和现代 file URL 类型，避免 pasteboard 拒绝无效 UTI。
14. 真实清理验收发现永久删除动作错误显示为“隐藏摘要”；已将代码、动作字段和中英日 key 统一改为明确的“删除历史记录”，并禁止旧 `clipboard.removeSummary` key 回归。
