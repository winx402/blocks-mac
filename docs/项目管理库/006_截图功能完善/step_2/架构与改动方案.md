# Step 2 架构与改动方案

状态：implemented
最后审阅：2026-07-14
来源级别：implementation architecture

## 1. 模块边界

- `BlocksCore`：数据库 v9 引入系统截图标签，数据库 v10 分离视觉去重签名与原始 PNG sidecar 摘要；同时承载截图历史原子事务、分页查询、OCR/search 状态和导出读取接口。
- `BlocksScreenshotCore`：工具栏 item 标识、OCR 区域几何和 scene revision 契约；禁止依赖 Vision、AppKit、数据库和 pasteboard。
- `BlocksApp/Features/Screenshot`：`ScreenshotHistoryCoordinator`、完成终态编排、设置、编辑器 OCR UI 和输出弱提示。
- App 共享服务：`LocalVisionOCRService` 封装 Vision；剪贴板后台 OCR 与编辑器手动 OCR 共用，不保留两套识别器。
- `BlocksActionBroker` / CLI：只传输结构化查询、状态、重试和 FileHandle 导出请求，不实现数据库或 OCR。

## 2. 数据库与原子提交

- 数据库 schema v9 新增 `ClipboardTagBuiltInKind.screenshot` 的唯一内建定义；v10 为 `clipboard_payloads` 增加 `visual_signature_sha256` 与 `png_payload_sha256`，视觉去重和 sidecar 完整性不再复用同一摘要。
- 迁移检测与系统标签本地化名称冲突的普通标签，改为“系统名（自定义）”，保留 ID 和关联。
- 创建系统标签时只设置初始普通排序位置；后续启动不得重置用户排序。
- `commitScreenshotHistory(request:)` 在事务外校验原始 PNG、一次解码计算视觉签名、计算原始 payload 摘要并准备临时 sidecar；事务内读取重复记录用户数据、删除旧重复项、插入当前 ID、payload metadata、系统标签关系、合并标签/收藏/标题、OCR/search/FTS。禁止 Base64 往返和整图二次 PNG 编码。
- 跨 SQLite 和 sidecar 的保证定义为“SQLite 原子 + 文件系统可恢复”，不宣称跨介质强原子。repository 使用 staging 文件和启动恢复协议处理事务前后中断、提升失败及旧文件提交后删除。
- `signature_sha256` 的全局唯一约束保留，不增加绕过或兼容分支。
- 测试故障注入点固定为临时 payload 写入、重复记录删除前、SQLite commit 前后、sidecar 提升、旧 sidecar 删除和 FTS 更新；每个失败点都断言数据库一致且 staging/orphan 可由恢复流程清理。

## 3. 完成链路

- 编辑器先产生不可变 `FinalizedScreenshot`，包含 capture ID、最终 render revision、规范化图片和输出 metadata；这是两个 sink 的唯一输入。
- `ScreenshotHistoryCoordinator` 只订阅最终渲染终态；同一 capture ID 最多提交一次，取消、丢弃和重截不提交。
- 输出协调器分别执行 pasteboard 和 history sink，并汇总 `.succeeded/.failed/.notRequested`；pasteboard 不再控制 `onComplete`，两者均失败也产生终态并关闭编辑器。
- 交互式 CLI 复用相同完成终态；无编辑 CLI 在捕获输出生成后调用同一 history sink。
- 历史 sink 不依赖 `ClipboardStore` 的当前分页或 UI 状态，直接依赖 repository。

## 4. OCR 架构

- `LocalVisionOCRService` 输入不可变 CGImage、方向、语言配置和 request token，输出按阅读顺序规范化的文本块；取消是协作式取消与结果废弃，并限制并发，不能假设同步 Vision perform 会立即停止。
- 历史自动 OCR 继续由队列驱动，同时校验 capture identity revision 与 content revision；`.notRequired` 永不进入 drain。
- 合并用户 OCR 时复制正文和来源，但把锁重新绑定到当前记录的新 content revision，不复制旧机器 OCR revision。
- 编辑器手动 OCR 先从最新 scene render cache 裁剪选区，创建 `(sceneRevision, requestID)` 请求；结果只有在两者仍匹配时发布。
- 编辑器 OCR 取消、超时和像素 revision 更新都会取消任务并清空临时结果。
- 手动 OCR 协调器以 request ID 实现 first-terminal-wins；重试创建新 request ID，旧任务回调无权发布状态。

## 5. 工具、对象编辑与偏好

- `ScreenshotToolbarItemID` 同时表达标注工具、专业 A 工具包和 `.ocr` 命令；OCR 默认在扩展工具区。
- 元素样式使用类型化 `ScreenshotElementAppearance`，工具默认值使用 `ScreenshotToolPreset`，公共属性与 line/shape/text/effect/counter/callout/spotlight/redact/magnifier 专属属性分离。
- `ScreenshotPreferences` 升级至 v10，包含历史、自动 OCR、统一工具顺序、快捷/隐藏集合和 typed preset。v9 仅执行一次映射，迁移后运行时不保留旧样式分支。
- 创建工具和临时对象选择是独立状态。创建工具保持 armed，但对象命中优先；Option 强制创建，Command 循环重叠对象，Crop/OCR 为独占状态。
- 编辑对象并提交样式后，同步更新对应工具 preset；文字正文、气泡正文和计数器当前编号不进入 preset。

## 6. Action / CLI

- Action registry 增加下表中的 handler；Screenshot host 改为按 action ID 路由的通用 host，不再假设只存在 capture action。
- cursor 使用带版本和查询摘要的 keyset，排序键固定为 `(lastCopiedAt, createdAt, changeCount, recordID)`；query 不匹配或解码失败返回 `invalid_cursor`，CLI 不读取数据库 offset。

- OCR retry 只入队，终态由后续 query 返回；`userEdited` 直接返回结构化 `ocr_locked`。
- 导出通过 XPC FileHandle 写入调用方已创建的 `0600` 文件；失败清理不完整文件。

| Action ID | Input | Result | 主要错误 |
| --- | --- | --- | --- |
| `blocks.screenshot.capture` | 现有 capture input | 增加 pasteboard/history/output 三个 sink status 和最终 capture ID | 现有 capture 错误、`history_write_failed` |
| `blocks.screenshot.history.query` | `cursor?`, `limit=24`, `includeOCR=false` | `items`, `nextCursor` | `invalid_cursor`, `invalid_limit` |
| `blocks.screenshot.history.search` | `query`, `cursor?`, `limit=24`, `includeOCR=false` | `items`, `nextCursor` | `invalid_query`, `invalid_cursor` |
| `blocks.screenshot.ocr.status` | `recordIDs` | 每条记录的 OCR state、capture identity revision、content revision | `record_not_found` |
| `blocks.screenshot.ocr.retry` | `recordID` | `pending`, record ID、capture identity revision、content revision | `ocr_locked`, `record_not_found`, `not_image` |
| `blocks.screenshot.history.export` | `recordID`, `format=png|jpeg`；FileHandle 带外传递 | bytes written、format | `record_not_found`, `invalid_format`, `export_failed` |

- history item 固定返回 record ID、创建/最近复制时间、像素尺寸、收藏、标签、标题、OCR state、content revision 和受限 OCR 摘要；只有 `includeOCR=true` 返回完整 OCR。
- `AppModel` 只创建一个 ClipboardRepository，并显式注入 ClipboardStore、ScreenshotHistoryCoordinator、Action handler 和共享 OCR 服务；禁止由 Screenshot feature 再打开数据库。

## 6.1 v19 截图标签与剪贴板排序返修

- `ClipboardTagRepository.loadRecordTags` 在截图标签启用时，对当前记录集中 `origin_kind = screenshot` 的记录派生系统标签；关闭标签只切换 `is_enabled`，不删除记录或关联。`attachScreenshotTag` 仅作为旧数据兼容/专项测试辅助，截图完成运行链路不再调用。
- `ClipboardRecordOrdering` 是内存唯一比较器；Repository 的 recent/search/action/history SQL 使用同样的四级降序键。截图归档通过 `onCommitted` 及时重载 Store、标签快照和当前搜索结果。
- 低敏诊断使用 `OSLog`，只写入 `stage/kind/changeCount/createdAt/lastCopiedAt`，不保留剪贴板正文、图片或文件路径。
