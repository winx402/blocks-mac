## 3. 调研结论

### 3.1 已核验事实

- macOS 原生截图通过统一控制层提供屏幕、窗口、区域和录制入口，并使用键盘完成高频操作。
- 成熟截图工具普遍提供区域调整、窗口选择、精确尺寸、放大辅助、标注、复制和导出；专业工具还提供快捷键和自动化入口。
- Apple 的设计指导强调材质应表达层级和功能，不应仅作为装饰；颜色需要适应系统外观和用户 accent；SF Symbols 应保持一致的视觉重量与可访问性。
- 外部工具的公开资料并不能证明其内部状态机、候选排序或跨屏像素实现，因此这些实现细节不能作为项目事实引用。

### 3.2 项目推断

- 截图开始前要求用户选择区域、窗口或屏幕，会把机器可推断的意图转移给用户；但完全自动判断又会在窗口层级和拖拽边界上产生误判。
- “窗口 hover + 单击捕获，拖拽接管区域，按键进入屏幕”能够保留立即操作，同时给专业用户明确的控制通道。
- 编辑器中的常见标注需要原位快速完成，精细属性又需要稳定窗口；因此快速浮层/完整编辑器应是可无损切换的工作流，而不是同一窗口的两套布局皮肤。
- 设置页、剪贴板和截图目前承担不同密度的任务，不应强制使用同一种表面；统一 token 和交互状态比统一成同一种玻璃外观更重要。

### 3.3 最终产品决策

- 采用混合统一入口，不采用开始前显式三选一，也不采用无控制的完全自动模式。
- GUI 只公开智能截图；CLI/Action 保留显式模式以支持无编辑和自动化。
- 具备冻结源上下文时默认快速浮层，需要精细编辑时进入完整编辑器；两者共用 Store/scene、工具主顺序和样式，仅显隐集合独立。
- 采用“功能层玻璃”：玻璃只用于工具条、导航和短时功能层，画布与设置内容使用稳定 surface。
- Phase 1 隐藏 OCR、翻译和总结入口，避免用不可执行入口干扰基础闭环。

## 4. 当前 App 设计审计

### 4.1 观察样本

- [当前剪贴板设置截图](../assets/design-audit/01-current-clipboard-settings.jpg)
- [当前截图页面截图](../assets/design-audit/02-current-screenshot-page.jpg)

### 4.2 事实

- 设置页使用侧边导航和安静的分组内容，信息密度适中，适合作为截图设置页的结构基线。
- 剪贴板面板使用紧凑工具区、类型色卡片和浮层反馈，适合作为高频操作密度和状态反馈的参考。
- 当前截图首页仍包含内部阶段文案、三个模式按钮和会话级最近结果，入口模型与智能截图决策冲突。
- 审计时截图结果仍是固定预览窗口，不具备快速浮层、完整编辑器、稳定属性区或工具配置。

### 4.3 设计问题

- 页面之间缺少统一的字体、间距、圆角和状态色 token，视觉一致性依赖局部常量。
- 截图模块色、系统 accent 和状态色职责未完全分开。
- 如果直接把剪贴板玻璃表面复制到编辑器，容易形成多层材质并降低截图内容可辨性。
- 如果直接沿用设置页的静态分组，无法满足编辑器高频工具、画布和检查器的空间关系。

### 4.4 收敛方案

- 全 App 先定义字体、间距、圆角、颜色和图标 token，Phase 1 只在截图及直接复用组件落地。
- 截图首页和设置沿用安静分组；选择层与编辑器只在功能控件层使用单层材质。
- 所有主操作和焦点使用系统 accent；截图橙只作为模块身份。
- 快速浮层和完整编辑器共享 scene、Store、renderer 和事务，不维护两套编辑逻辑。

## 5. 审计时代码边界

2026-07-11 审计时只读扫描得到以下事实；这些是历史基线，不代表 2026-07-12 当前工作树：

- 区域和窗口选择由不同 controller 承担，区域 mouseUp 后直接完成。
- 捕获服务当前不支持跨显示器区域。
- 结果 presenter 使用固定尺寸预览窗。
- 截图首页展示三模式按钮、P3-B 文案和会话级最近结果。
- 当前快捷键模型使用 `screenshotRegion`，CLI 默认区域模式。
- 当时截图门禁仍断言旧页面和旧结果视图；2026-07-12 P14-C/P14-D 已更新为双模式 breaking replacement 静态契约。
