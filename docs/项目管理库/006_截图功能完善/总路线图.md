# 006 截图功能完善总路线图

状态：phase-3-implementation-in-progress
最后审阅：2026-07-15
来源级别：project roadmap

## 1. 推进原则

- 每个阶段先补齐并确认 PRD；涉及可见界面的阶段必须同时确认 UI/UED。
- GUI、CLI 和 Action 共用捕获、文档、渲染、导出等核心能力。
- 每阶段必须有自动化验证和真实截图/录屏；静态门禁不能单独作为体验通过依据。
- 用户可见流程、权限或隐私边界未确认时，不提前开发远期能力。

## 3. Phase 1 子阶段

### 1A：采集与选区

- 用窗口 hover 单击、区域拖拽和 `F` 屏幕模式组成统一智能选择状态机。
- 建立虚拟桌面坐标模型和按显示器切片捕获。
- 支持跨屏区域、指定屏幕和全部屏幕物理布局合成。
- 区域手势固定为“按下并拖拽后，鼠标松开即完成”；比例、固定像素和吸附在拖动过程中实时生效，不进入二次调整确认态。
- 完成混合 DPI、负坐标、菜单栏/Dock、窗口阴影和指针能力验证。

### 1B：编辑文档与渲染

- 建立冻结源上下文、scene snapshot、交互 draft、revision 和当前渲染结果组成的 `ScreenshotSceneDocument`。
- 建立统一 Core Graphics/Core Image 渲染管线。
- 支持画布缩放、裁剪、标注、模糊/像素化、撤销/重做。
- 使用单一原屏编辑器、稳定属性栏和扩展工具 Popover；Store、scene、对象选择、撤销栈和类型化工具 preset 只有一套。
- SwiftUI/AppKit 仅负责交互、窗口和画布呈现，不复制图像处理逻辑。

### 1C：输出、设置与 CLI

- 选区确认及进入编辑器前不写剪贴板；显式复制写当前结果，完成写最终图并关闭，保存只写文件。
- 支持 PNG/JPEG、另存为、重截、关闭/新截图脏状态保护。
- 新增截图设置页和快捷键配置。
- 扩展 `blocks.screenshot.capture` 参数，并通过本地 Action bridge 协调交互式 App 会话。

## 4. Phase 3 已锁定边界

- 模式必须显式可见；单个会话只捕获一个显示器内的固定区域，只处理向下纵向滚动。
- 屏幕录制与 Input Monitoring 都是 Start 前硬门禁；不通过 Accessibility 或输入注入自动滚动。
- 可恢复错误进入 paused 并只允许进程内 Resume/Cancel；失败不输出部分长图，App 崩溃后不恢复会话。
- 高置信到底候选使用固定 3 秒倒计时；有效新增内容会撤销倒计时。
- 固定头部只在高置信时去重，不确定时保留重复，不能误删正文。
- 有效上限达到 90% 时预警；绝对边界不高于 `32768 px` 边长和 `120 MP` 总像素，原型可设更低生产上限。
- 拼接图进入统一编辑器后，只有完成或保存成功才提交 clipboard/history/OCR；取消完全无输出。
- CLI 只控制 GUI 已启动会话的 status/finish/cancel，不启动、恢复、选择区域或跳过编辑器。

## 5. 跨阶段架构约束

- `ScreenshotSceneDocument` 保存冻结源上下文、scene snapshot、交互 draft、revision 和派生渲染结果；完成后只输出扁平图。
- 捕获、选区、编辑状态、渲染、导出、剪贴板桥接、历史桥接和 CLI Action 分模块实现。
- 交互式 CLI 请求使用请求 ID 与运行中的 App 协作；CLI 不重做编辑器。
- Phase 2 需扩展固定 `screenshot` 系统标签和原子图片 payload 替换接口，但 Phase 1 不提前改剪贴板仓库。
- AI 审计日志不得记录图片正文、OCR 正文或 Provider 原始响应。
- 滚动长截图的中间帧、匹配特征、临时 manifest 和预览不得进入剪贴板历史或 OCR；崩溃后只清理，不恢复。

## 6. 路线图外项目

- GIF、视频、系统声音和麦克风录制：独立项目。
- 自动上传与云分享链接：当前不纳入；若重启，需单独解决账号、存储、访问控制、删除和成本模型。
