# Step 3 PRD：滚动长截图

状态：implementation-in-progress
最后审阅：2026-07-15
来源级别：confirmed product requirements

## 1. 目标

- 在显式滚动长截图模式中，让用户选择单个屏幕内的固定区域，手动向下滚动目标内容，由 Blocks 自动采集、匹配和纵向拼接。
- 用准备态、采集中 HUD、到底倒计时、失败暂停恢复和尺寸保护，让长时间会话的状态与下一步始终可见。
- 拼接成功后复用统一截图编辑器；只有用户“完成”后才写入剪贴板，并按设置写截图历史和 OCR 队列。“保存”只写文件，即使保存成功后关闭编辑器也不写剪贴板或历史。
- GUI 与 CLI 共用同一活动会话；CLI 只提供 `status`、`finish`、`cancel`，不启动会话、不选择区域、不自动滚动。

## 2. 范围与非目标

本阶段包含：显式工具条模式、单屏固定区域、纵向向下手动滚动、Input Monitoring 硬权限、准备态 Start、采集 HUD、3 秒到底倒计时、重叠匹配、保守固定头部去重、失败暂停恢复、90% 尺寸预警、硬上限、统一编辑器和延迟输出、CLI 会话控制。

本阶段不包含：

- 通过 Accessibility、脚本或目标 App 接口自动滚动。
- 横向、向上或跨屏拼接；滚动过程中移动或缩放捕获区域。
- 多个并发长截图会话、后台无人值守启动、CLI 启动或 CLI 选择区域。
- 捕获/拼接失败后的自动部分结果、App 崩溃后的会话恢复或中间帧恢复入口。
- 云端拼接、AI 修补、动态内容语义理解或针对特定浏览器/文档 App 的插件。

## 3. 入口、权限与准备态

- 滚动长截图必须是截图选择工具条中的显式模式，不使用隐藏手势、长按、滚轮组合键或对普通区域截图的隐式推断。
- 开始选择前必须同时满足屏幕录制和 Input Monitoring。Input Monitoring 是硬权限；缺失时不得进入可开始的长截图会话，也不得降级为定时盲采集。
- 本阶段不以 Accessibility 权限替代 Input Monitoring，也不使用 Accessibility 控制目标内容滚动。
- 捕获区域必须完整落在单个显示器内。选区确认后进入 `ready`，区域位置和像素尺寸冻结，工具条提供明确的 `Start`、`Reselect` 与 `Cancel`；需要修改范围时重新选择，不在 ready 内拖动旧选区。
- `ready` 只完成权限、区域和资源预检，不采集可用于输出的长图帧，不写剪贴板、历史、OCR 或文件。
- 同时只允许一个截图会话；普通截图、长截图和交互式 Action 复用同一会话互斥门禁。

## 4. 采集与拼接

- 用户点击 `Start` 后，Blocks 采集首帧并进入 `capturing`。用户只需在目标 App 内手动向下滚动，区域和目标显示器保持固定。
- Input Monitoring 只用于观察与当前会话相关的纵向滚动信号并驱动采样节奏，不记录按键正文、目标 App 内容或原始输入轨迹。单个输入事件及系统自然滚动方向不得直接决定页面移动方向。
- 每个候选帧只允许与最后一个已接受位置做纵向向下匹配。零位移、向上位移、横向漂移、低置信度或多解匹配不得追加到长图。
- 只有通过匹配的新增行进入已接受结果。重复帧可忽略；连续歧义或采集错误进入失败暂停，不得猜测位移后继续拼接。
- 固定头部去重采用保守策略：只有顶部区域在连续帧中满足高置信稳定条件时，才保留首次出现并从后续追加区排除。无法确定时保留重复内容，不以可能删除正文为代价追求视觉整洁。
- 重叠、稳定头部、无新增内容、歧义和采样节奏的生产阈值不在 PRD 中臆定，必须由 `拼接原型报告.md` 所列代码 fixture 与真实路径证据确定。

## 5. 到底、完成与尺寸保护

- 系统检测到高置信“已到底”候选后进入 3 秒倒计时。HUD 清晰显示 `3 -> 2 -> 1`；倒计时期间出现有效向下滚动或新增内容时立即返回采集态。
- 倒计时归零后按成功路径自动执行 `finish`。用户也可在正常采集期间主动 `Finish`，以当前已接受内容作为有意结束点。
- 产品硬边界同时满足：任一输出边长不得高于 `32768 px`，总像素不得高于 `120 MP`。生产实现可基于原型、内存和编辑器证据采用更低有效上限，但不得提高这两个边界。
- 预估结果达到当前有效上限的 90% 时，HUD 必须显示持续预警；预警不阻塞继续滚动，也不得自动写出结果。
- 达到任一有效硬上限前必须停止接受会超限的新行，并自动以当前有效内容进入 finalizing；不得生成超过上限的位图，也不得等待一次额外滚动后才停止。
- 最终拼接、解码或编辑上下文创建失败视为失败，不进入编辑器、不自动导出当前已接受片段。

## 6. 失败、暂停、恢复与取消

- 画面确认向上位移后进入 `recovering`：不追加内容、不改变最后有效锚点，用户向下滚回锚点或重新产生可信向下重叠后自动恢复采集，不要求点击 Resume。
- 反向画面、暂时重叠不足或匹配多解连续评估 3 个稳定候选帧仍失败时才进入 `paused`。无效帧、区域尺寸变化、采集源中断、滚动监听中断和临时资源压力仍按保守策略直接暂停。
- `paused` 保留本次进程内最后一个一致的已接受状态，HUD 显示低敏原因和 `Resume`、`Cancel`。恢复必须重新检查权限、区域、显示器和最后锚点；成功后才继续采集。
- 失败暂停时不得自动 `Finish`，CLI `finish` 也必须返回当前不可完成状态。无法恢复时只能取消，不能以“尽量保留”为由导出部分长图。
- App 退出、崩溃、被强制结束或机器重启后不恢复长截图会话。下次启动只清理遗留临时数据，不展示可恢复结果。
- 从 `ready`、`capturing`、倒计时、`paused`、尺寸上限、finalizing 或编辑器触发取消，都必须以 first-terminal-wins 收口：不写文件、不改剪贴板、不建历史、不入 OCR 队列，并清理会话临时数据。

## 7. 编辑与输出提交

- 拼接成功只产生编辑器输入，不是输出终态。与普通截图一致，长图进入统一截图编辑器前及编辑期间不自动写剪贴板。
- 长截图编辑器中的“完成”与成功的“保存”是两个允许的提交终态。保存面板取消或文件写入失败不构成提交终态，编辑器保持可继续操作。
- 成功保存作为本次长截图的终态，写入所选文件后关闭该长截图编辑会话；完成则按现有完成路径关闭。两者都基于同一不可变最终 render revision，且每个会话最多提交一次。
- 进入“完成”提交终态后，才允许写最终图到剪贴板，并按 Step 2 设置决定是否写截图历史及进入本地 OCR。“保存”使用独立零剪贴板/零历史终态。不得把任意中间帧、未编辑拼接图、预览或失败片段提交给这些 sink。
- 最终 sink 继续沿用 Step 2 的独立结果语义；单个 sink 失败显示对应状态，但不得退回去提交旧 revision 或中间图。
- 长截图编辑期间不提供会绕过上述终态的直接复制路径；取消编辑必须完全无输出。

## 8. CLI / Action 契约

Step 3 仅新增以下三个会话 Action；命名为当前实施契约，代码实现时必须同步注册 GUI host、Broker 和 CLI：

| Action ID | 输入 | 结果 | 边界 |
| --- | --- | --- | --- |
| `blocks.screenshot.scrolling.status` | 无 | 当前会话 ID、状态、当前像素尺寸、上限警告和权限状态 | 不返回图片、区域坐标、目标 App、输入轨迹或路径。无会话返回 idle snapshot。 |
| `blocks.screenshot.scrolling.finish` | `session_id` | 是否接受完成请求及转换后的状态 | 只等价于 HUD `Finish`；不能从 `ready`、`recovering`、`paused`、finalizing 或 editing 绕过状态机，不能跳过编辑器。 |
| `blocks.screenshot.scrolling.cancel` | `session_id`、显式 `confirm` | `cancelled` | 复用 GUI 取消清理；ID 不匹配不得取消新会话，CLI 必须显式确认破坏性取消。 |

- 不提供 `start`、`resume`、区域参数、输出路径、`--copy` 或无编辑模式。
- CLI 控制不改变权限要求，不把 App 拉起为无人值守采集器，也不返回拼接图字节或 Base64。
- GUI 和 CLI 的 finish/cancel 竞争必须 first-terminal-wins；迟到请求返回稳定的 `stale_session` 或终态结果，不重复执行 sink。

## 9. 成功标准

- 在单屏固定区域、用户向下手动滚动的网页和文档真实路径中，长图顺序正确，无缺行、错序、明显接缝或误删正文。
- 固定头部在高置信场景中只保留一次；低置信场景宁可重复，不误删内容。
- 到底 3 秒倒计时可被新增内容取消，归零后进入成功拼接与统一编辑器。
- 捕获/匹配失败可暂停并恢复；失败、取消、崩溃和超限路径都不产生自动部分输出。
- 90% 预警与有效硬上限按宽、高和总像素中最先触发者工作，且绝不超过 `32768 px` / `120 MP` 产品边界。
- 完成前，剪贴板 changeCount、历史记录和 OCR 队列均无本会话写入；保存只产生用户指定文件，取消后保持完全无输出。
- CLI 只有 status/finish/cancel，结果与 HUD 状态一致，不能启动或绕过编辑器。
