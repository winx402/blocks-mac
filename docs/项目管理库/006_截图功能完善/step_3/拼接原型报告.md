## 1. 当前结论

当前生产常量来自可重复 fixture，并列在第 6 节；安装版 Chrome 本地长页面已完成真实采样、连续追加、暂停、继续和取消，累计高度从 `1520 px` 增长至 `5120 px` 且未触发重叠不足。Safari、Preview、原生文档、真人输入设备和全输出链路仍需复核。任何未附 fixture 或真实证据的性能数字不得进入验收结论。

## 2. 原型需要回答的问题

- 在仅允许纵向向下拼接时，如何区分可靠重叠、零位移、向上位移、横向漂移和重复纹理多解。
- 最小有效重叠、最佳/次佳候选间隔、连续失败次数和 settle/capture 节奏应取何值。
- 固定头部的顶部范围、稳定帧数和置信条件如何设定，才能优先避免误删正文。
- 如何识别高置信到底候选，并让 3 秒倒计时在新增内容出现时可靠撤销。
- 动态内容、光标、加载占位、粘性工具条和轻微动画对匹配的影响及降级策略。
- disk-backed staging、final stitch、编辑器加载、PNG/JPEG 保存和历史/OCR 提交的峰值内存、耗时与有效上限。

## 3. Fixture 设计

代码 fixture 必须是可版本化、无敏感内容、可生成预期真值的图像序列，至少覆盖：

| 组别 | 变量 | 必须验证 |
| --- | --- | --- |
| 基础重叠 | 大/中/小滚动步长、不同重叠比例、非整数缩放 | 位移真值、追加行数、无接缝。 |
| 无效方向 | 零位移、向上、横向漂移、抖动 | 不追加错误内容，进入忽略或 paused。 |
| 重复纹理 | 表格行、代码行、列表、纯色区、周期图案 | 多解不被高置信误接。 |
| 固定头部 | 无头部、单一头部、动态头部、粘性工具条、正文相似顶部 | 高置信时只保留一次，低置信时不误删。 |
| 动态内容 | 时间、动画、加载骨架、视频占位、闪烁光标 | 局部变化不污染整段位移判断；无法可靠时暂停。 |
| 到底行为 | 真到底、短暂停顿、延迟加载、到底后新增内容 | 3 秒倒计时只在高置信候选触发，新增内容可撤销。 |
| 失败恢复 | 丢帧、capture 错误、event tap 中断、锚点重建 | 只从最后一致状态恢复，无部分输出。 |
| 尺寸资源 | 多宽度、多高度、接近有效上限、超限一行 | 90% 预警正确，分配前拒绝超限。 |

真实复核至少包含本地 fixture 页面、常见网页滚动容器和文档阅读路径；真实内容只使用低敏样本，不把真实录屏结果替代 fixture 真值。

## 4. 当前生产算法与开源参考

### 4.1 开源参考和取舍

- [Snapzy](https://github.com/duongductrong/Snapzy)（BSD-3-Clause）是当前最有价值的 macOS 参考。其长截图链路包含有界帧环、提交调度、预期滚动位移、固定页头/页尾识别、guided/recovery 搜索、分带像素差和 Vision 平移估计。当前实现吸收了“有界采集、局部分块共识、失败后恢复搜索”这些架构思路，但使用独立的后请求 request-ID 缓冲和 fail-closed 视觉验证，没有复制源码，也没有引入 Snapzy 依赖。
- [ScrollSnap](https://github.com/Brkgng/ScrollSnap)（MIT）使用 ScreenCaptureKit，并对多个图像区域执行 Vision 平移估计，再要求多数区域的偏移量一致。该方案说明“单一区域匹配不足，应要求多区域共识”是合理方向，但其持续维护整张 `NSImage`、直接合成长图和单一 Vision 路径不符合本项目的 Core 隔离、磁盘条带和资源上限要求，因此没有直接采用。
- [ShareX](https://github.com/ShareX/ShareX)（GPL-3.0、Windows）新版长截图强调边采边合成和自动化的简化流程。这里只参考渐进提交和失败时保守停止的产品思路；因平台、许可和实现边界不同，不使用其源码。
- [macshot](https://github.com/sw33tLie/macshot)（GPL-3.0）采用滚动期间周期采样、滚动停止后补稳定帧，并通过 Vision 位移估计和静态区域排除辅助拼接。这里只采用采样时序和静态区域隔离思路；GPL 源码不进入本项目。

开源基准不能直接作为生产保证。对 Snapzy 仓库自带的严格滚动准确率脚本实测，4 组用例中 3 组通过，变速滚动用例只生成 `604 / 932` 行并报告 5 个失败点。因此本项目不会直接依赖任一开源拼接器，而是保留独立 fixture、恢复预算和 fail-closed 校验。

许可证结论：当前生产代码是独立实现，不包含上述仓库的代码、资源或派生文件，因此不新增第三方许可证交付项。后续若直接引入任一实现，必须重新做许可证和 NOTICE 审查。

### 4.2 当前实现

1. 将每帧固定区域转换成宽 `192 px`、保持完整原始高度的灰度描述；原始彩色帧只用于确认后的条带写入。
2. 在全部可能纵向位移上做稀疏二维粗搜索，保留得分最高的 16 个候选，避免只看单行或只看最后一帧。
3. 对候选执行最多 `4 x 10` 个局部块的相关性复核，并允许 `+-2` 个采样像素的水平漂移；固定侧栏、滚动条和局部动画只能影响少数块。
4. 使用中位数、截尾均值和有效块比例形成鲁棒综合分数；低信息块不参与投票，大面积动态或有效区域不足时拒绝拼接。
5. Core 快路径无法唯一确认重叠时，App 层先使用 Apple Vision 对左、中、右 3 个区域分别估计平移；Vision 不可用时采用独立的多区域致密亮度匹配。只有多数区域一致才形成位移提示并重跑 Core 验证；低重叠候选还要求三分区全数一致且高置信，历史位移不能强行让视觉多解通过。
6. 顶部和底部稳定带在可信 append 时建立共识。页头只保留首帧；页尾作为独立延迟条带，最终化时只写入最底部一次。页尾变化但页头稳定时，匹配器从上一帧内容范围排除旧页尾、保留当前帧完整正文，并从旧页尾位置覆盖写入；页头和页尾同时变化时回退整帧重匹配。动态粘性区域不能成为永久硬约束。
7. 帧桥使用容量为 4 的后请求有界缓冲，为每个 demand 保留 request ID，只把请求之后产生的完整 surface 交回对应 demand；捕获协调器最多保留 8 个需求。滚动输入立即请求运动帧，约 80ms 再补一次运动帧，停止输入约 180ms 后请求稳定帧；被合并的旧需求同步从帧源取消，避免错误帧消耗新需求。回调只入队，匹配顺序由单一处理任务串行消费。
8. 单次反向、重叠不足或多解不会立即暂停，而是进入最多 3 个稳定采样的恢复预算；协调器每 180ms 主动获取恢复帧，不要求用户重复滚动，返回锚点或恢复可信向下重叠后自动继续。
9. 连续零新增且伴随滚动输入时进入 3 秒到底候选；倒计时期间任何可靠新增行立即撤销候选。

## 5. 指标与通过规则

每次 fixture 运行必须输出结构化结果，至少包含：

- fixture 集版本、算法版本、输入像素尺寸、预期位移和实际位移。
- 接受/拒绝是否符合真值，接缝垂直误差、缺失行、重复行和误删行。
- 固定头部保留次数、误删正文像素/行数和不确定时是否正确降级。
- 到底候选触发、撤销和归零事件序列。
- 单帧匹配 median/p95、final stitch 耗时、峰值 resident memory、临时磁盘和最终编码大小。
- 90% 预警与硬上限触发源：宽、高或总像素。

生产阈值晋级条件：

- 所有真值 fixture 无错序、无缺行、无正文误删；不确定输入必须拒绝或暂停，不能误接受。
- 固定头部策略的优先级是零正文误删，其次才是减少重复。
- 在目标机和最终安装版中，匹配不会造成明显滚动卡顿，final stitch 与编辑器加载处于可接受资源范围。
- 有效生产上限必须低于或等于实际通过的资源边界，并同时不高于 `32768 px` 边长和 `120 MP` 总像素。

## 6. 当前保守参数

下表是当前实现使用并由代码 fixture 覆盖的保守基线。真实路径或资源证据不满足时必须继续收紧，不能为了减少暂停放宽匹配。

| 参数 | 当前值 | 证据要求 |
| --- | --- | --- |
| 采样 settle / throttle | 滚动期间 `80 ms` 桥接采样，停止输入 `180 ms` 后补稳定帧；首帧立即 | 同一输入 burst 共享恢复预算；运动帧和最终稳定帧都必须进入候选。真实惯性滚动仍待录屏。 |
| 二维动态块容差 | `4 × 最多 10` 个局部块；单块最低 `0.78`，有效块比例至少 `0.58`，综合分数至少 `0.82` | 局部光标、动画、滚动条和固定侧栏不能污染整帧判断；大面积动态、低信息和重复纹理多解仍拒绝拼接。 |
| 帧源 | 最高 `30 fps`、`queueDepth = 6`；容量 4 的 post-demand request-ID 缓冲，捕获端 demand 最多 8 个 | 只接收 `SCFrameStatus.complete`；每个新帧精确对应语义 request，被合并需求可取消，转换 surface 瞬时失败时在后续完整帧重试，不让 SCStream 回调数量线性放大算法工作量。 |
| 最小有效重叠 | `24` 像素行 | 小步、过快和多解 fixture；真实缩放路径待补。 |
| 最佳/次佳置信间隔 | 稀疏候选分数差 `> 0.015`；多解再由致密纹理差或独立三区域高置信提示裁决 | 历史位移不能强制通过视觉多解；低重叠必须满足额外独立证据。 |
| 匹配搜索 | 192px 宽全高灰度描述；全范围稀疏搜索后保留 16 个候选，再做局部相关性和致密纹理差复核 | 不再使用单行 64-bit 指纹；固定侧栏和局部动画由多区域共识隔离。 |
| 最小重叠比例 | 默认 `30%`；只有独立多区域提示满足一致性和置信要求时允许更低重叠 | 防止 Page Down 过快时在窄重叠上猜测接缝；12 帧浏览器序列覆盖正常和末页短步长。 |
| 水平漂移容差 | frame 尺寸必须一致；局部复核允许 `±2` 个采样像素 | 固定 `sourceRect` 保证几何稳定；更大横移继续 fail-closed。 |
| 自动恢复预算 | 反向、重叠不足和多解均为 `3` 个稳定候选帧 | 单次匹配失败不立即暂停；返回锚点或恢复可信向下重叠时自动继续，预算耗尽才 paused。无效帧和尺寸变化仍直接暂停。 |
| 固定头部候选高度 | `8...512` 像素行 | 仅相邻帧顶部公共前缀且正文重叠唯一时去重；动态头部拒绝。 |
| 固定页尾候选高度 | `8...512` 像素行 | 可信 append 后形成共识并暂缓到 final stitch 底部只写一次；动态页尾以非对称内容范围替换旧尾部，逐行 ground truth 验证无缺失、重复或旧页尾残留。 |
| 到底候选条件 | 已有向下输入且 settle 后无新增；固定倒计时 `3 s` | 倒计时每秒复查最新完整帧，新增内容立即取消。 |
| 内存工作集和临时磁盘预算 | 58.5 MP final stitch、PNG/JPEG/TIFF 和截图历史提交显式 profile 已通过 | 继续补真实 Apple Vision 分块 OCR、最终安装版编辑和低内存机器曲线。 |
| 当前有效边长/总像素上限 | `16384 px` / `64 MP`，90% 预警；绝对边界仍为 `32768 px` / `120 MP` | 有效边界、整数溢出和分配前拒绝已覆盖；真实资源曲线仍待闭合，不宣称绝对边界可达。 |

性能门禁使用 `1400 × 96` 的二维描述、固定页头/侧栏和局部动态块，单次匹配预算低于 `0.5 s`。版本化浏览器资源的定向 matcher 用例本机耗时约 `0.016 s`。这两项都不替代最终安装版的滚动流畅度、峰值内存和真实页面 p95 证据。

## 7. 资源 profile 复现

- 普通回归默认跳过 58.5 MP profile，避免每轮测试重复分配数百 MB。
- 复现时先用 `BlocksAppTests` scheme 执行 `build-for-testing`，复制生成的 `.xctestrun`，在 `TestConfigurations:0:TestTargets:0:EnvironmentVariables` 注入 `BLOCKS_RUN_SCROLLING_RESOURCE_PROFILE=1`，再用 `test-without-building` 单独执行 `testNearEffectiveLimitResourceProfile`。
- profile 断言 90% 尺寸/像素警告、最终尺寸、final stitch、PNG/JPEG/TIFF、截图历史提交、临时目录清理和 RSS 上限；日志只输出尺寸、耗时和字节数，不输出图像或路径。
