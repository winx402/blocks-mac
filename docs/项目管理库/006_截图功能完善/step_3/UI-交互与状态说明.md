# Step 3 UI / 交互与状态说明

状态：implementation-in-progress
最后审阅：2026-07-17
来源级别：confirmed UED

## 1. 显式模式与选区

- 截图选择工具条增加可见模式控制，明确区分普通截图与“滚动长截图”；进入该模式不依赖隐藏手势或滚动行为猜测。
- 滚动长截图模式只允许区域选取。当前指针所在显示器成为目标显示器，选区边缘限制在该显示器内；跨屏拖拽不得形成跨屏区域。
- 选区确认后保留边界遮罩并进入 `ready`。此时区域已经锁定，可开始、重新选择或取消，但尚未采集长图内容。
- `ready` 的 Start、Reselect、Cancel 使用同规格 36pt 图标命令：开始为 `play.fill` accent、重新选择为 `arrow.counterclockwise`、取消为 `xmark` destructive。accent 只用于图标和 hover/focus 反馈，不使用常驻大色块；命令必须接收 first mouse，目标 App 保持激活时第一次点击也直接执行。只有屏幕录制、Input Monitoring、区域尺寸与会话门禁均通过时 Start 可用。
- 准备态与采集态复用同一个 `ScrollingScreenshotHUDController`、`NSPanel`、`NSHostingView` 和 `ScrollingScreenshotHUDView`。HUD 固定为 `520×64pt`；准备态左侧显示“准备采集”和锁定区域的像素尺寸，右侧显示开始、重新选择、取消；开始后只更新 phase、提示和命令，不替换窗口、根组件、材质或焦点上下文。
- 开始、继续和完成不使用独立的大号文字按钮；所有状态都复用同一命令语义、图标尺寸、命中区、圆角和 hover/focus/disabled 反馈。

## 2. 权限路径

- 进入长截图模式前同时预检屏幕录制和 Input Monitoring；选区锁定后以及点击开始时再次复核，权限在会话中途被撤销时必须停止进入捕获，不得展示可点击但必然失败的开始按钮。

- 缺少屏幕录制或 Input Monitoring 时，在进入可开始状态前显示对应权限缺失，不把两个权限合成含糊的“无法截图”。
- Input Monitoring 为长截图硬权限。主操作进入现有权限引导流程的对应系统设置页；用户返回后必须显式刷新并重新预检。
- 权限缺失、授权后尚需重启、签名身份不稳定或运行中权限被撤销，都使用具体状态反馈。未经真实检查不得显示“已授权”。
- 不展示或请求“辅助功能用于自动滚动”的文案；Accessibility 不是本阶段开始条件。

## 3. HUD 布局与共同规则

- 点击 `Start` 后，选择工具条收敛为可拖动 HUD。HUD 优先放在捕获区域外并限制在可见屏幕内；无可用外部空间时，捕获源必须排除 Blocks 自身 HUD 窗口。
- HUD 固定展示状态、当前拼接像素尺寸或已接受进度、尺寸风险和当前可用操作，不展示捕获内容缩略图。
- HUD 的 Pause/Resume、Finish、Cancel 复用截图编辑器的工具按钮组件、36pt 命中区、圆角和状态语义；不依靠颜色单独表达状态。每个控件有 tooltip、键盘焦点和 VoiceOver label。
- HUD 被拖动、状态文案变化、倒计时、警告或按钮 loading 不得改变捕获区域，也不得使布局跳动或文字溢出。

## 4. 状态与操作

| 状态 | 用户看到 | 可用操作 | 输出行为 |
| --- | --- | --- | --- |
| `ready` | 固定选区、权限就绪、`Start` | Start、Reselect、Cancel | 无输出。 |
| `capturing` | 采集中、当前尺寸、Finish、Cancel | 手动向下滚动、Finish、Cancel、拖动 HUD | 只积累临时帧。 |
| `bottom-countdown` | “已到底”与 `3 -> 2 -> 1` | 继续滚动以取消倒计时、立即 Finish、Cancel | 归零后开始 finalizing。 |
| `warning-90` | 持续尺寸预警，不遮挡主状态 | Finish、Cancel、继续滚动 | 不自动输出。 |
| `limit-reached` | 已到本机会话有效上限 | 自动进入 finalizing；仍可在生成期间 Cancel | 不再接受新行，不生成超限图。 |
| `recovering` | 正在重新定位，请向下滚动到上次位置 | 继续滚动、手动暂停、Cancel | 不允许 Finish，不追加未确认内容。 |
| `paused` | 已暂停、低敏原因、恢复提示 | Resume、Cancel | 不允许 Finish，不输出部分结果。 |
| `finalizing` | 正在拼接并准备编辑 | Cancel | 成功后进入编辑器；失败转 paused 或失败终态，无输出。 |
| `editing` | 现有统一截图编辑器 | 编辑、完成、保存、取消 | 完成/保存成功前无 clipboard/history/OCR。 |
| `cancelled` | 简短取消反馈 | 关闭 | 完全无输出并清理临时数据。 |

## 5. 手动滚动与到底倒计时

- `capturing` 状态明确提示用户在目标内容中向下滚动，但不显示教程式常驻说明，也不模拟滚动。
- 正常向下滚动时，HUD 的进度反馈只在新内容被接受后更新；收到滚动信号但未接受内容时不得伪增进度。
- 高置信到底候选出现后显示 3 秒倒计时。有效新增内容或继续向下滚动导致新内容出现时，倒计时立即消失并回到采集态。
- 倒计时归零、用户点击 Finish 或 CLI finish 只触发同一个完成转换，不得重复拼接或重复打开编辑器。

## 6. 固定头部、失败与恢复反馈

- 固定头部去重不提供用户调节阈值。HUD 不显示“已识别某头部”的技术信息，避免把不确定算法判断包装为事实。
- 固定页尾必须作为可替换的延迟条带处理。后续帧不再包含固定页尾时，上一份延迟页尾直接丢弃，当前帧从旧页尾起始位置覆盖并追加正文；新的固定页尾只保留底部当前版本，不能把旧页尾写入正文中间。
- 匹配器必须允许“上一帧存在固定页尾、当前帧页尾已变化”的非对称内容范围，但只有页头仍稳定时才可采用；页头和页尾同时变化时回退整帧重匹配，不能叠加结构假设。
- 最终化前必须验证输出从第 0 行到最终高度连续覆盖；发现任何空洞时暂停并提示拼接失败，不得输出带透明或黑色断层的图片。
- 单次滚轮、触控板或键盘输入只触发采样，不直接显示反向警告。画面确认向上位移后进入 `recovering`，返回最后有效位置时自动恢复；连续 3 次稳定画面仍无法恢复才进入 `paused`。
- 匹配歧义、采集源中断、权限变化或资源压力发生时，HUD 停在 `paused`，显示可理解但低敏的原因，如“内容暂时无法可靠衔接”。
- `Resume` 进入短暂检查态；权限、显示器、区域和锚点全部通过后恢复。检查失败则保持 paused 并更新原因，不丢弃最后一致状态。
- 失败暂停不展示“保留部分结果”或“仍然导出”入口。取消是无法恢复时的唯一退出路径。

## 7. 尺寸预警与硬上限

- 预警基于本次实现的有效上限，在达到 90% 时持续显示。文案同时给出当前像素尺寸与“接近上限”，不使用不可验证的剩余页数。
- 任一边长或总像素即将超过有效硬上限时停止接受新内容，并自动以当前有效内容进入 finalizing。产品绝对上限始终不高于 `32768 px` 与 `120 MP`。
- 上限触发只自动生成编辑器输入，不自动保存、复制或创建历史；finalizing 期间取消仍完全清理。

## 8. 编辑器提交语义

- 长截图进入统一编辑器时，不自动复制未编辑拼接图。编辑器中的直接复制操作对长截图会话不可用，避免绕过提交终态。
- “完成”使用当前最终 render revision 提交并关闭编辑器。
- “保存”先显示系统保存面板；取消面板或写盘失败时留在编辑器且不写 clipboard/history/OCR，保存成功后以同一 revision 提交并结束会话。
- 提交进行中禁用重复完成、保存和取消；终态由 first-terminal-wins 保证只发生一次。
- 编辑器取消、关闭后确认丢弃或 App 终止均不得留下文件、剪贴板、历史或 OCR 输出。

## 9. 可访问性、本地化与视觉验证

- 模式控制、Start、HUD 状态、倒计时、90% 预警、上限、Resume、Finish、Cancel 和权限路径覆盖中英日。
- ready、capturing、paused、finalizing 和 editing 的键盘焦点顺序稳定；Esc 触发当前会话取消并遵守脏状态/终态规则。
- VoiceOver 必须能读出状态变化、倒计时和按钮可用性；Reduce Transparency 下 HUD 使用稳定不透明 surface。
- 浅色、深色、不同缩放和窄屏空间下，HUD 不遮挡自身按钮、不溢出屏幕，并通过真实截图/录屏而非仅静态检查验收。
