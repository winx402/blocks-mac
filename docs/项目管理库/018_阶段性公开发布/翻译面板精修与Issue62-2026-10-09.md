# 翻译面板精修与 Issue #62

## 本轮范围

- 将用户确认的 HTML 示意落实到原生翻译窗口，不重做设置页。
- 原文、居中语言栏、始终展开的结果纵向排列；不提供翻译、取消、结果折叠按钮。
- 停止输入 800ms 后自动翻译，输入法组合期间暂停，提交后重新计时。
- 来源名称与运行状态语义分离；保留复制、朗读、收藏、重试、诊断及来源排序。
- 开窗依据初始输入选择尺寸，后续输入和结果更新不自动调整窗口；用户主动调整的尺寸优先。
- 新增 issue 仅 #62；本轮不据此关闭旧的未完成验收项。

## 验证记录

### 自动化

- 最终受控 DebugTesting 构建及 100 项定向 XCTest 通过（0 失败）：输入法事件桥接、防抖、陈旧快照隔离、Apple 同语言对配置更新、窗口几何与尺寸保存、Broker 排空和升级协议，包括真实运行后 unlink 的独立进程回归及正式/开发扫描策略隔离。
- 最终结果：`Test-BlocksAppTests-2026.10.09_02-35-40-+0800.xcresult`；静态翻译门禁 P5-P / P7-C 使用显式 `--skip-build`，P7-E 静态检查通过，构建证据来自前述独立构建而非 skip-build。
- 安装器隔离场景 16 类、开发入口隔离场景 12 类通过；应用更新安全自测、源码升级传输测试与 UI 设计系统静态门禁通过。
- 静态契约与自动化测试不代替以下实机观察，也不证明所有辅助功能或第三方翻译来源通过。

### 原生 App 实测

- 使用固定签名开发版，原有安装路径和数据保持不变。
- 英文输入 `The meeting starts tomorrow at nine.` 自动出现中文译文；替换为 `你好，我们明天见。` 自动出现英文译文，无手动翻译操作。
- 源语言自动识别与目标语言自动选择随输入切换。
- 切换日语时，当前机器缺少语言包，明确显示下载语言包提示；恢复自动目标后重新得到英文结果。没有为测试下载额外资源。
- 深色实图检查确认居中语言栏、展开结果、轻量分隔和窗口稳定性；实测发现状态文字被压缩隐藏，改为保留固有宽度后已再次截图确认“已完成”可见。
- 连续编辑实测发现 Apple 同语言对第二次输入会卡住。修复运行配置的版本失效与请求身份隔离后，同一窗口三条连续英文均自动出现正确中文结果；随后五行 278 字符的原卡住输入也完成翻译。结果列表实际滚动时，窗口与原文区域保持稳定。
- 系统真实中文选词、多来源并发、浅色/增强对比度、截图入口及跨显示器完整矩阵尚未在本轮完成，不计为通过。

## Issue #62 边界

- 仅在两个用户 launchd 域都明确不存在旧任务，且没有旧 Broker 进程时，允许清理残留 SM 注册。
- 对仍加载但启动被拒绝的任务、未知进程状态或超时继续安全拒绝；不强杀服务、不修改签名信任策略。
- 第一次安装成功后，连续升级测试发现进程探针对无关的已删除可执行文件后台进程过度拒绝。已修复为用内核进程名称排除确定无关者，未知或完整/截短 Broker 名继续拒绝；相关真实进程测试通过。正常退出旧 App 与 Helper 后安装成功，再次对运行中的新 App 执行原地升级成功，未强杀无关进程。
- 严格跨安装进程扫描仅用于源码版的旧服务迁移；正式沙盒版继续使用当前 bundle 的精确路径扫描及原有认证排空协议。本轮不以开发版验证冒充正式沙盒完整升级验收。
- 原报告环境中的 Launch Constraint 根因、CLI SIGKILL 以及仍加载的 spawn-failed 任务尚未解决，#62 / #59 保持开放。旧版本自身的升级准备逻辑不会被新源码提前修正。
