# Issue #68 与 Beta 20

## 根因与方案

当前 Sparkle 2.9.6 的标准界面在首次“安装并重启”点击后清空自己的安装按钮回调。
Blocks 使用 relaunch postpone 回调暂停安装，安全准备失败后仅更新设置页，因此旧窗口留着失效按钮。
另有 SelectionHelperClient.load() 将钥匙串读取失败折叠成 nil，使日志无法区分真正未配对。

保留 Sparkle 引擎、下载验证和安装职责，不修改依赖源码。通过公开 userDriver.dismissUpdateInstallation
关闭已消费的标准界面，使用应用拥有的非模态小窗口展示准备／失败及显式重试／稍后。
此 user-driver 方法只清 UI；不调用 core abort，不重置 session 或丢弃已验证下载。

安全准备失败后先等待恢复完成、清除旧 task，再开放重试。安装 continuation 调用前置空，
窗口动作带 session UUID，取消后的旧动作不能用于新更新。稍后只隐藏窗口；菜单／设置可继续当前更新。
错误 UI 与日志仅使用白名单参与者和原因，不传原始错误正文。

Helper 更新路径改用 loadForAssociation：缺密钥与不可读分别报告。缺密钥但 Helper 正运行时指导正常退出后重试；
不增加未认证退出 IPC、自动清配对或强杀。现有 locator 不能证明运行进程的动态身份，不能把磁盘签名当成自动退出授权。

## 验证

环境：macOS 27.0（26A428）、Xcode 26.6（17F113），arm64。

- DebugTesting 无证书 build-for-testing 完成；出现已验证 Xcode ibtoold 残留时经受控清理、一次增量重试通过，非首次清理即通过。
- 最终 67 项定向 XCTest 零失败，覆盖更新窗口立即重试、同步安装中止、恢复等待、取消、旧 session 动作、
  单次 continuation、Helper 缺密钥／Keychain 故障无 IPC／不删除密钥，以及模拟正常退出后重试。
- application_update_safety_self_test、quit_watchdog_self_test、helper_keychain_acl_self_test、
  release_pipeline_self_test 和 test_ui_design_system 通过。钥匙串自检仅使用临时合成条目。
- 独立只读审查未发现阻断性缺陷；补齐其指出的同步中止测试和真实窗口验证。
- app_update_recovery_runtime_probe 使用本次生产协调器／窗口与真实 Sparkle framework。
  通过 CUA 点击标准安装按钮后显示未配对原因；稍后隐藏，菜单继续后显示模拟 CLI 阻塞，点击重试后 saved continuation 恰好一次。
  另确认准备中 Retry／Later／关闭禁用，Command-W 未关闭窗口。统一日志可见 started／failed／deferred／completed。
  UI 探针的 drain 为合成失败，不下载、不安装、不接触实际 Helper、TCC 或用户数据库。

## 交付与保留项

计划交付 0.1.0-beta.20；签名、公证、DMG、GitHub Release 及 Beta appcast 以发布流水线实际证据为准。
#68 原 beta.18→beta.19 安装环境的正常退出助手、真实升级／重新打开与数据保持尚未验收，保持开放。
新代码不能修复已经运行中的旧版本 UI；旧版本可正常退出助手并用设置中的原重试入口，或正常退出后用 DMG 安装。
不因此关闭 #66/#67 或其他已有验收保留项。
