## 新发现及修复

此前适配器及设置界面已支持连接丢失、超时和限流分类，但 `TranslationSourceManagementService.connectionTest` 只保留管理层错误码，丢弃 `TranslationServiceAdapterError.errorCode`。因此 CLI 的 `translation-source test` 仍得到泛化 `connection_test_failed` 与原始通用文案。

修复管理服务结果转换：优先保留管理层代码，其次保留适配器代码；适配器错误使用与设置界面相同的 `TranslationErrorPresentation`，仍限制为 512 字符。其他未知错误和披露确认门禁不变。回归覆盖 -1005、超时、HTTP 429 的 summary 与 action 执行错误两条路径。

## 结论与限制

- 旧的 -1005 / HTTP 429 故障当前未复现；不能把恢复归因于本次错误展示补丁。
- 历史的客户端差异并不足以单独证明具体安全软件或 TLS 指纹过滤是根因；本轮未做停用网络扩展的 A/B，也没有绕过安全保护。
- 社区源仍可能受配额、上游限流或网络环境影响，一次在线成功不是永久可用承诺。现有“非官方、可能限流或失效”提示保留，不因单次历史 429 全局下架来源。
- 已安装 App 的 CLI 集成目前关闭，实际 CLI 调用返回 `broker_unavailable`。未绕过或打开该门禁；错误转换通过同一管理服务与 action 接口测试验证，未声称完成启用 CLI 后的安装版端到端调用。
