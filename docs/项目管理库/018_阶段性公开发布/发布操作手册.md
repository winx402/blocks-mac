# 发布操作手册

状态：local-dry-run-only
最后更新：2026-08-15

## 0. 外部身份门禁

品牌、域名和全部标识以[外部身份锁定](外部身份锁定.md)为准。从 `apps/Blocks/Config/ReleaseIdentity.local.example.xcconfig` 创建被 Git 忽略的 `ReleaseIdentity.local.xcconfig`；公开 URL 已写入渠道配置，local 文件只补本机 Team/签名环境。不得把真实 Team ID、证书、profile、Notary 凭据或账号信息提交到仓库。

外部账号门禁：先注册 Explicit App ID `app.blocks.app`，描述使用 `Blocks for Mac`，不启用工程未使用的额外 capability；再创建对应 Mac App Store provisioning profile。Selection Helper 和普通包内辅助进程不预先创建额外 App ID。

最终标识不能只修改主 App Bundle ID。必须逐项冻结并复核：主 App、PluginRunner、ClipboardBroker、ActionBroker、Selection Helper、URL Scheme、LaunchAgent label/Mach service、Keychain service 和数据库/设置路径。上述身份已经锁定；后续如提出变更，必须停止发布流程，先完成单独的身份迁移设计和覆盖安装验证。

2026-08-08 实时状态：本机已有有效的 Developer ID Application 和 Apple Distribution，均包含私钥；Apple Developer 后台尚无 App ID 和 provisioning profile，Notary Keychain profile 也尚未创建。证书本身不再是阻断项，但不得绕过上述最终身份门禁直接构建发布包。

## 1. Direct Beta

只用于本地结构审计、不可发布：

```bash
script/release/build_direct_beta.sh --unsigned
```

App ID/profile 与外部资源门禁完成，且 Developer ID Application 可用后：

```bash
export BLOCKS_DEVELOPER_ID_APPLICATION='Developer ID Application: CONFIRMED NAME (TEAMID)'
export BLOCKS_EXPECTED_SIGNING_CERT_SHA1='CONFIRMED_40_HEX_SHA1'
export BLOCKS_EXPECTED_TEAM_ID='CONFIRMED_TEAM_ID'
script/release/build_direct_beta.sh
script/release/build_selection_helper_beta.sh
script/release/package_dmg.sh \
  --artifact direct-beta \
  --app DerivedData/DirectBeta/Build/Products/Release/Blocks.app \
  --release-name 0.1.0-beta.1 \
  --output-dir dist/direct-beta \
  --expected-team-id "$BLOCKS_EXPECTED_TEAM_ID" \
  --expected-cert-sha1 "$BLOCKS_EXPECTED_SIGNING_CERT_SHA1"
script/release/package_dmg.sh \
  --artifact selection-helper-beta \
  --app 'DerivedData/SelectionHelperBeta/Build/Products/Release/Blocks Selection Helper.app' \
  --release-name 0.1.0-beta.1 \
  --output-dir dist/direct-beta \
  --expected-team-id "$BLOCKS_EXPECTED_TEAM_ID" \
  --expected-cert-sha1 "$BLOCKS_EXPECTED_SIGNING_CERT_SHA1"
export BLOCKS_NOTARY_KEYCHAIN_PROFILE='confirmed-keychain-profile'
script/release/notarize_dmg.sh \
  dist/direct-beta/Blocks-0.1.0-beta.1-arm64.dmg \
  --evidence-dir dist/evidence/Blocks-0.1.0-beta.1 \
  --expected-team-id "$BLOCKS_EXPECTED_TEAM_ID" \
  --expected-authority "$BLOCKS_DEVELOPER_ID_APPLICATION" \
  --expected-cert-sha1 "$BLOCKS_EXPECTED_SIGNING_CERT_SHA1"
script/release/notarize_dmg.sh \
  dist/direct-beta/Blocks-Selection-Helper-0.1.0-beta.1-arm64.dmg \
  --evidence-dir dist/evidence/Blocks-Selection-Helper-0.1.0-beta.1 \
  --expected-team-id "$BLOCKS_EXPECTED_TEAM_ID" \
  --expected-authority "$BLOCKS_DEVELOPER_ID_APPLICATION" \
  --expected-cert-sha1 "$BLOCKS_EXPECTED_SIGNING_CERT_SHA1"
```

三个 notarize pin 必须直接复用锁定身份中的同一组 Team ID、精确 Developer ID Application Authority 与 leaf 证书 SHA-1，不能从 DMG 元数据推导或替换。脚本要求逐层 Developer ID 签名、Hardened Runtime、安全时间戳、严格 codesign 检查、Notary `Accepted`、notary log、staple、stapler validate 和 Gatekeeper assessment。DMG 在制作前必须重新通过渠道、Team ID 和证书 SHA-1 审计；SHA-256 只能在 staple 和最终 Gatekeeper 验证完成后生成。上传前失败不提交，提交后失败不产出发布 checksum 并保留证据。

主 App 与 Selection Helper 由两个构建脚本分别构建、签名和审计，再分别制作 DMG、公证和发布。两者的签名、公证和真实配对证据当前仍是 Beta 1 发布前阻断项。

Direct 发布版本由 `Distribution.DirectBeta.xcconfig` 中的 `MARKETING_VERSION`、`CURRENT_PROJECT_VERSION` 和 `BLOCKS_RELEASE_NAME` 锁定。Helper bundle audit 要求三项 Info.plist 字段均为字符串且与该配置逐字一致；缺失、重复的配置定义、未展开变量或不匹配的产物会失败。构建 Helper 后先做结构与版本审计，再施加最终签名，打包及公证路径仍会重跑审计。主 App 与 Helper 的 `package_dmg.sh --release-name` 还必须与包内 `BLOCKS_RELEASE_NAME` 一致，避免正确的包被命名成另一个发布版本。发布旧版本时须使用该版本对应的冻结检出，不能拿当前配置审计不同版本的包。

上述是发布产物一致性门禁。Helper 可独立更新，运行时仍按已认证的协议兼容范围判断，营销版本号本身不是安全信任根；若后续安全变更要求拒绝旧 Helper，必须同步提升协议最低兼容版本并补升级与重配对测试，不能仅改展示版本号。

## 2. App Store Beta

只用于本地结构审计、不可上传：

```bash
script/release/build_app_store_beta.sh --unsigned
```

App ID/profile 与外部资源门禁完成，且 Apple Distribution/profile 可用后：

```bash
export BLOCKS_APPLE_DISTRIBUTION_IDENTITY='Apple Distribution: CONFIRMED NAME (TEAMID)'
export BLOCKS_EXPECTED_SIGNING_CERT_SHA1='CONFIRMED_40_HEX_SHA1'
script/release/build_app_store_beta.sh
```

上述 Authority 必须与 `ReleaseIdentity.local.xcconfig` 中确认的 `DEVELOPMENT_TEAM` 对应，SHA-1 必须是同一 Apple Distribution leaf 证书的 40 位值；缺失、类型错误或不匹配时脚本会在 Archive 前 fail closed。Profile specifier 仍只保存在被 Git 忽略的 local xcconfig 中。

脚本只创建并审计 Archive，不上传 App Store Connect。上传是阶段 0 之后的显式外部动作，必须另行确认，并在上传前完成隐私清单、Required Reason API、出口合规、审核说明和真实权限演示路径复核。

## 3. 官网与下载托管

- `site/` 生成 24 页三语纯静态草案；当前保持 `noindex`，包含锁定的正式 URL 与保留邮箱标识，但明确标注邮箱尚未启用，并且不含反馈表单、下载、遥测、客户端脚本或 Worker。
- 外部资源门禁完成后才创建 Cloudflare Pages 项目并绑定最终域名。
- 生产 DMG、SHA-256、文件大小、最低系统和公证状态发布到 R2 自定义下载域名，不使用 `r2.dev` 作为生产地址。
- 版本文件使用不可变 URL，例如 `/beta/0.1.0-beta.1/Blocks-0.1.0-beta.1-arm64.dmg`；“最新版本”页面只能引用该不可变对象，不能覆盖旧对象。
- 官网使用 `blocks.orangeforge.top`，下载使用 `downloads.orangeforge.top`；注册商保留阿里云，只有进入部署阶段才迁移 DNS 托管和配置跳转。
- 部署前必须再次核对已写入发布配置的最终 HTTPS 下载、支持和隐私 URL，并重新构建；空值、模板值和非 HTTPS URL 不得进入发布产物。

## 4. 发布后门禁

每个候选包都要在干净用户账户和真实浏览器下载路径验证隔离属性、安装、首启、拒绝/授予/撤销权限、覆盖安装和恢复。外部 TextEdit、Safari、Preview 和 Electron App 的真实交互证据不能由单元测试或构建成功替代。

## 5. 本地开发安装验收（不是发布包）

`script/build_and_run.sh --verify-permissions` 会构建、替换并启动稳定路径下的主 App，不是只读检查；P7-K 默认调用此入口。`--verify-permissions-existing` 不构建，但仍会停止并重启已有主 App。执行前应确认本次验收允许影响该安装版；独立 Selection Helper 不由该脚本停止或替换。

当前 Development entitlement 已包含用于 Helper 安全配对的共享 Keychain access group，因此本地 Apple Development 签名也需要授权这些访问组的匹配 provisioning profile；不能认为 profile 仅在 Store 分发时需要。缺文件时应配置/导入合法开发 profile，不得删除 entitlement 或以 ad-hoc 包冒充已签名验收版。新增 Apple Developer 后台资源需单独确认；不因本地安装许可而自动创建。

主 App 的 Debug `PROVISIONING_PROFILE_SPECIFIER` 通过 `BLOCKS_MAIN_APP_DEVELOPMENT_PROFILE` 读取本机被忽略的 `Signing.local.xcconfig`；真实 profile 名称/UUID 不写入已跟踪工程。独立 Helper 和其他配置不引用该变量，不把主 App profile 广泛施加到整个构建依赖图。首次导入后应核实生成包的 App ID/Team、精确 Keychain groups、embedded profile 与正在运行代码身份，而不只检查构建退出码。

安装前先在稳定目录内完整暂存产物，确认主可执行文件存在并通过 `codesign --verify --deep --strict`；完成后才停止主 App、暂存旧包并提升新包。普通复制/校验失败不停止或删除旧 App，提升失败会尝试恢复旧包。新包成功到位后才清理暂存目录内的旧包；这不提供启动失败后的自动降级，需保留长期回滚包时应另行备份。

同一路径用 `.Blocks-install.lock` 阻止脚本安装相互覆盖。中断遗留锁不会自动判定为过期；先核查安装进程与 `.Blocks-install.*/previous.app`，确认是否需恢复旧包，再由操作者决定清理。两次目录移动不是断电级原子交换，不得宣称已经验证系统崩溃/断电恢复或 App 数据迁移。

无安装副作用的自检入口为 `PYTHONDONTWRITEBYTECODE=1 python3 tools/verification/stable_app_install_self_test.py`：18 个用例均使用临时假 App，其中真实系统工具用例只为合成包作 ad-hoc 签名，不读取开发证书、不启动 App、不改 TCC。P7-H 已纳入该自检；静态/夹具通过仍不代替当前安装版体验验收。
