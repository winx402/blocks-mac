# Issue #47 与 Beta 5

## 实现

- 截图、剪贴板、翻译源、插件四模块由 App 持久授权，默认关闭，不从旧总开关迁移全部授权。总开关保留为断路；明确授权后的模块选择跨升级保留。
- `blocks list` 经现有签名身份验证及 Broker/App 实时查询；不回退全量静态列表。Host 入口、等待全文授权之后及只读响应交付前检查授权，撤销取消对应任务，已提交写入仍报告真实结果。
- App 持有共享 CLI 安装控制器。明确启用模块时配置命令，启动时仅刷新、更新既有受管记录；源码版默认 `.local/bin/blocks-dev`，官方版首次通过系统面板授权目录后管理 `blocks`。
- 保留文件身份、摘要、原子操作和 journal 恢复。拒绝静态符号链接父目录、外来命令或修改过的受管文件；不修改 shell 配置。卸载抑制自动重装，不改变模块权限；安全隔离的恢复文件可能仍需用户核对处理。
- 安装、恢复、卸载与面板等待纳入应用升级 admission；退出先取消面板/任务，再按既有退出策略处理。
- 离线反馈与隐私命令保留原独立通道及确认规则，设置明确说明不受四模块控制，不把 App 模块开关描述为系统级隔离。

## 验证与修复过程

- 模块、自动安装与隐私相关测试分批完成：7 项模块测试、13 项安装管理测试、16 项全文授权测试、4 项 Store/Host 测试最终通过；原有45项 CLI 安装/恢复回归通过。
- 新增独立模块的7项优化编译动作列表回归，原23项 CLI 输出优化测试、剪贴板 CLI 自检、P14/P15 合约和 UI 设计系统检查通过。
- 集成时真实 `blocks list` 曾 SIGTRAP：分离模块 `swiftc -O` 可复现，反汇编显示在编码前直接进入 brk。已把列表错误判断和编码放入非泛型普通返回值函数；真实无身份 CLI 返回JSON错误和exit1，已安装已签名CLI在服务关闭时返回broker_unavailable，不再崩溃。
- 目录测试确证 Foundation 把 `/private/var` 标准化回 symlink `/var`，触发安全拒绝。改用原始路径组件、测试采用POSIX realpath；真实临时目录探针创建0700目录成功，symlink父目录仍拒绝。
- 修补启动reconcile吞显式配置请求、缺失受管目录无法恢复、插件等待后缺取消检查等边界；普通取消与模块撤销错误码分开。
- 卸载测试首次错误期待完全清理，核对旧worker发现其原有安全约定为隔离并保留quarantine/journal。修正测试验证该约定，未放松生产文件身份校验。
- 本机开发版已保持同一证书更新，设置页实见四个关闭的模块开关及自动管理说明；未代用户启用模块，未查询其真实历史。

## 沙盒与发布边界

官方版保留沙盒，首次不能无授权写入真实PATH目录。按 [Apple文件访问文档](https://developer.apple.com/documentation/security/accessing-files-from-the-macos-app-sandbox)，Direct主App增加 `com.apple.security.files.user-selected.executable`，用于向用户已授权位置写入命令；不增加任意路径或AX权限例外。分发审核精确允许并要求此key=true，缺失/false负向用例失败；Store旧策略与嵌套组件白名单不扩大。

安装权限与目录bookmark测试使用隔离fixture。真实官方沙盒首次目录授权、模块切换的完整XPC回路及实际跨版本自动更新仍未验证；不把单元测试或签名审核等同这些交互已通过。#47 暂保留开放。

目标 `0.1.0-beta.5`，签名、公证、公开下载与更新源验证后补充发布证据。
