# Issues #66 / #67 与 Beta 19

本轮只处理新增权限恢复与助手设置问题；#64 的钉钉输入、#65 的完整登录启动、
#59 / #62 中仍加载且不可启动的旧 Broker 迁移不因本轮测试通过而关闭。

## 实施

- 主 App 权限恢复由 PermissionStore 单独拥有，最多检查三次。签名类型不再限制重启入口。
- 两字段票据仅记录目标权限与恢复阶段；新进程一次性消费并回到权限页。scheduled 仅表示启动器接手。
- 权限重启有独立的可恢复准备所有权，与 Sparkle / 源码更新互斥；准备失败、取消及超时不强退 App。
- 独立启动器先报告 READY，再等待 owned stdin 的 COMMIT。没有确认时，父进程退出也不打开 App。
- 取消只操作登记的 Process 对象，确认退出后才恢复业务与允许重试；写管道不会传递 SIGPIPE。
- 权限页与翻译页共用助手设置弹窗，打开弹窗不启动助手。人工配对失败不被被动健康刷新覆盖。
- Helper 的“监听已就绪”不再代表与主 App 的认证连接；不改变配对协议、信任或安全存储。
- 配对码在助手提交后消费。主 App 保存密钥失败是可能的单边状态，旧码重试不能假装恢复。

## 验证

环境：macOS 27.0（26A428），Xcode 26.6（17F113）；不同于 #66 / #67 原报告的系统环境。

- LocalDevelopment 完整构建通过。该配置固定登记安装身份，拒绝临时助手 fixture 是预期边界；
  初次新助手测试在此配置失败，不通过修改产品信任来消除。
- 使用仓库测试入口同类的 DebugTesting 配置，无证书构建及最终 103 项定向 XCTest 全部通过。
  覆盖 PermissionRecoveryFlowTests、PermissionRestartTests、SelectionHelperSetupFlowTests、
  AppUpdateCoordinatorTests、ActionBrokerUpdateSafetyTests 及现有权限/重启回归。
- Xcode ibtoold 残留两次经受控验证确认并清理，增量重试通过；不声称首次构建清理检查成功。
- application_update_safety_self_test、quit_watchdog_self_test、helper_keychain_acl_self_test、
  selection_helper_association_self_test（7 项）、release_pipeline_self_test 与 UI 设计系统门禁通过。
- 隔离主 App 实际打开权限页与恢复弹窗：没有终端命令出现在主恢复流程；复查不会重启或重复弹授权。
  此界面验收使用测试权限快照，不能证明真实 TCC 已授权。
- permission_restart_runtime_probe 使用完整生产重启/终止实现，在 Developer ID 签名的临时沙盒 App
  中验证旧 PID 消失后仅重新打开一次；拒绝准备后等待超过普通退出 deadline，原进程仍存活。
  它不包含完整业务参与者，也不验证 TCC 或用户数据迁移。
- 实机复验曾观察到旧进程退出后 open 失败；最终改为明确新实例启动当前绝对路径（open -n），
  并增加两阶段确认，重新完成签名沙盒探针。保留失败事实，不把早期一次通过当成稳定结论。
- 历史 permission_gate_helpers_self_test 的静态匹配器未适配现有拆分形态，运行未通过；不是本轮 CI
  的必经门禁。此结果单独记录，不混同 XCTest 与已通过的设计系统检查。
