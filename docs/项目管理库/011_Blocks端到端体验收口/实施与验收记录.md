# Blocks 端到端体验实施、审计与验收记录

状态：implementation-validation
最后审阅：2026-07-21
来源级别：implementation and acceptance record

## 已确认根因

### 全屏编辑器两侧棋盘格

- 编辑器为顶部状态条和底部工具栏保留空间后，会按比例缩小全屏截图；旧画布把整个 NSView 背景无条件绘制成透明棋盘格，因此截图之外的对称留边被错误显示为马赛克。
- 该现象只属于编辑器 Chrome，不代表截图本身存在透明像素；导出尺寸和图像像素没有因此变化。

### 窗口截图无高亮或命中错误

- 旧候选只按 `isOnScreen` 和最小尺寸过滤，没有把普通窗口、App 浮层、菜单、Tooltip、系统覆盖层和 Blocks 自身选区层收敛成同一表面分类。
- 旧遮挡计算虽然能够扣除前方矩形，但无法判断前方表面是否应参与遮挡；系统覆盖层可能抢占命中，完全被正常窗口遮挡的后方窗口也缺少最终捕获前的统一复核。
- 初始选择、冻结画面和最终输出曾分别读取窗口列表，分类口径与前后顺序快照不保证一致。
- 安装版低敏窗口夹具暴露了第二个真实根因：选区层消失后 Blocks 主窗口会重回前台，旧最终校验只排除临时选区窗口，会把 Blocks 主窗口当成正常遮挡物，将已高亮的外部窗口误判为不可见，最终不进入编辑器。
- 同一交接路径还将“仅选区层”作为显式排除列表传入屏幕像素捕获，从而绕过既有的“排除 Blocks 全部自身窗口”默认分支；这是 Blocks 设置窗口会出现在编辑器源图中的直接原因。

### 剪贴板筛选空列表

- Store 已统一维护历史与搜索 revision，但面板只有可见记录出现时才触发下一页。当当前加载页在标签、来源或类型筛选后恰好为零项时，后续页即使存在匹配记录也不会继续加载，表现为错误空状态。

## 当前实现

- 编辑器根视图与 AppKit 画布统一使用系统 `windowBackgroundColor` 作为 Chrome 背景；棋盘格不再铺满画布。截图按原比例居中，留边保持对称，输出路径不变。
- 新增 `ScreenshotWindowSurfaceRole` 和统一分类器；普通窗口与 App 浮层可选并参与遮挡，瞬态表面、系统覆盖层和 Blocks 自身所有窗口不可选且不参与遮挡。
- 窗口按真实前后顺序逐层扣除前方可遮挡表面。候选保存完整 frame 和露出命中区域：部分可见窗口只能从露出区域选择，完全遮挡窗口不进入候选。
- 延迟或选区层交接后，最终窗口捕获重新生成同一分类和可见性结果；目标若已经完全遮挡或消失则拒绝捕获，仍可见时按完整精确 frame 输出。
- 交接后的屏幕像素与编辑底图统一使用完整 `excludedCaptureWindows`，同时排除临时选区层和所有 Blocks 持久窗口；延迟捕获使用延迟后的 live content 重新计算该集合。
- 剪贴板面板增加纯策略分页判断；有活动筛选且当前结果为空时继续逐页回填，直到找到可见项或历史耗尽。取消、revision 和单次加载任务仍沿用既有门禁。
- 设置审计修正收藏保留语义、翻译语言本地化展示、主要快捷键与快速粘贴数量区分、权限技术字段折叠，以及通用页说明和诊断信息层级；底层存储值未迁移。

## 低敏 UI 审计

- 使用独立 Bundle ID、独立 Application Support 根目录和空白测试数据检查设置页，不接触正式历史。
- 已检查截图、剪贴板、翻译和通用设置的深色状态，以及截图和通用设置的浅色状态；控件尾列、基线、语义色和折叠诊断信息保持一致。
- 设置证据存放在 `evidence/settings/`。稳定签名安装版的窗口高亮、窗口编辑器和全屏中性背景证据存放在 `evidence/screenshot/`。

- Debug 签名构建与安装、Release 构建、Xcode Analyze、String Catalog JSON 解析和 `git diff --check` 通过。
- 真实窗口验收使用前景窗口、后方窗口和浮动面板组成的低敏夹具：`Tab` 进入的高亮严格落在可见前景窗口，点击后稳定进入编辑器，裁剪像素尺寸 880×984 与夹具完整 440×492pt frame 的 2x 缩放一致。关闭编辑器，没有完成或保存用户屏幕内容。

- 真实鼠标“仅从部分露出区域命中”和多屏/竖屏仍缺当前硬件条件下的完整录屏；几何、候选循环、完全遮挡排除与完整 frame 输出已有自动化覆盖，该缺口不写成实机 PASS。
