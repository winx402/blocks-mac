# 品牌重命名方案：旧称到积木工具 / blocks

状态：implemented / manual-permission-verification-pending
最后审阅：2026-07-05

本文记录将旧称“奇点 / JDTool”体系统一改为“积木工具 / blocks”的实施方案。2026-07-05 已执行首轮迁移；实施记录见 [2026-07-05 工具重命名实施记录](2026-07-05-工具重命名实施记录.md)。本文中的旧称用于说明迁移来源，不再代表当前有效命名。

## 目标

- 中文产品名统一为“积木工具”。
- 英文和日文公开产品名统一为“Blocks for Mac”；工程技术名仍为 `Blocks`。
- 正式描述整体产品时，可使用“积木 AI 工具箱”。
- 技术名统一为 `blocks`。
- 系统身份全量换新为 `app.blocks.*` / `group.app.blocks.*`。
- 当前有效文档、代码、App、CLI、schema、脚本和验证工具已在首轮实施中统一迁移。

## 命名决策

| 层面 | 旧命名 | 新命名 |
| --- | --- | --- |
| 中文显示名 | 奇点工具 | 积木工具 |
| 中文正式描述 | 奇点 AI 工具箱 | 积木 AI 工具箱 |
| CLI | `jdtool` | `blocks` |
| Swift / Xcode 技术名 | `JDTool` / `JDToolCore` | `Blocks` / `BlocksCore` |
| Action namespace | `jdtool.*` | `blocks.*` |
| Bundle ID | `com.jdtool.*` | `app.blocks.*` |
| App Group | `group.com.jdtool.*` | `group.app.blocks.*` |
| 环境变量前缀 | `JDTOOL_*` | `BLOCKS_*` |

## 实施范围

- App/Xcode：迁移 project、scheme、target、product、module、import、Info.plist、entitlements、登录项 Helper、日志 subsystem 和 dev build 路径。
- CLI：将可执行文件、命令文案、脚本调用和验证入口从 `jdtool` 改为 `blocks`。
- Action contracts：将 `jdtool.clipboard.search`、`jdtool.screenshot.capture`、`jdtool.translate.text` 等 action id、schema 文件、examples、catalog 和 hook manifest 迁移为 `blocks.*`。
- 代码与脚本：迁移 `JDTool` / `jdtool` / `JDTOOL_*` / `com.jdtool.*` / `group.com.jdtool.*` 等技术命名。
- 文档：当前有效文档统一改为“积木工具 / 积木 AI 工具箱 / blocks”；历史验收、证据和记录仅在必要处保留“旧称”说明。
- 验证工具：同步更新 verification scripts、spikes、smoke tests 和旧名残留扫描规则。

## 明确不做

- 不重命名父级工作区 `/Users/bot/Documents/Mac 工具集`。
- 不保留 `JDTool` / `jdtool` / `com.jdtool.*` 兼容层。
- 不在历史证据中机械替换所有旧称，避免削弱旧记录的可追溯性。

## 兼容性影响

- macOS 会将全量换新后的 App 识别为新应用。
- 旧 TCC 权限不会自动继承，需要用户重新授权屏幕录制、辅助功能等系统权限。
- 旧 Keychain service 和旧 App Group 容器数据不做自动迁移。
- 旧 CLI `jdtool` 不提供别名，后续脚本和文档应改用 `blocks`。

## 后续实施验证

- 执行旧名残留扫描：`rg "奇点|JDTool|jdtool|com\\.jdtool|JDTOOL|group\\.com\\.jdtool"`，只允许归档和本项目旧称说明命中。
- 验证 Xcode project、scheme、target、product、bundle id、entitlements 和 CLI executable。
- 跑 schema catalog、CLI smoke、App build、Helper / spike 验证和文档链接检查。
- 确认当前有效文档不再暴露旧品牌，历史记录中的旧称均有合理语境。
