## 当前源码范围

以下是源码与构建产物事实，不等同于安装版验收：

### 统一会话与结果

- `TranslationInput`、`TranslationSessionSnapshot`、BCP-47 语言模型和最多四个
  服务的稳定顺序并发。
- 输入防抖、revision 取消、迟到结果拒绝、独立结果卡失败/重试和整次收藏。
- 截图翻译复用区域捕获和 Vision OCR，不进入截图编辑器、不写截图历史或剪贴板。

### 数据与翻译源

- 数据库迁移目标从 v12 升至 v13：
  - v12 保留翻译收藏、收藏结果和插件元数据。
  - v13 新增 `translation_service_profiles` 和模板/更新时间索引。
  - Apple 本地 Profile 由数据库唯一索引保持单例；其他模板可创建多个稳定实例。
- Profile 只保存非敏感配置；API Key、AK/SK、Token 与会话凭据由 Keychain 边界
  管理，Repository 会拒绝敏感字段落入普通配置。
- Profile 加载采用逐行恢复：无法解码的 v13 行作为明确 load issue 上报，其余健康
  Profile 继续进入 Store 与 Registry；数据库级读取失败时保留最后一份有效状态，
  不把瞬时失败解释为空配置并覆盖用户启用顺序。
- 当前官方适配器包含：
  - Apple 本地翻译。
  - OpenAI-compatible。
  - DeepL API Free。
  - Microsoft Translator。
  - Google Cloud Translation Basic。
  - 阿里云机器翻译。
  - LibreTranslate。
- 外部 Profile 默认关闭；流程收敛为
  `添加 → 配置 → 保存并启用 → 可选连接验证 → 排序`。配置完整即可运行，连接验证
  是独立状态和操作；验证失败不得回滚已保存配置，也不得被误写成配置缺失。
- LibreTranslate 仅第一方适配器允许用户明确配置的 loopback HTTP；公网端点要求
  HTTPS 并通过既有地址策略。
- LibreTranslate Base URL 在 Repository 持久化前即执行统一策略：
  - 拒绝 user-info、query 和 fragment，避免凭据借 URL 进入 SQLite。
  - 只允许公网 HTTPS，或用户明确配置的 `127.0.0.1`、`::1` loopback HTTP。
  - 拒绝其他本机名和私网地址，并限制长度。
  - 写入前规范化 scheme 与 host；运行时 `/languages`、`/translate` 端点构造复用
    同一策略，不能静默丢弃曾被设置页接受的 URL 组件。
- LibreTranslate 连接验证先通过实例 `/languages` 获取 source→target 有向能力图，
  不再使用静态语言集合或固定 `en → zh`：
  - 保留服务端原始语言码，并将 `zh`、`zt` 分别映射为 `zh-Hans`、`zh-Hant`。
  - 从该实例真实支持的有向边中确定低敏验证语言对与文本。
  - 能力快照按 Profile ID 和配置 revision 独立缓存，并限制语言数、边数和编码尺寸。
  - 缓存缺失、损坏、超限或 revision 不匹配时，该 Profile 不得作为已验证服务运行。

### 划词与焦点

- 主 App 保持 App Sandbox，不直接访问 `com.apple.axserver`。
- Direct Debug/Release 嵌入 `BlocksSelectionAgent`：
  - 可执行文件位于 `Contents/Resources/BlocksSelectionAgent`。
  - LaunchAgent plist 位于 `Contents/Library/LaunchAgents/`。
  - Helper 非沙箱，仅提供单次 AX 选区读取、权限状态/请求与取消。
- XPC 请求包含 request ID、目标 PID/Bundle ID、截止时间与字符上限；结果返回文字、
  选区范围、屏幕位置、role/subrole 或明确失败码。
- 总超时从快捷键触发开始，包含注册与连接；超时会向 Helper 发送取消并拒绝迟到结果。
- 面板骨架在 Helper 返回前立即显示，不再等待同步冻结；成功或失败后都会展开并请求
  输入框真实第一响应者。
- 用户开始输入后 revision 会拒绝迟到的 AX 内容覆盖。
- AppStoreRelease 不包含 Helper 或 Selection Agent Mach lookup；该渠道降级为聚焦
  手动输入和截图翻译。
- 安装/替换稳定 App 时，脚本通过 `app.blocks.selection-agent` launchd service
  精确读取旧 Helper PID，发送 `SIGTERM` 并有界等待退出；替换 App 前再次停止。
  旧 `pkill -x BlocksSelectionAgent` 因 Darwin 进程名匹配长度限制无法可靠命中，已
  删除。

### 设置侧栏

- 旧扁平侧栏已替换为 AppKit `NSOutlineView` Source List：
  - 工具：截图、剪贴板、翻译、翻译收藏。
  - 系统：快捷键、权限。
  - 智能：AI 服务、本地自动化、自动化触发。
  - 数据：数据与审计。
  - 应用：通用。
- 5 个分组标题不可选择；只有 11 个真实路由可选择。
- `.settings` 内部路由值保持不变，用户可见标题改为“通用”。
- 外部跳转和尺寸变化会把当前路由滚入可见区域。

### 原生插件

- `.blocksplugin` Manifest 目标版本为 v2，继续兼容 v1。
- v2 配置字段支持 `text`、`url`、`secret`、`boolean`、`choice`、
  `sessionCredential` 及说明、必填、默认值、枚举、长度和帮助链接。
- v1 `permissions.secrets` 和 v2 敏感配置字段都由同一声明解析边界驱动保存、删除、
  最大长度校验与 Keychain 生命周期；v1 兼容不再停留在清单解码层。
- v2 Manifest 的 Secret 声明与敏感配置字段必须一一对应；升级契约比较 schema
  版本、敏感字段类型和规范化 `allowedDomains`。删除、类型变化、域名变化及
  v1/v2 跨版本均撤销旧 Secret，契约不变才保留。
- 插件始终以禁用状态安装；只有包哈希、规范化配置哈希和凭据 revision 对应的当前
  连接验证成功后才能启用。
- 包、配置、Secret 变化或连接验证失败会使验证失效并禁用插件。
- Runner 继续在签名 XPC 中执行；连接测试使用 Host 保留入口，普通执行不能绕过
  生命周期门禁。

## 已确认并修复的本轮偏差

- 旧口径把 AX 直接放在主 App；真实沙箱拒绝证明该架构不可运行，现已收敛到最小
  Selection Agent。
- Helper 的 Debug/ad-hoc 身份绕过已删除；Direct 产物要求主 App 与 Helper 都有
  非空且相同 Team。
- Helper 的初始总超时曾不包含注册时间；现已从触发时开始计时。
- 初版 Helper 放在 `Contents/MacOS`；现迁到 `Contents/Resources`，降低被误识别为
  主可执行入口的风险。
- 面板骨架曾等待 Helper 冻结完成才出现；现已改为触发后立即呈现，AX 读取独立进行。
- 初版服务设置会把“已保存但验证失败”显示成整体保存失败；现分离保存结果与验证结果。
- 初版插件配置缺少必填字段阻断和可见连接验证；现已补齐保存禁用、行内错误、连接
  测试和重新验证反馈。
- 初版第三方插件签名文案可能产生“发布者已验证”误解；当前未建立可信发布者链时只
  显示“发布者未验证”。
- 旧设置证据记录的是扁平 11 路由；当前实现已恢复 5 组 Source List，该旧证据不能
  继续用于验收新侧栏。
- 初版 v13 Profile 列表遇到一条损坏数据时会使整批加载失败；现逐行隔离损坏行并
  保留健康服务，数据库级失败继续使用最后良好状态。
- 初版 LibreTranslate 使用静态语言能力和固定 `en → zh` 验证，既不能表示自托管实例
  差异，也可能验证一个服务不支持的方向；现改为 `/languages` 有向图、实例级动态
  验证与有界缓存。
- 初版 LibreTranslate Base URL 只在运行时检查，含 user-info、query 或 fragment 的
  敏感值可能先进入普通配置；现已把规范化和拒绝策略前移到 Repository 保存边界，并
  与运行时端点策略共用同一实现。
- 初版 v1 插件 Secret 只兼容清单解码，保存和删除仍只查 v2 字段；现已统一 v1/v2
  Secret 声明与生命周期。
- 代码复审发现同 ID 插件升级只按 Secret ID 判断保留，删除敏感字段、改变字段类型
  或改变会话凭据域名时可能继续复用旧凭据；现已补齐双向一一对应校验和升级契约，
  并复用持久化 tombstone 对中断撤销做幂等前向恢复。
- 初版安装脚本以 `pkill -x` 停止 Selection Agent；20 字符 Helper 名称无法被该
  路径可靠匹配，现改为 launchd label→PID 的精确停止和替换前二次确认。
- 代码复审还发现稳定 App 安装校验可能接受旧 PID 或同 Bundle ID 的错误进程；现已
  删除宽泛 `pkill -x Blocks`，替换前按精确 bundle 枚举旧 PID 并有界等待，启动后
  必须同时满足新 PID、精确可执行路径、`finishedLaunching` 以及 Identifier、
  TeamIdentifier、CDHash 与安装产物一致。

- 每次入口在 `beginEntry` 冻结鼠标所在显示器；异步剪贴板读取和收藏重译会把该

  设置 frame 后再 `orderFront`，窗口动画为 `.none`；删除选区四方向布局、
  Helper 二次移动和历史位置恢复，只保留尺寸偏好。
- 设置动作改为 `openTranslationSettings`；`AppModel` 的导航 generation 使相同
  路由请求也会同步原生 Source List 并滚入可见区域。
- 空选区类失败静默转入空输入并请求第一响应者；Helper、辅助功能、版本、超时和
  目标退出等仍显示恢复信息。兼容取词和截图翻译保留在原文区操作菜单。

## 2026-07-29 翻译方向、结果操作与排序收口

### 根因

1. 会话启动前没有生成所有适配器共用的确定翻译方向。短文本的系统语言识别失败
   时，空源语言被交给 Apple、MyMemory 和其他适配器，各适配器又按自己的规则处理，
   同一输入因此可能出现不一致结果。Natural Language 对极短文本的低置信结果也会
   被直接采用，`no/ok/hi` 等短词可能被误识别为关注语言之外的语种。
2. 已启用服务列表可以保留尚未完成配置的 OpenAI-compatible 项；它会进入运行队列

## 2026-07-31 面板、自定义翻译源与 CLI 收口

### 根因与修复范围

1. 翻译面板顶部空白并非内容数据异常，而是一个没有固有高度的 AppKit 拖动承载视图
   参与 SwiftUI 纵向布局后接受了剩余高度。当前标题栏固定为 50pt，窗口高度变化只
   分配给结果区；窗口拖动仍只覆盖标题及空白区域，不覆盖操作按钮。
2. 结果卡排序此前混用 AppKit 拖动源和 SwiftUI Drop 状态，投放阶段依赖拖动中的
   `@State` 取源 ID，真实生命周期下可能丢失或迟到。第一轮改为原生
   `NSDraggingSession` 后，安装版确认普通设置窗口可以收到投放回调，但非激活翻译
   `NSPanel` 只启动拖影、不进入目标回调。为保持面板不抢占外部翻译目标，最终由面板
   与设置页共用 `TranslationServiceOrderDragCoordinator`，AppKit 承载视图在同一
   `mouseDown / mouseDragged / mouseUp` 生命周期内维护真实 `serviceID`、目标、2pt
   插入线、取消和投放；不再读取 SwiftUI 拖动 `@State`。一次成功投放只执行一次
   顺序更新和一次持久化。
3. Apple Vision observation confidence 在现有中文样本中长期返回 `0.5`，该原始值
   没有经过面向用户的准确率校准。产品界面已删除百分比和统一阈值警告，只保留
   “已识别 N 行”；原始 confidence 继续用于诊断和测试，不再被解释为识别准确率。
4. 自定义翻译源此前没有与内置源共用完整输入、状态和终态契约，设置与 CLI 也缺少
   统一管理边界。当前内置、官方、社区和插件源统一消费
   `TranslationSourceInvocation` 并产生 `TranslationSourceEvent`；Host 仍是状态机
   唯一所有者，插件只能发送有界状态、诊断以及唯一成功或失败终态。
5. 代码复审发现配置写入失败与插件运行快照刷新失败可能形成两类不一致：
   - 无效配置若先写后验，可能破坏当前仍可运行的已启用插件。
   - Secret 已变更但权威插件快照刷新失败时，旧启用顺序可能继续引用无法确认有效的
     插件。
   当前配置保存先完整校验、校验失败不进入变更；Secret/配置变更后的权威快照采用
   fail-closed，同步失败会从运行启用顺序移除陈旧插件，不把旧内存状态冒充当前有效。

## 2026-07-31 语言能力、收藏确认与 Input Echo 收口

### 根因和修复

- 冷门语言结果不一致不全是正常措辞差异。真实网络响应确认腾讯网页源会把多个不支持的
  `en → target` 请求回退为中文，并返回 `target=zh`；旧实现只验证非空译文，所以形成
  假成功。现在翻译源先验证有方向的语言对，接口提供返回目标时还必须与请求一致。
- 不兼容服务仍保留在结果列表原位置并显示“该语言方向不支持”；兼容服务继续运行，
  不因单源能力不足取消整次会话。
- 源语言和目标语言菜单使用同一分组模型：母语、最近使用关注语言、其余关注语言去重后
  置顶，全部语言按当前界面语言排序；当前选择即使不属于常用语言也不会丢失。
- 收藏成功改用全局 `.compactConfirmation`：星标与单行文字整体居中、内容宽度自适应、
  无错误卡状态线和关闭按钮，约 2 秒自动关闭；失败继续使用标准错误通知。
- 新增 `Blocks Input Echo` 示例插件，动态回显所有获准文字/语言/上下文和截图附件元数据，
  不返回原图 Base64，超限时以 `echo_output_too_large` 明确失败。
