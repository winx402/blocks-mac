# OCR 识别质量与调度实施记录

状态：complete
最后审阅：2026-07-21
来源级别：implementation record

## 根因与证据

### 已确认事实

- 原实现固定开启 Vision 语言纠错。真实合成图上，纠错会把“截图文字识别”错误识别为近形繁体/日文字形，并破坏 `v19.2 100% @MainActor` 的空格。
- 原长图按 tile 先转字符串，再仅以完全相同的首尾字符串去重。9000px 合成图期望 72 行，旧实现得到 76 行。
- 剪贴板自动 OCR 会一次连续排空至少 4 项；截图编辑器、钉图和历史队列直接共用底层串行 OperationQueue，但没有显式场景优先级。
- 钉图 OCR 没有重复请求合并、关闭取消和迟到结果门禁。
- Repository 的通用 OCR 更新方法在 `.running` 和终态都会增加 `ocrAttemptCount`，一次实际识别可能被计为两次。

### 实施结果

- 默认识别关闭语言纠错，保留四语言自动检测；仅对空结果或稀疏低置信度结果尝试纠错，并且只有覆盖度与平均置信度同时改善才替换主结果。
- 对短东亚文字行增加日文优先的局部候选复核；只替换几何位置相同且字符覆盖更完整的行，避免日文词尾被中文优先级吞掉，同时不覆盖同长度的简体中文结果。
- Observation 保留置信度和几何；长图先映射到整图坐标，再按位置、文本相似度和置信度去重，最后只做一次全局阅读顺序解析。
- 新增共享 `LocalOCRCoordinator`：编辑器和钉图为交互优先级，GUI/CLI 重试为用户优先级，剪贴板、截图历史和启动恢复为后台优先级。
- 普通图片与截图历史在最后一次入库后静默 1.5 秒再识别；后台每次只处理一项，项目之间至少让出 250ms；启动恢复等待 3 秒。低电量或严重/临界热状态暂停启动后台识别。
- 钉图 OCR 同一窗口只允许一个在途请求；关闭窗口取消，generation 门禁拒绝迟到结果，并显示明确进度状态。
- OCR attempt 只在进入 `.running` 时增加一次；完成和失败保留该次数，取消回到 `.pending`，用户编辑锁仍然优先。
- OCR 完成后只刷新受影响的预览、搜索结果和已打开详情，不再重新加载整个剪贴板历史。
- 使用 `OSSignposter` 记录队列等待、像素规模桶、解码、Vision、布局、持久化和终态；不记录识别文本、图片、路径或完整记录 ID。

## 真实像素质量与性能门禁

新增 `tools/verification/p18_ocr_quality_checks.py`，运行生产 `LocalVisionOCRService` 和真实 Vision，合成语料覆盖：

- 浅色 2x 中英日混排。
- 深色 UI、尺寸/延迟/水印、百分比和 URL。
- 紧凑 UI、版本号和 Swift 标记。
- 繁体中文与日文。
- 透明背景。
- 72 行长图及重叠 tile。
- 3840×2160、24 行 UI 截图。

2026-07-21 当前本机每项连续运行 5 次的最终门禁结果：大号混排 CER `0%`、P95 `317.32ms`；深色 CER `1.43%`、P95 `236.87ms`；紧凑 UI CER `1.96%`、P95 `68.86ms`；繁日 CER `0%`、P95 `259.86ms`；透明背景 CER `0%`、P95 `117.54ms`。72 行长图每次行数与唯一序号均为 `72/72`，P95 `718.46ms`；4K 每次均为 `24/24`，P95 `242.09ms`。这些是本机证据，不作为跨机器绝对性能承诺。

## 自动化覆盖

- 主识别关闭纠错、受支持语言缓存、低置信度回退接受/拒绝。
- 全局几何去重容忍轻微字符差异。
- 横向行、多栏、日文竖排以及拉丁高框不误触发竖排。
- 交互请求优先于已经排队但尚未开始的后台请求。
- 手动 OCR 的取消、超时、revision 和最终合成图语义继续由 P15-C 覆盖。
- OCR 终态 attempt 只累计一次。
