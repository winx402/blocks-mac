# 第一阶段实施计划 v0

状态：ready-for-development
最后审阅：2026-07-05
来源级别：implementation plan

本计划承接 Step 1 架构方案和 App 架构师评审。第一阶段目标是低风险建立 Clipboard feature 边界，不做功能新增，不重写 UI，不重建 SQLite 基础设施。

## 目标

- 围绕既有 `ClipboardRepository` 建立 `ClipboardStore` / 用例层。
- 让 `AppState` 对剪贴板保持兼容 facade，但内部尽量转发到 `ClipboardStore`。
- 补齐结构门禁，防止后续新剪贴板逻辑继续写回 `AppState`。
- 修正或显式门禁 Provider route/runtime 契约不一致，避免第二阶段拆分前继续扩大风险。
- 保证用户可见功能不丢失。

## 本阶段不做

- 不重建 `StorageEnvironment`、`SQLiteConnection`、`AppDatabase`、`BlobStore`、`ClipboardRepository`。
- 不大规模搬迁 SwiftUI view。
- 不改变剪贴板产品行为。
- 不启用 helper 生产写库、App Group、CLI 读取完整剪贴板。
- 不默认采用 Observation 替换 `ObservableObject`。

## 开发任务

### Task 1：建立 ClipboardStore 边界

建议文件：

- 新增：`apps/Blocks/BlocksApp/Features/Clipboard/ClipboardStore.swift`
- 修改：`apps/Blocks/BlocksApp/Stores/AppState.swift`
- 修改：`apps/Blocks/Blocks.xcodeproj/project.pbxproj`

要求：

- `ClipboardStore` 为 `@MainActor final class ClipboardStore: ObservableObject`。
- 持有现有剪贴板 view state：records、payloads、filterState、pinboards、pinnedMetadata、recorderPaused、recorderExcludeFrontmost、recorderSessionDurationSeconds、recorderRuntimeState、pasteAttempt、floatingSelectedRecordID。
- 接收 `ClipboardRepository?` 和必要 service / closure 依赖，首轮可以保持薄封装，不强行拆所有 use case。
- `AppState` 初始化 `ClipboardStore`，保留现有公开属性和方法作为 facade，避免一次性改所有 View。
- 迁移后不得删除现有功能入口。

### Task 2：迁移剪贴板核心用例入口

建议迁移范围：

- load repository state。
- ingest live capture。
- filtered records / source filter options / preview / payload lookup。
- pin、move、rename、delete、clear unpinned。
- apply policy。
- copy plain text、paste / auto-paste 可先由 `AppState` 转发，但业务状态应在 `ClipboardStore` 内维护。

要求：

- 先保证行为一致，再考虑进一步拆 `ClipboardUseCases`。
- repository 不可用时不得静默承诺生产持久化；至少要保留可见状态或明确 debug/test fallback。
- 默认 payload 预载可以保留以保护当前 UI，但要在代码或门禁中标记为过渡，不新增新的批量完整 payload 读取 API。

### Task 3：补结构和契约门禁

建议文件：

- 新增或修改 `tools/verification/` 下的架构门禁脚本。

要求至少覆盖：

- `ClipboardStore.swift` 存在并由 `AppState` 持有。
- `AppState` 中剪贴板相关公开 API 作为 facade 存在，但不得新增 reset fixture 或第二套内存生产事实源。
- `BlocksCore` 不得 import SwiftUI / AppKit / Security / URLSession。
- `ProviderRouter` 与 Translation runtime 的 `.llmBacked` 契约不得继续互相矛盾；如果本阶段不修 runtime，门禁至少要标记该风险并防止继续扩散。

### Task 4：更新项目记录

建议文件：

- 新增：`docs/项目管理库/003_架构升级/step_2/开发记录-v0.md`

要求：

- 记录开发范围、未做事项、行为保全清单、验证命令和剩余风险。
- 明确本阶段是否修正 Provider route/runtime；如果未修，列为 Step 3 前置风险。

## 行为保全清单

开发完成后必须确认：

- App 启动后剪贴板记录能从 repository 加载。
- live capture 写入后面板刷新。
- 搜索、类型筛选、时间筛选、来源筛选、Pinboard 筛选仍可用。
- 固定、取消固定、移动分组、重命名、删除、清空未固定仍可用。
- 策略裁剪仍按 retention、max items、preserve pinned、excluded bundle 运行。
- copy plain text、paste / auto-paste、内部写入抑制仍可用。
- bottom / side 面板、hover detail、card width、bottom height、item font 设置不回归。
- debug recorder / preflight / import / reset debug store 仍是 debug 路径，不变成生产事实源。
