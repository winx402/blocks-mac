## 1. ClipboardStore / AppState facade 边界

### P1：边界符合 Step 1 / Step 2 目标

事实：

- `apps/Blocks/BlocksApp/Features/Clipboard/ClipboardStore.swift` 已新增 `@MainActor final class ClipboardStore: ObservableObject`。
- `ClipboardStore` 持有 records、payloads、filterState、pinboards、pinnedMetadata、recorder runtime、paste attempt、floating selection 等剪贴板状态。
- `ClipboardStore` 已接管 repository load、live capture ingest、preview、payload lookup、filter/source options、pin、move、rename、delete、policy prune、clear unpinned。
- `AppState` 保留原有剪贴板公开属性和方法，但内部通过 `clipboardStore` 转发，并用 `clipboardStore.objectWillChange` 继续驱动现有 SwiftUI 观察链。
- `apps/Blocks/Blocks.xcodeproj/project.pbxproj` 已把 `ClipboardStore.swift` 加入 Blocks app target。

判断：

该实现符合第一阶段“围绕既有 `ClipboardRepository` 建立 Clipboard feature store，用 `AppState` facade 保住现有 UI 行为”的目标。它不是最终形态，但已经把剪贴板生产 repository 和主要用例从 `AppState` 中抽出到 feature 边界内。

### P2：`AppState` 中保留的剪贴板编排可接受，但要进入 Step 3 收敛

事实：

- copy plain text、paste / auto-paste、内部 pasteboard 写入抑制、面板 presenter、权限失败后的 retry、debug recorder import/session/reset 仍在 `AppState` / service 编排路径中。
- debug import/reset/watch 通过 `clipboardRecords` / `clipboardPayloads` facade 写入 `ClipboardStore`，没有看到新建第二套生产事实源。

判断：

这符合 Step 2 计划中“先保功能、不大规模搬 UI / service 编排”的边界。本次不应为了追求纯粹分层继续扩大改动面；这些路径应在 Step 3 随 AppState 瘦身继续拆。

## 4. 应进入 Step 3 的风险

### P1：Provider route/runtime 契约

`ProviderRouter.resolve()` 对 `.llmBacked` 返回 unsupported，而 translation runtime 仍可走 OpenAI-compatible 执行入口。Step 3 开始前必须统一 `.llmBacked` 的 route 语义、secret gate、runtime readiness 和 audit 结果。

### P1：AppState 继续瘦身

`AppState` 还承担 paste / auto-paste、权限 retry、面板 presenter、debug recorder runtime、provider / translation、shortcut 和 screenshot 编排。Step 3 应继续按 feature store / use case / platform adapter 拆，不要让新逻辑继续回流到 `AppState`。

### P1：repository 降级策略

`repositoryUnavailable` 已经存在，但生产体验还需要决定是 fail closed、UI 显示降级，还是仅允许 debug/test fallback。这个策略要在下一阶段明确，不建议在本次 ClipboardStore 迁移中追加产品行为变化。

### P1：payload read model

当前仍按 recent records 预载 payload，以保护 paste、preview、hover、copy 和搜索行为。长期应转向 redacted list read model，并让完整 payload 只在 paste、hover detail、copy、translation preview 等明确动作中 lazy read。

### P2：SettingsView 与 settings pane 边界

Settings 仍通过全局 `AppState` 和 `@AppStorage` 驱动多个 feature。Provider / Translation 拆分时应同步拆对应 settings pane；Clipboard settings pane 可随后改为面向 `ClipboardStore` / preference adapter。

### P2：helper / App Group / CLI 边界

本次没有改变 helper 生产写库、App Group 共享容器、CLI 读取完整剪贴板等能力边界。下一阶段仍必须把这些作为未来扩展风险处理：helper 保持 debug / preflight / redacted watch，CLI 不绕过 confirmation，不默认返回完整敏感 payload，App Group 只能经 signing/provisioning 复测后接入。

### P2：验证门禁治理

P4/P5/P8/P9 已对齐 Step 2 边界；P7-A 仍依赖旧平铺路径和旧故事，后续应退役、替换或改造成当前项目视图下的验收门禁，避免继续产生误导性失败。
