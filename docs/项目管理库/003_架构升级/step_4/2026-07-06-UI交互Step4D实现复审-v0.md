## 2. 总体判断

UI / 交互侧当前不能建议直接最终接受，结论为 `changes-requested`。

阻断原因是最新安全 / 主会口径要求“默认 redacted title/search 不再使用 historical pinned `displayName`”，但当前静态代码中 `ClipboardController.filteredRecords` 仍把 `pinnedMetadata[record.id]?.displayName ?? ""` 拼入 searchable 文本。该路径影响 Clipboard panel 搜索 / 过滤结果，属于用户可见的信息结构行为，且当前 P11E 只检查 `ClipboardRedactedPreviewBuilder` body 是否包含 `.displayName`，没有覆盖 `ClipboardController.filteredRecords` 的 searchable 拼接。

展示层面已经看到主要 hardening 成果：

- `ClipboardRedactedPreviewBuilder.preview` 的 title 改为 `redactedTitle(for:)`，不再优先使用 pinned display name。
- 默认 row / card / tray 通过 `appState.clipboardPreview(for:)` 使用 redacted metadata preview。
- `ClipboardStore.loadRepositoryState(limit:)` 不再批量读取 payload，并在 reload 时清空 payload cache。
- payload cache 已改为 `(recordID, purpose)` keyed 的 `ClipboardPayloadCacheKey`。
- hover detail 通过 `.hoverDetail` lazy explicit read，并有 loading / unavailable 文案。
- Settings Clipboard 和 DataAudit 增加 storage / redacted policy / allowlist 说明，沿用现有 Settings shell / pane / section / row。

## 3. P0 / P1 / P2

### P0

无。

### P1

1. `ClipboardController.filteredRecords` 仍信任 historical pinned `displayName` 作为搜索文本。

事实依据：

- `apps/Blocks/BlocksApp/Stores/ClipboardController.swift` 的 `filteredRecords` 中，`searchable` 仍包含 `pinnedMetadata[record.id]?.displayName ?? ""`。
- `tools/verification/p11e_clipboard_hardening_checks.py` 当前只在 `ClipboardRedactedPreviewBuilder` body 中查 `.displayName`，没有覆盖 `ClipboardController.filteredRecords` 的 searchable text。

影响：

- 默认展示标题已不显示 pinned display name，但搜索结果仍可能受 historical pinned display name 影响。
- 这与“默认 redacted title/search 不再使用 pinned displayName”的最新口径不一致。
- 用户可通过搜索行为观察到由历史自定义名称驱动的匹配，信息结构上仍把该字段当成默认可搜索 metadata。

建议修复：

- 从 `ClipboardController.filteredRecords` 的默认 searchable 拼接中移除 `pinnedMetadata[record.id]?.displayName`。
- P11E 增加对 `ClipboardController.filteredRecords` / redacted searchable path 的检查，确保 historical pinned display name 不参与 default search。
- 复跑 P11E / P8 / P9B / Blocks App build，并在开发记录中说明 display title 和 default search 均不信任 pinned display name。

### P2

1. Clipboard panel 在 repository unavailable 且仍有 records 可显示时，没有明显的全局 degraded banner。
   - `emptyState` 中的状态优先级是 unavailable > empty > filtered > redacted，符合空列表路径。
   - 但 `filteredRecords` 非空时会直接展示 records，panel 里没有看到 header / strip 级 storage degraded 提示。
   - 这不阻断当前修复，但最终验收需要低敏证据证明用户能理解 storage degraded，或后续补一个轻量 header strip。

2. Translation preview explicit read failure 反馈偏弱。
   - `prepareClipboardTranslationPreview(record:)` 调用 `.translationPreview` read，但没有根据 `ClipboardPayloadReadResult.failure` 调整 status。
   - 当前 preview 是 redacted metadata，不展示正文，也未触发 provider call，因此不升 P1。
   - 建议最终验收保留失败态证据，或后续补充 “content unavailable, preview uses metadata only” 类状态。

3. Settings 文案密度需要实物验收。
   - `settings.clipboardHardening.allowlistDetail` 和 redacted policy detail 清楚，但英文 / 日文句子较长。
   - 需要窄宽度、三语言、VoiceOver reading order 低敏截图或记录，确认不挤压 trailing column。

4. `ClipboardHistoryView` 仍显示 `record.summary`，但当前未发现主路由直接实例化。
   - `ContentView` 的 `.clipboardSettings` 已路由到 `SettingsView(mode: .clipboard)`，不是 `ClipboardHistoryView`。
   - 若未来重新启用该 view，必须先改为 redacted preview 或明确删除，避免旧 summary 路径回流。

5. Hover loading 文案存在，但真实体感未验证。
   - `ClipboardFloatingDetailCard` 在 `onAppear` 同步读取 hover payload，loading 文案可能只在极短时间出现。
   - 不阻断静态实现；最终验收需确认 hover 进入、退出、panel close、repository reload 后不会残留上一条 payload。

## 4. 重点路径复审

### 4.1 四类状态优先级与文案

方案层面基本保持。

`ClipboardFloatingPanelView.emptyState` 的判断顺序为：

1. `clipboardRepositoryUnavailable`
2. `clipboardRecords.isEmpty`
3. non-empty query 或 active filters
4. redacted fallback

这对应 unavailable > empty > filtered > redacted，符合 PRD 状态优先级。文案有中 / 英 / 日本地化，且 unavailable detail 明确“已有内容并未被删除”，能降低误解为内容丢失的风险。

残余问题是非空列表下的 global unavailable 反馈不明显，列为 P2。

### 4.2 默认 Redacted List

展示路径基本通过，但搜索路径有 P1。

通过部分：

- `ClipboardRedactedPreviewBuilder.preview` 不再使用 pinned display name 作为 title。
- 默认 title 来自 kind / localized title；body 来自 format summary、file count、url count、byte count、pinboard summary 或 redacted detail。
- Floating panel row / card / tray 传入 `preview: appState.clipboardPreview(for: record)`，未看到 payload 传入默认 row / card。

阻断部分：

- `ClipboardController.filteredRecords` 仍把 historical pinned display name 放入 searchable text。

### 4.3 Hover Detail Lazy Read

静态实现可接受。

- `ClipboardHoverDetailItem` 不存 payload。
- `ClipboardFloatingDetailCard` 在 appear / record change 时调用 `readClipboardPayload(... purpose: .hoverDetail)`。
- 有 loading 文案 `clipboard.hardening.hover.loading` 和 unavailable 文案 `clipboard.hardening.hover.unavailable`。
- hover panel close / window close / disappear 会隐藏 detail panel；Store reload / delete 会按 record id 修剪 cache。
- payload cache 已变为 `(recordID, purpose)` keyed，避免不同 purpose 之间共享同一 cache key。

未实测项保留为 P2：真实 hover 退出、panel close、repository reload、record delete 后的体感和残留状态。

### 4.4 Settings 与 DataAudit

静态实现可接受。

- `ClipboardSettingsPane` 新增 Clipboard Storage section，包含 storage state、default list protection、explicit content reads。
- `DataAuditSettingsPane` 只展示 clipboard record count 和 storage state summary，未看到 payload 输出。
- 使用现有 `SettingsTableSection` / `SettingsFormRow`，未引入视觉重设计。

残余风险是长句、窄宽度、三语言和 VoiceOver 读序，需要最终低敏实物验收。
