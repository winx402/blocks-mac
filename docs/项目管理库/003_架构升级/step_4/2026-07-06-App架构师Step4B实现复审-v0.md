## 4. 重点复审结论

### PermissionStore 边界

`PermissionStore` 边界合理，没有过宽到 Clipboard、Provider、Translation、Screenshot 或 Shortcut。它持有权限快照，封装 refresh、权限请求 assist、系统设置 / Finder / restart 入口，并通过协议依赖外部平台实现。职责对 Step 4B 来说不宽也不过窄。

需要注意的是，`PermissionStore` 初始化时会读取一次 snapshot。该读取不触发权限 prompt；它是状态事实源初始化的一部分，和 PRD 中禁止的静默 request / open settings / Show in Finder / restart 不同。

### PermissionSystemActions adapter

`PermissionSystemActions` 作为 system action adapter 合适。`PermissionStore` 只依赖 `PermissionSystemActioning` protocol，不直接出现 `NSWorkspace.shared.open`、`NSWorkspace.shared.activateFileViewerSelecting`、`NSWorkspace.shared.openApplication` 或 `NSApp.terminate`。

P11B 对白名单文件进行了检查，本次输出确认系统动作 token 没有出现在 adapter / 既有 presenter 之外的 Step 4B 关注路径中。

### AppState facade 与 Clipboard retry

`AppState` 方向符合 AppShell / coordinator facade：

- 继续对 View 层暴露现有 permission facade。
- 通过 `permissionStore.objectWillChange` 转发 UI 更新。
- `refreshPermissionState()` 的顺序为 refresh store 后 retry Clipboard pending paste。
- Permission assist 的 `afterRefresh` closure 由 `AppState` 触发 retry，`PermissionStore` 不知道 Clipboard record 或 pasteboard。

该实现保留了兼容性，也避免了 store mesh。

### Settings / Screenshot 兼容性与范围控制

Settings Permissions 和 Screenshot Home 仍通过 `AppState` facade 访问权限能力，未引入 Settings shell 拆分或视图直接依赖 platform API。`Features` 目录下没有新增 `ScreenshotStore` 或 `ShortcutStore`。本切片未静默扩展到 Screenshot capture/result、Shortcut 注册或 Clipboard hardening。

### P11B 覆盖度

P11B 覆盖了我在方案复审中要求的核心结构约束：

- target membership；
- `PermissionStore` contract；
- `AppState` 持有 store、computed facade、public facade、`objectWillChange` 桥接；
- refresh 后 Clipboard retry 顺序；
- `PermissionStore` forbidden token；
- View forbidden token；
- permission feature forbidden token；
- system action adapter 白名单；
- `PermissionStore.init` 副作用；
- `objectWillChange` / `onAppear` / timer / background 附近副作用扫描；
- snapshot 字段保持。

限制是：P11B 仍是静态 token / 结构门禁，只能证明边界形状和高风险 token 未明显散落，不能替代真实 UI 操作、TCC 状态矩阵或可访问性验收。
