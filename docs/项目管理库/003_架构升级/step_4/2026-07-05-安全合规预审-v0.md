## 1. 总体结论

Step 4 预初始化方案可以继续做预规划，但进入 `ready-for-development` 前必须把截图图片、ScreenCaptureKit、Permission Assist、Accessibility、Shortcut 自动化、Settings pane 和 agent/CLI 的安全边界写成可验证门禁。

当前没有 P0 reject。主要风险是 Step 4 会迁移多个高敏入口，如果只做 facade 搬迁而不加静态禁止项和实物验收脱敏规则，容易在新 store / pane 中重新引入截图外发、权限静默触发、自动化扩大或日志泄漏。

## 2. 阻断项

当前预初始化阶段无阻断项。

以下情况若出现在 Step 4 最终 PRD 或开发实现中，应升级为 P0 / P1 阻断：

- 在无独立 PRD 和安全复审前，让 Screenshot AI action 触发真实 OCR、图片 LLM、截图翻译、截图总结或任意 provider call。
- 新增 agent/CLI 默认读取截图图片、完整剪贴板 payload、Keychain secret 或 provider 原始输出。
- Permission Assist、Accessibility 或 Shortcut 回调被设计为静默触发系统授权、系统设置跳转、自动粘贴重试或任意自动化。
- 实物验收、日志、audit、开发记录或测试 JSON 输出截图图片、base64、OCR 原文、完整剪贴板内容、真实选中文本、真实 API key、Authorization header、完整 request body 或 provider raw response。

## 3. 必改项

P1-1 ScreenshotStore 边界必须写入最终 PRD：`ScreenshotStore` 只能组织截图动作、状态映射、recent capture 元数据和 result presenter 入口；不得直接执行 provider call、不得上传截图图片、不得新增真实 OCR / image LLM 外发。Screenshot AI action 只能是 route preview。

P1-2 ScreenCaptureKit 必须收敛在 `ScreenshotCaptureService` 或更窄 platform adapter 内。新 store / View / Settings pane 不得直接调用 `SCShareableContent.current`、`SCScreenshotManager`、屏幕枚举或窗口枚举 API。测试输出只允许尺寸、字节数、短 hash、模式和脱敏来源摘要，不输出图像内容或完整窗口标题。

P1-3 PermissionStore 边界必须明确：权限 snapshot 来自系统状态或明确辅助流程，不用 UserDefaults 假造授权状态；打开系统设置、请求 Screen Recording / Accessibility 辅助、重启提示必须由用户动作触发；自动粘贴重试不归 PermissionStore 静默执行。

P1-4 Accessibility 相关能力必须保持最小化。Step 4 只能迁移权限辅助和状态投射，不新增读取前台 UI 内容、抓取选中文本、发送键鼠事件或 AppleScript 自动化。若后续需要这些能力，必须单独 PRD、安全复审和实物验收。

P1-5 ShortcutStore 必须只注册项目已声明的固定动作，动作由 AppShell 注入窄闭包；不得持有完整 `AppState` 并任意调用跨域方法；不得引入任意 shell、AppleScript、CGEvent 发送或外部 CLI 执行能力。

P1-6 Settings shell / pane 拆分必须保持“设置入口不碰敏感 API”。Settings pane 只能调用 AppState facade 或 feature store 的明确方法，不得直接访问网络、Keychain、pasteboard、ScreenCaptureKit、Accessibility 或外部进程。

P1-7 Agent/CLI 设置必须保持描述和 preview-only。不得把完整剪贴板 payload 读取、截图图片读取、provider secret 读取、hook runtime、外部 CLI provider 或图片外发写成已启用能力；需要敏感数据或外发时仍必须返回或触发 `requires_confirmation` 类确认流程。

P1-8 如果 Step 4 拆 Provider / Translation settings pane，必须继承 Step 3 安全复审结论：Keychain 读取后置、外部 provider 默认 HTTPS、route ready 不等于执行授权、真实 secret 不输出原文或 hash、翻译正文 runtime 不进入 audit / 测试 JSON / 开发记录。

P1-9 P11 门禁必须包含静态禁止 token 检查和 no-call 行为检查。仅靠构建通过和 UI 回归不足以接受 Step 4。

## 4. 必须保持 preview-only 的能力

以下能力在 Step 4 中只能保持 preview-only，不得触发 provider call、图片外发、真实外部 CLI 或敏感数据读取：

- Screenshot AI action route preview：只能展示 OCR / translate / summarize 的 route readiness，不上传截图图片。
- 云 OCR、多模态 LLM OCR、截图总结、截图翻译、图片转文字 provider call。
- Agent/CLI action preview、hook manifest、外部 CLI provider 探测和能力说明。
- Settings 中 Provider / Translation / AgentCLI pane 的配置摘要和风险说明，除非 Step 3 已验收并且相关 gate 明确允许。
- Clipboard hardening 中的完整 payload 读取能力；若 Slice 4F 纳入，也只能在明确用户用例下读取，例如 paste、copy、translation preview，不得默认列表预载。

## 5. 新 store / View 层禁止直接 API token

P11 静态门禁建议按层检查。新 View、Settings pane 和 feature store 默认不得直接出现以下 token；如确有例外，必须写明对应 service / adapter 和复审原因。

通用敏感外联 / 凭据 token：

- `URLSession`
- `SecItem`
- `Authorization`
- `Bearer`
- `Process(`
- `getenv(`
- `NSAppleScript`

截图 / 屏幕内容 token：

- `SCShareableContent.current`
- `SCScreenshotManager`
- `SCContentFilter`
- `CGWindowListCopyWindowInfo`

剪贴板 / 自动化 token：

- `NSPasteboard.general`
- `CGEvent`
- `CGEventPost`
- `AXUIElement`
- `AXIsProcessTrustedWithOptions`

快捷键底层注册 token：

- `RegisterEventHotKey`
- `UnregisterEventHotKey`

允许方向：这些能力应位于既有 service / presenter / controller 或新建 platform adapter 中，由 store 通过窄接口调用；Settings pane 和普通 View 不应直接触达。

## 6. 实物验收和日志 / 审计禁止项

实物验收可以覆盖真实权限路径、快捷键路径和截图路径，但必须使用低敏场景，并遵守以下输出限制：

- 不提交、不打印、不 base64 编码真实截图图片；测试临时截图只能写入 ignored 临时目录，并在记录中只保留尺寸、字节数、短 hash 和 mode。
- 不输出完整窗口标题、屏幕文本、OCR 原文、选中文本原文、剪贴板原文、真实 URL、真实文件路径或用户主目录。
- 不输出真实 API key、token、secret hash、Authorization header、完整 request body、provider raw response 或外部 CLI raw output。
- Permission Assist 验收只记录状态枚举、触发入口、是否用户动作、audit id 和错误码；不记录前台 App 内容。
- Shortcut 验收只记录 action id、binding 摘要、注册状态、错误码和是否用户触发；不记录当前窗口标题或用户输入。
- Agent/CLI 验收只能用低敏 fixture 和 mock transport；不得要求真实 provider、真实外部网络或真实凭据。

## 7. 建议项

P2-1 Step 4 最终 PRD 建议按 4A rebaseline、4B ScreenshotStore、4C PermissionStore、4D ShortcutStore、4E Settings shell 分阶段接受；Clipboard hardening 若加入，应作为独立 slice 并单独验收。

P2-2 建议 P11A 覆盖 ScreenshotStore：截图 capture service 边界、AI action preview no-provider-call、日志不含图像内容、View 不直接调用 ScreenCaptureKit。

P2-3 建议 P11B 覆盖 PermissionStore / ShortcutStore：权限动作必须用户触发、PermissionStore 不伪造授权状态、ShortcutStore 只接收窄动作闭包、无任意自动化 token。

P2-4 建议 P11C 覆盖 Settings pane split：pane 拆分后不直接出现敏感 API token，Provider / Translation / AgentCLI pane 不扩大 Step 3 和 secret handling 边界。

P2-5 建议对实物验收建立固定低敏桌面场景，例如空白测试窗口、低敏 fixture 文本和测试快捷键，避免验收记录被真实用户内容污染。

## 8. 待验证项

- Step 3 是否已最终接受；若 P10A / P10B 或 Step 3 安全必改项未完成，Step 4 不应基于 ProviderStore / TranslationStore 拆 Settings pane。
- ScreenCaptureKit 多屏、跨屏、权限拒绝、权限撤销、重授权路径仍需在目标 macOS 环境实测。
- Accessibility 授权撤销、Permission Assist 打开系统设置的用户体验和失败路径仍需实测。
- Shortcut 注册冲突、禁用、恢复默认、权限变化和前台 App 冲突仍需实测。
- App Store / 直接分发、sandbox entitlement、notarization 对截图、Accessibility、后台 helper、外部 CLI 和 hook 的影响仍是后续分发前风险，不阻塞 Step 4 预规划。

## 9. 对最终 PRD 的接受条件建议

Step 4 最终 PRD 至少应补齐：

- 明确每个 slice 的敏感 API 所在层级和禁止触达层级。
- 明确哪些行为是 preview-only，哪些行为需要用户显式动作，哪些行为本阶段不做。
- 明确 P11A / P11B / P11C 的静态 token 检查和行为 no-call 检查。
- 明确实物验收的低敏输入、输出脱敏规则和禁止记录项。
- 明确 Step 3 回调后的 rebaseline 结果，避免基于未验收产物继续扩范围。
