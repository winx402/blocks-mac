## 1. 总体结论

Step 4B 选择 `PermissionStore` 单切片是合理的。PRD 已明确不创建 `ScreenshotStore` / `ShortcutStore`，不拆完整 Settings shell，不新增 OCR、图片外发、provider call、外部 CLI、AppleScript、CGEvent 或 secret 读写能力；权限请求、系统设置跳转、Show in Finder 和 restart 也已定义为用户触发式动作。

当前无 P0 reject。进入开发前有 1 个 P1 必改项：系统动作 token 白名单需要补齐 `NSWorkspace` / `NSApp` 相关调用，并由 P11B 验证这些调用只能存在于明确的 system action adapter 或既有 presenter/service 中，不能散落到 `PermissionStore`、View、初始化、`onAppear`、timer 或 refresh callback。

## 2. 代码抽查事实

- `AppState` 当前仍直接声明 `@Published var permissionSnapshot: PermissionStateSnapshot = PermissionStateService.snapshot()`，与 PRD 要迁移的事实源一致。
- `refreshPermissionState()` 当前刷新权限 snapshot 后调用 `retryPendingClipboardPasteIfPossible()`；PRD 要求 retry 保留在 AppShell / Clipboard 协调层，不迁入 `PermissionStore`，方向正确。
- `requestScreenRecordingPermissionAssist()` / `requestAccessibilityPermissionAssist()` 当前会调用 `PermissionStateService` 的权限请求方法，并展示 `PermissionAssistPanelPresenter`。
- `openScreenRecordingSettings()`、`revealCurrentAppInFinder()`、`restartForPermissionRefresh()` 当前直接使用 `NSWorkspace` / `NSApp`。
- `SettingsView` 中权限请求、restart、Show in Finder 均挂在 Button action 下；`ScreenshotHomeView` 的 Screen Recording Settings 入口也挂在 Button action 下。
- `PermissionAssistPanelPresenter` 内含 `CGRequestScreenCaptureAccess`、`AXIsProcessTrustedWithOptions`、`NSWorkspace.shared.open`、`CGWindowListCopyWindowInfo`、签名检查和 app icon / drag fallback 逻辑；这些属于 permission service / presenter 或未来 platform adapter 可接受范围，不应迁入普通 View 或 store。

## 3. 阻断项

P0：无。

P1-1 系统动作 token 必须补进白名单和 P11B。PRD 第 6 节列出了多类敏感 token，但未显式列出以下系统动作 token：

- `NSWorkspace.shared.open`
- `NSWorkspace.shared.activateFileViewerSelecting`
- `NSWorkspace.shared.openApplication`
- `NSApp.terminate`

这些调用直接对应打开系统设置、Show in Finder 和 restart，必须被标为 adapter-only / presenter-only。`PermissionStore`、Settings / Screenshot View、新 permission 普通文件不得直接出现这些 token；如果新建 `PermissionSystemActions.swift`，它必须是唯一白名单文件，并且所有入口都必须来自用户动作。

P1-2 P11B 必须验证“用户触发”不是仅靠约定。至少应检查 `PermissionStore.init`、`onAppear`、timer、background refresh、permission assist refresh callback、`objectWillChange` 绑定路径中不会调用 request access、open settings、Show in Finder 或 restart。允许的例外只有明确用户动作 facade，以及用户触发 clipboard paste 后因 Accessibility 缺失进入的辅助流程；该例外仍不得自动打开系统设置或重启。

上述两项回写 PRD 或开发派单后，本方案可进入开发。

## 4. 安全边界判断

用户触发边界：总体充分，但需通过 P1-1 / P1-2 加强验证。权限请求、系统设置跳转、Show in Finder 和 restart 都应由按钮或等价明确用户动作触发；刷新权限只允许读状态和触发既有 pending paste retry，不得引入新系统动作。

敏感 API token：PRD 对 `URLSession`、`SecItem`、`Authorization`、`Bearer`、`Process(`、`getenv(`、`NSAppleScript`、ScreenCaptureKit、pasteboard、CGEvent、AXUIElement、热键注册等禁止项定义合理。需要补充 `NSWorkspace` / `NSApp` 系统动作 token 的层级约束。

日志 / audit / 证据：PRD 禁止输出真实用户主目录、完整路径、完整窗口标题、屏幕文本、选中文本、剪贴板正文、截图图片、base64、OCR 原文、真实 API key、secret hash、Authorization、完整 request body 和 provider raw response，边界足够。建议开发记录中对 app path 只记录 basename、bundle ID、是否存在、签名类型枚举和 team ID 是否存在。

新增能力风险：PRD 明确不新增 Accessibility 内容读取、ScreenCapture 调用、AppleScript、CGEvent、外部 CLI、provider call 或 secret 读写，符合 Step 4B 单切片边界。

## 5. 建议回写项

P2-1 `PermissionSystemActioning` 建议拆为只含系统动作的 adapter，并在命名和 P11B 中明确为唯一可触达 `NSWorkspace` / `NSApp.terminate` 的位置。

P2-2 `PermissionAccessRequesting` 建议只封装 `CGRequestScreenCaptureAccess` 和 `AXIsProcessTrustedWithOptions`，并要求方法名保留 `request` 语义，避免被误用于普通 refresh。

P2-3 `PermissionAssistPresenting.present(...)` 建议在调用侧传入 `trigger: .userAction | .clipboardPasteUserFlow` 这类低敏枚举，便于测试确认不是后台自动触发。

P2-4 实物证据建议统一使用低敏模板：记录触发按钮、权限状态枚举、bundle ID 是否存在、签名类型、team ID 是否存在、错误码和测试命令结果；不要记录完整 app path、用户主目录或截图。

P2-5 如果开发时移动 `PermissionStateSnapshot` / `PermissionDiagnosticSnapshot`，应保持字段语义，不顺手重写 presenter 状态机或扩大权限诊断范围。

## 6. 开发 / 测试必须验证项

- P11B 检查 `PermissionStore.swift` 存在并进入 target，`AppState` 持有 store，`permissionSnapshot` 改为 computed facade，`AppState` 不再直接 `@Published permissionSnapshot`。
- P11B 检查 `PermissionStore` 不持有完整 `AppState`，不持有 Provider / Translation / Screenshot / Shortcut store，不包含 Clipboard retry、pending paste、pasteboard 或 provider / secret token。
- P11B 检查新 permission 普通文件和 View 不直接出现第 6 节禁止 token，以及本复审新增的 `NSWorkspace` / `NSApp.terminate` token。
- P11B 或实物验收检查 request access、open settings、Show in Finder、restart 都只能由用户动作触发；refresh、init、onAppear、timer 和 callback 不得触发这些动作。
- P7 系列回归继续覆盖 Permission Assist flow、state refresh、position drag、settings interaction、identity gate 和 UX checks。
- 若无法覆盖权限授权 / 未授权 / revoked 全矩阵，验收记录必须逐项标记未覆盖，不得写成通过。
- 开发记录、测试 JSON、audit 和实物证据不得包含截图内容、base64、完整路径、用户主目录、窗口标题全文、选中文本、剪贴板正文、真实凭据或 provider 原始输出。

## 7. 最终判断

在 P1-1 / P1-2 回写后，Step 4B 可以进入开发。若开发实现新增 Screenshot capture、Shortcut 注册、AppleScript、CGEvent、外部 CLI、provider call、secret 读写或图片外发，应暂停并重新走范围确认与安全复审。
