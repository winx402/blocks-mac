## 2. 总体判断

Step 4C 作为 umbrella PRD 收纳 ScreenshotStore、ShortcutStore、Settings shell split、Clipboard hardening 是可以理解的，但必须保持“子批次独立开发、独立验收、独立回调”的硬边界。PRD 已写出这一点，因此不建议 rejected。

但当前 PRD 仍有两个 P1：Screenshot Result 的最小体验证据不够细，Clipboard hardening 的用户可理解反馈契约不够具体。它们不应等到开发后由测试猜测验收口径，必须在派开发前回写。

本复审结论为 `changes-requested`。P1 回写后，可降为 `approve-with-changes` 或进入开发准备。

## 3. P0 / P1 / P2

### P0

无。

### P1

1. Screenshot Result 最小体验验收不完整。
   PRD 在 3.1 提到 copy/save/retake/close、outcome banner、blocked detail、no-upload/provider-not-called 文案不丢失，但第 8 节最小实物证据只写了 copy/save/retake/close 不退化和 AI preview 仍是 preview。派开发前应把 outcome banner、copy/save 成功/失败/取消、retake 后状态、close 行为、AI preview ready/blocked、localized blocked detail、provider profile / confirmation level、`image_not_uploaded` / provider-not-called 文案都写进 Screenshot 子批次的阻断验收。

2. Clipboard hardening 缺少具体用户反馈契约。
   PRD 要求 repository unavailable 有用户可理解降级、默认列表不读取完整 payload、完整 payload 只在明确操作读取，但没有说明这些状态出现在哪些 UI 面、使用什么级别的反馈、用户如何区分“无历史”“存储降级”“内容已 redacted”“需要显式读取 payload”。派开发前必须补一个 Clipboard hardening UX contract，否则实现可能只完成内部 read model，而用户看不懂降级状态。

### P2

1. Shortcut settings 验收需要更细。
   当前 PRD 覆盖注册 / 禁用 / 失败 / 自定义绑定 / 恢复默认和 recorder 一次只录一个命令，但建议补充 invalid shortcut、Esc/cancel recording、切换行、切换 pane、关闭 Settings 后 recorder 停止、恢复默认后的状态反馈。

2. Settings shell split 需要把 Step 4B 残余风险转成硬验收。
   Step 4B 接受记录明确留下 Settings 窄宽度、长路径、长 bundle ID、长 recommended action、三语言长句和 VoiceOver label 低敏实测证据缺口。Step 4C PRD 已提到抽查，但建议明确作为 Settings 子批次验收门槛，而不是可选说明。

3. 截图低敏证据应明确使用低敏窗口 / fixture。
   Step 4C 涉及 screenshot capture 和 result presenter，建议要求截图证据使用低敏桌面、低敏窗口标题和低敏图片，不得把真实屏幕内容写入记录。

4. 四个子批次不应连续开发后一次性验收。
   PRD 已要求子批次回调；建议强调 4C-1 / 4C-2 / 4C-3 / 4C-4 每批次 P0/P1 为 0 后才进入下一批次。

## 4. Screenshot Home / Result 复审

当前 PRD 覆盖了 ScreenshotStore 的职责和安全边界，方向正确。

必须回写到验收门槛：

- Screenshot Home：region / window / fullscreen 入口、Screen Recording 缺权提示、Screen Recording 设置入口、last capture summary、recent captures 空态和列表态。
- Screenshot Result：copy、save、retake、close 全部可操作且反馈清楚。
- Outcome banner：copy success、copy failure、save success、save cancelled、save failure 至少有可观察证据；无法真实触发的失败态应记录为未覆盖或用低敏测试替代。
- AI route preview：action 选择后预览卡出现；ready 和 blocked 都有本地化 detail；provider profile、confirmation level、dependency note 或等价信息不丢失。
- 安全文案：必须可见表达 no image upload / no provider call，不只保留内部 token。
- Retake：从结果页重新截图后状态更新，不留下旧结果误导。
- Close：关闭结果页不会丢失主界面状态或造成重复窗口。

## 5. Shortcut Settings 复审

当前 PRD 对 ShortcutStore 边界判断合理：不持有完整 `AppState`，只接收 AppShell 注入窄动作闭包，不扩大为任意自动化。

建议补充验收门槛：

- Shortcut settings pane 显示 registered / disabled / failed 三类统计。
- 每个 command 行显示当前 binding、binding source、注册状态、enable toggle、record、restore default。
- Recorder 一次只能录一个命令；录制中切换行、切换 pane、关闭 Settings 后停止监听并恢复 idle。
- Invalid shortcut 有明确反馈，不能静默失败。
- Disabled shortcut 不注册全局快捷键，状态与统计同步。
- Restore default 和 restore all defaults 后，binding source 与注册结果同步更新。
- Failed registration 展示 OSStatus 或等价失败摘要，不只写日志。
- 快捷键动作只触发声明动作；不新增通用 shell / AppleScript / CGEvent / CLI 执行能力。

## 6. Settings Shell Split 复审

当前 PRD 对 Settings shell 的保持项较完整，尤其是 `SettingsViewMode`、`clipboardPrivacy` 返回、setting key、pane 局部状态和固定 trailing column。

建议把以下内容写为阻断验收：

- `all`、`general`、`clipboard`、`clipboardPrivacy`、`translation`、`shortcuts`、`providers`、`agentCLI`、`hooks`、`dataAudit`、`permissions` 均能打开。
- `clipboardPrivacy` 返回目标必须是 Clipboard 设置，不能回到全部设置或关闭窗口。
- setting key 不改名、不迁移、不丢失；关闭重开后关键设置保持。
- Provider secret 输入、外发确认、连接测试状态不泄漏到其他 pane。
- Translation pane 使用 Step 3 accepted 的 `TranslationStore`。
- Permission pane 使用 Step 4B accepted 的 `PermissionStore`。
- Shortcut pane 保持单一 recorder 状态。
- 固定 trailing column、窄宽度、长路径、长 bundle ID、长推荐动作、中文 / 英文 / 日文长句不出现明显重叠、截断到不可理解或控件丢失。
- 隐藏 label 的 Toggle / Picker / icon button 必须通过可访问性检查，VoiceOver 能读出具体设置名和动作名。
- Settings 拆分不顺手做视觉重设计；任何 IA 改动应另立 UX spec。

## 7. Clipboard Hardening 复审

这是 UI 风险最高的子批次。PRD 的安全边界正确，但用户反馈契约不足。

派开发前建议新增 Clipboard hardening UX contract：

- Repository unavailable：用户在哪看到，文案如何区分“存储暂不可用”“历史不可写入”“功能降级但复制/粘贴仍可用”。
- Redacted list：默认列表显示哪些 metadata，正文占位如何表达，不让用户误以为内容丢失。
- Payload explicit read：paste、copy、hover detail、translation preview 这些明确用例如何触发读取，触发前后是否有反馈。
- Empty / unavailable / filtered / redacted 四类状态要能区分。
- Settings 中是否需要一个 storage degraded 或 repository status 说明入口；若不做 Settings UI，也要说明用户在哪里得到反馈。
- 验收记录只能使用低敏 fixture；不得输出剪贴板正文。

如果无法在 Step 4C 内补齐上述 contract，建议把 Clipboard hardening 拆成 Step 4D，不阻断 Screenshot / Shortcut / Settings shell 的收口。

## 8. 建议拆分策略

建议保留 Step 4C umbrella PRD，但开发必须硬拆为子批次：

1. 4C-1 ScreenshotStore。
2. 4C-2 ShortcutStore。
3. 4C-3 Settings shell split。
4. 4C-4 Clipboard hardening。

每个子批次都应有单独开发记录、低敏 UI 证据、测试/质量验收和必要复审。不要四个子批次连续实现后一次性验收。

如果 P1 只来得及补 Screenshot 和 Settings，Clipboard hardening 应拆出 Step 4D。

## 9. 建议回写项

1. 在第 8 节 Screenshot 最小证据中补 outcome banner、copy/save 成功/失败/取消、retake、close、recent captures 更新、AI preview ready/blocked、blocked localized detail、provider profile、confirmation level、no-upload/provider-not-called 文案。

2. 在 Clipboard hardening 下新增 UX contract，明确 repository unavailable、redacted list、explicit payload read、empty/unavailable/filtered/redacted 状态和 Settings / Clipboard UI 反馈面。

3. 在 Shortcut 最小证据中补 invalid shortcut、Esc/cancel recording、切换行 / pane / 关闭 Settings 停止监听、restore default 后状态反馈。

4. 在 Settings 最小证据中把 Step 4B 残余风险转为硬验收：窄宽度、长路径、长 bundle ID、三语言长句、VoiceOver label。

5. 在角色流程中增加：每个子批次 P0/P1 为 0 后才进入下一子批次；若 Clipboard hardening UX contract 未补齐，则移出 Step 4C。

6. 在 P11 脚本或开发记录模板中要求引用低敏 UI 证据路径，而不是只输出静态 token 检查。

## 10. 体验验收门槛

Screenshot 门槛：

- Region / window / fullscreen 低敏实测。
- 缺 Screen Recording 权限路径有提示和辅助路径；无法撤权时明确未覆盖。
- Result copy/save/retake/close 与 outcome banner 覆盖。
- AI preview ready / blocked、blocked detail、no-upload/provider-not-called 可见。

Shortcut 门槛：

- Settings 中注册、失败、禁用、自定义、恢复默认路径可见。
- Recorder 单一录制状态、取消、无效输入、关闭清理可验证。
- 快捷键动作只触发声明动作。

Settings 门槛：

- 所有 `SettingsViewMode` 可打开。
- `clipboardPrivacy` 返回正确。
- setting key 保持。
- pane 局部状态不串扰。
- 窄宽度、长文本、多语言、VoiceOver label 有低敏证据。

Clipboard 门槛：

- repository unavailable 有用户可理解降级反馈。
- redacted list 不误导用户正文丢失。
- 默认列表不读取完整 payload。
- 明确操作读取 payload 时有可理解反馈。
- 验收输出不包含剪贴板正文。

## 11. 最终结论

结论：changes-requested。

没有 P0。存在两个 P1：Screenshot Result 最小体验验收不完整、Clipboard hardening 用户反馈契约不足。P1 回写后，Step 4C 可以继续按子批次进入开发准备；如果 Clipboard hardening UX contract 暂时补不齐，建议拆到 Step 4D。
