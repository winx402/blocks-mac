## 安全事实依据

1. Settings shell 拆分符合 PRD 边界。
   - `SettingsView.swift` 已退化为 wrapper，仅保留 `mode` 和 `SettingsShellView(mode:)`。
   - `SettingsShellView.swift` 明确映射 `all/general/clipboard/clipboardPrivacy/translation/shortcuts/providers/agentCLI/hooks/dataAudit/permissions`，其中 `clipboardPrivacy` 仍进入 Clipboard pane。
   - P11D 报告 `settings_view_wrapper.line_count = 13`、mode mapping 无缺失、26 个 setting key 无缺失、target membership 无缺失。

2. 新 Settings pane 未出现 PRD 禁止的直接敏感 API token。
   - P11D `forbidden_tokens.hits = []`。
   - 追加静态扫描 `Features/Settings` 和 `SettingsView.swift` 未命中：`URLSession`、`SecItem`、`Authorization`、`Bearer`、`NSWorkspace`、`NSPasteboard.general`、`ProviderRouter`、`readUserSecretForProviderCall`、`clipboardPayload`、`ClipboardRecorderPayload`、`Process(`、`getenv(`。
   - `AppState.swift` 中仍有既有剪贴板/权限 facade 与历史实现 token，但本次新增 Settings pane 没有直接调用这些系统 API。

3. Permission pane 的系统影响动作仍是用户显式动作路径。
   - `PermissionSettingsPane.swift` 中刷新、restart、Screen Recording request、Accessibility request、Show in Finder 均位于 `Button` closure 内。
   - pane 不直接调用 `NSWorkspace`、`NSApp.terminate` 或 TCC reset。
   - 系统动作实际落点仍在既有 `PermissionStore` / `PermissionSystemActions`：`revealCurrentAppInFinder()`、`restartForPermissionRefresh()`、`openScreenRecordingSettings()` 由 `DefaultPermissionSystemActions` 承接。

4. Provider secret、连接测试和 route check 未被 pane 直连。
   - `ProviderSettingsPane.swift` 使用局部 `@State` 保存 `secretCandidate`、`providerUserSecretStoreConfirmed`、`openAITestConnectionConfirmed`。
   - 保存用户 secret 需要非空 alias、非空候选 secret 和显式确认 toggle，之后通过 `appState.performProviderUserSecretGate(...)` 进入既有 gate。
   - OpenAI 连接测试只在按钮点击后进入 `appState.runOpenAIConnectionTest(...)`，且按钮受 `openAITestConnectionReady && openAITestConnectionConfirmed` 禁用条件保护。
   - 预览和连接 gate 通过 `appState.previewOpenAIConnection(...)`、`appState.validateProviderConnectionGate(...)`，未在 pane 内出现 `URLSession`、Keychain `SecItem` 或 Authorization header。

5. Translation route check 未绕过既有 provider gate。
   - `TranslationSettingsPane.swift` 的 route check 是显式 Button，调用 `appState.resolveTranslationEngineRoute(...)`。
   - 外发确认仍来自 `translation.runtime.externalEnabled`，未在 pane 中直接构造 provider 请求或读取 secret。

6. Clipboard / AgentCLI / Hooks / DataAudit pane 未扩大敏感读取或执行能力。
   - Settings 侧 clipboard 内容保持策略、计数、bundle id 和配置项展示；未命中 full payload 读取 token。
   - Agent/CLI pane 静态扫描未出现 `Process(` / `getenv(` / 外部 CLI 执行 token。
   - 本切片未启动 Step 4C-4 Clipboard hardening，不改变完整 payload allowlist / denylist。

7. Verifier 输出与旧事实源处理保持低敏。
   - `p11d_settings_shell_split_checks.py` 输出使用相对路径，`baseline_reference` 明确旧 story/archive/project docs 不参与 `ok` 判定。
   - P7B/P7C/P7D/P7E/P7F/P8G 静态读取显示使用当前 PRD、当前开发记录和当前代码事实源，并保留 `baseline_reference` 说明。

### P2

1. P11D 可以继续加固 facade 方法位置规则。
   - 当前 P11D 已 fail closed 检查 direct sensitive token，但对 `restartForPermissionRefresh`、`requestScreenRecordingPermissionAssist`、`requestAccessibilityPermissionAssist`、`revealCurrentAppInFinder` 这类 facade 方法是否只出现在用户按钮内，仍依赖本轮人工复核。
   - 建议后续把这些方法纳入 P11D 或新增轻量 verifier：允许只出现在 `Button` action / 明确 user action adapter 内，禁止出现在 `init`、`onAppear`、`.task`、timer、background refresh、`objectWillChange`、permission refresh callback。

2. Permission diagnostics UI 会显示 app path / running paths。
   - 当前仅在用户可见 UI 中显示，且不是日志或 verification JSON；不构成本切片 P1。
   - 后续验收记录、截图说明和 bug 报告仍应避免复制真实完整本地路径，必要时使用相对路径或 `<HOME>` / `<APP_PATH>` 占位。

3. 真实 UI 和真实系统动作未由本复审触发。
   - 开发记录声明未触发真实权限请求、系统设置、Show in Finder、restart、provider call、Keychain secret 读取或剪贴板完整 payload。
   - 本复审保持同样边界；真实点击、真实系统设置跳转、真实连接测试和多语言 UI 实物验收应由主 agent 或测试/质量在串行验收中按需确认。

## 残余风险

- Provider pane 保留真实外部连接测试入口；风险边界可接受，因为它需要用户显式确认 toggle 和按钮点击，并经既有 AppState / ProviderStore gate。安全复审未运行该真实外发路径。
- Permission pane 保留真实权限请求、Show in Finder 和 restart 入口；风险边界可接受，因为它们均为用户显式按钮触发，并经既有 PermissionStore / system action adapter。安全复审未运行这些真实系统动作。
- Clipboard hardening 仍属于后续 Step 4C-4，Settings shell split 本身未关闭 Step 4C-4 的 payload read model 风险。

## 回写建议

- 可在 P11D 后续版本加入 facade 方法位置检查，覆盖权限请求、系统设置、Show in Finder、restart、provider connection test、route check 等 user-action-only 方法。
- 验收记录继续保持低敏：只记录相对文件路径、命令、PASS/FAIL、audit id 或状态，不记录真实 secret、Authorization header、request body、provider raw response、剪贴板正文、屏幕文本、窗口标题、真实截图/base64 或真实完整本地路径。
