## 2. 总体判断

从静态实现看，ShortcutStore 迁移没有发现导致 Settings shortcut 用户语义退化的 P0/P1：

- `ShortcutStore` 接管 `shortcutRegistrationResults`、注册/禁用/失败计数、binding source、custom binding、global modifier、save、enable、restore default、refresh 等快捷键事实和动作。
- `AppState` 保留 public facade，并桥接 `ShortcutStore.objectWillChange`，Settings 仍通过原有 `appState.*` API 读取和写入，界面调用语义保持稳定。
- `SettingsView` 仍使用单一 `@State private var shortcutRecorderState: ShortcutRecorderState = .idle`，一次只标记一个命令处于 recording。
- 注册、禁用、失败、自定义、恢复默认的用户可见语义仍有对应文案：registered / disabled / failed OSStatus / source global-custom / restore default / restore all defaults / refreshed status。
- global modifier preset 仍通过 Settings picker 修改，并经 AppState facade 到 ShortcutStore，再写入 `ShortcutBindingStore` 后强制重新注册；每行仍展示 source，避免用户误解全局修饰键会覆盖单项自定义。
- 面板焦点快捷键路径仍是声明动作闭包：区域截图、剪贴板浮层、翻译浮层，不是任意自动化入口。

建议主 agent 允许进入测试/质量最终接受流程。最终接受前，测试/质量仍需补齐低敏真实 UI 证据，特别是真实 Settings 录制/取消/切换/关闭清理和真实 OSStatus 冲突展示。

## 4. 重点路径复审

### Settings Shortcut 配置与诊断

Settings shortcut 区仍保留：

- global modifier picker。
- registered / disabled / failed 三类诊断 badge。
- 每个 command 的 binding display、source、registered/disabled/conflict 状态。
- enable toggle。
- record / recording。
- restore default。
- re-register shortcuts。
- restore all defaults。

`ShortcutRegistrationResult.localizedStatus` 对 disabled、registered、conflict 分别给出用户可见状态；失败路径保留 `OSStatus` 摘要，符合 PRD 对“失败不只写日志”的最低要求。静态复审未发现迁移后 Settings 行直接成为业务事实源。

### ShortcutRecorderState

`ShortcutRecorderState` 仍是 Settings 层单一 `@State`，状态只有 `idle` 与 `recording(ShortcutCommand)`。这保证界面上一次只会有一个 command 被标记为录制中。

Esc/cancel 路径：local key monitor 捕获 keyCode 53 后调用 `stopRecording()`，并回到 idle。

invalid shortcut 路径：`ShortcutBinding.make` 返回 nil 时触发 beep 并继续录制；按钮 help 文案说明“至少一个修饰键加一个普通键”。这不是静默失败，但是否足够清楚需要真实 UI 验收。

切换行路径：新 row 开始录制会把全局 state 改为新 command，旧 row monitor guard 会放行事件，不再保存旧 command；但旧 monitor 的立即清理依赖 row 消失或再次启动同 row。本点应保留为 P2 实物验收项。

切换 pane / 关闭 Settings：每个 row 有 `.onDisappear { stopRecording() }`，静态路径合理；真实窗口关闭和 pane 切换仍需测试/质量确认。

### Global Modifier 与面板焦点快捷键

global modifier 的解释文案保留“应用到默认快捷键；单个功能自定义后优先级更高”，每行 source 继续显示 global/custom。该组合能让用户理解 preset 与 custom binding 的优先级关系。

Shortcut action handlers 只包含：

- `screenshotRegion`
- `clipboardHistory`
- `translationPanel`

AppState 注入的动作分别指向区域截图入口、剪贴板浮层展示/聚焦、翻译浮层展示/聚焦。静态实现未看到任意 shell、AppleScript、CGEventPost、外部 CLI、Accessibility 前台 UI 操作或未声明动作分发入口。

按开发记录，P11C/P6A/P6B/P6C/P7C/P7D 均 PASS。静态读取脚本后，本次判断如下：

- P11C 覆盖 ShortcutStore 边界、AppState facade、allowlist、target membership、旧事实源不得参与阻断。
- P6A 覆盖 shortcut panel / translation panel / clipboard panel 相关静态符号、当前事实源、三语言文案和隐私边界。
- P6B 覆盖 recorder、custom binding、restore、面板 polish、press/release 防重复触发和三语言文案。

- P7C 覆盖 global modifier、source global/custom 和三语言文案。

这些脚本适合作为迁移不退化的静态/构建门禁，但不能替代真实 Settings UI 操作、真实系统快捷键冲突和 VoiceOver 验收。

## 6. 体验残余风险

- 用户按下 invalid shortcut 时，真实反馈是否足够明确仍不确定；beep 对听觉关闭或无声环境用户不够稳。
- 录制中切换行可能保留旧 local monitor；静态 guard 降低误录风险，但真实事件链和焦点行为仍需验证。
- 系统级 shortcut 冲突依赖 macOS 当前环境，OSStatus 真实展示和失败计数同步需实测。
- Global modifier 切换后，默认 shortcut、custom shortcut、source label 和诊断统计是否同步刷新，需要低敏 UI 证据。
- `.labelsHidden()` 控件的 VoiceOver label、长文案截断、窄宽度布局未本轮验证。

## 7. 建议回写项

建议测试/质量或最终接受记录补充：

1. 低敏 Settings shortcut 实物证据：打开 Shortcuts pane，展示 registered / disabled / failed / custom / global source / restore default / restore all defaults。
2. recorder 实测：录制成功、invalid shortcut、Esc/cancel、录制中切换行、切换 pane、关闭 Settings 后停止监听并恢复 idle。
3. Global modifier 实测：切换 preset 后默认 binding 更新；已有 custom binding 仍显示 custom 且不被覆盖；诊断统计同步。
4. 真实或可控替代冲突证据：failed registration 展示 OSStatus 或等价失败摘要，并同步 failed count。
5. 面板焦点快捷键实测：快捷键触发剪贴板浮层和翻译浮层时，已有面板应 focus，不误关闭；区域截图入口仍触发声明动作。
6. 可访问性与布局证据：VoiceOver label、键盘焦点、窄宽度、中文/英文/日文长句不造成状态不可理解。
