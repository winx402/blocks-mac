## 4. 事实依据

### 4.1 SettingsView wrapper 与 shell split

- `apps/Blocks/BlocksApp/Views/SettingsView.swift` 仅保留 `mode`、初始化和 `SettingsShellView(mode:)`，符合 compatibility wrapper 方向。
- `SettingsShellView` 负责 scroll/layout 和 route switch；`.all` 组合 Shortcut、General、Permission、Clipboard、Clipboard privacy、Agent CLI、Hooks、Data Audit、Translation、Provider pane；单 mode 分别映射到对应 pane。
- `SettingsSectionList.swift` 中 `SettingsViewMode` 保留 `all`、`general`、`clipboard`、`clipboardPrivacy`、`translation`、`shortcuts`、`providers`、`agentCLI`、`hooks`、`dataAudit`、`permissions` 全量 case。

### 4.2 mode mapping 与新增 pane

- `clipboardPrivacy` 映射到 `ClipboardSettingsPane(showPrivacySection: true)`，并在 header 返回按钮中通过 AppState shell 选择状态回到 clipboard settings。
- `hooks` 映射到 `HooksSettingsPane()`。
- `dataAudit` 映射到 `DataAuditSettingsPane()`。
- `all` 模式包含上述新增 pane，不再依赖旧 `SettingsView` 巨型 body。

### 4.3 局部状态与既有 store/facade 边界

- `ProviderSettingsPane` 保留 provider secret candidate、用户确认、OpenAI test connection confirmation 等局部 `@State`，敏感动作通过 `appState.performProviderUserSecretGate` / `performProviderKeychainGate` facade，不直接持有 Keychain、网络或 provider runtime。
- `TranslationSettingsPane` 使用 translation/provider 相关 setting key 与 AppState/TranslationStore facade 读取 route/settings 能力，没有把 route resolver 或 provider runtime 拖入 Settings shell。
- `PermissionSettingsPane` 通过 `appState.permissionSnapshot` 和 permission action facade 协作，没有直接持有 `PermissionStore` 或系统权限 adapter。
- `ShortcutSettingsPane` 把 recorder state 和局部 event monitor 留在 pane/row 内，快捷键注册、绑定、恢复和诊断仍经 AppState facade/ShortcutStore 边界。
- `ClipboardSettingsPane` 保留既有 clipboard settings key，未启动 Clipboard hardening 或引入 clipboard payload 事实源迁移。

### 4.4 P11D 门禁

P11D 当前具备可维护的 fail-closed 架构门禁价值：

- 必要文件存在性和 Xcode target membership 检查覆盖完整 Settings shell/pane 文件集。
- `SettingsView` wrapper、全量 mode、mode mapping、setting key、局部状态边界、forbidden tokens、历史 verifier 当前事实源规则均被纳入。
- 当前输出无 failure，能守住 4C-3 的主要架构边界。

### P2

1. Settings pane 仍普遍通过 `@EnvironmentObject AppState` 访问 facade。作为 Step 4C-3 的 compatibility shell split 可接受，但后续如继续瘦身 Settings，应优先把 pane 输入收窄为 feature facade/protocol 或显式 closure，降低 Settings shell 对 AppState 表面积的长期依赖。
2. `ProviderSettingsPane` 仍是较大的 pane，包含 provider readiness、secret gate UI 和 lifecycle test UI。当前状态保持局部且敏感动作经 facade，未构成本阶段阻断；后续若 provider 设置继续增长，建议拆出更窄的 Provider subpane 或 view model。
3. 本轮复审未覆盖真实 UI 点击、滚动视觉、多语言布局、VoiceOver/键盘导航和真实系统动作。这些不属于 App 架构 P1，但应由测试/质量在最终接受流程确认。
4. 当前工作区显示 `Features/Settings/`、P11D、开发记录/验收记录等为未跟踪文件或未提交改动。流程上主 agent 接受前应确认开发侧变更集完整纳入，但这不是架构实现阻断。
