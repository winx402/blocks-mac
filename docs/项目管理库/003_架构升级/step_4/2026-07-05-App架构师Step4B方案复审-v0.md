## 1. 总体判断

Step 4B 选择 `PermissionStore` 单切片进入开发是合理的，可以交给开发实施。

依据：

- Step 3 最终接受范围明确停留在 Provider / Translation / AppState facade，不包含 Permission / Screenshot / Shortcut / Settings 拆分；因此 Step 4 继续消化 `AppState` 中的权限状态是顺序合理的后续动作。
- `PermissionStore` 是 Screenshot、Settings 权限页、Clipboard pending paste retry 等路径的共同上游状态输入，但它本身不需要同时搬迁截图捕获、快捷键、Settings shell 或 Clipboard 业务逻辑，适合作为单切片。
- Step 4B PRD 明确要求 `AppState` 继续作为 AppShell / coordinator facade，保留既有 facade API 和 object change 转发，不把视图一次性改为直接依赖新 store，符合 Step 2 / Step 3 的渐进式 facade 策略。
- PRD 已把 Clipboard pending paste retry 保留在 `AppState` / Clipboard 协调层，而不是下沉到 `PermissionStore`，可以避免权限 store 变成 Clipboard 业务事实源。
- PRD 已把真实权限请求、系统设置跳转、Show in Finder、restart 等行为约束为用户触发，并要求通过 service / presenter / system action boundary 隔离，方向正确。

## 2. 是否应继续避免与 ScreenshotStore 同批

建议继续避免与 `ScreenshotStore` 同批。

原因：

- `PermissionStore` 目标是剥离权限快照和权限辅助动作；`ScreenshotStore` 会涉及截图状态、ScreenCaptureKit 路径、结果 presenter、AI 处理入口和错误体验。两者虽然有关联，但变更风险和验收路径不同。
- 如果同批迁移，权限状态、截图执行状态、missing permission UI、结果流转和 AppState facade 改动会相互遮蔽，P11B 很难判断到底是哪一层破坏了边界。
- 先完成 `PermissionStore` 后，后续 ScreenshotStore 可以依赖更窄的 `PermissionReadable` / snapshot facade，反而降低截图拆分风险。

结论：Step 4B 作为单切片合理；不建议把 ScreenshotStore 加入同一开发批次。

## 3. 依赖方向复审

PRD 中的依赖方向基本清楚，未发现进入开发前必须返工的 P0/P1。

认可的方向：

- `PermissionStore` 持有权限快照，封装刷新和用户触发的权限辅助动作。
- `AppState` 持有 `PermissionStore`，绑定其 `objectWillChange`，并继续暴露兼容现有视图的 computed facade。
- `SettingsView` / `ScreenshotHomeView` 在本阶段尽量继续走 `AppState` facade，不做大范围依赖倒置。
- `PermissionAssistPanelPresenter` 保持 presenter / AppKit 边界，不把 presenter state machine 重写为本阶段目标。
- 权限状态查询、真实权限请求、签名诊断、系统设置跳转、Show in Finder、restart 等平台动作通过 protocol / closure / adapter 隔离，避免视图和业务 store 直接散落调用平台 API。

需要开发中特别守住的边界：

- `PermissionStore` 不应持有 `AppState`、`ProviderStore`、`TranslationStore`、`ScreenshotStore`、`ShortcutStore`。
- `PermissionStore` 不应导入或调用 Clipboard 业务、pending paste、`NSPasteboard`。
- `PermissionStore` 可以编排权限 feature 内部动作，但不应成为通用系统动作中心。
- 如果新增 `PermissionSystemActioning` adapter，应明确它是平台动作白名单位置，避免未来把任意 AppKit 系统动作都塞入权限模块。

## 4. Clipboard pending paste retry 判断

PRD 将 Clipboard pending paste retry 留在 `AppState` / Clipboard 协调层是可维护的。

该设计的好处：

- 权限 store 只表达权限状态和权限辅助动作，不理解 Clipboard pending paste record。
- `AppState.refreshPermissionState()` 继续在刷新权限快照后调用 `retryPendingClipboardPasteIfPossible()`，能保留现有行为兼容性。
- 后续如果 Clipboard 单独拆 store，可以把 retry 协调从 `AppState` 移到 Clipboard coordinator，而不需要再从 `PermissionStore` 中拆回。

建议在开发实现中明确调用顺序：先完成 `PermissionStore` refresh 并发布新 snapshot，再由 `AppState` facade 或注入的 `afterRefresh` closure 触发 pending paste retry。不要让 `PermissionStore` 直接依赖 retry 函数名或 Clipboard 数据结构。

## 5. P11B 架构边界检查复审

Step 4B PRD 中的 P11B 检查方向足够支撑本阶段开发，覆盖了关键边界：

- `PermissionStore` 文件存在并进入 App target。
- `PermissionStore` 是主线程 observable store。
- `AppState` 持有 `PermissionStore` 并绑定 `objectWillChange`。
- `AppState` 不再直接 `@Published var permissionSnapshot`。
- `AppState.permissionSnapshot` 保持 computed facade。
- `AppState` 保留权限相关 public facade methods。
- `AppState.refreshPermissionState()` 刷新权限 store 后继续触发 Clipboard pending paste retry。
- `PermissionStore` 不包含 Clipboard / pending paste / `NSPasteboard` 等业务 token。
- `PermissionStore` 不持有其他 store 或 `AppState`。
- `SettingsView` / `ScreenshotHomeView` 不直接调用敏感权限 API。
- 新增 permission feature 文件不散落敏感系统 API token，除非位于明确白名单 adapter。
- 如果移动 snapshot 类型，保留字段和语义。

建议补充为 P2 的细化检查，不阻塞进入开发：

- 在 P11B 中显式检查 `PermissionStore` initializer 不调用真实权限请求、系统设置跳转、Show in Finder、restart 等副作用函数。
- 明确 `PermissionSystemActioning` 或等价 adapter 的白名单文件名，P11B 只允许这些文件出现 `NSWorkspace`、`NSApp.terminate` 等系统动作 token。
- 将 Clipboard retry 的顺序写成可检查条件：`AppState.refreshPermissionState()` 必须在权限 refresh 后触发 retry，且 `PermissionStore` 内不得出现 retry 函数名、pending paste record ID 或 Clipboard store token。
- 如果 P11B 脚本命名仍受 Step 4 预初始化旧名影响，应统一为 Step 4B PermissionStore 专用名称，避免与后续 ShortcutStore / ScreenshotStore 检查混淆。

## 8. 建议开发顺序

1. 先新增 `PermissionStore` 和最小协议 / closure 边界，使用可注入依赖承接 snapshot provider、access requester、assist presenter、system actions。
2. 再让 `AppState` 持有 `PermissionStore`，绑定 `objectWillChange`，把 `permissionSnapshot` 改为 computed facade，保留既有 facade 方法签名。
3. 迁移 `refreshPermissionState()` 的权限快照刷新到 `PermissionStore`，但将 Clipboard pending paste retry 留在 `AppState` refresh facade 之后触发。
4. 迁移用户触发的 Screen Recording / Accessibility assist、open settings、Show in Finder、restart 到权限 feature 边界或白名单 adapter。
5. 最小化改动 `SettingsView` 和 `ScreenshotHomeView`，优先继续通过 `AppState` facade 读取，避免本阶段扩散视图依赖。
6. 与实现同步落地 P11B，再运行 PRD 要求的 P7 / P10B / build gates；若触及 Screenshot capture/result 或 ScreenCaptureKit，暂停并回到主 agent 重新确认范围。
