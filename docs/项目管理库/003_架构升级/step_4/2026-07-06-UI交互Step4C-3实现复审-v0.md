## 2. 总体判断

从静态实现看，Settings shell split 没有发现 UI/交互 P0/P1 阻断：

- `SettingsView` 已退化为 wrapper，只保留 `mode` 并委托 `SettingsShellView(mode:)`。
- `SettingsShellView` 保留滚动容器、header、mode route mapping 和 `all` 组合，不是视觉重设计。
- `SettingsSectionList` 继续提供 `SettingsTableSection`、`SettingsRowShell`、`SettingsFormRow`、`SettingsActionRow`、`SettingsRowDivider` 等共享布局组件。
- 固定 trailing column 仍由 `SettingsLayout.trailingColumnWidth = 280` 和 `SettingsRowShell` 承接，section / row / action row 语义保持。
- `clipboardPrivacy` 明确映射到 `ClipboardSettingsPane(showPrivacySection: true)`，并提供返回 Clipboard 设置的 back action。
- Provider / Translation / Permission / Shortcut pane 的核心用户语义仍通过既有 AppState facade / store 路径承接，未看到 pane 直连敏感系统动作或 provider route。
- Shortcut recorder 仍在 `ShortcutSettingsPane` 内保持单一 `@State`，并在 row disappear 时清理 local monitor。

因此 UI/交互侧建议主 agent 允许进入测试/质量最终接受流程；最终接受仍需补真实 UI、窄宽度、多语言和 VoiceOver 低敏证据。

## 4. 主要 UI 事实依据

### 视觉和信息密度

实现保留了原有桌面设置页的密集表格语义：

- Shell 使用 `ScrollView`、`VStack(spacing: 16)`、`contentMaxWidth = 760`、左右 padding 28、顶部 42、底部 48。
- Section 使用轻量 bounded group：标题 + 内容区，内容区保留 row divider 和紧凑 padding。
- Row 使用标题、detail 和固定 trailing column 的双区结构；action row 仍把按钮收束到 trailing column。

未看到 marketing/landing 式重做或视觉风格重写。实物层面仍需截图验证长内容是否被过度截断。

### Sidebar / Route / Header

静态实现和脚本覆盖显示：

- `SettingsViewMode` 保留 `all`、`general`、`clipboard`、`clipboardPrivacy`、`translation`、`shortcuts`、`providers`、`agentCLI`、`hooks`、`dataAudit`、`permissions`。
- `hooks` 映射 `HooksSettingsPane()`，`dataAudit` 映射 `DataAuditSettingsPane()`。
- `all` mode 通过多个 `SettingsPaneGroup` 组合 pane，不再由 `SettingsView` 单体承载所有主体。
- `SettingsPageHeader` 继续按 mode 给出标题、说明、图标和颜色。
- `clipboardPrivacy` header 提供 back button，目标是 `appState.selectedSection = .clipboardSettings`。

### Pane 用户语义

Provider pane：

- secret candidate、store confirm、test connection confirm 仍是 pane 局部状态。
- save / verify / delete / preview / test connection 继续通过 AppState gate 方法，不在 pane 中直接出现 `URLSession`、`SecItem` 或 provider route 直连。
- 外发测试仍有确认 toggle 和 disabled gate。

Translation pane：

- 继续使用 translation runtime gate、target language、route check 等既有语义。
- route check 通过 AppState facade，不在 pane 中直接调用 provider runtime。

Permission pane：

- 继续读取 `appState.permissionSnapshot`，保持 Step 4B PermissionStore 用户语义。
- refresh、restart、permission assist、Show in Finder、drag card 均保留在用户显式动作路径上。

Shortcut pane：

- global modifier、诊断 badge、record / restore / enable / restore all / re-register 均保留。
- recorder state 是 pane 内单一 `@State`，row disappear 会调用 `stopRecording()`。

Clipboard pane：

- 普通 Clipboard settings 与 `clipboardPrivacy` 独立入口保留。
- 本切片未启动 4C-4 Clipboard hardening；repository unavailable / redacted list / payload read model 不应在本次接受中写作已完成。

## 6. 建议最终接受记录补充的低敏证据

建议测试/质量或主 agent 最终接受记录补充：

1. Settings 各 mode 低敏截图：all、general、clipboard、clipboardPrivacy、translation、shortcuts、providers、agentCLI、hooks、dataAudit、permissions。
2. Sidebar / route 证据：从 sidebar 进入各 pane，`clipboardPrivacy` 返回 Clipboard 设置。
3. 视觉密度证据：header、section、row、action row、fixed trailing column 在正常宽度和窄宽度下不重叠、不丢控件。
4. 长文本证据：长 app path、长 bundle ID、长 recommended action、长 provider requirement、长 audit ID、长中文/英文/日文文案。
5. VoiceOver 证据：hidden-label Toggle / Picker / icon button 能读出具体设置名和动作名。
6. Shortcut recorder 证据：录制中切换 pane、关闭 Settings 后停止监听并恢复 idle。
7. Provider 局部状态证据：secret input、store confirm、test connection confirm 切换 pane 后的状态行为被记录为预期或残余风险。
8. Permission pane 证据：不触发真实权限请求的前提下，refresh / restart likely / request assist / Show in Finder / drag card 文案和按钮可理解。
