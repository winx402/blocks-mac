## 4. 重点复审结论

### ScreenshotStore 边界

边界合理。

`ScreenshotStore` 没有持有完整 `AppState`、`ProviderStore` 或全局 coordinator。权限、route preview、status 发布和 retake 都通过窄闭包进入。Store 承担 screenshot facts、capture action、recent capture list 和 result presenter 入口，职责对 4C-1 来说不宽也不过窄。

### AppState facade

符合 AppShell / coordinator 方向。

`AppState` 保留 `lastCaptureSummary` / `recentCaptures` / `startScreenshot(mode:)` / `routeSummaryForScreenshotAIAction(_:)` facade，桥接 `ScreenshotStore.objectWillChange`，并负责缺权 alert 与 window-level status 发布。没有重新成为 screenshot facts 的事实源。

### Permission 顺序与缺权路径

符合 PRD。

`ScreenshotStore.startScreenshot(mode:)` 先 refresh permission，再读取 snapshot，再检查 `screenRecordingGranted`。缺权返回 `.screenRecordingPermissionMissing`，由 `AppState.startScreenshot(mode:)` 调用 `showScreenRecordingAlert()`。Store 内未出现真实权限请求 token，不会静默触发权限请求。

### Result presenter / routeResolver

窄接口可维护。

Presenter 只接收 capture、routeResolver、retake；View 只持有 routeResolver closure，不依赖 `AppState`。AI route preview 仍是本地 preview，没有把 `ProviderStore`、provider runtime、Keychain 或 provider call 引入 ScreenshotStore / View。

### P11A 与旧事实源

P11A 覆盖了 Step 4C P1 回写要求中的最低职责矩阵，并且本次运行通过。它还检查 P3D / P3E / P3F / P7Q 不再把旧归档 / 旧 story / 旧 acceptance / 旧 AppState 字符串作为阻断事实源。对本子批次的架构边界来说足够。
