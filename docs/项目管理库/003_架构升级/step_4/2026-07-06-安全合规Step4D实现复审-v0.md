## 已确认通过的安全事实

1. 默认 repository load / reload 不再预读完整 payload。
   - `ClipboardStore.loadRepositoryState(limit:)` 只加载 records、pinboards、pinned metadata，并清空 cache。
   - P11E `denied_default_sites.repository_load_no_payload = true`。

2. 完整 payload 读取已收敛到 explicit purpose allowlist。
   - `ClipboardPayloadReadPurpose` 仅包含 `paste`、`copyPlainText`、`hoverDetail`、`translationPreview`。
   - AppState 调用点均带 purpose：paste、copy plain text、hover detail、translation preview。
   - 未发现无 purpose 的 `clipboardPayload(for:)` facade。

3. Payload cache 生命周期已按最新事实收紧。
   - `ClipboardPayloadCacheKey(recordID:purpose:)` 已存在。
   - `ClipboardStore.payloadCache` 为 `[ClipboardPayloadCacheKey: ClipboardRecorderPayload]`。
   - repository load 不填充 cache；fixture / in-memory 兼容路径通过 purpose-scoped cache 暴露。
   - P9B 已同步通过；cache 不作为本轮 P1。

4. 默认 UI / Settings / DataAudit / CLI denylist 主路径闭合。
   - `ClipboardFloatingPanelView` 默认 bottom tray 和 record list 不再向 row/card 传入 payload。
   - `ClipboardRecordViews` 不再持有 `ClipboardRecorderPayload`。
   - hover overlay 不再为所有 filtered records 预构造 payload；detail card onAppear 后才 `.hoverDetail` lazy read。
   - `ClipboardController.filteredRecords(...)` 不再把 historical pinned `displayName` 拼入默认 search/filter。
   - Settings Clipboard 和 DataAudit 只展示 count / state / policy / allowlist 说明。
   - BlocksCLI 当前未新增 clipboard payload 默认输出。

5. 低敏输出有明显改善。
   - P11E 输出相对路径、pattern label 和结构状态，不输出 matched sensitive content。
   - P9A 输出 `storage_root = <TMP>`、`database_file = Blocks.sqlite`，没有临时目录完整路径。
   - 开发记录未写真实剪贴板正文、URL 全文、file path 全文、图片/base64、OCR 文本、窗口标题、屏幕文本、真实凭据或请求内容。

6. 未发现本切片新增外发 / 系统动作能力。
   - 新增 Clipboard hardening 文件未引入 provider call、network、Keychain、OCR、App Group、helper 生产写库、CLI clipboard payload、TCC reset、系统设置、Show in Finder 或 restart。
   - 既有 AppState paste/copy 的 `NSPasteboard.general` 属于明确用户动作路径，不是默认展示路径。

## P1 关闭情况

### P1-1：历史 pinned `displayName` 不再进入默认 redacted preview / search/filter

状态：已关闭。

复核事实：

- `ClipboardRedactedPreviewBuilder.preview(...)` 固定使用 `redactedTitle(for:)`，不再把 `metadata?.displayName` 作为默认 title。
- `ClipboardRedactedPreviewBuilder.searchableText(...)` 只拼接 pinboard name、source display name、kind、format summary、signature 和 redacted body，不再拼接 `metadata?.displayName`。
- `ClipboardController.filteredRecords(...)` 的默认搜索文本由 preview searchable、redacted searchable 和 pinboard name 组成，不再拼接 `pinnedMetadata[record.id]?.displayName`。
- P11E 已新增 `redacted_preview_uses_pinned_display_name` 与 `filtered_records_uses_pinned_display_name` fail-closed 检查；当前 P11E PASS，且 `denied_default_sites.filtered_records_no_pinned_display_name = true`。
- 开发记录已补充该 P1 修复说明。

残余判断：

- 历史 pinned `displayName` 仍可存在于 repository metadata 中，但不再进入默认 redacted preview / search/filter 的已复核路径。
- 如后续重新开放用户自定义 pin title 展示，应先定义低敏来源标记或迁移策略，并扩展 P11E。

- Hover detail allowlist 会显示完整 payload，这是明确业务用例；验收截图不得包含真实正文、URL 全文、file path 全文或图片/base64。
- P9A / P11E 输出当前低敏，但后续新增 failure detail 时仍需沿用 sanitizer，避免把 subprocess stdout/stderr 原样写入 JSON。
- Provider / Keychain / OCR / network 相关 token 仍存在于项目既有模块和本地化文案中，但本次 Clipboard hardening 新增范围未引入这些能力。
