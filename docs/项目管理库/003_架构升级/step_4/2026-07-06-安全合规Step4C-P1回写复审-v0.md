## 3. 上一轮 P1 关闭情况

### P1-1 Clipboard hardening payload allowlist / denylist

状态：已关闭。

事实依据：

- PRD 已把 Clipboard hardening 定义为 conditional 4C-4，而不是 Step 4C core 必交项。
- PRD 已要求进入 4C-4 前做 go/no-go；若 P11E、payload allowlist / denylist、UX contract 或安全/质量门禁无法闭合，则拆为 Step 4D。
- PRD 已新增 Clipboard hardening UX contract，区分 `repositoryUnavailable`、redacted list、explicit payload read、empty / unavailable / filtered / redacted 状态。
- PRD 已新增完整 payload allowlist / denylist：默认列表渲染、普通面板列表、Settings summary、CLI 默认输出禁止读取完整 payload；paste、copy、hover detail、translation preview 允许在明确动作或明确业务用例下读取。
- PRD 已要求 P11E 输出 read model allowlist / denylist 摘要，且验证输出、开发记录、验收记录、audit、logs 不得包含剪贴板正文。

备注：实现阶段仍需由 P11E 静态或混合检查证明默认展示路径没有读取完整 payload；这属于开发验收项，不再阻塞 PRD 回写。

### P1-2 P11A/C/D/E 专项敏感 token、例外口径和低敏输出

状态：已关闭。

事实依据：

- PRD 第 7.1 已为 P11A、P11C、P11D、P11E 分别列出最低检查清单。
- P11A 已覆盖 ScreenshotStore target membership、AppState facade、权限检查顺序、route resolver 窄接口、禁止 provider/network/Keychain/OCR/image upload/base64/window title/screen text 等要求。
- P11C 已覆盖 ShortcutStore target membership、AppState facade、声明动作闭包、禁止动态 action 字符串派发、shell、AppleScript、CGEvent、外部 CLI、Accessibility 前台 UI 操作或未声明自动化入口。
- P11D 已覆盖 Settings shell / pane 文件、mode mapping、setting key 保持、pane 局部状态隔离，以及禁止直连敏感 API / provider route / clipboard full payload token。
- P11E 已覆盖 repository unavailable、默认路径禁止完整 payload、allowlist 读取、helper / App Group / CLI 默认完整 payload 禁止、低敏输出和 read model 摘要。
- PRD 已补充历史门禁当前事实源规则，要求旧归档 / 旧 story / 旧 acceptance / 旧字符串形态只能作为 `baseline_reference`，不得参与 `ok` 判定。

备注：P11 脚本实现时应把 PRD 的文字禁止项转成明确 token、调用路径和 allowlist 文件检查，不能只检查文档关键词。

### P1-3 Settings shell pane 不得绕过 provider / permission / clipboard gate

状态：已关闭。

事实依据：

- PRD Settings shell 边界已新增：Provider secret 输入、连接测试、route check、permission request / settings open、clipboard full payload 读取都必须继续由既有 store、adapter、gate 或用户显式动作路径承接。
- PRD 明确新增 pane 不得直接调用 `URLSession`、`SecItem`、`NSWorkspace` 系统动作、`NSPasteboard.general` 或 provider route。
- P11D 最低检查清单已要求新 settings pane 不含未经白名单解释的敏感 API token，并验证 Provider / Permission / Shortcut / Translation 等局部状态不进入全局 store 且不跨 pane 串扰。

备注：后续若 Settings pane 因 UI 拆分新增系统动作入口，仍需回到安全合规复审；本次 P1 回写本身已足够。
