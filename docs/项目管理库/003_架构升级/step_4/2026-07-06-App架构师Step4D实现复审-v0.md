- payload cache 已从 recordID-only 改为 `ClipboardPayloadCacheKey(recordID:purpose:)`，repository load 不填充 cache，fixture / in-memory 兼容路径通过 purpose-scoped cache 暴露。

本轮未发现阻断接受的 P0/P1。建议主 agent 进入最终接受流程，并把真实剪贴板 / hover / paste-copy / translation preview 的实物路径留给测试/质量做最终验证。

## 3. 架构事实依据

- Store/API：`ClipboardStore.loadRepositoryState(limit:)` 只加载 records、pinboards、pinned metadata，并清空 `payloadCache`；唯一完整 payload 读取入口是 `readPayload(recordID:purpose:)`。
- Cache 生命周期：`payloadCache` 类型为 `[ClipboardPayloadCacheKey: ClipboardRecorderPayload]`，key 包含 `recordID` 与 `ClipboardPayloadReadPurpose`；repository 读取成功后不写入广义 cache，fixture/in-memory 兼容路径也按 purpose scope 暴露。
- AppState facade：`AppState` 只保留 `readClipboardPayload(recordID:purpose:)`、`clipboardPreview(for:)`、`clipboardRepositoryStateSummary` 等协调层 facade；无无目的 payload facade。
- Read model：`ClipboardRedactedPreviewBuilder` 使用 kind、format summary、source app、pinboard name 等低敏 metadata；不使用 `record.summary`，也不使用 pinned `metadata?.displayName` 作为默认 title/search。
- 默认搜索：`ClipboardController.filteredRecords` 仍可使用 pinboardID/pinboardName 进行过滤和低敏检索，但不再拼入历史 pinned `displayName`。
- View 调用点：panel row/card/tray 默认路径不传 `ClipboardRecorderPayload`；hover detail 通过 `.hoverDetail` 懒读取；paste、copyPlainText、translationPreview 分别走显式 purpose。
- Settings / DataAudit / CLI：Settings storage summary 和 DataAudit 只展示 redacted repository state；CLI 默认路径不引用 payload 类型或 payload read。
- Target membership：P11E 检查确认 `ClipboardPayloadAccess.swift`、`ClipboardReadModel.swift` 已进入 Xcode project。

## 5. P0 / P1 / P2

### P0

无。

### P1

无。

已关闭的 P1 风险：

- recordID-only payload cache：已改为 `ClipboardPayloadCacheKey(recordID:purpose:)`，P9B 已同步检查。
- redacted preview/search 信任历史 pinned `displayName`：已移除该依赖，P11E 已加入 fail-closed 检查。
- default search/filter 拼入历史 pinned `displayName`：`ClipboardController.filteredRecords` 已移除该默认搜索依赖，P11E 已加入 fail-closed 检查。

### P2

1. P11E 对 cache lifecycle 的机器输出仍主要通过代码结构与 P9B 间接证明；建议后续把 `purpose_keyed_cache`、`load_clears_cache`、`repository_read_does_not_cache`、`fixture_cache_scoped_by_purpose` 加入 P11E 的显式摘要，便于审计。
2. `ClipboardRecorderRecord.preview(metadata:payload:)` 旧 helper 仍存在，可用于显式 payload 预览路径；当前默认调用点已迁移到 redacted preview，P11E 已覆盖回归，但后续若重构 preview API，应进一步命名区分 default redacted 与 explicit payload preview。
3. `repositoryStateSummary()` 对非空 repository 默认返回 `.redacted`，符合 Step 4D 默认低敏策略；若后续需要更细运营诊断，可增加“storage normal but content redacted”的双层状态，不阻塞本阶段。
4. `translationPreview` 当前是显式 purpose read 边界，但后续真正消费 payload 时仍需保持低敏预览/审计契约，不应通过 AppState 或 TranslationStore 引入无目的 payload 通道。
5. 真实 UI/系统路径仍需测试/质量最终确认：真实 hover detail、paste、copyPlainText、translation preview、panel close/hover exit 生命周期、多语言与可访问性。本轮架构复审未执行这些实物动作。
