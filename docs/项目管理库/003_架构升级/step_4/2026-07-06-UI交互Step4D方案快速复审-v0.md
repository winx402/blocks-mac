## 2. 总体判断

UI / 交互侧同意 Step 4D 继续进入开发，允许开发按 `P11E-first` 实现。

理由：

- PRD 已把 Step 4D 收敛为默认读取边界 hardening，而不是新增 Clipboard 能力或视觉重设计。
- Redacted list、repository degraded、empty / unavailable / filtered / redacted 四类状态、hover detail lazy explicit read、Settings 解释面、copy / paste / translation feedback 和低敏实物证据均已写入 PRD。
- P11E-first 的顺序合理：先建立 fail-closed 证据和 read model，再修改默认列表 / hover detail / Settings 用户反馈，能降低并行开发中把 payload 读取重新扩散到 UI 的风险。
- 方案没有要求真实 provider call、网络外发、OCR、Keychain、helper 生产写库、App Group 或 CLI 默认完整 payload 输出，符合本轮用户可见体验和隐私边界。

允许开发继续的条件：

- 4D-1 必须先交付 P11E、read model / allowlist / denylist 和默认 load 不预读 payload 的证据。
- 4D-2 才进入 Clipboard panel / Settings / hover detail / copy / paste / translation preview 的用户可见状态。
- 任何新增完整 payload 读取 purpose 必须先回写 PRD 和 P11E。
- 最终接受前必须补足低敏实物证据；本轮静态复审不能替代真实 UI / VoiceOver / 窄宽度验收。

## 3. 重点复审结论

### 3.1 Redacted List

方案层面通过。

PRD 已明确默认列表、普通 row / card、Settings summary、DataAudit 和 CLI 默认输出只能使用 metadata-first / redacted display item，不得使用 payload text、完整 URL、完整 file path、图片 / base64、OCR 原文或未证明低敏的 `summary`。

体验侧关键点是文案必须让用户理解“内容被保护”而不是“内容丢失”。最终验收需要至少一张低敏 redacted list 实物证据，证明默认列表仍可扫读 kind、source、time、pin / restorable / excluded、format summary 等信息。

### 3.2 Repository Degraded / Unavailable

方案层面通过。

PRD 要求 Clipboard panel 覆盖 repository unavailable / storage degraded banner 或等价可见反馈，Settings 覆盖 normal / degraded / unavailable storage 状态。这个契约足够派开发。

最终实物验收要确认 degraded 与 empty、filtered、redacted 不互相混淆，尤其不要把 storage degraded 表达成历史内容被删除。

### 3.3 Empty / Unavailable / Filtered / Redacted 四类状态

方案层面通过。

PRD 已要求四类状态可区分，并把它纳入 P11E 与最终低敏证据。建议开发实现时明确状态优先级，避免多个状态同时出现时 UI 层级打架：

- unavailable / degraded 优先于 list 内容状态。
- filtered 只用于有历史但当前搜索 / 过滤无结果。
- empty 只用于没有历史摘要。
- redacted 用于有记录但正文被保护。

该优先级建议作为 P2 回写或开发记录细化项，不阻断 P11E-first 开发。

### 3.4 Hover Detail Lazy Read

方案层面通过。

PRD 已明确 hover detail 是 lazy explicit read，不得为所有 filtered records 预读 payload，并要求 P11E 检查该路径。该设计能避免普通列表渲染或 hover overlay 初始化时误读完整 payload。

残余 UX 风险是“鼠标经过”是否足以算明确用户意图。最终验收需要保留低敏证据，说明 hover detail 的触发、loading、unavailable / blocked / not restorable 反馈，以及退出 / panel 关闭 / reload 后 cache 策略。

### 3.5 Settings 解释面

方案层面通过。

PRD 已要求 Settings Clipboard 展示 storage 状态、metadata-first / redacted 策略、完整 payload allowlist，以及不启用 helper 生产写库、App Group、CLI 默认完整 payload 的范围说明。

体验侧建议保持 Step 4C-3 Settings shell 现有密度和结构，不借 Step 4D 做 Settings 视觉重设计。长文案应优先拆成短句或标签 + 说明，不应挤压固定 trailing column。

### 3.6 Copy / Paste / Translation Feedback

方案层面通过。

PRD 已把 paste、copy plain text、hover detail、translation preview 定为完整 payload 读取 allowlist，并要求失败结果区分 not found、repository unavailable、payload unavailable、record not restorable 或 permission / policy blocked。这个契约能保住主动动作的用户语义。

最终验收需要确认失败反馈不静默，且不会让用户误以为 copy / paste 成功但内容为空，或 translation preview 已调用 provider。

### 3.7 低敏实物证据

方案层面通过。

PRD 的最小证据列表覆盖正常 redacted list、repository degraded、四类状态、paste / copy / hover / translation explicit read、Settings、DataAudit、CLI、VoiceOver / keyboard / 窄宽度 / 三语言长句。证据边界也明确禁止真实正文、完整 URL、完整 file path、图片 / base64 或 OCR 文本。

本轮未采集截图或真实 UI 证据，因此这些仍是最终接受前的待验证项。

## 4. P0 / P1 / P2

### P0

无。

### P1

无新增 UI / 交互 P1。

PRD 当前已经具备派发 P11E-first 开发所需的体验契约。若实现过程中出现以下任一情况，应升级为 P1 并停止进入最终接受：

- 默认 list / row / card / Settings / DataAudit / CLI 默认输出重新读取或展示完整 payload。
- Empty / unavailable / filtered / redacted 四类状态无法区分。
- repository unavailable / storage degraded 无用户可见反馈。
- paste / copy / hover detail / translation preview 失败静默或误导用户。
- 验收证据、日志或 verifier 输出包含真实剪贴板正文、完整 URL、完整 file path、图片 / base64、OCR 文本或 provider raw response。

### P2

1. 建议回写状态优先级：repository unavailable / degraded、empty、filtered、redacted 同时满足时的展示优先级。
2. 建议回写 hover detail 的“明确意图”细节：触发时机、loading / failed / unavailable 文案、退出或 reload 后 cache 清理。
3. 建议回写 Settings 文案密度约束：不做视觉重设计，沿用现有 Settings shell / pane / section / row 结构，长句不要挤压 trailing column。
4. 建议主会同步 PRD 第 11 节流程措辞与当前“快速复审和开发并行”口径：允许开发按 P11E-first 先行，但最终接受和进入 4D-2 仍以 P0 / P1 为 0 为门槛。

建议主 agent 回写或要求开发记录补充：

## 6. 最终体验验收门槛

最终接受前，UI / 交互侧建议至少保留以下低敏实物证据：

- Clipboard panel 默认 redacted list，不显示正文、完整 URL、完整 file path 或图片内容。
- repository unavailable / storage degraded 与 empty / filtered / redacted 各自状态。
- paste、copy、hover detail、translation preview 的 explicit read 成功 / 失败反馈，证据只记录 purpose 和低敏 record id。
- Settings Clipboard storage / redacted policy / allowlist summary。
- DataAudit / CLI 默认输出低敏。
- 窄宽度、长 source / bundle id / pinboard name、中文 / 英文 / 日文长句、VoiceOver label / reading order 抽查。
