## 2. 总体结论

Step 4C PRD 已把 ScreenshotStore、ShortcutStore、Settings shell split 和 Clipboard hardening 的主要安全边界写入方案，且明确开发必须按子批次推进、P0/P1 触发暂停、P11A/C/D/E fail closed。因此从安全合规角度可以进入方案回写和开发前准备。

但当前 PRD 对部分门禁的可执行细节仍偏高层，尤其是截图图片不可记录 / 不可外发、剪贴板默认列表不得读取完整 payload、ShortcutStore 不得演变成任意自动化执行器，以及 Settings pane 不得绕过 provider / permission / clipboard gate。建议主 agent 在派开发前回写 P1 条款；未回写前不建议直接进入实现。

建议进入开发前准备：有条件建议。条件是先关闭本文 P1，或将 Clipboard hardening 拆为独立 Step 4D 后，仅让 Step 4C-1/2/3 进入开发前准备。

## 3. P0 / P1 / P2

### P0

未发现必须拒绝 Step 4C 方案的 P0。

### P1

P1-1：Clipboard hardening 必须补充可执行的 payload 访问 allowlist / denylist。
PRD 已要求默认列表转向 redacted / metadata-first，并禁止默认 payload 读取路径；但开发前还需要明确：哪些方法、View、command handler 可以读取完整 payload，哪些默认列表 / 面板渲染路径必须禁止读取完整 payload。`p11e_clipboard_hardening_checks.py` 必须对默认展示路径 fail closed，并验证验证输出不包含剪贴板正文。若该规则无法在 Step 4C 内写清，建议把 Clipboard hardening 拆为 Step 4D，不阻塞 ScreenshotStore、ShortcutStore 和 Settings shell split。

P1-2：P11A/C/D/E 需要回写敏感 token 与低敏输出规则的专项细化。
PRD 已列通用 forbidden token，但四个专项脚本还需要分别说明检查对象和例外口径：

- P11A：ScreenshotStore / screenshot feature 新文件不得记录、持久化、序列化、上传截图图片；不得新增 OCR、image upload、image LLM/provider call；verification JSON 和开发记录不得含图片 base64、OCR 原文、窗口标题或屏幕文本。
- P11C：ShortcutStore 只能通过声明动作 allowlist 触发截图、剪贴板面板、翻译面板等窄闭包；不得出现动态 action 字符串派发、shell、AppleScript、CGEvent、外部 CLI 或未声明自动化入口。
- P11D：Settings shell / pane 文件不得直接持有 provider secret、Authorization header、Keychain、外发、permission system action、clipboard payload 读取等能力；只能通过既有 store / adapter / gate。
- P11E：Clipboard hardening 必须验证默认列表和普通面板渲染不读取完整 payload，且 CLI / helper / App Group 默认完整 payload 仍未开启。

P1-3：Settings shell pane 的安全 gate 不得因拆分退化为 View 直连敏感 API。
PRD 已说 pane 不新增敏感 API token，但开发任务还应明确：Provider secret 输入、连接测试、route check、permission request / settings open、clipboard full payload 读取都必须继续由既有 store、adapter 或用户显式动作路径承接。新增 pane 若直接调用 `URLSession`、`SecItem`、`NSWorkspace` 系统动作、`NSPasteboard.general` 或 provider route，应视为 P1。

### P2

P2-1：四个子批次放入同一 Step 4C 会增加验收定位成本。PRD 已要求分批回调，建议开发记录和验收记录严格按 4C-1/2/3/4 分段，不要用一份笼统记录覆盖全部改动。

P2-2：Screenshot Result 的 copy / save 是用户显式导出路径，不等同于日志或外发；开发记录应区分用户主动保存与应用静默持久化，避免误判。

P2-3：Settings shell 文件移动量可能较大，低敏证据应聚焦路由、state isolation 和敏感 token 检查，不建议把完整 UI 文案、路径或本机环境细节写入验收记录。

P2-4：Step 4B 残余的 fresh / denied / revoked TCC 全矩阵、真实权限点击、真实 Show in Finder / restart 未覆盖，不阻塞 Step 4C 方案，但触碰相关路径时必须继续标为残余或补实测证据。

## 4. 必须保持的安全边界

### ScreenshotStore

- 严禁把截图图片、图片 base64、OCR 原文、屏幕文本、窗口标题写入日志、audit、开发记录、验收记录或 verification JSON。
- 严禁新增 OCR、image upload、多模态 provider call、图片 LLM 外发或 provider raw response 记录。
- 截图结果只允许在用户明确动作下 copy / save / retake / close；recent captures 默认应是低敏 summary，不应持久化真实图片内容。
- AI action route preview 必须保持 preview-only；可以组织 route 输入摘要，但不得上传图片或调用真实 provider。
- 权限状态必须通过 `PermissionStore` / 窄协议 / facade 读取，不得在新 store 中绕过权限 gate 或静默触发真实权限请求。

### ShortcutStore

- 只允许声明动作 allowlist，不得扩大为任意自动化执行器。
- 不新增 shell、AppleScript、CGEvent、外部 CLI、Accessibility 前台 UI 操作、未声明 action dispatch。
- 快捷键动作闭包应由 AppShell 注入，`ShortcutStore` 不持有完整 `AppState`。
- 快捷键录制仍保持一次只录一个命令，失败 / 禁用 / 自定义 / 恢复默认路径不得产生额外自动执行。

### Settings Shell / Pane

- pane 不得直接读取或保存 provider secret，不得直接拼接 Authorization / Bearer，不得直接发 provider 网络请求。
- permission request、打开系统设置、Show in Finder、restart 等系统动作只能留在既有白名单 adapter / presenter / 用户显式动作路径中。
- clipboard pane 不得默认读取完整剪贴板 payload；Agent/CLI pane 不得承诺或启用 CLI 默认完整 payload。
- Provider / Translation / Permission / Shortcut / Clipboard 的局部状态不得因为拆 pane 泄漏到全局 store 或跨 pane 串扰。

### Clipboard Hardening

- 默认列表和普通面板渲染应使用 redacted / metadata-first read model。
- 完整 payload 只允许在明确用户动作或明确业务用例读取，例如 paste、copy、hover detail、translation preview。
- 不启用 App Group、helper 生产写库、CLI 默认读取完整 payload。
- 剪贴板正文不得进入日志、audit、开发记录、验收记录、测试 JSON 或 verification 输出。
- 若无法为默认展示路径建立静态门禁和低敏实测证据，应从 Step 4C 拆出独立安全切片。

## 5. 建议回写项

- 在 PRD 第 7.1 为 P11A/C/D/E 补充每个脚本的专项 deny token、allowlist 文件、允许例外和低敏输出字段。
- 在 Clipboard hardening 章节新增“完整 payload 读取 allowlist”，并把默认列表 / 面板渲染路径列入 denylist。
- 在 ScreenshotStore 章节新增“截图图片生命周期”：内存态、用户显式保存、recent summary、verification 输出分别允许什么、禁止什么。
- 在 ShortcutStore 章节新增“声明动作列表”，并要求任何新增 action 必须更新 PRD / P11C / 测试矩阵。
- 在 Settings shell 章节新增“pane 不直连敏感 API”验收项，明确 provider、permission、clipboard 三类 gate 只能通过既有 store / adapter。
- 在角色流程中保留“任一子批次出现 P0/P1 即暂停，不继续下一子批次”的规则；Clipboard hardening 若被拆出 Step 4D，应在 Step 4C 接受记录中明确未接受范围。

## 6. 可后续处理的风险

- Step 4B 残余 TCC 全矩阵和真实系统动作未自动化覆盖，可继续作为残余风险，不阻塞 Step 4C 方案。
- Settings 窄宽度、长文本、长路径、多语言、VoiceOver 的低敏实测证据可在对应子批次验收时补，不要求 PRD 阶段完成。
- Clipboard repository unavailable 的具体 UI 文案可由 UI/交互和测试/质量在实现验收中细化；安全侧只要求不暴露正文、不静默读取完整 payload。
- Screenshot capture service 与 result presenter 的回归面较大，但在 P11A 和 P3C/D/E/F/P7Q 门禁覆盖下可作为开发风险管理，不构成方案阻断。

## 7. 开发和测试必须验证的安全项

- P11A/C/D/E 均存在、fail closed，并输出 checked files、target membership source、命中 / 未命中摘要和失败原因。
- 新增 store / pane 无未经白名单解释的 `URLSession`、`SecItem`、`Authorization`、`Bearer`、`Process(`、`getenv(`、`NSAppleScript`、ScreenCaptureKit 直连 token、`NSPasteboard.general`、`CGEvent`、`AXUIElement`、hotkey 注册 token。
- P11A 证明 ScreenshotStore 不记录、不持久化、不外发截图图片，不新增 OCR / image upload / provider call。
- P11C 证明 ShortcutStore 仅能触发声明动作，不存在任意自动化、shell、AppleScript、CGEvent 或外部 CLI 执行能力。
- P11D 证明 Settings pane 不绕过 provider、permission、clipboard gate，敏感局部状态未上提到全局 store。
- P11E 证明默认 clipboard list / panel render 不读取完整 payload，完整 payload 只在明确用例读取，验证输出不含剪贴板正文。
- 开发记录和验收记录必须明确是否触发真实系统动作；若未触发，应列为残余而非暗示已覆盖。
- 所有低敏证据不得包含真实用户主目录、完整本地路径、窗口标题、屏幕文本、选中文本、剪贴板正文、真实截图、图片 base64、OCR 原文、真实凭据、Authorization header、request body 或 provider raw response。
