## 2. 总体结论

ScreenshotStore 实现本身未发现新增 Keychain、secret、URLSession、Authorization、Bearer、Process/env、OCR、image upload、多模态 provider call、base64、窗口标题 / 屏幕文本 / 剪贴板正文输出等敏感路径。AI route preview 仍通过 `routeResolver` 窄闭包取得本地 route summary，未见直接 provider call、图片上传或绕过 provider gate/runtime policy 的实现。

但本轮复审观察到 `p3f_screenshot_ai_route_ready_checks.py` 在失败路径中稳定输出完整本地路径，且嵌套 P3E/P3D/P3C/P5M 失败详情同样未脱敏。按照 Step 4C PRD 的低敏证据要求，verification JSON、开发记录和验收记录不得包含完整本地路径或用户 home。该问题不证明 ScreenshotStore 业务代码存在数据外发，但会污染失败证据和后续验收记录，因此列为 P1。

不建议主 agent 直接允许测试/质量最终接受。建议先修复或隔离 P1 低敏输出问题，再由测试/质量在停止并发 build 争用后串行确认 P3/P7/Xcode 门禁最终 PASS/FAIL。

事实：本轮两次运行 P3F，失败详情中均出现完整本地路径，包括项目根、DerivedData 和用户 Applications 路径。P7Q 已对 ROOT/HOME 做脱敏，但 P3F 及其嵌套回归的失败详情没有同等级低敏处理。风险是后续开发记录、验收记录或回调若直接粘贴失败 JSON，会把完整本地路径写入项目文档。

- 嵌套脚本输出被作为 failure detail 嵌入时，应递归脱敏，不能只脱敏顶层 command。
- 修复后由测试/质量串行重跑并确认 P3F/P3/P7/Xcode 最终结果。

## 5. 安全边界复核

### ScreenshotStore / Screenshot feature

- `ScreenshotStore.swift` 未命中 P11A forbidden tokens；本轮另行静态扫描也未见 Keychain、secret、URLSession、Authorization、Bearer、Process/env、OCR、image upload、多模态 provider call、base64、窗口标题 / 屏幕文本 / 剪贴板正文输出路径。
- `ScreenshotStore` 不持有完整 `AppState`，不直接持有 `ProviderStore` 或 `TranslationStore`。
- `AppState.lastCaptureSummary` 和 `AppState.recentCaptures` 已为 computed facade；`ScreenshotStore` 持有 screenshot facts，并通过 `objectWillChange` 桥接。
- `ScreenshotStore.startScreenshot(mode:)` 先调用 permission refresh，再取 snapshot；缺少 Screen Recording 时记录 status 并返回 `.screenRecordingPermissionMissing`，未见静默触发真实权限请求、系统设置、Show in Finder、restart 或 TCC reset。
- `ScreenshotResultPresenter` 中仍有 `NSPasteboard.general` 和 `NSSavePanel`，但位于用户显式 Copy / Save As 导出动作路径，不是 ScreenshotStore 默认日志、持久化、provider call 或 verification 输出路径；本轮不列为新增 P1。
- `screenshot.result.windowTitle` 是本地化 key / panel title，不是采集到的真实窗口标题。

### AI route preview

- `ScreenshotResultView` 通过 `routeResolver(selectedAIAction)` 构造 `ScreenshotAIActionRoutePreview`。
- `ScreenshotStore` 只持有 `(ScreenshotAIAction) -> ProviderRouteResolution` 闭包；`AppState` 注入的实现调用 `ProviderStore.routeSummaryForScreenshotAIAction(...)`。
- 抽查 `ProviderStore.routeSummaryForScreenshotAIAction` 显示该方法只选择 profile 并调用 `providerRouter.resolve(ProviderRouteRequest(profile: profile))`，未读取 Keychain，未发网络请求，未执行 provider runtime。
- UI 中仍显示 no-upload/provider-not-called 类承诺；未见图片上传、OCR 执行或多模态 provider call。

### 旧事实源处理

- P11A 输出显示 `historical_gate_current_sources.hits = []`。
- P3D/P3E/P3F/P7Q 脚本均声明 current PRD、current development record、current code facts 为当前事实源，并输出 `legacy_story_used_for_ok = false` 或 `legacy_archive_used_for_ok = false`。
- 本轮未见旧归档 / 旧 story / 旧 acceptance 被用于阻断 ok 判定。
