## 2. 已验证项

- `ProviderStore` 已存在，路径为 `apps/Blocks/BlocksApp/Features/Provider/ProviderStore.swift`。
- `TranslationStore` 已存在，路径为 `apps/Blocks/BlocksApp/Features/Translation/TranslationStore.swift`。
- 两个 store 已进入 `apps/Blocks/Blocks.xcodeproj/project.pbxproj` 的 file reference 和 Sources。
- `AppState` 持有 `let providerStore: ProviderStore` 和 `let translationStore: TranslationStore`，并绑定两个 store 的 `objectWillChange`。
- `AppState` 不再直接声明 PRD FR-3 所列 Provider / Translation `@Published` 事实源；这些名称保留为 computed facade 或 facade method。
- `ProviderStore` 承接 provider profile、selected IDs、route、audit、Keychain gate、connection test 和 LLM mock adapter 等事实源。
- `TranslationStore` 承接 translation provider / engine、selected IDs、preview、mock result、runtime result 和 translation route。
- `TranslationStore` 不强持有 `ProviderStore`，通过 `auditRecorder` 闭包写入 audit；未声明第二套 `providerAuditEvents`。
- Provider audit 仍只有 `ProviderStore.providerAuditEvents` 一个事实源。
- `.llmBacked` route/runtime 契约已统一：runtime configured + alias + external confirmed 时 ready；missing config / missing alias / missing confirmation 正确阻断；dedicated API 和 local CLI 仍 unsupported。
- route check 本身不读取 Keychain、不访问网络、不执行 CLI。
- gate false、missing alias、missing base URL、missing model、invalid URL、非 loopback HTTP 都是 0 Keychain read / 0 network call。
- HTTP policy 符合 PRD：外部 provider 需要 HTTPS；loopback HTTP 作为本地网关例外被单独覆盖。
- `ProviderStore` / `TranslationStore` / 相关 View 层通过 P10B forbidden token 静态检查。
- `ProviderUserSecretMaterial` 未进入 `@Published` 或 stored property；secret material 只在 ready runtime call 局部作用域内读取。
- translation runtime audit 只记录状态、耗时、字符数、request id / audit id 等元数据；未记录译文正文。
- 开发记录与 Step 3 文档中未发现真实 secret、Authorization header、Bearer token、完整 request body、provider raw response 或真实译文正文；命中的相关字符串均为安全要求描述。
- 未发现 Step 3 静默扩大范围到完整 SettingsView 拆分、真实 provider、真实 OCR、图片外发、helper/App Group 或 CLI 完整 payload。

## 5. 安全 / 隐私边界复核

- 通过 P10A 确认 route contract runner 不依赖真实 Keychain、真实网络或真实 provider。
- 通过 P10B 确认 `ProviderStore`、`TranslationStore`、`TranslationHomeView`、`TranslationFloatingPanelView`、`SettingsView` 不直接出现 forbidden runtime token：`URLSession`、`SecItem`、`Authorization`、`Bearer`、`Process(`、`getenv(`、`NSPasteboard.general`、`rawProviderOutput`、`providerRawOutput`。
- 通过 P5O 确认 runtime gate 的 blocked cases 不读取 Keychain、不访问网络。
- 通过 P5O 确认 success / loopback HTTP case 使用 mock transport 与低敏 fixture，不调用真实外部 provider。
- 通过代码抽查确认 `TranslationStore` 仅在 gate ready 后局部执行 `readProviderSecret(keychainAccountAlias)`，且未将 `ProviderUserSecretMaterial` 存为发布状态或持久属性。
- 通过代码抽查确认 runtime audit 的 `resultSummary` 使用 `result.outputText?.count`，不记录 `outputText` 正文。
- 通过文档 / 代码搜索确认 Step 3 文档和相关 store / view 中没有真实 secret、Authorization header、Bearer token、完整 request body、provider raw response 或真实翻译正文；搜索命中的敏感词均在 PRD / 安全复审中作为禁止项描述。

## 6. 残余风险

- `AppState` 仍保留较多跨 feature facade 和协调入口；Step 4 仍需继续拆 Screenshot、Permission、Shortcut、Settings shell。
- `SettingsView` 仍是大型聚合 View；本阶段仅调整 route/runtime context，没有做全量拆分。
- Clipboard `repositoryUnavailable` 生产降级策略、redacted list + lazy payload、helper / App Group / CLI 完整 payload 读取仍未解决。
- 真实 provider 兼容性、真实 API key 生命周期、真实网络失败形态不是 Step 3 验收目标，后续启用真实 provider 前需要单独验收。
- `FloatingPanelSupport.swift` 的 main actor isolation build warnings 不是本阶段改动目标，也未阻断 build；建议后续 UI / AppShell 相关阶段清理。

结论：`accepted`。

Step 3 满足 PRD 验收标准，没有发现测试/质量阻断项。建议进入 App 架构师最终实现复审。
