## 3. 实现记录

- `ProviderStore` 承接 LLM / OCR provider profile、selected IDs、provider route、provider audit、Keychain gate、OpenAI-compatible connection test、LLM mock adapter 等 Provider 事实源和动作。
- `TranslationStore` 承接 translation provider / engine profile、selected IDs、preview、mock result、runtime result 和 translation route。它不强持有 `ProviderStore`，只通过 `auditRecorder` 闭包写入 Provider audit，Provider audit 仍只有 `ProviderStore.providerAuditEvents` 一个事实源。
- `AppState` 新增 `let providerStore` 与 `let translationStore`，绑定两个 store 的 `objectWillChange`，并通过 computed properties / facade methods 继续向现有 View 暴露兼容入口。
- `AppState` 行数从 PRD 记录的约 2342 行降至 P10B 实测 1921 行。P10B 同时记录 `ProviderStore` 596 行、`TranslationStore` 479 行。
- `ProviderRouter` 新增 runtime preflight 入口和 `ProviderRuntimeGate`，统一 `.openAICompatible` / `.llmBacked` 的 ready、missing configuration、missing secret、confirmation required 语义。
- HTTP policy 已收敛为：外部 provider 必须 HTTPS；HTTP 只允许 localhost / loopback。本地 gate 阻断时不读取 Keychain、不发网络。
- `AICapabilityProfiles.swift` 中 LLM-backed translation metadata 已调整为 route-capable，避免 route ready 与 UI metadata “not implemented” 冲突。
- `SettingsView` 与 `TranslationHomeView` 的 translation route check 已传入 base URL、model、alias 和 external gate runtime context。
- `OpenAICompatibleConnectionService` 与 `OpenAITranslationRuntimeService` 增加 HTTP policy 防线；`TranslationStore.runTranslation` 先做本地 gate，再在 ready case 内局部读取 Keychain material。

## 4. 安全边界结果

- route check 只做本地判断，不读取 Keychain、不访问网络、不执行 CLI。
- `ProviderStore` / `TranslationStore` 和 View 层禁止敏感 API token 的静态检查已由 P10B 覆盖并通过。
- `TranslationStore` 不把 `ProviderUserSecretMaterial` 放入 `@Published` 或 stored property；secret material 仅在单次 runtime 调用局部作用域内存在。
- provider audit、开发记录和验证输出不包含运行态译文正文、真实 secret 原文、secret 摘要、完整请求体或 provider 原始响应。
- P5O 覆盖 local mock、unsupported、gate false、missing alias、missing base URL、missing model、invalid URL、非 loopback HTTP 均不读取 Keychain、不访问网络；loopback HTTP 作为本地网关例外单独覆盖。
