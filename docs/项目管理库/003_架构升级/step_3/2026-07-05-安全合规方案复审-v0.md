## 1. 复审结论

无 P0 reject。Step 3 PRD 方向符合既有 secret handling 边界：真实 secret 只在 Keychain，外发翻译 runtime 需要 gate，审计只保留脱敏元数据。开发前必须补入 Keychain 读取顺序、HTTP base URL 策略和新 store / View 层禁止直接接触敏感 API 的边界。

## 2. 必须补充的安全边界

- Keychain 读取必须后置。base URL、model、alias、外发 gate 均通过本地校验后，才允许调用 `readUserSecretForProviderCall`。
- HTTP base URL 策略必须明确：外部 provider 要求 HTTPS；HTTP 只允许 localhost / loopback 本地网关例外。
- `.llmBacked` route ready 不等于执行授权；route check 不得读取 Keychain、访问网络或执行 CLI。
- `ProviderStore`、`TranslationStore` 和 View 层不得直接出现 `URLSession`、`SecItem`、`Authorization`、`Bearer`、`Process(`、`getenv(`、`NSPasteboard.general`。
- `translationRuntimeResult.outputText` 属于敏感运行态数据，不得进入 audit、开发记录、验证 JSON、日志或持久化存储。
- 真实用户 secret 不得输出原文、hash、Authorization header、完整 request body 或 provider raw response。

上述要求已回写 Step 3 PRD。

## 3. 可后续处理风险

- Dedicated translation API、DeepL 类 provider、cloud OCR、多模态图片外发、streaming、模型列表保持 Step 3 非目标。
- provider audit 持久化、保存期限、一键清空策略可后续决策；Step 3 继续内存态 20 条容量即可。
- alias 可能被用户误填成 secret 的输入校验和提示可后续增强，但 Step 3 不应把 alias 当 secret 读取或迁移。
- App Store 审核、notarization、Developer ID、长期分发政策不是 Step 3 阻断项。

## 4. 开发 / 测试必须验证项

- P10A 覆盖 `.llmBacked` ready / missing secret / confirmation required，并断言 route 不触发 Keychain、网络或 CLI。
- P5O / P10A 增加 no-call 覆盖：local mock、unsupported、gate false、missing / invalid base URL、missing model 都不得读取 Keychain 或访问网络。
- 验证 HTTP 策略：外部 `http://` 被阻断；如允许 localhost HTTP，必须单独 case 覆盖。
- P10B 静态检查新 store / View 层禁止 token：`Authorization`、`Bearer`、`URLSession`、`SecItem`、`Process(`、`getenv(`、`NSPasteboard.general`。
- 自动化 runner 只用 mock transport、低敏 fixture 或空 Keychain；不得要求真实 API key、真实 provider 或真实外部网络。
- 验证 audit、开发记录、测试输出不包含 secret 原文、secret hash、Authorization、完整 request body、provider raw response 或真实翻译正文。
