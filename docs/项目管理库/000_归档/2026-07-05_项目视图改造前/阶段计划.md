# 阶段计划

状态：proposed
最后审阅：2026-07-01
来源级别：execution status

本计划用于约束从构想到可执行项目的推进顺序。阶段内容仍是建议，不代表已经完成决策。

V1 详细实施拆解见 [V1 实施阶段计划](V1实施阶段计划.md)。当前 V1 以产出三类通用工具为目标：截图、剪贴板、翻译。文件与图片批处理保留为后续候选能力，不作为当前前三工具的默认承诺。

## P0：项目空间初始化

目标：建立独立仓库文档结构，保留来源和边界。

交付物：

- 文档总览与知识治理规则。
- 项目总览、产品定位、MVP 范围假设、技术边界与架构假设。
- 初始资料导入记录和待验证问题。

验收标准：

- 读者能从 `README.md` 和 `docs/index.md` 找到当前项目状态。
- 文档明确区分事实、建议和待验证项。
- 来源资料路径清晰，未把来源讨论误写成最终决策。

## P1：V1 产品范围和深度规格

目标：确认 V1 三类通用工具的核心 Jobs、使用场景和深度标准。

建议任务：

- 为三类工具分别定义核心 Jobs、输入来源、输出形态和失败场景。
- 为每个工具列出必须做到的深度、首版不做的范围和验收场景。
- 定义统一交互原则：快捷入口、结果预览、AI 确认、历史记录、隐私提示。

## P2：技术验证和 action core 基础

目标：验证三类工具是否可以共享同一套 action core、CLI 输出、权限模型和 AI 调用边界。

建议任务：

- 设计 action schema、权限检查、执行日志和结果结构。
- 做一个最小 CLI JSON 输出原型。
- 验证 macOS 截图、剪贴板、文件访问和图片处理权限。
- 判断 MCP server、App Intents / Shortcuts 是否需要首阶段同时支持。

## P3：工具 1 纵切：截图

目标：完成第一个足够深的截图工具纵切，验证 UI、action core、权限、AI 调用确认和历史记录的完整链路。

建议任务：

- 实现截图触发、区域选择、图片预览、标注、复制和导出。
- 保留 OCR、翻译、总结作为可接入 action，但不把所有图片处理能力都塞进截图工具首个纵切。
- 实现结果保存、复制、导出和历史记录。
- 暴露同等能力的 CLI action。

## P4：工具 2 纵切：剪贴板

目标：完成第二个深做工具，并复用阶段 3 已验证的 action core、AI 调用和历史记录能力。

建议任务：

- 实现剪贴板历史采集、去重、搜索、固定和清理。
- 实现基础搜索、AI 改写、翻译入口、敏感信息识别和遮蔽建议。
- 暴露同等能力的 CLI action。

## P5：工具 3 纵切：翻译

目标：完成第三个通用工具，验证文本、截图 OCR 文本、剪贴板文本和文件/图片输入之间的统一翻译 action。

建议任务：

- 实现文本输入、剪贴板输入、截图 OCR 文本和图片 OCR 文本的翻译入口。
- 实现原文/译文对照、结果编辑、复制、替换剪贴板和历史记录。
- 明确 AI 调用前的文本预览和用户确认边界。
- 暴露同等能力的 CLI action。

## P6：三工具整合和一致性打磨

目标：让三个工具像同一个产品的一部分，而不是三个互不相关的功能。

建议任务：

- 统一入口、快捷键、空状态、结果面板、历史记录和错误提示。
- 统一权限说明、AI 调用确认、日志查看和隐私设置。
- 整理 action 列表、CLI 帮助和使用文档。

## P7：V1 Alpha 验收

目标：判断 V1 是否达到“可日常试用”的质量，而不只是功能可运行。

建议任务：

- 执行三类工具的端到端验收。
- 做性能、稳定性、权限撤销、离线场景和异常输入测试。
- 记录阻塞问题、体验问题和 V1.1 延后项。

## P8：V1 Beta / 发布准备

目标：准备面向真实用户的小范围试用版本。

建议任务：

- 完成安装、更新、权限引导、首次使用路径。
- 准备用户反馈入口和本地诊断信息导出。
- 整理隐私说明、AI 调用说明、发布检查清单和回滚方案。
