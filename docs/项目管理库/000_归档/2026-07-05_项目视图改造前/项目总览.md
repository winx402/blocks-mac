## 项目目标

建立一个独立项目空间，用于推进「奇点 AI 工具箱」：先验证少数高频工具是否能做深，并把这些工具沉淀为人和本地 agent 都能稳定调用的 macOS 工具能力。`jdtool` 是 P2 阶段暂定技术前缀，不代表最终品牌定稿。

## 当前判断

方向有可操作性，但应控制范围。当前最有价值的切口不是“把所有工具装进一个 App”，而是：

- 做一个统一 action core。
- 先深做 2-3 组高频、本地、AI 增益明确的通用工具，当前优先口径为截图、剪贴板和翻译。
- 让 UI、CLI、MCP、App Intents / Shortcuts 尽量复用同一套动作接口。
- 把截图、剪贴板、文件、图片等敏感能力的权限和审计机制作为产品核心，而不是后补安全说明。
- 正式 App 按 sandbox-first 设计；前期开发保留 Direct Download 和 App Store 双出口，不锁死最终分发渠道。
- JSON Schema 文件是 action 接口事实源；P2 保留轻量 smoke，`swift-json-schema` 已完成候选 spike但未正式采用，正式工程外部输入和 hook manifest 必须走完整或等价严格校验。
- P2-L 已把 P3 前 scaffold 形态收敛为 `SwiftUI + AppKit + sandbox-first + SMAppService helper + shared action core`；P3-A 已按该约束创建正式工程，但不代表完整 App 已完成。

## 当前非目标

- 不在初始化阶段确定完整功能清单。
- 不把录屏、日历、计算器、壁纸、启动器等所有工具都列入首版承诺。
- 不在没有验证的情况下确定 MCP、App Intents、商业模式或最终分发渠道。
- 不把 AI 做成外接聊天框；AI 能力必须服务具体工具流程。

## 下一步

1. 剪贴板下一步优先补生产级 `ClipboardRepository` / 单一数据源，并明确 live capture 是否持久化；当前真实 payload 只在 App 内存态路径稳定展示和恢复。
2. 补保存前 `ClipboardCapturePolicy`：暂停、排除 App、drop/redact/accept 应在 payload 进入生产 store 前发生，而不是只靠后续 apply policy。
3. 补真实 UI / 实物回归：hover detail、筛选、条目宽度、bottom 高度、自动粘贴、自写入抑制和第三方复杂剪贴板样本不能只依赖静态字符串门禁。
4. Packaging / Tester Readiness 仍需推进：安装包、签名/notarization 策略、测试员安装路径、日志/崩溃收集边界和 Alpha bug backlog 尚未完成。
5. 后续新增 UI 必须同步 String Catalog，并复用统一 glass wrapper / material fallback；多屏、权限撤销和 Permission Assist revoked-flow 保留为环境依赖复测。
