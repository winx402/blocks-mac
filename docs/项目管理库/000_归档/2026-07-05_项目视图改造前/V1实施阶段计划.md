# V1 实施阶段计划

状态：proposed
最后审阅：2026-07-01
来源级别：execution status

## 计划目标

V1 以产出三类通用工具为目标：

1. 截图。
2. 剪贴板。
3. 翻译。

这里的“三个工具”不应理解为三个垂直人群产品，也不应理解为三个浅层 demo。当前口径是三个通用、高频、可日常使用，并且同时接入统一 action core 的工具模块。文件与图片批处理保留为后续候选能力。

## V1 深度标准

每个工具进入 V1 前，都必须满足同一套深度标准：

- 有完整人工 UI 路径：用户不依赖命令行也能完成核心任务。
- 有机器可调用路径：至少提供 CLI JSON 调用；MCP / App Intents 是否首版支持由技术验证决定。
- 有结构化 action schema：输入、输出、错误和权限需求可描述、可测试。
- 有权限和隐私边界：明确哪些数据本地处理，哪些需要用户确认后才可交给 AI。
- 有历史与结果记录：用户能查看最近操作、复用输出，并理解失败原因。
- 有基础质量保障：核心流程有自动化测试或可重复验收脚本，关键失败场景有明确处理。

## 阶段 0：项目空间和基础约束

目标：完成项目文档空间、知识归属和初始边界。

需要做什么：

- 建立仓库入口、文档总览、知识治理规则。
- 迁移管家项目中的初始构想，保留来源和不确定性。
- 明确 V1 不做通用启动器、不做所有小工具集合、不把 AI 做成外接聊天框。

产出：

- `README.md`
- `docs/index.md`
- `docs/知识治理库/知识库结构.md`
- `docs/项目管理库/项目总览.md`
- `docs/调研与验证库/2026-06-29-初始资料导入.md`

退出条件：

- 读者能从文档入口理解项目目标、当前阶段和不确定性。
- 技术栈、商业模式和分发路径没有被误写成既定事实。

## 阶段 1：V1 产品范围和深度规格

目标：把截图、剪贴板、翻译从方向描述细化成可设计、可开发、可验收的产品规格。

需要做什么：

- 为三类工具分别定义核心 Jobs、输入来源、输出形态和失败场景。
- 为每个工具列出“必须做到的深度”和“首版不做的范围”。
- 定义统一的交互原则：快捷入口、结果预览、AI 确认、历史记录、隐私提示。
- 把三类工具按依赖关系排序，避免同时开三条互相阻塞的线。

产出：

- V1 产品规格。
- 三个工具的深度规格：
  - [截图与图片处理交互整合](../产品知识库/交互整合/截图与图片处理/index.md)。
  - [剪贴板文本工作台交互整合](../产品知识库/交互整合/剪贴板文本工作台/index.md)。
  - [翻译工作台交互整合](../产品知识库/交互整合/翻译工作台/index.md)。
- V1 非目标清单。
- 每个工具的验收场景表。

退出条件：

- 每个工具至少有 3 个明确高频 Jobs。
- 每个工具都有 UI 流程和 agent 调用流程。
- 每个工具都有不可做、暂缓做和必须做的边界。

## 阶段 2：技术验证和 action core 基础

目标：先验证统一 action core 是否能支撑三类工具，再进入完整开发。

需要做什么：

- 选择首轮技术栈，并用决策记录说明选择依据和复审条件。
- 设计 action schema：输入、输出、权限、错误、日志、AI 调用策略。
- 做 CLI JSON 调用原型，验证 agent 可调用的最小闭环。
- 验证 macOS 权限：截图、剪贴板、文件访问、图片处理分别需要什么授权。
- 判断 MCP 和 App Intents / Shortcuts 是 V1 必需，还是 V1.1 扩展。

产出：

- 技术架构说明。
- action schema 草案和示例。
- CLI 调用约定。
- 权限与隐私验证记录。
- 技术栈决策记录。

退出条件：

- 至少一个 action 可以通过 CLI 输入结构化参数并返回结构化结果。
- 权限失败、输入错误、AI 调用失败有统一错误形态。
- 三个工具都能映射到同一套 action 模型，而不是各自独立实现。

## 阶段 3：工具 1 纵切：截图

目标：先做一个完整的截图工具纵切，用它验证 UI、action core、权限、AI 调用确认和历史记录的完整链路。

需要做什么：

- 实现截图导入或截图触发的基础路径。
- 实现区域选择、标注、结果预览、复制和导出。
- 将 OCR、翻译、总结作为可接入 action 保留，但首个纵切不要求一次性完成所有图片处理能力。
- 实现结果保存、复制、导出和历史记录。
- 暴露同等能力的 CLI action。

产出：

- 可用的截图工具。
- 对应 action schema 和 CLI 命令。
- 权限提示和失败处理。
- 核心验收用例和测试结果。

退出条件：

- 用户能用 UI 完成截图、区域选择、标注、复制或导出的完整流程。
- agent 能通过 CLI 触发或处理指定截图输入并获得 JSON 结果。
- 对无权限、截图失败、图片过大、导出失败等情况有明确提示。

## 阶段 4：工具 2 纵切：剪贴板

目标：完成第二个深做工具，并复用阶段 3 已验证的 action core、AI 调用和历史记录能力。

需要做什么：

- 实现剪贴板历史采集、去重、搜索、固定和清理。
- 实现基础搜索，并评估语义搜索是否进入 V1。
- 实现 AI 改写：润色、压缩、扩写、翻译、格式化。
- 实现敏感信息识别和遮蔽建议。
- 暴露同等能力的 CLI action，并支持批量文本输入。

产出：

- 可用的剪贴板/文本处理工具。
- 本地索引或搜索方案说明。
- AI 改写和敏感信息识别策略。
- 对应 action schema、CLI 命令和验收用例。

退出条件：

- 用户能快速找回、搜索、改写和复用剪贴板内容。
- 默认不会把剪贴板内容静默发送到云端 AI。
- agent 能对文本输入执行改写、识别或检索，并得到结构化结果。

## 阶段 5：工具 3 纵切：翻译

目标：完成第三个通用工具，验证文本、截图 OCR 文本、剪贴板文本和图片 OCR 文本之间的统一翻译 action。

需要做什么：

- 实现手动文本、剪贴板文本、截图 OCR 文本和图片 OCR 文本的翻译入口。
- 实现原文/译文对照、结果编辑、复制、替换剪贴板和历史记录。
- 支持至少中英互译，并保留语言检测、术语表、多语言批量翻译为后续候选。
- 明确 AI 调用前的文本预览和用户确认边界。
- 暴露同等能力的 CLI action。

产出：

- 可用的翻译工具。
- 统一 translation action 输入/输出模型。
- 文本预览、确认和隐私提示。
- 对应 action schema、CLI 命令和验收用例。

退出条件：

- 用户能从文本、剪贴板和截图/OCR 入口完成翻译并复用译文。
- 默认不会静默发送剪贴板或截图文本到云端 AI。
- agent 能提交翻译任务，并得到结构化译文、来源、目标语言和错误信息。

## 阶段 6：三工具整合和一致性打磨

目标：让三个工具像同一个产品的一部分，而不是三个互不相关的功能。

需要做什么：

- 统一入口、快捷键、空状态、结果面板、历史记录和错误提示。
- 统一权限说明、AI 调用确认、日志查看和隐私设置。
- 整理 action 列表，让 CLI 帮助信息、文档和 UI 能对应。
- 清理三类工具之间重复的存储、AI 调用和结果渲染逻辑。

产出：

- V1 工具总入口。
- 统一设置页和权限页。
- action 目录和 CLI 帮助文档。
- 三工具一致性验收报告。

退出条件：

- 三个工具的交互模式一致，用户不需要重新学习三套逻辑。
- CLI action 命名、参数、错误和输出结构一致。
- 权限和 AI 调用规则在三类工具中一致。

## 阶段 7：V1 Alpha 验收

目标：判断 V1 是否达到“可日常试用”的质量，而不只是功能可运行。

需要做什么：

- 执行三类工具的端到端验收。
- 做性能、稳定性、权限撤销、离线场景和异常输入测试。
- 找 3-5 个真实任务样本跑完整流程。
- 记录阻塞问题、体验问题和 V1.1 延后项。

产出：

- Alpha 验收报告。
- 缺陷清单和修复优先级。
- V1.1 延后项清单。
- 是否进入 Beta 的判断。

退出条件：

- 三类工具均可完成核心任务。
- 没有会导致截图丢失、剪贴板误传、翻译隐私泄露或历史记录不可追踪的已知阻塞问题。
- 已知问题都有明确优先级和处理归属。

## 阶段 8：V1 Beta / 发布准备

目标：准备面向真实用户的小范围试用版本。

需要做什么：

- 完成安装、更新、权限引导、首次使用路径。
- 准备用户反馈入口和本地诊断信息导出。
- 整理隐私说明、AI 调用说明和数据保存说明。
- 完成发布包、版本号、变更说明和回滚方案。

产出：

- V1 Beta 包。
- 首次使用引导。
- 隐私与数据处理说明。
- 发布检查清单和回滚方案。

退出条件：

- 新用户可以完成安装、授权、首次任务和反馈提交。
- 关键权限和 AI 数据边界解释清楚。
- 发布前检查清单全部通过。

## 建议实施顺序

不要三类工具完全并行开发。推荐顺序是：

1. 先做阶段 1 和阶段 2，冻结共同标准。
2. 用截图工具做第一个完整纵切。
3. 在复用 action core 的基础上做剪贴板工具。
4. 最后做翻译工具，因为它需要复用截图 OCR、剪贴板文本和通用 AI 调用确认。
5. 三个工具都能跑通后，再进入一致性打磨和 Alpha。

这个顺序的理由是：截图最能验证权限、UI、结果记录和 CLI 的共同链路；剪贴板能验证隐私和本地历史；翻译依赖截图 OCR、剪贴板文本和 AI 调用确认，应该在前两类工具沉淀出可复用基础后再做。文件与图片批处理保留为 V1.1 候选。
