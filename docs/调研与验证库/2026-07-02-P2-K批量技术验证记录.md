本记录保存 P2-K 第一轮批量技术验证结果。P2-K 仍是 spike，不是正式 App scaffold；不接真实支付、不调用真实 API、不保存敏感内容。

- 截图边界：display、屏幕边缘 rect、窗口候选、`NSScreen` / `SCDisplay` 映射、单屏/多屏状态。
- 复杂剪贴板：HTML、多格式 item、transient/concealed/autogenerated/source marker、多文件 URL fixture。
- helper 承载能力：sandbox Login Item/helper 中的低敏剪贴板 recorder roundtrip、非零退出观察、注销清理。
- provider 设置确认链路：mock API profile、CLI provider profile、外发确认 preview。
- Swift JSON Schema validator 候选：`ajevans99/swift-json-schema` `0.13.1`，仅隔离在 spike 包内。
- 批量入口：`tools/spikes/p2k_validation_suite.py --all --timeout 180`。

## 关键观察

- 截图基础链路已经覆盖全屏、边缘 rect、窗口候选和 `NSScreen` / `SCDisplay` 映射；本机没有多屏，不能伪造多屏结论。
- 复杂剪贴板 fixture 证明 HTML、多格式 item、marker 类型和多文件 URL 可以做 redacted 摘要和恢复写回。
- `org.nspasteboard.TransientType`、`org.nspasteboard.ConcealedType`、`org.nspasteboard.AutoGeneratedType` 和 `org.nspasteboard.source` 只作为低敏 marker fixture 验证；正式产品仍需要对第三方 App 实物样本复测。
- helper recorder roundtrip 证明 sandbox helper 在收到显式 start 通知后可以读取低敏剪贴板变化并发送 redacted event；默认心跳不读取内容。
- 同一命令内 `unregister -> register` 需要短暂等待，否则 helper 可能不会在测试窗口内启动；当前命令已加入 1 秒沉淀时间。
- `swift-json-schema` `0.13.1` 能通过本轮基础用例和部分项目 fixtures，但这仍是候选依赖 spike，不是采用决策。

## 未覆盖项

- 多屏和跨屏真实拖拽：当前机器只有一个 display。
- 屏幕录制权限拒绝、撤销、重授权：本轮不使用 `tccutil reset`，只能后续手动系统设置复测。
- NSPasteboard detection patterns 运行时调用：SDK 可见但 Swift refined API 命名未在本轮落地。
- 密码管理器、浏览器隐私字段、Office/设计软件真实复杂样本：本轮只用低敏 fixture。
- helper 长期运行功耗、崩溃自动恢复、用户撤销 `requires_approval`：本轮只做短时 roundtrip。
- Provider 真实 API 调用和正式设置 UI：本轮只验证配置确认 envelope。
- 统一 envelope 的跨文件 `$ref` 完整 validator 测试：本轮只跑 action output 和 hook manifest fixture。

## 当前结论

- P2 第一轮技术验证已基本完成，可以进入正式 App scaffold 前的架构收敛：主 App / helper / CLI / hook runtime 边界、设置页确认路径和敏感数据审计模型。
- 仍不应直接承诺完整 App Store 审核可行性、长期 recorder 性能、复杂第三方剪贴板兼容或真实 provider 调用安全性。
- 下一步建议从“继续堆 spike”转为整理正式 App scaffold 的最小架构方案和 P3 第一个纵切故事，但保留多屏、权限撤销、第三方复杂样本为环境依赖复测项。
