# 剪贴板设置页方案

状态：pending review
最后审阅：2026-07-03
适用范围：Settings > Clipboard

## 设计目标

剪贴板设置页应像 macOS 系统设置中的一个成熟偏好页，而不是 recorder debug 面板。用户打开它时，应该能完成四类任务：

1. 控制记录多久、保存多少。
2. 控制面板怎么出现。
3. 控制筛选状态如何保留。
4. 管理固定分组、本地数据和 Agent/CLI 访问。

诊断信息仍需要保留，但必须折叠在高级区域，不占据主路径。

## 信息架构

### 1. 记录策略

用途：设置历史保留规则。

建议控件：

- `保留时间`：分段选项 `7 天 / 30 天 / 90 天 / 永久 / 自定义`。
- `最大条目`：分段选项 `200 / 500 / 1000 / 自定义`，自定义时显示 stepper。
- `固定内容不清理`：toggle，默认开启。
- `策略摘要`：一句话说明，例如“普通历史保留 30 天，最多 500 条；固定内容不会自动清理。”

不要把 retention days 和 max items 只做成裸 stepper。

### 2. 面板显示

用途：控制 `Control + Option + V` 打开的历史浮层。

建议控件：

- `面板位置`：segmented control `底部 / 左侧 / 右侧`。
- `底部面板高度`：只在 bottom 模式出现，显示当前高度和恢复默认。
- `左/右侧宽度`：保留为后续扩展；V1 可先只展示默认宽度。
- `打开后聚焦搜索`：toggle，默认开启。
- `点击外部关闭`：toggle，默认开启，不建议关闭。

### 3. 筛选行为

用途：控制浮层顶部格式、时间、分组、来源筛选的保留方式。

建议控件：

- `关闭面板后清空筛选`：segmented control `立即 / 15 秒 / 30 秒 / 1 分钟 / 永不自动清空`，默认 `30 秒`。
- `打开时保留上次搜索词`：toggle，默认关闭；搜索词和筛选项分开管理。
- `显示 active filter 标签`：toggle，默认开启；关闭后只显示图标高亮，不显示筛选名称。
- `清空筛选按钮`：说明性 row，说明该按钮只清空格式、时间、分组、来源，不清空搜索框。

### 4. 固定分组

用途：管理 Pinboard 式长期内容组织。

建议控件：

- 分组列表：名称、颜色、条目数、排序。
- 新建分组。
- 重命名分组。
- 删除分组。
- 删除分组时选择：
  - 仅删除分组，条目回到“未分组固定”。
  - 删除分组及其中固定条目。

V1 可以不在设置页展示每个条目详情；条目移动主要在浮层右键菜单中完成。

### 5. Agent CLI / MCP 访问

用途：控制 agent、CLI 或 MCP 工具读取剪贴板历史时的默认权限。

建议控件：

- `允许读取摘要`：toggle，默认开启；摘要只包含条目 ID、类型、时间、来源候选、短摘要、pinned 状态。
- `完整内容读取`：状态 row，固定为“需要每次或按范围授权”，不提供永久无确认开关。
- `授权范围默认值`：segmented control `单条 / 当前筛选 / 手动选择`，默认 `单条`。
- `授权有效期默认值`：segmented control `一次 / 5 分钟 / 30 分钟 / 当前会话`，默认 `一次`。
- `最近授权记录`：只显示脱敏摘要，例如请求方、时间、范围、条目数量和结果。

完整内容授权面板不在设置页内直接展开；由 agent/CLI 请求触发，设置页只控制默认策略。

### 6. 数据管理

用途：清理历史和导出/重置本地数据。

建议控件：

- `清理普通历史`：不删除固定内容。
- `清理全部历史`：需要确认。
- `清理排除 App 的历史占位`：可选。
- `重置低敏示例数据`：只在开发/调试模式出现。

### 7. 高级诊断

用途：保留 recorder、App Group、helper、store 的工程状态，但不打扰普通用户。

默认折叠，内容包括：

- recorder runtime state。
- helper / App Group readiness。
- store path。
- schema version。
- 最近错误摘要。

高级诊断里可以保留技术字段；主设置页不展示工程术语。

## 隐私排除独立页面

适用范围：Settings > Clipboard Privacy / 隐私排除。

用途：决定哪些 App 的剪贴板内容不进入历史。

隐私排除从 Clipboard 设置主页面拆出，原因是它既影响数据保存，又涉及敏感 App 选择，不应被挤在普通布局设置之间。

建议交互：

- 主体是 App 列表，每行包含：
  - App 图标。
  - App 名称。
  - bundleId 次级展示。
  - 来源标记：最近来源、手动添加、系统建议。
  - toggle：是否排除。
- 添加入口：
  - `从最近来源添加`：展示最近复制来源 App，勾选加入。
  - `选择应用...`：打开 Applications 文件选择器，自动解析 bundleId。
  - `手动输入 bundle ID`：折叠在高级入口。
- 列表操作：
  - 搜索 App。
  - 按已排除 / 未排除 / 最近命中过滤。
  - 批量开启或关闭最近来源中的 App。
- 规则说明：
  - 排除只影响之后的新记录。
  - 已保存历史可单独清理。
  - 命中排除时只保留来源和时间，不保留内容预览。

## 页面布局建议

- 采用左标签、右控件的 macOS form row。
- 每个 section 最多 5-7 行，超过则拆分。
- section 之间留出清晰间距，但不要卡片套卡片。
- 重要状态用小号说明文字，不用长段落。
- 危险操作放在页面底部的数据管理区。

## 验收标准

- 用户不输入 bundleId 也能添加排除 App。
- 用户能在独立隐私排除页面用 toggle 管理每个 App。
- 用户能一眼看到保留策略和最大条目当前值。
- 用户能设置筛选在面板关闭后的自动清空时间。
- 用户能创建和管理固定分组。
- 用户能理解 Agent/CLI 默认只能读摘要，完整内容读取需要 UI 授权。
- 普通用户不需要看到 recorder/debug/App Group 术语。
- 设置页的 Clipboard route 与浮层右上角设置按钮一致。
