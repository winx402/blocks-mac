## P2-H JSON Schema validator 决策结果

决策记录：[JSON Schema 校验策略](../决策记录库/2026-07-02-JSON-Schema校验策略.md)

当前核验结论：

- 本项目 schema 声明使用 JSON Schema Draft 2020-12；P2 子集尚未覆盖 Draft 2020-12 的完整能力。
- JSON Schema Test Suite 可作为后续候选 validator spike 的行为基线。
- `ajevans99/swift-json-schema` 是 Swift 侧候选之一，但本项目尚未接入或实测。
- `kylef/JSONSchema.swift` 当前自述显示 draft-2019-09 / draft-2020-12 支持不完整且不支持 remote referencing；不作为未复测前默认选择。
- Apple Foundation 的 JSON 解码和序列化 API 不等同 JSON Schema validator。

当前决策：

| 项 | 结论 |
| --- | --- |
| P2 spike runtime | 不新增第三方 validator；继续使用 `p2_action_smoke.py` 做本项目 schema 子集校验。 |
| 接口事实源 | `docs/技术知识库/action-schemas/` 和 `actions.catalog.json` 继续作为 UI、CLI、agent、hook 的共同来源。 |
| 第一方 action | 正式 App 优先使用 Swift typed model / `Codable` / 显式业务校验。 |
| 外部输入与 hook | agent 外部输入、CLI 外部输入、hook manifest 进入 enabled 或执行路径前，必须通过完整 JSON Schema validator 或等价严格校验。 |
| 候选依赖 | P2-K 已完成 `swift-json-schema` 候选 spike；当前仍没有正式采用任何第三方 Swift validator。 |

边界：

- 不把 P2 Python 子集校验器写入正式 action core。
- 不在未实测前把任何 Swift validator 写成已采用依赖。
- schema 演进在 validator spike 前不使用当前子集之外的复杂 Draft 2020-12 关键字。

## P2-L 正式 App scaffold 架构收敛

详细决策：[正式 App Scaffold 架构](../决策记录库/2026-07-02-正式AppScaffold架构.md)。
架构文档：[正式 App Scaffold 架构 v0](../技术知识库/正式AppScaffold架构-v0.md)。

当前结论：

- P3 前正式工程形态暂定为 `SwiftUI + AppKit + sandbox-first + SMAppService helper + shared action core`。
- 主 App 负责 UI、权限引导、设置、确认卡片、Keychain 和审计展示。
- Helper 首轮优先承载剪贴板 recorder、后台心跳和轻量事件采集，不默认执行外部 CLI provider 或 hook。
- CLI 继续使用 `blocks` 前缀和统一 JSON envelope；需要确认时返回或触发 `requires_confirmation`。
- JSON Schema 文件继续是接口事实源；第一方 action 用 Swift typed validation，外部输入和 hook manifest 预留完整 validator adapter。

未覆盖：

- 本轮不创建正式 App 工程，不接真实支付，不调用真实 API，不启用任意 hook 脚本，不实现完整三工具 UI。

## P2-G sandbox-first 分发与运行形态结果

决策记录：[Sandbox-first 与分发渠道](../决策记录库/2026-07-01-sandbox-first与分发渠道.md)

技术约束：[分发与运行形态 v0](../技术知识库/分发与运行形态-v0.md)

当前核验结论：

- App Sandbox 通过 entitlement 限制 App 对系统资源和用户数据的访问，适合作为正式 App 的默认安全边界。
- Developer ID 与 notarization 是 Mac App Store 外分发的主要信任路径，Alpha 外部分发前需要准备。
- SMAppService 是 macOS 13+ 注册和控制 Login Item、LaunchAgent、LaunchDaemon helper 的主要候选 API。
- Apple 自动续订订阅属于 App Store Connect / StoreKit 路线；直接下载版不应写成使用 Apple 订阅作为默认正式收费方案。
- StoreKit Testing 可在 Xcode 本地模拟 IAP；本轮不接真实支付、不购买云服务器、不实现账号或 license server。

当前决策：

| 项 | 结论 |
| --- | --- |
| App 运行边界 | sandbox-first。 |
| 前期开发 | Xcode/local signing；不需要 Developer ID；不依赖 iOS 风格模拟器。 |
| 分发渠道 | Direct Download 和 App Store 保留双出口，暂不锁死最终渠道。 |
| 直接下载 | 后续需要 Developer ID + Hardened Runtime + notarization；商业化应另行设计自有 license/payment。 |
| App Store | StoreKit/IAP/订阅作为候选路线，但可能带来审核和能力裁剪。 |
| 服务器 | 前期不购买；只有账号、订阅、远程撤销、设备绑定、云同步等需要后端或第三方服务。 |

## macOS 官方资料核验摘要
