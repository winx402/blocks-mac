# 待验证问题

状态：active
最后审阅：2026-07-02
来源级别：execution status

## 用户与市场

- 截图、剪贴板、翻译作为通用高频工具时，哪些 Jobs 最能形成稳定留存？
- 后续商业化或分发时，是否需要再收敛到 AI agent 用户、效率工具用户、创作者或开发者中的某个主付费人群？
- 用户愿意为“集合 + AI + agent 可调用”付费，还是只愿意为单个深工具付费？
- Raycast、Alfred、macOS Shortcuts、Spotlight 和 Apple Intelligence 已覆盖的入口价值中，哪些不应再正面竞争？

## MVP 范围

- 截图、剪贴板、翻译是否是当前最合适的前三类通用工具，并且能在 4-8 周内做到可用质量？
- 截图工具首个纵切应做到标注/导出即可，还是必须同步接入 OCR/总结？
- 剪贴板语义搜索和敏感信息识别是否能在隐私边界内形成明确价值？
- 翻译应作为独立工作台，还是作为截图、剪贴板和文本处理中的共享 action？
- 文件与图片批处理是否应推迟到 V1.1，以避免首版引入过多格式兼容和性能问题？

## Agent 调用层

- 本地 agent 调用应该优先支持 CLI、MCP、App Intents，还是分阶段推进？
- action schema 如何设计，才能同时服务 UI、CLI 和 agent？
- agent 调用本地敏感能力时，哪些操作必须要求用户确认？
- 调用日志、结果缓存、回放和撤销应该做到什么程度？
- `swift-json-schema` 候选已经通过 P2-K 基础 spike；正式 App 是否采用该依赖、如何封装跨文件 `$ref` 和错误提示，仍需决策。

- [JSON Schema 校验策略](../决策记录库/2026-07-02-JSON-Schema校验策略.md) 已确认 P2 不新增第三方 validator，正式工程外部输入和 hook manifest 需要完整或等价严格校验。
- [P2 技术验证记录](2026-07-01-P2-技术验证记录.md) 已记录本机 CLI provider 快照和 smoke test 结果。
- [P2-K 批量技术验证记录](2026-07-02-P2-K批量技术验证记录.md) 已记录 Swift validator 候选 spike、provider 设置确认 smoke 和批量 runner 结果。

## macOS 权限与分发

- 截图、录屏、剪贴板、文件访问分别需要哪些权限和用户提示？
- 在 sandbox-first 前提下，直接下载分发和 App Store 分发在权限能力上有哪些关键差异？
- P2-L 已决定 helper 首轮优先承载剪贴板 recorder、后台心跳和轻量事件采集；后续仍需验证全局热键、长期功耗、崩溃恢复和用户撤销路径。
- P2-I/P2-K 已验证 recorder 数据策略和 helper 低敏 roundtrip 后，正式 App 如何把暂停记录、排除 App、固定、分组和清理策略设计进设置页与主界面？
- Direct Download 路线的 Developer ID、Hardened Runtime、notarization 和自动更新最小链路何时进入 Alpha 准备？
- App Store 路线是否需要 StoreKit/IAP；如果走 Direct Download，自有 license/payment 是否需要后端或第三方服务？
- 用户如何理解并信任一个读取截图、剪贴板和文件的 AI-native 工具？

## AI 能力

- 哪些 AI 能力可以本地完成，哪些必须云端模型参与？
- BYOK、本地模型、内置云端额度分别适合什么用户和商业模式？
- AI 输出失败、幻觉或处理敏感信息时，产品应如何提示和兜底？
- OpenAI-compatible adapter 的真实 request / response / streaming / error 边界如何设计，才能同时服务翻译、总结、改写、OCR 和未来 LLM 转换类工具？
- 真实工具内容 OpenAI-compatible 调用如何在 P5-L 低敏 test connection 之后增加内容预览、Keychain secret 短生命周期读取、超时、错误归一化、本地化错误文案和必要审计边界？
