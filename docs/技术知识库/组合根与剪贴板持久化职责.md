# 组合根与剪贴板持久化职责

状态：当前实现说明
更新：2026-09-05

## 文件职责

| 文件 | 职责与所有权 |
|---|---|
| `AppModel.swift` | 组合根，保留初始化顺序、组件实例、跨功能配置和窗口导航入口。 |
| `AppModel+StoreBindings.swift` | 同一 AppModel 的 Store 订阅绑定、可用性同步与插件生命周期差异计算；订阅和快照仍由原实例持有。 |
| `ScreenshotColorSampleCoordinator.swift` | 原有独立取色协调器；保留一次活动采样、取消收敛与迟到回调隔离，不新增取色 UI。 |
| `ClipboardFeatureCoordinator.swift` | 剪贴板功能编排、依赖与状态、面板/粘贴/用户动作入口。 |
| `ClipboardFeatureCoordinator+CapturePersistence.swift` | 同一协调器的采集持久化、最新待处理快照合并、隐私准入复核、插件资源释放和提交后的效果发布。 |

## 边界

- 文件拆分不是增加一套协调器、业务分支或事实源；原组件实例和 `@MainActor` 隔离保持不变。
- 仅跨文件使用的成员采用模块内可见性，不新增 public API；独立取色类型整体迁移，私有会话状态仍由其自身持有。
- 采集撤权、generation/owner、数据库提交与后续发布的区别保持原有契约；不得为了简化源文件恢复已淘汰的同步写入/近期排序或 hover-detail 逻辑。
- 组合根内仍有较集中的配置代码，达到非增长基线不等于所有架构债务已经消除。
- 清理从组合根转发到预览/确认流程；记录删除经面板动作进入功能协调器与 Store，不要求恢复旧 AppModel 删除 facade。
- 复制产生有效写入凭据后，近期使用记录与物理写入事实保持一致；迟到 UI、插件发布和自动粘贴仍受当前请求准入约束。不能把旧的同步 `markCopied` 调用次数当成这一契约。

## 搜索筛选与结果限制

- 历史读取仍由 ClipboardHistoryReadPipeline 的串行队列执行，Store 只接收当前 generation 的结果。
- 带查询的读取将当前筛选传入仓库 `filteringBatch` 回调：仓库按既有近期排序遍历数据库游标，每批最多 256 条候选，筛选后才计入可见数量限制。未填满时继续读取，直到游标耗尽；不再设置 5000 条全局候选截断。
- 回调只能返回当前批次的有序子集，不读取原始图片/富文本 payload；标签筛选继续使用现有 TagRepository 语义，包括启用状态和截图来源虚拟标签。返回结果的标签和预览在结果确定后加载。
- FTS 与 LIKE 降级路径共用批次读取；无筛选的已有仓库调用仍使用 SQL LIMIT。筛选回调失败不作为 FTS 故障重试，避免把失败改写为成功。
- 批次数量限制只约束解码候选数组，不保证数据库总扫描时间或任意规模下的延迟。扫描继续受现有 SQLite 串行连接约束；未新增锁、系统权限或界面状态。

## 验证约束

P8-M 对原文件继续使用原非增长基线，三个新文件也纳入项目源码成员检查；逻辑契约检查按职责文件组合读取，行数统计仍读取实际单文件。相关采集/隐私检查也应覆盖持久化扩展，不能因代码移出原文件而漏检。

P9-B 读取当前组合根扩展、面板/复制动作、持久化、历史读取和 OCR 调度边界。它验证源码契约，明确不代替运行测试；方法体识别必须越过参数中的默认闭包，并排除注释/字符串伪证据和模糊重载。

具体通过、失败和历史脚本适用性记录见[阶段性发布验收记录](../项目管理库/018_阶段性公开发布/门禁与验收记录.md)。
