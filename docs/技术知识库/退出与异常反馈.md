# 退出与异常反馈

## 退出边界

用户退出与安装升级是两个独立意图。用户退出先隐藏窗口、关闭外部任务准入并停止反馈发送，再给予最多 5 秒清理时间。独立队列上的 watchdog 不依赖主线程、数据库或反馈存储；超过期限直接退出进程，不把强退当作数据库安全关闭或升级成功。

已接纳任务先排空。现有 `appWillTerminate` Hook 在限定的任务上下文中获得清理准入，随后再排空其工作；其他 UI、CLI 和外部操作不获得该上下文。挂起的任务或 Hook 也受同一硬截止限制。更新准备/回滚若撞上退出，不能恢复准入或继续调用安装回调。

普通退出不注销共享 Broker 服务，也不停止独立启动的 Helper。强退清理仅限本次主 App 实际启动的剪贴板子进程及已认证的私有 Runner；再次核验 PID、进程出生时间、UID 和精确可执行文件路径。登记快照供 watchdog 无锁读取，不使用进程名称批量终止。

## 诊断与公开反馈

退出只向独立本地队列记录白名单事件，不上传完整日志、输入正文、截图、文件路径或凭据。字段为版本、架构、阶段、模块、标准错误码、耗时、attempt ID 和强退标记。任务数 `-1` 表示未采样，不等于零任务。

硬退出可能来不及写入最后一条事件。下一次主 App 启动可以识别之前已保存的 requested 但缺少终态的记录；这只表示“退出记录不完整”，不声称已证明强退原因。正常 graceful 记录不会据此被归类为异常。

自动报告默认关闭；开启前确认公开仓库 `winx402/blocks-mac` 和当前 GitHub 账号。只复用用户已有的 `gh`，不安装、不登录、不保存令牌。账号改变暂停发送，关闭开关停止后续自动提交，已开始的请求不能承诺撤回。

报告最多 20 份、保留 7 天。自动报告按版本及指纹在 7 天内去重，每个 UTC 日最多新建 3 个；人工明确提交不使用自动额度。未知提交不盲目重发；即使报告过期，仍保留不含正文的防重发标记，先查询 GitHub。不会重新打开已关闭 Issue。

## CLI

以下命令不需要主 App 或 Helper 运行，也不经过 Action Broker：

源码版的 CLI 随包位于 `~/Applications/Blocks.app/Contents/Resources/CLI/blocks`。
若未将 `blocks` 加入 PATH，可在下面命令中直接使用这个完整路径，无需另装 Helper。

```sh
blocks feedback doctor
blocks feedback list
blocks feedback preview --latest
blocks feedback preview --id REPORT_UUID
blocks feedback submit --id REPORT_UUID --confirm
blocks feedback submit --latest --confirm
blocks feedback create --title '问题标题' --body-file ./report.md --dry-run
blocks feedback create --title '问题标题' --body-file ./report.md --confirm
```

`--confirm` 授权本次参数指定的内容。希望固定报告时使用 `--id`，不要依赖可能变化的 `--latest`。缺少确认返回 `confirmation_required`；预览和 dry-run 不创建 Issue。人工反馈不会开启自动开关，请勿把密码或令牌写入报告文件。
