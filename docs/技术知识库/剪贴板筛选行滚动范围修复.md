# 剪贴板筛选行滚动范围修复（#60）

## 实现

- 删除标签内容HStack尾部占用至少120pt的透明新建目标。
- 在可视区剩余空白中提供新建目标，不参与滚动内容尺寸；初始未测量、非有限值、恰好填满或内容溢出时不创建覆盖层。
- 溢出时由可视区上下文菜单保留新建标签入口，不覆盖实际标签和筛选控件。
- 新建编辑器使用稳定滚动标识，在出现后滚入可视区；已有编辑器再次收到新建请求时也能重新定位。
- 保留既有排序插入位置。原空白目标本身只有右键菜单，没有外部文本拖放处理，不能宣称本次新增或验证了外部文本拖放建标签。

## 验证

- DebugTesting构建成功，144项设置／外观相关定向测试通过（0失败、0跳过）。
- 新增少量标签、狭窄剩余空间、恰好填满、溢出、零值／NaN初始测量检查。
- 真实NSHostingView中的260pt侧边筛选行含16个合成标签：内容宽度大于可视区，但最终真实标签之后仅保留既有排序插入位置，不再多出120pt空白。
- P13B标签模型静态门禁及`git diff --check`通过。
- 独立Bundle ID／数据目录的实机预览中创建多个合成标签，确认溢出时右键“新建标签”可用，输入框出现在标签行可视区内。第一次实现存在输入框落到屏幕外的问题，已补充滚动定位后复验。

自动化横向滚轮操作未造成可观察位移，本轮滚动范围证据来自实际渲染文档宽度测量，不冒充完整手动滚轮或拖拽验收。未修改日常安装的数据；验证结束后注销并清理临时应用包。
