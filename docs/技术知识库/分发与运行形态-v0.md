# 分发与运行形态 v0

状态：proposed
最后审阅：2026-07-02
来源级别：technical constraint

本文记录当前分发与运行形态约束。2026-07 的双出口决策已被取代，历史依据保留在：[Sandbox-first 与分发渠道](../决策记录库/2026-07-01-sandbox-first与分发渠道.md)。

## 官方核验来源

- App Sandbox：<https://developer.apple.com/documentation/security/app-sandbox>
- Developer ID：<https://developer.apple.com/developer-id/>
- Notarization：<https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution>
- SMAppService：<https://developer.apple.com/documentation/servicemanagement/smappservice>

## 当前结论

- 官方发行固定为 MIT 开源、Developer ID 签名、Hardened Runtime 和 notarization 的 App Sandbox 直发包；不计划 App Store、StoreKit/IAP 或 App Review 路线。
- `LocalDevelopment` 不启用 App Sandbox，且必须以独立 runtime identity、数据目录和 Keychain namespace 与官方包隔离；它不是官方发行形态。
- 官方包的敏感能力仍必须有 entitlement、TCC、用户确认和失败路径说明。
- 本轮不购买云服务器；商业化、账号或支付如有需要，须另行决策，不能恢复 Apple 订阅路线。

## 分发矩阵

| 形态 | 当前用途 | sandbox | 签名/分发 | 支付/订阅 | 后端需求 |
| --- | --- | --- | --- | --- | --- |
| LocalDevelopment | 本机开发与验证 | 不启用 App Sandbox；必须与官方包隔离 | Xcode/local signing；不代表可发行 | 不接真实支付 | 不需要 |
| Official Direct | 唯一官方发行形态 | App Sandbox；必要能力遵循 entitlement/TCC/确认路径 | Developer ID + Hardened Runtime + notarization；安装与更新待验收 | 如需商业化另行决策 | 早期可无 |

## 能力影响

| 能力 | sandbox-first 要求 | 后续验证 |
| --- | --- | --- |
| 截图 | 仍需屏幕录制 TCC；截图前后必须有可解释状态和失败提示。 | 多屏、权限拒绝/撤销、完整截图 UI。 |
| 剪贴板历史 | 长期 recorder 必须有暂停、排除 App、保留策略和敏感提示；P2-I 验证数据策略，P2-J/P2-K 验证最小 helper 常驻和低敏 recorder roundtrip。 | 正式 helper、长期功耗、第三方复杂格式、正式 UI。 |
| 翻译 / AI 外发 | 外发前必须预览、确认、记录 provider 和审计摘要；P2-K 已验证 provider 设置确认 smoke。 | provider 设置页、数据出境确认、失败重试。 |
| Keychain | API key 默认走 Keychain，不写仓库或普通配置文件。 | 正式 provider account 命名、迁移和删除路径。 |
| 文件访问 | 优先用户选择文件/目录；需要保存访问时再评估安全范围书签。 | 截图保存目录、拖拽导出、历史文件引用。 |
| Login Item / helper | 后台常驻用 SMAppService 候选，不把后台能力硬塞进主进程。 | P2-J 已验证最小注册、启动心跳和注销；P2-K 已验证低敏 recorder roundtrip 和非零退出观察；后续补长期功耗和用户撤销。 |
| 外部 CLI provider | 不允许主 App 无提示任意执行；需要路径确认、超时、输出 schema 和审计。 | P2-L 决定 helper 默认不承载 CLI provider 执行；后续在 provider 设置页和 adapter 中产品化。 |
| Hook runtime | agent 生成 hook 默认草稿；启用、阻断、修改、删除必须显式确认。 | P2-L 决定 helper 默认不运行 hook；hook runtime 沙箱、权限和撤销策略后续单独设计。 |

## P2-L 运行边界

- Main App：UI、权限引导、设置、确认卡片、Keychain、审计展示。
- Helper：剪贴板 recorder、后台心跳和轻量事件采集；默认不执行外部 CLI provider 或 hook。
- CLI：`blocks` 前缀和统一 JSON envelope；需要确认时返回或触发 confirmation path。
- Provider / hook：外发、启用、阻断、修改和删除必须走预览、确认和审计。

## 后续顺序

1. P3-A：制定最小正式 App scaffold 或截图纵切计划。
2. Provider 设置页产品化：Keychain account、base URL、模型名、外发预览和审计日志。
3. 复杂 pasteboard 实物补测：密码管理器、浏览器隐私字段、Office/设计软件样本，以及 detection patterns runtime。
4. 环境依赖补测：多屏、跨屏选区、权限撤销/重授权、用户撤销 Login Item 和 `requires_approval`。
5. 分发补测：Alpha 前验证 Developer ID、Hardened Runtime、notarization 和最小更新路径。
