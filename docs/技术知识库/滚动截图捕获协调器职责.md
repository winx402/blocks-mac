# 滚动截图捕获协调器职责

状态：当前实现说明
更新：2026-09-05

## 文件边界

- `ScrollingScreenshotCaptureCoordinator.swift`：唯一的 `@MainActor` 捕获协调器及其存储状态、依赖注入、捕获入口、动作入口、帧评估、暂停/恢复和 HUD 状态发布。
- `ScrollingScreenshotCaptureScheduling.swift`：该协调器的扩展，负责启动/首帧 watchdog、输入监听、健康检查、运动/稳定/恢复采样及可能结束倒计时。
- `ScrollingScreenshotCaptureTermination.swift`：同一协调器的扩展，负责完成、确认取消、失败、continuation 收敛、帧源有界停止和界面资源清理。
- `ScrollingScreenshotCaptureSupport.swift`：既有采样/终态辅助类型、帧需求队列与处理管线扩展；不把这些类型搬回捕获编排文件。
- `ScrollingScreenshotSessionCoordinator`：独立 actor，继续负责拼接会话和磁盘生命周期，不与捕获协调器合并。

## 状态与并发约束

拆分不创建新的协调器、状态副本或 UI 控制器。扩展共享原实例，仍受 `@MainActor` 隔离；仅跨文件使用的成员改为模块内可见，同文件私有辅助方法保持私有，不新增 public API。

- generation 隔离不同会话；work revision 与 owner 隔离同会话内被撤销或替换的异步工作。
- 捕获终态继续由同一个 terminal gate 实现 first-terminal-wins，continuation 不得重复恢复。
- 取消、失败和最终完成继续使用原有清理顺序及有界帧源停止；迟到回调不得影响替代会话。
- 窗口、HUD、布局、输入协议与调用方接口没有因文件拆分而变化。

## 自动验证入口

- P16-B `--static-only`：只做结构/源码检查，结果明确标记 runtime 未运行。
- P16-B 默认：隔离构建后通过受控 xctestrun 运行滚动截图套件，核对实际用例集合、重复、结果与汇总；仅允许两个明确的资源 opt-in 用例默认 skip。
- `--derived-data` 可显式复用测试构建缓存；只选择当前 SDK/arm64 的正式生成 xctestrun，不能误选历史诊断副本。
- 构建仅在编译器成功且受控运行器确认残留已清理时允许一次增量重试；首次失败保留在结果中。编译失败或第二次失败不得无限重试。
- P16-C 同时读取三个协调器职责文件，保留权限、物理取消键语义和 HUD 静态契约。
