# 技术边界与架构假设

状态：proposed
最后审阅：2026-07-02
来源级别：derived summary

## 技术目标

验证是否能用同一套本地 action core 支撑 Mac UI、CLI、agent 调用和系统自动化入口。

## 架构假设

当前假设如下；其中 action schema、Keychain、截图、复杂剪贴板 fixture、剪贴板 recorder、App Sandbox 官方包、JSON Schema 策略、Swift validator 候选、最小 Login Item/helper 和 P2-L 正式 App scaffold 架构已有 P2 第一轮验证或决策，其余仍为 proposed：

- Mac 原生壳：P2-L 暂定正式 scaffold 采用 SwiftUI + AppKit，负责菜单栏、权限、快捷键、系统集成和高性能 UI。
- 运行形态：官方包按 App Sandbox 约束设计，敏感能力必须列出 entitlement、TCC 权限、用户确认和失败路径；`LocalDevelopment` 非沙盒且与官方身份、数据和 Keychain 隔离。
- Action core：所有工具能力封装成稳定 action，输入输出使用结构化 schema。
- Schema validation：JSON Schema 文件是接口事实源；P2 smoke 只做子集校验；P2-K 已用 `swift-json-schema` `0.13.1` 通过候选 spike，但正式工程第一方 action 仍优先 typed validation，外部输入和 hook manifest 需要完整或等价严格校验。
- Login Item / helper：P2-J 已验证最小 sandbox helper 的注册、启动心跳和注销；P2-K 已验证低敏 recorder roundtrip 和非零退出观察；P2-L 决定 helper 首轮优先承载剪贴板 recorder、后台心跳和轻量事件采集，不默认执行外部 CLI provider 或 hook。
- CLI：提供 JSON 输出，便于本地 agent 和脚本调用。
- MCP server：让 ChatGPT、Codex、OpenClaw 等 agent 能直接调用工具。
- App Intents / Shortcuts：接入 macOS 系统自动化入口。
- 本地存储：SQLite / CoreData 保存历史、索引、配置、调用记录和权限状态。
- AI 层：支持 BYOK、本地模型或云端模型；按工具场景定义 prompt、schema、确认策略和隐私边界。
- 开源产品依赖边界：成熟开源整包产品不作为截图、剪贴板、翻译主路径的默认运行依赖，也不作为技术实现路线的默认依据；其价值主要归入产品功能、交互深度和边界设计参考。
- 分发渠道：官方发行固定为 MIT 开源、Developer ID + Hardened Runtime + notarization 的沙盒直发；不计划 App Store。安装、公证、更新和恢复链路仍须验收。

## 必须验证的技术边界

- macOS 截图、录屏、剪贴板、文件访问权限的申请、提示和撤销体验。
- CLI / MCP / App Intents 是否能共享同一 action schema，而不是形成三套接口。
- 正式工程的 schema validator 或等价严格校验是否能覆盖 agent 外部输入、CLI 外部输入和 hook manifest。
- agent 调用涉及敏感操作时的确认、预览、审计和撤销机制。
- 本地 OCR、图片处理、文本索引和批处理的性能边界。
- Developer ID 沙盒直发与权限能力之间的取舍，以及 LocalDevelopment 非沙盒隔离是否完整。
- 官方沙盒包下 Login Item/helper、外部 CLI provider 和 hook runtime 是否能满足完整 V1 体验。
- 若引入底层开源库或命令行工具，必须单独验证许可证、分发方式、可替换性、隐私边界和失败降级路径。
- 外部开源 App 只允许作为一次性产品功能验证或体验对照，不进入技术依赖设计。

## 不确定性

- SwiftUI + AppKit 已作为 P3 前 scaffold 暂定组合，但仍需要在正式工程中验证菜单栏、overlay、快捷键和窗口层级体验。
- MCP server 是否首版必须内置，还是先提供 CLI 再接入 MCP。
- App Intents 是否适合作为首版硬要求，取决于通用工具的入口需求和系统版本覆盖。
- `swift-json-schema` 已完成候选 spike，但尚未采用；正式 App scaffold 可以预留 validator adapter，正式依赖、封装方式和跨文件 `$ref` 策略仍需单独决策。
- 本地模型能力是否足以支撑 OCR 后总结、敏感信息识别和批量改写，需要实测。
- 官方发行渠道已锁定；Developer ID 直发的公证、自动更新和用户信任链路仍需验证。
