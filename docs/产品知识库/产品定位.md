# 产品定位

状态：proposed
最后审阅：2026-07-01
来源级别：derived summary

## 一句话定义

一个面向 macOS 的 AI-native 本地工具集合：把少数高频桌面能力做深，并让这些能力同时适合人使用和本地 agent 调用。

## 核心差异假设

当前差异点不应只是“工具更多”或“入口更统一”，而应是：

- 每个工具都有稳定、可脚本化、可审计的动作接口。
- UI、CLI、MCP、App Intents / Shortcuts 调用同一个 action core。
- AI 功能嵌入具体任务流，例如 OCR 后翻译、截图总结、剪贴板文本处理和跨入口翻译。
- 敏感数据默认本地处理，云端 AI 调用必须由用户明确触发或确认。

## 目标用户口径

当前前三类工具是通用桌面高频工具，不以具体垂直目标用户作为 P1 前置条件。当前应先按 Jobs 定义场景和深度，后续再验证哪个用户群最愿意长期使用或付费。

候选商业/市场人群仍保留为后续验证项：

| 用户 | 可能痛点 | 风险 |
| --- | --- | --- |
| AI agent power user | 需要本地工具稳定、结构化、可调用 | 人群较窄，普通用户感知弱 |
| 个人效率用户 | 截图、剪贴板、文件处理等高频流程分散 | 已有 Raycast、Alfred 和单点工具竞争 |
| 内容创作者 | 录屏、截图、转写、素材处理链路繁琐 | 视频和素材链路复杂，首版成本高 |
| 开发者 | 更容易理解 CLI / MCP / 自动化价值 | 可能更偏工具链，不一定接受通用 Mac App |

## 产品原则

- 少而深：首版只选 2-3 组工具深做，避免 60 分工具集合。
- 可调用优先：每个工具从第一天就设计机器可调用接口。
- 本地优先：截图、剪贴板、文件、录屏等敏感能力默认本地处理。
- 动作可追踪：agent 调用需要可预览、可确认、可回放或有清晰输出记录。
- AI 增益具体：每个 AI 功能都必须绑定明确任务，而不是泛化聊天入口。

## 非定位

- 不是单纯启动器替代品。
- 不是 Raycast / Alfred 插件集合的直接复制。
- 不是把所有 macOS 小工具统一换皮。
- 不是只有聊天界面的 AI 助手。
