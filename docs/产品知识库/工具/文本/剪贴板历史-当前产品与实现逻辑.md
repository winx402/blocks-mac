# 剪贴板历史：当前产品与实现逻辑

状态：current snapshot
最后审阅：2026-07-05
来源级别：implementation-informed product note
适用范围：`Blocks` 当前剪贴板历史、底部浮层、侧边浮层、实时捕获、预览、筛选、粘贴与浮层交互。

## 1. 文档目的

这份文档记录“当前已经实现出来的剪贴板产品是什么”，以及“它现在靠哪些代码路径运行”。它不是新一轮 PRD，也不是未来愿景。

写这份文档的原因是：剪贴板模块在多轮快速修复中同时改过数据捕获、面板 resize、条目预览、筛选、条目宽度、hover 详情、粘贴触发模式和自动粘贴。现在需要先固定产品事实和架构边界，否则后续继续局部修补会反复顾此失彼。

## 2. 当前产品定位

当前剪贴板模块是一个本地剪贴板历史浮层工具，核心目标是：

- 用户复制内容后，能在剪贴板浮层中看到历史条目。
- 用户能直接从条目里识别真实内容，而不是只看到工程摘要。
- 用户能搜索、筛选、预览、粘贴、固定、分组和删除历史条目。
- 底部面板像系统浮层一样贴底展示，支持通过窗口顶部边缘改变高度。
- 详情浮层跟随条目显示，不被底部面板边界裁剪。

当前产品明确不包含：

- 云同步。
- 团队共享 Pinboard。
- 自动上传完整剪贴板内容给 AI。
- 以第三方剪贴板产品作为运行依赖。

## 3. 当前用户入口

### 3.1 打开剪贴板

入口包括菜单栏剪贴板入口和配置的剪贴板快捷键。打开时会捕获当前前台应用作为后续自动粘贴目标，排除本 App 和系统设置类应用。

### 3.2 面板位置

当前支持三种位置：

| 位置 | 当前行为 |
| --- | --- |
| bottom | 使用当前屏幕可用宽度，底部始终贴 `screen.frame.minY`；无论底部 Dock 显示或隐藏都不预留底部空间。高度可调，宽度和位置不可调。 |
| left | 固定贴左侧，使用屏幕可见高度，侧边列表布局。 |
| right | 固定贴右侧，使用屏幕可见高度，侧边列表布局。 |

bottom 模式是当前主要打磨对象，side 模式保留同一数据和粘贴逻辑，但视觉和交互没有同等深度打磨。

## 4. 当前产品能力

### 4.1 实时捕获

App 启动后会启动轻量剪贴板监听。监听通过轮询 `NSPasteboard.general.changeCount` 识别变化，当前支持生成记录和 payload 的类型：

- 文本。
- 富文本 RTF + plain text fallback。
- URL。
- file URL。
- PNG / TIFF 图片，TIFF 会转为 PNG payload。

捕获后生成 `ClipboardRecorderRecord` 和 `ClipboardRecorderPayload`，插入内存态历史最前方。去重依据包括 `changeCount` 和内容签名。

当前事实：

- 实时捕获的真实 payload 当前进入 App 内存态 `clipboardPayloads`。
- 当前 live capture 没有走长期生产持久化仓库。
- helper/debug recorder store 仍存在，但主要用于调试、fixture、inspect 和历史验证，不等同于当前 live capture 的产品主存储。
- 自动粘贴和“复制纯文本”这类 App 内部写入会把写入后的 pasteboard `changeCount` 登记给 `ClipboardLiveCaptureService`，避免被当前 live capture 再当成用户复制内容回捕。
- live ingest 成功后会立即套用当前 retention days、max items、preserve pinned 和 excluded bundle IDs 策略，并把不再存在的 payload 裁掉；这仍是“插入后策略裁剪”，不是保存前 capture policy。

### 4.2 条目展示

条目采用内容优先预览：

| 类型 | 当前条目展示 |
| --- | --- |
| 文本 | 直接显示文本内容。 |
| 富文本 | 显示文本 fallback，保留富文本类型和 RTF payload。 |
| URL | 显示 host / path / URL 文本。 |
| file URL | 显示文件路径或文件名信息。 |
| 图片 | 直接显示图片缩略图。 |
| 排除/跳过 | 显示隐私占位，不展示内容。 |

bottom 卡片按类型使用淡色背景区分，不再依赖类型图标作为主要识别方式。

### 4.3 搜索与筛选

当前筛选组包括：

- 格式：全部、文本、富文本、图片、URL、文件、混合、排除。
- 时间：全部、今天、昨天、前天、最近三天、最近一周、上周。
- 分组：全部、默认固定分组、工作、个人等当前内置 Pinboard。
- 来源：按历史来源 App 聚合。

交互规则已经收敛为：

- 点击筛选组标题展开或收起。
- hover 不负责展开。
- 展开后鼠标离开该筛选组则收起。
- 点击筛选项整颗胶囊都有效。
- 再次点击当前已选筛选项会取消该组筛选。
- 点击“全部”清空该组筛选。
- 多筛选组叠加取交集。
- 面板关闭后按 `clipboard.filter.clearDelay` 延迟清理筛选，默认 30 秒。

### 4.4 条目详情

详情浮层当前不再是 SwiftUI 面板内部 overlay，而是单个透明 borderless child `NSPanel`：

- 详情显示在当前条目上方。
- 水平跟随当前条目中心，并 clamp 到屏幕 visibleFrame 内。
- 文本 / URL / 文件 / 富文本默认尺寸约 `380x300`。
- 图片默认尺寸约 `420x360`。
- 详情内部可滚动，不再通过压缩外层高度裁切。
- 鼠标在条目、详情 panel、两者之间的 bridge 区域内时保持详情打开。
- 离开联合区域后立即隐藏，没有延迟隐藏。
- 点击详情区域不关闭剪贴板面板。

### 4.5 粘贴触发模式

bottom header 提供“单击粘贴 / 双击粘贴”切换，持久化 key：

`clipboard.panel.pasteActivationMode`

当前默认值是 `doubleClick`，但用户选择会立即保存。行为：

| 模式 | 行为 |
| --- | --- |
| 单击粘贴 | 单击条目直接粘贴。 |
| 双击粘贴 | 单击只选择条目，双击粘贴。 |

bottom 卡片和 side 行共用同一触发逻辑。

### 4.6 自动粘贴

自动粘贴流程：

1. 打开剪贴板面板前捕获目标前台 App。
2. 用户触发粘贴。
3. 关闭剪贴板面板。
4. 将该条目的 payload 写回系统剪贴板。
5. 检查 Accessibility 权限。
6. 激活目标 App。
7. 发送 `Command + V`。

如果 Accessibility 不可用，当前会提示权限辅助；如果 payload 不可恢复或目标 App 不可用，会写入失败状态。

### 4.7 条目宽度

bottom 条目宽度是全体统一宽度，不是单条独立宽度。

- 用户可在两个条目之间拖动透明命中区调整宽度。
- 范围：`180...520`。
- 默认：`270`。
- 持久化 key：`clipboard.panel.bottom.cardWidth`。
- hover 显示左右 resize 光标，并提供 tooltip：`拖动调整条目宽度`。

### 4.8 面板高度

bottom 面板使用系统 resizable panel，并加透明顶部命中区补齐无标题栏窗口的顶部 resize 体验。

不显示可见自定义拖拽条。约束：

- 高度范围：`260...430`。
- 宽度固定为当前屏幕 visibleFrame 宽度。
- x 固定为 `visibleFrame.minX`。
- y 固定为 `visibleFrame.minY`。
- 只保存高度，不保存位置或宽度。
- 持久化 key：`floatingPanel.clipboard.bottom.height`。

### 4.9 条目内容字体

Settings 的 Clipboard 面板展示设置提供条目内容字体大小 slider。

- 范围：`10...18 pt`。
- 默认：`12 pt`。
- 持久化 key：`clipboard.panel.itemFontSize`。
- 作用范围：bottom card、side row 和 hover detail 的内容正文。
- 非作用范围：标题、时间、badge、footer、按钮、筛选胶囊和其他 chrome 不随该设置缩放。
- bottom 卡片会根据卡片高度和字体大小调整正文行数，避免字体变大后挤压布局。

## 5. 当前实现路径

### 5.1 核心数据模型

位置：`apps/Blocks/BlocksCore/ClipboardRecorderFoundation.swift`

主要类型：

- `ClipboardRecorderItemKind`：文本、富文本、图片、URL、file URL、mixed、unknown。
- `ClipboardRecorderRecord`：历史记录元数据，包括时间、来源、格式摘要、签名、pinned、restorable、excluded、summary。
- `ClipboardRecorderPayload`：真实可恢复内容，包括 text、RTF base64、PNG base64、URL。
- `ClipboardRecorderStoreDocument`：调试 / fixture store 文档，包含 records 和 payloads。

### 5.2 App 内状态和用例

位置：`apps/Blocks/BlocksApp/Stores/AppState.swift`

当前 `AppState` 仍是跨模块协调入口，保留对既有调用面的兼容方法，但剪贴板专属查询和展示规则已下沉到：

- `apps/Blocks/BlocksApp/Stores/ClipboardController.swift`

当前分工：

- `AppState` 持有 records / payloads / filters / pinboards / pinned metadata 的 published 状态，负责启动 live capture、连接 presenter、权限辅助和全局状态。
- `ClipboardController` 负责 fixture 默认值、计数、preview、source filter options、live ingest 去重、搜索筛选和 pinboard name。
- 粘贴、复制纯文本、删除、固定、移动分组、重命名等仍由 `AppState` 暴露为 app-level 用例入口，后续可继续下沉。

### 5.3 实时捕获

位置：`apps/Blocks/BlocksApp/Services/ClipboardLiveCaptureService.swift`

职责：

- 轮询 pasteboard changeCount。
- 从 pasteboard 读取支持类型。
- 生成 record + payload。
- 生成内容签名并去重。
- 推给 `AppState.ingestLiveClipboardCapture`。

### 5.4 浮层窗口和自动粘贴

窗口位置：`apps/Blocks/BlocksApp/Services/ClipboardHistoryPanelPresenter.swift`

职责：

- 剪贴板浮层 `NSPanel` 生命周期、frame、系统 resize、顶部透明 resize hit view、关闭与快捷键。
- 捕获打开面板前的目标前台 App。
- 维持 bottom frame / resize / dismiss island 约束。

自动粘贴位置：`apps/Blocks/BlocksApp/Services/ClipboardAutoPasteCoordinator.swift`

职责：

- 将选中记录的 payload 写回系统剪贴板。
- 检查 Accessibility 权限。
- 激活目标 App。
- 发送 `Command + V`。
- 维护自动粘贴错误类型和 paste attempt 状态。

### 5.5 面板 frame 和 dismiss

位置：`apps/Blocks/BlocksApp/Services/FloatingPanelSupport.swift`

职责：

- 计算 bottom / left / right frame。
- bottom 高度 clamp 和保存。
- 监听点击外部关闭浮层。
- 将 child detail panel 视为同一交互岛，避免点击详情关闭父面板。

### 5.6 SwiftUI 面板视图

位置：`apps/Blocks/BlocksApp/Views/ClipboardFloatingPanelView.swift`

当前包含：

- header、搜索、筛选、粘贴模式菜单的装配。

`ClipboardFloatingPanelView.swift` 现在是 composition root，不再定义 AppKit detail coordinator、width resize view、filter group 或 record card。

位置：

## 6. 当前架构问题

### 6.1 当前状态：剪贴板主视图已收敛为装配层

P8-M 前，`ClipboardFloatingPanelView.swift` 同时包含 SwiftUI 布局、AppKit tracking、child panel、filter UI、card UI、detail UI、width resize 和多个交互状态。

P8-M 后，视图已拆为 filter bar、record views、width resize handle 和 hover detail layer。当前剩余职责是 header/search/tray/list 装配、selection、hover record id、展开筛选组和粘贴模式组合。

仍需关注：

- `ClipboardFloatingPanelView.swift` 仍接近 600 行，后续如继续增长，可再拆 `ClipboardPanelHeaderView` 和 `ClipboardBottomTrayView`。
- 交互类问题仍不能只依赖静态门禁，必须用实物或 UI harness 验收。

### 6.2 当前状态：`AppState` 仍是跨业务协调器，但剪贴板规则已部分下沉

P8-M 后，`ClipboardController` 承接了剪贴板默认数据、计数、preview、source options、live ingest、搜索筛选和 pinboard name。

`AppState` 仍同时管理截图、翻译、provider、权限、快捷键和剪贴板，剪贴板的粘贴、删除、固定、移动分组、重命名等 app-level 用例还在其中。

影响：

- 剪贴板变更仍可能触碰主 App 状态文件。
- 只针对剪贴板 use case 的单元测试仍不够独立。
- 后续如果加入持久化、隐私策略、Pinboard 编辑、Paste Stack，应继续向 `ClipboardStore` / repository 下沉。

建议：

- 下一步提取 `ClipboardStore`，作为 `@MainActor ObservableObject` 或等价状态容器。
- `AppState` 最终只保留跨模块协调入口，例如打开面板、展示状态、权限协调。
- 固定、删除、移动分组、重命名、copy/paste use case 可继续迁入剪贴板专属 store/controller。

### 6.3 事实：生产 live capture 和 debug recorder store 是两条数据链

当前 live capture 直接进入内存态 records/payloads。`ClipboardRecorderStore` 仍用于 fixture/debug/helper inspect，但不是 live capture 的生产持久化路径。

影响：

- 用户复制的新内容重启后不会以同一生产路径恢复。
- 调试记录、fixture 记录和真实 live 记录容易在产品文案里混用。
- “显示真实内容”和“本地持久保存真实 payload”的边界没有统一产品决策。

建议：

- 明确一条生产 repository：`ClipboardRepository`。
- repository 负责 records/payloads 的读写、裁剪、去重、迁移和隐私策略。
- debug/helper store 可以继续存在，但应命名为 debug adapter，不参与主产品路径。

### 6.4 事实：策略裁剪已接入 ingest 后路径，但保存前策略仍未完成

当前 live capture 在 capture 层会处理暂停状态和内部写入忽略；`AppState.ingestLiveClipboardCapture` 在插入成功后立即调用 `applyClipboardPolicySilently`，应用 retention days、max items、preserve pinned 和 excluded bundle IDs，并调用 `pruneClipboardPayloadsToCurrentRecords()`。

影响：

- “暂停记录”和“排除 App”在产品心智上同属记录策略，但 capture 层和 ingest 后裁剪仍是两段逻辑。
- 用户复制真实内容后，payload 仍可能先进入内存态，然后再被 apply policy 标记排除或裁剪；这不等同于“保存前排除”。
- 当前策略裁剪能减少列表和 payload 残留，但还不是完整隐私策略。

建议：

- live capture ingest 前必须经过 `ClipboardCapturePolicy`。
- 策略输出应有三种结果：accept、redact placeholder、drop。
- 排除 App 的逻辑应发生在 payload 进入 store 前。

### 6.5 当前状态：窗口管理和自动粘贴已拆分

P8-M 后：

- `ClipboardHistoryPanelPresenter.swift` 只保留 `NSPanel` lifecycle、top resize view、window delegate、target app capture 和 dismiss monitor。
- `ClipboardAutoPasteCoordinator.swift` 独立承载自动粘贴错误类型、payload 写回、Accessibility 检查、目标 App 激活和 `Command + V`。

仍需关注：

- 自动粘贴和复制纯文本已通过 `ignorePasteboardChange(changeCount:)` 抑制常见内部写入回捕；仍需要实物回归覆盖更多目标 App、失败分支和第三方剪贴板工具。

### 6.6 当前状态：产品域模型已从 Localization 文件拆出

P8-M 后：

- `ClipboardFilters.swift`：筛选模型。
- `ClipboardPinboard.swift`：Pinboard 和来源筛选。
- `ClipboardRecordPreview.swift`：preview 和 searchable text。
- `ClipboardRecorder+Localization.swift`：类型本地化。

剩余风险：

- 后续新增 domain type 时必须继续按概念命名文件，不能把新逻辑重新塞回 Localization 文件。

### 6.7 当前状态：剪贴板 settings key 已集中一层

P8-M/P8-N 后，剪贴板 filter、card width、paste activation mode、filter clear delay 和 item font size key 集中在：

- `ClipboardPanelSettings.Keys`

bottom 卡片布局范围和 clamp 集中在：

- `ClipboardBottomTrayLayout`

仍未完全统一：

- `floatingPanel.clipboard.bottom.height` 和 `clipboard.panel.position` 仍由 `FloatingPanelFrameStore` 管理。
- 后续如做设置迁移/重置，应建立更完整的 `ClipboardSettingsStore`。

### 6.8 事实：测试门禁偏静态，交互缺陷主要靠实物验收暴露

这几轮 hover、child panel、resize 命中、筛选点击区域的问题，静态门禁多次无法提前发现。

影响：

- 代码里存在某个字符串不等于交互真实可用。
- AppKit/SwiftUI 叠层、鼠标事件、窗口焦点类问题必须有实物或自动 UI 验证。

建议：

- 静态门禁保留，但不能作为交互通过的唯一证据。
- 为剪贴板建立最小 UI harness：打开面板、移动鼠标、截图比对、点击筛选、拖动宽度、进入详情、离开详情。
- 每个高风险交互改动必须附一张实物截图或录屏证据。

## 7. 建议的目标架构

### 7.1 模块边界

P8-M 后，剪贴板已经部分进入以下层级；未完成的 repository / policy 仍是后续 story：

```text
ClipboardDomain
  - Record / Payload
  - Preview / Filter / Pinboard
  - Policy (deferred)

ClipboardRepository (deferred)
  - load / save / append / prune / migrate
  - records + payloads single source of truth

ClipboardCaptureService
  - NSPasteboard polling / extraction only
  - no UI, no filtering UI state

ClipboardController
  - default fixtures / counts / preview
  - ingest
  - search/filter
  - source filter options
  - pinboard name
  - pin/move/rename/delete (partially still in AppState)
  - copy/paste use cases (partially still in AppState)
  - settings/policy application (deferred)

ClipboardPanelPresenter
  - NSPanel lifecycle
  - frame and resize
  - target app capture
  - dismiss island

ClipboardPanelViews
  - FloatingPanel composition root
  - FilterBar
  - Card / Row
  - Detail content

ClipboardInteractionCoordinators
  - hover detail child panel
  - card width resize
  - top edge resize
```

### 7.2 必须维护的产品不变量

后续改动必须同时满足这些不变量：

1. bottom 面板底边永远贴当前屏幕的物理底边 `screen.frame.minY`，不为底部 Dock 预留空间；多屏使用所在屏幕坐标（可以为负数），不是固定全局 `y = 0`。（2026-09-08 用户明确更新）
2. bottom 面板只允许高度变化，高度范围 `260...430`。
3. bottom 高度只保存 height，不保存 x/y/width。
4. 条目宽度是全体统一宽度，范围 `180...520`。
5. 条目内容直接展示 payload；图片直接显示缩略图。
6. 详情只能有一套状态机，当前实现为单 child panel。
7. 详情不被父面板裁剪，且必须跟随当前条目。
8. 筛选组是点击展开；hover 只负责展开后离开收起。
9. 粘贴触发模式持久化，bottom 和 side 行为一致。
10. 条目内容字体只影响内容正文，不影响标题、footer、按钮和筛选 chrome。
11. 内部 pasteboard 写入必须登记并抑制回捕，避免自动粘贴或复制纯文本生成重复历史。
12. 完整内容只在本地显示/恢复，不写日志、不上传网络。

## 8. 当前产品缺口

以下不是本轮必须修复项，但需要进入后续 backlog：

1. **生产持久化缺口**：live capture 只进内存，重启恢复还不是完整产品路径。
2. **保存前隐私策略缺口**：排除 App 应在 payload 进入生产 store 前阻断或脱敏；当前 ingest 后策略裁剪不等同于保存前策略。
3. **Pinboard 编辑缺口**：当前有默认分组和移动能力，但完整创建、改名、颜色、排序仍未产品化。
4. **重命名缺口**：当前 context menu 的重命名路径不是完整用户输入式重命名。
5. **Paste Stack 缺口**：方案中列为 V1，但当前未见完整队列实现。
6. **文本/富文本预览编辑缺口**：方案中列为 V1，但当前未实现完整编辑副本/替换语义。
7. **side 模式体验缺口**：side 共用数据和粘贴逻辑，但 hover、详情、筛选、宽度等主要围绕 bottom 打磨。
8. **自动粘贴回捕实物覆盖缺口**：代码已登记内部写入 change count，但仍需要在更多目标 App、失败分支和第三方剪贴板工具下做实物回归。

## 9. 推荐整改顺序

P8-M 已完成第一轮模块化。后续不要继续先做视觉微调，建议按以下顺序收敛：

1. **继续守住产品不变量**：第 7.2 节必须作为剪贴板模块开发门禁。
2. **补真实交互测试**：优先覆盖 hover detail、筛选、宽度 resize、面板 resize、自动粘贴，而不是继续只加静态字符串门禁。
3. **提取 ClipboardStore / Repository**：决定 live capture 是否生产持久化；如果是，让 records/payloads 只有一个写入入口。
4. **补保存前 Capture Policy**：排除 App、暂停、drop/redact/accept 应在 payload 进入生产 store 前发生；当前 ingest 后裁剪只能作为过渡。
5. **继续瘦身 AppState**：固定、删除、移动分组、重命名、copy/paste use case 逐步迁入剪贴板专属 store/controller。
6. **再做 Pinboard / Paste Stack / 编辑能力**：在数据源和交互验收稳定后补后续产品能力。

## 10. 结论

当前剪贴板已经从“调试摘要面板”推进到“可用的本地剪贴板历史浮层”：实时捕获真实内容、内容预览、图片缩略图、底部系统 resize、条目宽度调节、点击筛选、单/双击粘贴、跟随条目的完整详情浮层、内部写入回捕抑制和条目内容字体设置都已具备。

P8-M/P8-N 后，UI、AppKit 事件、产品域模型、settings key、自动粘贴、controller、live capture 自写入抑制和条目字体门禁已经完成第一轮收敛。剩余主要架构风险转为：`AppState` 仍承担较多剪贴板 use case、live capture 仍未接入生产 repository、保存前策略仍未统一、实物交互验证仍不足。下一步应优先补真实交互测试、生产数据源和保存前策略，而不是继续在装配层上叠新产品功能。
