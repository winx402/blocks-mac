# 截图与图片处理交互整合

状态：proposed
最后审阅：2026-07-01
来源级别：authoritative definition

## 整合定位

本入口整合截图捕获和图片处理两类能力。用户可以先截图再处理，也可以直接打开一张本地图片后使用同一组图片功能。

## 入口

| 入口 | 进入方式 | 主要组合的底层工具 |
| --- | --- | --- |
| 截图入口 | 默认 `Control + Option + A`、用户自定义快捷键、菜单栏、主窗口 | 截图捕获、图片打开与预览、图片标注、OCR、AI 翻译、AI 总结、内容识别、结果导出 |
| 图片文件入口 | 选择图片文件、拖拽图片、选中文件后快捷键 | 图片打开与预览、图片标注、OCR、AI 翻译、AI 总结、内容识别、结果导出 |
| CLI / agent 入口 | 传入图片路径和 action | OCR、AI 翻译、AI 总结、内容识别、结果导出、Action 调用 |

用户自定义或禁用时，以设置 > 快捷键当前绑定为准。

截图完成后显示，菜单混合两类动作：

| 菜单动作 | 来源模块 | 说明 |
| --- | --- | --- |

## 关键交错关系

- 截图入口产出的图片，可以继续进入图片文件入口同一套功能。
- 图片文件入口不需要截图捕获，但需要图片打开、OCR、标注、AI 处理和导出。
- CLI / agent 入口不展示 UI，但应复用 OCR、AI 翻译、AI 总结、内容识别和结果导出 action。
- 历史记录应同时记录截图来源和图片文件来源。
- AI 处理结果应回到截图结果面板，而不是只打开外部聊天窗口。

## V1 不确定项

- 滚动截图是否进入 V1.1，取决于截图基础链路质量。
- 截图触发是否开放给 agent，取决于权限和安全策略。
- 图片文件快捷键具体形态需要在交互设计阶段确认。
