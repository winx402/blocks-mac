# 验收与证据

## 基础矩阵

每项 UI／交互改动至少覆盖：

- 浅色、深色、跟随系统和窗口失活。
- 降低透明度、提高对比度和减少动态效果。
- 中文、英文、日文及长文本。
- 最小、默认和宽窗口；涉及浮层时覆盖多屏和负坐标。
- 鼠标、键盘、焦点、VoiceOver 名称和值。
- 正常、加载、空、错误、禁用、保存和危险确认状态。

## 设置页强制验收

- 分区标题与设置行标题左边缘误差不超过 1pt。
- 所有主要值控件尾端误差不超过 1pt。
- 使用真实 `NSHostingView` 渲染 820、980、1440pt 宽度，测量分区标题、行标题、Switch、Picker、文本框、Slider 和操作组；不得只测试数学布局模型。
- 值控件与标题首行视觉中心误差不超过 1pt，不得依赖固定像素偏移达到。
- 持久二态设置全部使用统一 Switch；一次性确认和多选才使用 checkbox。
- 长标题或说明换行后，值控件仍与标题首行和统一尾列对齐。
- 主题和语言切换不改变几何、滚动位置、焦点或窗口数量。
- 与同一窗口状态的 macOS 系统设置并排检查标题层级、分组底色、行高节奏与标签／值的距离。

## 证据层级

1. 安装版真实操作、截图、录屏和外部 App 行为。
2. AppKit／SwiftUI 集成测试与像素／几何测试。
3. 单元测试、静态门禁和构建。
4. 代码审查与文档推断。

低层级证据不能替代用户明确要求的高层级证据。无法取得的平台状态必须标记待验证，不能写成通过。
